# @cognia/plugin-sdk

TypeScript SDK for authoring Cognia plugins. This package owns the `define-*` authoring helpers and provides a **stable public façade** over the host runtime's plugin contracts — manifest schema, plugin context, registry functions, and hook/event types.

The SDK keeps lightweight authoring helper implementations in `packages/plugin-sdk/src/define/` and re-exports the canonical runtime registries and type contracts from `lib/plugin/` and `types/plugin/`. Plugin authors get a stable import path that survives internal refactors of the host runtime.

## Quick start

```ts
import { definePlugin } from "@cognia/plugin-sdk/manifest"
import type { PluginContext } from "@cognia/plugin-sdk/context"
import {
  defineNativeAnthropicTool,
  registerNativeAnthropicTool,
} from "@cognia/plugin-sdk/api/native-anthropic-tool"

const tool = defineNativeAnthropicTool({
  id: "screenshot",
  name: "screenshot",
  type: "computer_20251124",
  executeIpc: { invoke: "plugin_screenshot_take" },
})

export default definePlugin({
  manifest: {
    id: "com.example.screenshot",
    name: "Screenshot",
    version: "0.1.0",
    description: "Capture the screen.",
    type: "frontend",
    capabilities: ["native-anthropic-tool"],
    main: "src/index.ts",
    nativeAnthropicTools: [tool],
  },
  async activate(ctx: PluginContext) {
    registerNativeAnthropicTool(ctx.pluginId, tool)
  },
})
```

Some manifest capability ids predate the SDK's singular subpath names. The
package keeps these compatibility aliases so authors can import by the same
name they declare in `manifest.capabilities[]`: `@cognia/plugin-sdk/api/tools`,
`@cognia/plugin-sdk/api/skills`, `@cognia/plugin-sdk/api/connectors`,
`@cognia/plugin-sdk/api/components`, `@cognia/plugin-sdk/api/modes`,
`@cognia/plugin-sdk/api/themes`, `@cognia/plugin-sdk/api/commands`,
`@cognia/plugin-sdk/api/exporters`, `@cognia/plugin-sdk/api/importers`,
`@cognia/plugin-sdk/api/scheduler`, `@cognia/plugin-sdk/api/tray`,
`@cognia/plugin-sdk/api/hooks`, `@cognia/plugin-sdk/api/fonts`,
`@cognia/plugin-sdk/api/wallpapers`, and

The `processors` capability remains experimental in the host contract and does
not have a stable TypeScript SDK facade yet.

## What this package is not

- **Not publishable to npm as-is.** The SDK re-exports types from `@/lib/plugin/*` and `@/types/plugin/*` — paths that live outside this package. Inside the cognia-next monorepo that resolves cleanly through the shared `tsconfig.json` path alias. To publish externally you would either flip the dependency direction (move the source-of-truth modules into this package) or run a bundling build that vendors the cross-package re-exports into `dist/`. Both are deliberate follow-ups; see the project plan for context.
- **Not a renderer.** UI extension slots (`<PluginExtensionSlot id="..." />`) are mounted by the host. Plugins use `ctx.ui` or the extension API on `PluginContext`; the SDK only re-exports the contract enum so authors can reference slot IDs.
- **Not an MCP-tool registration surface.** Plugins cannot yet contribute MCP tools to the external bridge (per ADR-0008). The host owns that surface.
- **Not the consent overlay itself.** The SDK doesn't ship the consent UI — the host mounts it. But generic human-in-the-loop consent now exists end-to-end: any permission the guard classifies as the `confirm` tier routes through `getPluginConsentBroker().request(...)` in `lib/plugin/security/permission-guard.ts`, and the broker in `lib/plugin/security/consent-broker.ts` turns that into a `plugin:consent-request` event which the host's `<PluginConsentOverlay />` resolves (with an optional per-session grant cache). The boundary is deliberate: this gates the **declared** `confirm`-tier permissions a plugin requests — it is not a universal interceptor that prompts on every individual tool action, and non-`confirm` permissions are still resolved silently or forbidden by their tier. Plugins declare `permissions` in the manifest; `ctx.settings` / `ctx.storage` remain for any additional plugin-defined consent state.

## i18n

Plugins ship locale files (e.g. `locales/en.json`, `locales/zh-CN.json`) and declare them in the manifest's `i18n` block. At runtime the host merges them under the `plugin.<id>.*` namespace in `next-intl`. Plugins read translations through `ctx.i18n` (type re-exported from `@cognia/plugin-sdk/context`).

## WIT contract (WASM plugins)

The WIT interface for WASM plugins is mirrored at `plugin-sdk/wit/cognia-plugin.wit` — the canonical source remains `src-tauri/wit/cognia-plugin.wit`. Run `pnpm sync:plugin-sdk-wit` after editing the source, and `pnpm lint:plugin-sdk-wit` (or rely on CI) to fail builds when the two files drift.

## Versioning

Version `0.1.0` tracks WIT contract `cognia:plugin@0.1.0` (see ADR-0013). Bumping the SDK minor version is reserved for additive surface changes; major bumps follow the WIT contract major.
