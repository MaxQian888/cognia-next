# OMP RPC acceptance matrix

Date: 2026-10-06. Target: official OMP 18.6.1, reconfirmed against the official latest-release redirect on this date.

This audit distinguishes implemented protocol surface from tested behavior. It does **not** claim all features are fully usable. The 60-command count is checked against `RpcWireCommands` and named methods in `session-client.ts`; a typed wrapper or successful empty/error response is not positive functional acceptance.

## Evidence and status rules

- **DeepSeek**: behavior asserted by the completed baseline and extended live runs recorded in `deepseek-2026-10-06.md`, their `provider-smoke.mjs` assertions and the current test runner outcome. This matrix audit itself made no additional cloud calls.
- **Process**: behavior asserted by the completed official-binary `process-smoke.mjs` run, extended to 23 checks and 5 synthetic loopback model calls. It includes active delegated-shell cancellation through the adapter. Its model server is a synthetic loopback fixture, not DeepSeek.
- **Unit**: relevant mocked/regression assertion exists in package tests. It is not evidence that native OMP or the provider executed it.
- **Dispatch only / Surface only**: typed facade exists, with dispatch-only testing where explicitly stated. No positive functional acceptance is implied.
- **Limited / prerequisite**: exact limit is stated in the final column. Unsupported-feature and idle/error-path checks remain valuable negative checks but do not change this to full acceptance.

This matrix is intentionally conservative. Rows are upgraded only after concrete assertions and observed results are available.

The completed `controls-smoke.mjs` run adds **26 assertion groups and 57 loopback HTTP requests** against the official native binary. Its control, dialog, URI, shell and history checks are positive process evidence; unsupported fast mode and unknown OAuth provider remain negative evidence, and native abort_bash is an idle check. Running subagent and native retry paths were tested separately with positive assertions.

The final extended DeepSeek run exited successfully with **16 checks and 11 completed parent turns**, including image interpretation, handoff/compaction with recall, native JSONL import, decoded HTML export, native child completion/transcript and parent quiescence. The cancellation target reached HTTP200 before termination. The harness checked every request as HTTP200 or explicitly cancelled; no exact request total is claimed here because the final tool output was truncated. Cleanup observed zero processes/listeners, three releases and no stderr. See `deepseek-2026-10-06.md` for run history and harness corrections; prior partial attempts are not silently counted as clean full runs.

## Regression checks from the extended audit

The complete package suite passed **13 suites / 119 tests** in this audit, including eleven focused adapter acceptance regressions. These are mocked behavioral checks, separate from native process/provider evidence:

- Fork retains the source permission and instruction binding unless explicitly overridden.
- A pending process occupies one admission slot and cannot be counted twice.
- Native replacement prompts cannot bypass a high-level turn reserved during awaited model configuration.
- A stale state response cannot restore a previous native identity/resume locator after transition.
- Identity transitions invalidate old dialogs, prevent approval ID reuse and abort old host work while suppressing late results.
- New-generation dialogs arriving at the guard handshake survive adoption.
- A dialog emitted after a local command admission ACK remains answerable.
- Failed host resource release is retryable after confirmed process termination.
- A locally denied unsent transition preserves the unchanged live session; uncertain transport outcomes remain fail-closed.

These failures were reproduced before repair; the passing suite verifies the repaired paths without certifying a real production host's account, permission, sandbox or device integration.

## Prerequisites and architecture boundaries

**Native subagents** use OMP's native `task` tool/lifecycle registry; they are not a separate RPC spawn command. DeepSeek can power them. The extended native run covers spawned children, scoped subscription events, real transcript offsets, steer admission, active cancellation, yielded completion, and cleanup under the isolated fixture. The final live DeepSeek run additionally verifies real child completion, transcript result42 and parent quiescence; active steer/cancel remains fixture-provider evidence. Missing-child or empty-list responses validate boundaries only. The test host must attest and enforce guard rebinding and egress restrictions for descendants; declaration booleans alone do not establish this.

**Live voice** is specifically the GPT/Codex realtime surface. Upstream `live/transport.ts` selects `openai-codex`, requests OAuth access and emits `No Codex OAuth credential is available for a live call.` when unavailable. `live/controller.ts` then starts native microphone capture and speaker playback. A DeepSeek API key can run delegated text tasks but cannot authenticate this realtime connection. Active voice/mute/cleanup remains separate credential/device acceptance; no microphone recording is part of this audit.

**Word prediction** is local, not a DeepSeek completion. Upstream selects `ngram`, `smollm`, or macOS `apple` using a daemon scoped by agent directory; `off` returns null before contacting it. The extended run checked actual ngram prediction without another cloud provider; apple remains untested and smollm may require local weights. A safe test must isolate its agent directory and own daemon cleanup, because killing the parent RPC process alone does not prove a globally brokered daemon stopped. Startup can take about two minutes, longer than the package's default 30-second request timeout; use an explicit host timeout budget.

**Handoff** uses the current selected model and credential to generate a document and commits same-session compaction maintenance. It does not inherently require a new provider or product integration. The final DeepSeek run verifies the real summary, persisted entry and post-handoff context. **Compaction**, retry, queue interruption, native tool flows and host-URI callbacks likewise can be accepted in isolated package tests.

**Login** invokes a supported provider's OAuth flow, not API-key installation. Upstream rejects secret input and input requested before the authorization URL. A real OAuth acceptance needs that provider's account and browser/user interaction. Ordinary OAuth input has an upstream 600-second UI timeout; the adapter host must choose a compatible operation timeout. An unknown-provider rejection cannot be called successful login.

**Fast mode, cache warming and images** are model-specific. The final DeepSeek run verifies actual image forwarding and color interpretation. Fast mode was tested only as an unsupported-model rejection, and cache warming only as native setting selection; real fast inference and cache-hit/billing effects are not established.

Production package imports remain limited to local files, `@cognia/agent-contracts` and `@cognia/agent-runtime-kit`. A literal registration/import search in application `lib`, `components`, `hooks`, `app`, `cli`, `src-tauri`, `scripts` and `packages/agent-orchestration` found no `@cognia/agent-omp` or `omp-rpc` references in code (generated documentation and tests excluded). Product registration, account lifecycle, discovery/migration, permission UI, CLI and real desktop host enforcement remain outside this package and require the user's separate integration approval.

`OMP_CAPABILITIES` marks native entries with `evidence: "protocol-spec"`; this is an upstream declaration, not certification. Consumers must intersect these declarations with runtime model support, host policy and actual integration availability. The README's complete typed-surface statement is accurate, but it must not be paraphrased as "all functionality verified".
