# DeepSeek live provider acceptance

Date: 2026-10-06
Result: PASS (latest extended live run: 16 checks; prior baseline runs retained below)

## Tested route

`OmpRpcClientAdapter` → official OMP 18.6.1 darwin-arm64 → loopback credential-injecting transport → `https://api.deepseek.com/chat/completions`, model `deepseek-flash`.

The loopback transport forwarded real provider requests and streamed real responses. It generated no model responses. OMP retained its built-in DeepSeek model configuration and pricing; only the endpoint, ephemeral local token and test output limit were overridden. macOS Seatbelt limited OMP egress to loopback. The actual credential existed only in the test launcher's and forwarding process's memory, and was never passed to OMP or saved in configuration/source/test reports.

The authenticated `/models` endpoint returned HTTP 200 and advertised `deepseek-flash`. Each of the two earlier baseline runs made eight chat completion requests; all returned HTTP 200. Those baseline runs account for sixteen completion requests and two model-list probes; they are separate from the extended runs below.

## Extended live acceptance

The final extended run exited **0** and passed all **16 checks** against `deepseek-flash`. It used the independently packed ESM distribution and an offline-installed dependency snapshot, avoiding stale workspace sibling `dist` files. The package tarball passed all 14 exports and strict NodeNext consumption checks before this run.

| Extended behavior               | Observed assertion                                                                                                                                          |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Baseline chat/tool/session path | Streaming, multi-turn recall, thinking, reasoning continuation, fork and resume all passed again                                                            |
| Reasoning                       | High effort on a small constraint problem produced 24 mapped thinking deltas; actual provider SSE reasoning was counted without storing content             |
| Image                           | A synthetic 64x64 red PNG reached DeepSeek as image input; model answered `RED`                                                                             |
| Handoff                         | Native handoff persisted a compaction summary containing `COBALT-731`; next model turn recalled it                                                          |
| Compaction                      | Manual native compaction returned summary, retained-entry ID and nonzero prior tokens; next model turn recalled the code                                    |
| History                         | Pure package JSONL parser preserved native identity/context; decoded native HTML session payload contained the code                                         |
| Native subagent                 | Parent invoked native `task`; child completed and its actual transcript contained `42`; native lifecycle events and parent settled state were both observed |
| Cancellation                    | Target request correlation identified the cancellation prompt's real HTTP 200 response before process cancellation; active iterator rejected                |
| Cleanup                         | No child processes or listeners remained; three prepared resources released; zero stderr bytes                                                              |

Eleven parent turns completed, in addition to maintenance, child and cancellation requests. The extended harness limits the run to 32 completion requests and every request to at most 2048 output tokens. The passing assertion allows only HTTP 200 or an explicitly cancelled transport request; cancellation is distinguished from a provider failure. No exact extended HTTP-request total is claimed because the captured verbose output was truncated. Provider token/cache/cost values are native estimates, not billing reconciliation.

The extended input adds only a generated color fixture, synthetic ledger text, and arithmetic subagent instructions. OMP and its native children have loopback-only network access; native file/shell tools are denied by the isolated guard. The API credential remains solely in the forwarding process's memory and is never written into the prepared OMP environment.

Several development runs stopped on acceptance assertions before the final pass. These were retained as diagnostic findings: exported HTML embeds base64 JSON; low-effort thinking may legitimately emit no reasoning for trivial arithmetic; parent prompt completion can precede child completion; child completion can precede the parent's background continuation settling. The harness now decodes the export, uses an explicit reasoning task, waits for child and parent boundaries, and correlates the exact cancellation request. Those earlier partial runs are not reported as full passes.

## Reproduction and limits

`../scripts/provider-smoke.mjs` reads a JSON object containing `apiKey` from stdin and requires `OMP_BINARY`. Supply secrets through a hidden prompt/pipe, never literals in command arguments. The script verifies the official binary SHA256, limits each request to at most 2048 output tokens, and caps the baseline run at twelve completion requests or the `OMP_EXTENDED=1` run at 32. It does not automatically install OMP. Set `OMP_PACKAGE_ROOT` to an isolated packed installation when workspace dependency artifacts are stale; `pack-test.mjs` with `OMP_KEEP_PACKED=1` creates that installation without changing sibling builds.

This validates the isolated package's real DeepSeek chat, image, tool, maintenance and native subagent paths. It does not register OMP in the application, certify application UI/CLI behavior, test live audio/OAuth, exercise every model-specific RPC behavior against DeepSeek, or certify a production host's descendant sandbox enforcement. See the complete [60-command evidence matrix](rpc-acceptance-matrix.md). Product integration still requires separate approval.
