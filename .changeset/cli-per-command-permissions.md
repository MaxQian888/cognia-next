Judge a shell call in the CLI by the command it runs, not by the name of the tool that runs it. The built-in tool catalogue rates a tool, and `bash` is rated `high` because `bash` can do anything, so every single shell call arrived at the approval prompt wearing the same red badge: `ls` was as ceremonious as `rm -rf /`. A prompt that never varies is one people stop reading, which cost them the prompts that mattered. The repository already had the answer in `lib/claude/permissions/command-safety.ts`, the classifier the desktop Auto-mode runs on, and the CLI now runs on it too. It reads the command line, follows `&&` chains and command substitutions, knows `git status` from `git push`, escalates anything behind `sudo`, refuses to call a write redirect read-only, and names catastrophes outright. Read-only work now runs without interrupting anybody, an ordinary mutating command still asks and the prompt says which part of it is the risky part, and a command the classifier calls catastrophic opens on Deny so the dangerous answer is never one reflex Enter away. The headless gate gained the same rung, where the only way past a denied `ls` used to be `--yes`, which turns the whole gate off. "Allow always" also narrowed to the call the user actually read: it used to remember the tool, so agreeing to one build silently bought every future `git push --force` and `rm -rf`, and it now remembers the command, listed and removable by command in `/permissions`.
