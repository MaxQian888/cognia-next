Run external agents from a browser paired to a Host, and see which agent CLIs that Host actually has before choosing one. A stdio agent was refused anywhere but the desktop app, with "the stdio transport requires the desktop (Tauri) runtime", even though the spawn commands already crossed the companion plane and the Host could have started the process immediately. The gate now asks where the process would actually run and names the real obstacle when there is one, so a Host mid-handshake, a Host too old to spawn, and a device without the Agent Control grant each say what to do instead of all reading as "install the desktop app". The Add Agent picker asks the Host what it has and badges every preset with installed (and its version), not found, or fetched-on-launch for the runtimes that only exist once npx downloads them, so a missing CLI shows before the form is filled in rather than as a spawn error after connecting. A verdict of this kind is no longer kept across restarts: it recorded which runtime the app happened to be in, which changes when a Host is paired or the Agent Control grant arrives while nothing about the agent moves, so a stored copy outlived the situation it described and the panel preferred it to a fresh check. Existing profiles drop theirs on load, which is what lets an agent that was refused before this change report its real state without the user clearing anything.
