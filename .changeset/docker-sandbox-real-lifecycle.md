Computer-Use sandboxes become real machines. Containers are no longer created with `docker run --rm`, so stopping one keeps it and everything written inside it, and deleting is a separate, genuinely destructive action (it used to just call stop). Adds provision, suspend and resume alongside start and stop, with suspend implemented as `docker pause` so the desktop session survives it rather than silently rebooting. Docker's own state is now read back through `docker inspect`, so a health check can say whether a machine is stopped instead of only that it did not answer, and a container that outlived an unclean quit is adopted by name instead of leaving that connection permanently unstartable. Machines keep running after you quit the app and are picked up again on the next launch. A session bound to a machine can now run its shell and file work inside it: this was previously withdrawn because a bound desktop only proved GUI isolation, and it is re-enabled only for providers that actually carry it, with any per-call request for stricter confinement than the container was built with refused rather than quietly run. Settings and the device console show lifecycle state and reachability as separate answers, with every lifecycle action and the container's frozen policy in a detail panel.
