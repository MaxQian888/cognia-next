Companion sync now completes, connects and stops freezing the shell. Four fixes that only showed up against a real Host: the Host charged every read to the strict rate-limit bucket, so a first pairing synced 10 of 25 tables and then refused even the manifest refresh — the wide read-only bucket that was built for exactly this burst is now used, and a paired client boots 25/25 with clean cursors. A browser reaching the Host over its plaintext loopback listener was refused an event socket as if it needed pinned TLS, leaving a correctly paired tab with a working RPC plane that never synced and never left "the current host is offline". Subscribers to the connection state kept listening to the transport instance that pairing had replaced and destroyed, so the status bar read "Offline" over a live connection. And the sync itself is now staged — preferences, characters, the chat list and its per-conversation state land first and the client goes online there, while transcripts, plans, runs and then the libraries fill in behind the running UI, applied 200 rows at a time with the main thread handed back between slices and pages. Host-side writes to every syncable table now announce themselves too, instead of only the five the Inbox relay covered, so a session, plan, memory, skill, MCP server or template created on the Host reaches paired clients immediately rather than at the next unrelated sync.
