Workflow nodes: options the executors already honour now have fields in the inspector. A node with a dedicated config form has no raw-JSON escape hatch, so any param the form omitted was unreachable from the editor even though the runtime read it — seventeen of them across thirteen node kinds. The worst was long-term memory: `action.memory.store` could not set the memory type, its stable key, or its provenance, which made the entire procedural-memory path ("always do X" rules) impossible to author from a workflow and left the step failing on a rule the user had no way to satisfy. Also newly reachable: relevance floor and type filter on memory recall; temperature and turn timeout on the agent turn; the twin-bound character on an AI prompt; the preferred teammate, dependencies, workspace access, task kind, repository and file ownership on a team task — the last four of which a synthesized team workflow already carried invisibly; command arguments on all three terminal kinds; the event correlation key on Wait; the reducer seed on Aggregate; merge-forwarding several messages at once on a connector forward, which also stops claiming the single-id field is required when a list is set; clearing a scheduled task's end date, previously impossible once set; and the two framework-codegen switches on Web clone.
