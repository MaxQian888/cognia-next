Desktop automation is one feature again instead of several disconnected ones. The global whitelist and the sandbox "automation policy" were two rule sets gating the same call from two Settings sections that never mentioned each other. They merge into a single Access rules tab that states which stage each rule belongs to (admission, which any one match satisfies, and post-consent restrictions, which every filled list must satisfy) along with the hard boundary no setting can open. A paired phone or browser can now watch a desktop host's automation engine and halt it: engine state, default tier, decision counts and the recent decision list, plus a kill switch gated on the same remote-control capability as the consent prompt. Driving a desktop from another device is still refused by design. The mobile Computer Use page shows that supervision instead of the desktop settings section it used to embed, which could not run there at all: its tabs reported "requires the Tauri desktop runtime", its six-tab strip overflowed the viewport, and tapping a tab navigated the reader into desktop settings. The audit log renders as cards below the `sm` breakpoint rather than a six-column table, the "no automation engine here" notice is now one translated component rather than three hand-written variants (one of which told users to run a build command), and the same four supervision commands are reachable from the CLI through `cognia host`.
