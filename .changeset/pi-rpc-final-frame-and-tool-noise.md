Stop losing a Pi turn to a missing newline, and stop printing a line per tool call about nothing. Pi's RPC framing is newline-delimited, and whatever was left in the decoder at end of stream was reported as a truncated frame and discarded. That is right when the process died halfway through writing, and wrong when it simply finished the frame and exited without a trailing newline, which is what a lot of programs do on their last line. The report is terminal, so a complete 63k-character final message was thrown away and the turn failed with "Pi RPC stream ended mid-frame (63471 chars discarded)": a sentence about a newline, and not one word about what the user had lost. A leftover frame is now parsed before it is judged, delivered when it is whole, and quoted in the error when it genuinely is truncated, so a real framing failure says what the agent was in the middle of. Separately, an external agent finishing the arguments of a tool call emitted a transcript row reading "External tool input completed: call_09be7183…". A turn with fourteen tool calls therefore ended with fourteen of them stacked under it, pushing the answer off the screen to say something the tool card above already said. It is progress on a call, and it now goes where the rest of the progress goes, along with two more rows that reported only their own existence: a count of the agent's configuration options, and a session-metadata update carrying no title.
