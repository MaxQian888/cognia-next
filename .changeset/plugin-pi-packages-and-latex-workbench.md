Plugins can ship a Pi package: a plugin's detail page now prepares its dependencies, installs it into your Pi (user or project scope, falling back to a settings edit when Pi is not on PATH) and removes it again, and a Pi agent can opt in to load a plugin's Pi extension in its Cognia-hosted sessions. The new Pi LaTeX Workbench plugin uses this: Cognia agents drive the `latexwb` host CLI (import, build, draft lint, page rendering, release pipeline) with LaTeX skills and `/latex-write`, `/latex-revise`, `/latex-tune`, `/latex-check`, while approvals stay with you. Plugin conversion now keeps a whole Pi package (extensions, prompts, themes) instead of failing, follows the vendors' October 2026 documentation (Agent Plugins 1.1.0 and Copilot/OpenHands namespace folders, Kimi's real `plugin.json`, Codex, Cursor, Copilot, Devin, OpenCode, Claude Code and Gemini CLI hooks), and adds Factory Droid, Qoder, CodeBuddy, Auggie and Open Plugins (`.plugin/plugin.json`). For plugin authors: `cliTools` argv literals and env values now expand `${COGNIA_PLUGIN_ROOT}` (shown expanded in the consent prompt), and settings fields can be localized with `titleKey`, `descriptionKey` and `enumItemLabelKeys`.
