Make remote supervision of desktop Computer Use actually work when your phone is asleep. Previously a per-call consent prompt only reached devices with an open WebSocket, so a backgrounded phone never saw it and the request fail-closed after a hard-coded 30 seconds — remote computer-use effectively could not be approved away from the desk. Consent prompts are now a push trigger, so a locked phone gets a notification naming the action and the app it targets (never the window title or the command detail, which stay on the encrypted channel). Each prompt now carries a downscaled screenshot of the host screen so you can see what you are approving instead of deciding from a bare set of coordinates; if the desktop is focused on a password or credential prompt the frame is blanked and labelled as such, regardless of the global screenshot-redaction setting. The consent wait is now configurable (Settings → Automation → Model behavior) and defaults to 90 seconds, bounded so an answer can never arrive after the underlying tool call has already given up. Finally, "always allow this session" is replaced by a time-boxed grant — 15, 30, or 60 minutes — that is scoped to the conversation it was granted in, so an agent can work through a task uninterrupted without leaving a standing authorization behind.
