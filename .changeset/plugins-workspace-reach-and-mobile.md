Plugin workspace overhaul. `/plugins` gets a phone body: tapping a row used to write a store nothing was watching, so the detail was reachable only through a 16px icon, and `/me/plugins` carried a second, weaker plugin surface with no install, permissions, configuration or uninstall. Both now render the same list, detail, filters and dialogs the desktop uses, and every enable/disable goes through one host-aware seam instead of three call sites that disagreed. On the desktop the capability rail and the row's capability chips were gated above the width the default pane split ever reached, so the library showed only name, version and status. The panes are rebalanced and the rail and its Sheet fallback now share one container query. Discover's eight-item switch is split into ranking and source, moved onto the shared header toolbar, and search matches the author and manifest keywords. The product also stops hiding what it cannot do: desktop-only install lanes and sections render disabled with the reason, plugins whose runtime this host cannot run carry a compatibility badge, the WASM and VS Code loaders record the degraded runtime the way Python already did, and the install button says why it is unavailable instead of failing into an untranslated toast. Plugin icons, screenshots, keywords and version changelogs are rendered for the first time, the capability filter covers every capability rather than 18 of 69, secret config fields get a masked input, and three dead paths are connected: a plugin asking for a permission at runtime no longer hangs forever, "notify only" auto-update actually notifies, and the analytics view has something to show.
