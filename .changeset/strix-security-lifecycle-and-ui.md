Strix Security keeps its scans honest across reloads and is easier to use in the workbench. A scan row left "running" by a previous session is now marked cancelled on activation instead of spinning forever, and deactivating or reloading the plugin aborts an in-flight scan rather than orphaning its terminal session — a remounted panel still offers Cancel. `/security <target>` now pre-fills the scan form, and the panel remembers your last target and model override between sessions. The scan form tucks the model and session-only API-key overrides behind an Advanced disclosure and re-arms the authorization checkbox the moment you edit the target, so consent can never carry silently to a different system. Scan history shows each run's timestamp, duration and a status-colored badge, highlights the run you're viewing, and refuses to delete a scan while it's still running; both delete and "Clear all" now ask for confirmation through the host dialog and remove the on-disk report directory that holds the proof-of-concept exploits. Findings show their code locations with file/line ranges, carry a verdict badge once triaged, and can be filtered between all, open and muted, spreading into two columns when the panel is docked wide; a failed, cancelled or in-progress run shows a status banner so an empty findings list can no longer pass for a clean scan. The console bounds itself to the newest output, says so when earlier lines were dropped, and stops yanking the scroll position while you read upward; terminal output no longer mangles multibyte characters split across PTY chunks. The plugin also drops a database permission it never needed.
