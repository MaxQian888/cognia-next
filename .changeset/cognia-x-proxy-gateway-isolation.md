`cognia-agent x <claude|codex>` launches are now isolated instances with real proxy and gateway support. New flags and per-backend config (`agentBackends.<agent>.*`): `--gateway <url>` picks the gateway listener, `--proxy <url|off>` / `--proxy-bypass` route both the fallback proxy's upstream hop and the agent's own traffic through an HTTP, HTTPS or SOCKS5 egress proxy (loopback and the gateway are always exempt), and `--profile <name>` / `--shared-home` run each launch in its own `~/.cognia/x/<agent>/<profile>` home instead of the user's `~/.claude` / `~/.codex`. The agent no longer inherits `ANTHROPIC_*`, `OPENAI_*` or `CLAUDE_CODE_OAUTH_TOKEN` from the shell, so the gateway credential is the only one it holds, and the route ticket minted for a launch is revoked when the agent exits (new bridge route `POST /api/dev/gateway/route-ticket/revoke`). A configured provider `baseURL` now actually reaches the fallback proxy. On the host side the LLM gateway's upstream calls follow the live network-proxy policy and its bypass list per request instead of a client frozen at startup, and headless `cognia-server` publishes `HTTPS_PROXY` / `NO_PROXY` from its environment as that policy.
