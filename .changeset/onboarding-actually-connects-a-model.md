First-run setup now leaves you with a model that actually works, whichever provider you use. Seven defects made it possible to walk the whole flow and end up with nothing usable:

- **The browser and BYOK-mode phones got a sign-in step they could not use.** Those shells resolve chat credentials from `providerSettings` only — the OS keyring is never read — so the three subscription sign-ins configured nothing, and the pasted API key went to a legacy slot (`settings.apiKey`) that neither reads. The key now goes to `providerSettings.anthropic` (where every runtime looks) with the legacy slot written alongside, and standalone shells are offered that path alone, under their own heading, with the reason stated.
- **Connecting ChatGPT or OpenCode dispatched your first run to Anthropic.** Nothing in the sign-in path wrote `defaultProvider`, so the turn fell through to its literal default. Connecting now writes all three pointers the runtime reads — the vault's active account, the ADR-0028 scoped default, and `defaultProvider` (which also re-syncs `defaultModel`).
- **"Do you already have a model?" read the wrong field.** It tested `defaultProvider`, which is the active provider _id_, not evidence of a credential — so a user who had just connected Claude Pro was told they had no model, and a user who had only picked a provider in Settings was skipped past sign-in. It now folds together the chat path's own credential probe, a settings-resolved AI-SDK provider, the legacy key, and an authenticated `claude-code`, and latches the answer so the step sequence cannot change underneath you mid-flow.
- **A machine with an existing Claude Code login was sent through a full browser sign-in.** The step forced the Anthropic dialog past its own "reuse this login" default — the exact machine the preceding scan step exists to find.
- **The last step let you "succeed" with no model.** Its cards open a session, queue a prompt and mark setup complete, so the failure surfaced later in the chat pane. They are now inert without a model, above a notice that offers the way back to sign-in.
- Connecting shows which account and plan it connected and lets you continue from the action row, instead of advancing out from under you.
- **Only Anthropic, ChatGPT and OpenCode had a first-run path at all.** If you pay for OpenAI or Google, run a local Ollama, or use an Anthropic-compatible endpoint like Kimi or GLM, setup had nothing to offer you and you had to find Settings → Providers unaided. The key step now offers the whole built-in catalog through a searchable picker, with the form adapting per provider — a key where one is required, a base URL where one is needed (prefilled with the well-known port for a local server), and an honest "this one needs more than a key" for the few that do.
