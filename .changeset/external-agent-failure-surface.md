Say which external agent failed, where you pressed the button, and what the failure was wrapping. A connect failure used to be one string for the whole panel, drawn as a red banner above the list of agents and repeated as a toast, so with more than one agent configured it could not name the one that failed, and Dismiss was the only state it had: the single record of a failed connection was gone after one click, and a retry that failed the same way looked like it had done nothing. The report is now recorded against the agent, drawn in that agent's row with a retry, cleared when a new attempt starts, and it carries the cause chain, which is the difference between "could not connect" and the sentence that names the actual obstacle. The connection pills lost their solid fills, since an error beside an agent name is one field of that agent's state rather than an alert about the panel. Choosing an agent that lists no models of its own now says why: not connected, connected with nothing open, or asked and unable to answer, three situations that previously all rendered as an unchanged model list. Connection state also stopped having two answers: the panel rendered a copy of the agent list rebuilt inside its own hook, while every other surface read the shared map, so the two disagreed for as long as the rebuild took and an agent could read connected in the composer and disconnected in the manager. Both now read the map, which the runtime projects into, and the projection listener moved to app startup: it used to live inside a hook that only three panels mount, so an agent that changed state with all of them closed changed nothing anywhere. Picking a runtime in a conversation works again: the chip wrote the conversation's lane but read its current selection back from the app default, so the radio group answered with the row the user had just left and choosing an external agent looked like it did nothing. The catalog now resolves against the same lane the chip writes. The chip also stops hiding its own name on a wide composer, where it had been reduced to a bare icon beside empty toolbar: the built-in runtime collapses to a glyph on a genuinely narrow row, by the same measurement the rest of that row lays itself out by, and an external agent keeps its name at any width. Choosing an external agent now brings it up. A configured agent that had never been connected was selectable with nothing saying the lane could not dispatch, and the first send reached the manager's adapter map and came back `Agent not found: <id>`, a sentence about the manager's internals offered as the reason the agent would not run. Selection registers the agent and connects it, the connect button does the same rather than assuming startup already registered it, and a failure is recorded against the agent where the panel draws it. Subscribing to a host event channel also waits for the host to acknowledge it: the companion plane's subscribe is synchronous and its control frame is dropped while the socket is still opening, so a caller that subscribed and immediately started the work it wanted to watch raced its own subscription and read an empty stream, which is what made a healthy Pi report as an unsupported version on a paired browser.
