Memory V2 hardening: identity-bound, conditional, idempotent external memory operations. Agent-declared memory policy is now a hard ceiling that session toggles can only narrow; plugin/MCP/companion/workflow surfaces resolve caller identity from the host binding instead of request-supplied namespace fields, so a request can only narrow — never grant — access. External update/forget accept `expectedVersion` compare-and-swap and `operationId` idempotency keys backed by a new `memoryOperations` ledger (schema v228); memory jobs carry a fencing epoch so stale workers cannot commit after lease replacement; vector retrieval searches only the authorized corpus instead of querying globally and post-filtering; chat branch/workspace context comes from the session's execution binding rather than the UI-active store; backups now carry retrieval tombstones so restored data cannot resurrect deleted memories; same-source evidence counts once toward claim support; shared external-agent files record all consuming runtimes; and each memory-context injection ships an inspectable snapshot receipt (rows, versions, content hash, expiry, delivered state) on the assistant message.
