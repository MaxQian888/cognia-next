Cloud/self-host installs now run three subsystems that previously booted only in the desktop WebView. The issue tracker's runtime half — its four issue sources, the run bridge that dispatches an issue to an agent engine, the lifecycle notification watcher, label seeding and the GitHub refresh schedule — starts in the headless brain, so a cloud board actually drives runs instead of only rendering rows synced from elsewhere. Plan approval/discard notification actions and character-pack warning refresh likewise now start server-side. A new `pnpm audit:headless-registry` gate makes this class of defect fail the build: it reports any provider-initializer runtime effect the brain never calls, and requires a per-symbol reason for anything deliberately kept desktop-only. `pnpm audit:host-parity` also stops being report-only — its ratchet now enforces, and it no longer miscounts guards that appear solely in comments.

The companion API's published response contract gets substantially more precise: 95 commands that previously declared a response matching any JSON now carry real schemas. That covers the whole read surface of Source Control (status, log, diffs, branches, refs, tags, stashes, worktrees, blame and conflicts) derived from the Rust wire DTOs, the entire scheduler RPC surface including the full `ScheduledTask` and `TaskExecution` envelopes, and the background-job, external-bridge, task-workspace, Matrix-crypto, code-server, workspace-file and connector-attachment families. Date fields are documented as the ISO-8601 strings they actually are on the wire rather than the `Date` objects the client rehydrates them into. `connectors_ensure_server` also gains the command descriptor and disposition it shipped without.
