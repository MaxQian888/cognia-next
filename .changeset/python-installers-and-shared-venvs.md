Python plugin environments can now be shared, and are provisioned by `uv` when it is available. Every plugin used to get its own virtualenv built by `pip`, which meant a second plugin depending on the same packages paid for them again in disk and install time. Environments are now shared by default, but only behind a resolution the host performs before installing anything: the union of every contributing plugin's requirements is solved as a dry run, and a plugin whose requirements do not fit is given its own environment and told why. A new plugin can never break one that already works. A plugin can opt out up front with `pythonVenv: "isolated"` in its manifest, and the user's setting overrides that either way. The installer is pluggable — `uv` when it is on PATH (much faster, and its resolver makes the dry run cheap), `pip` otherwise, or a custom tool driven by argv templates; a custom installer never gets the shared environment, because sharing depends on a dry run the host cannot express in an arbitrary CLI. Switching installers deletes nothing: each environment records what built it, and the next install notices the mismatch and rebuilds, so a switch is safe to make offline. The same check catches an environment built against a different interpreter version. `uv` can be installed from the app using the detected interpreter's own pip rather than a piped shell script.
