Fixes across the workspace-concurrency work: a split pane's composer now reads the draft state it writes, so its permission mode, reference chips, staged context and per-send toggles belong to its own conversation instead of the pane beside it. Two turns can no longer end up in the same working tree when the concurrency cap was saturated, and a turn's tree is now identified by the directory it actually runs in, so two plain conversations sharing a workspace are serialized. The tray menu keeps updating while a conversation streams. The execution monitor stops blaming the folder for a turn that is only waiting for a permit. A message starred in a background pane stays starred. Scheduled tasks are scoped to their workspace in both schedule views, and a schedule created by a workflow node or an interval `/loop` is attributed to the conversation that created it. "N running" counts and the background-runs chip no longer present a conversation that already failed as work in flight.

Follow-up correctness fixes on the same work: a turn queued on a working tree can no longer be stranded when the leg parked ahead of it is cancelled — the tree is drained whenever a permit frees, not only when its previous holder releases. The send path now consumes the composer's own conversation for staged context selections, the per-send web-search toggle, ad-hoc skills and slash-command overrides, so a background pane no longer sends the material staged in the pane beside it; the skill chip's × and the permission-mode slash command act on the pane they are in. Starring a message keeps every open conversation's view of the starred set in step. A scheduled task created through the UI no longer re-runs the workspace lookup a second time.
