Fix plugin teardown never running, plus four defects found auditing the built-in plugins against the current plugin SDK. Disabling a plugin now actually releases what it holds: the runtime was calling a plugin's `deactivate()` without its context, so every built-in whose cleanup is guarded on that context silently skipped it — most visibly, Clipboard History's clipboard-polling loop kept reading the clipboard after you disabled the plugin and revoked its clipboard permission, and the slash commands of Computer Use, OCR, Screenshot, Web Clone and Clipboard History stayed in the command list after their plugin was turned off. Ripgrep Tools no longer lets a search pattern or path be reinterpreted as a ripgrep option, closing a path from a crafted search argument to command execution. The Backend Refactor roles no longer carry a permission bypass into ordinary chat — picking "Refactorer" from the character list now prompts for file and command permissions as usual, while the headless refactor workflow keeps running unattended. That workflow also passes each step's output to the next again, instead of feeding the following agent an empty analysis, plan, or gate output. Deep Research now declares the two search hosts it contacts and drops a secrets-write permission it never used.

Security and correctness fixes across the rest of the built-in plugins. GitHub Delivery no longer leaves your repository token inside the cloned worktree's git config, where the AI agent working in that clone could simply read it — the credential is now supplied per-operation instead — and the operations its prompt already forbade (`git push`, `git remote`, the `gh` CLI) are now blocked by the permission gate rather than by asking the agent nicely, which matters because issue text is written by anyone who can open an issue. GitHub Delivery's inbound webhook UI no longer offers to start a public tunnel and hand you a URL to paste into GitHub: nothing was listening on the other end, so those deliveries could only fail silently; repos continue to be tracked by polling. Strix Security no longer reports a scan as "Done · 0 findings" when it produced a report it could not read — that now shows as an inconclusive run — and deleting scans (or "Clear all") now also removes the scan files on disk, which hold the full proof-of-concept exploits, instead of only clearing the list. Web Clone rejects a relative `-o` output path that would write outside your workspace. Workspace Tools' three agent tools now describe their parameters to the model instead of exposing none, its search skips `node_modules` and similar build directories with depth and file-size limits (and says so when results are truncated), and it drops a filesystem-write permission it never used.

Several built-in plugins that could not work at all now do. Deep Research runs: it asks for model access up front instead of failing mid-run with a raw permission error, and its web searches now reach Exa/Tavily on the desktop app, where they were previously blocked before leaving the app. The Python Demo plugin can be enabled — it declared a message hook without the permission that hook requires, which failed the entire plugin load. The WASM example formatter's workflow node appears with a proper label and parameter form and actually runs, instead of failing every invocation. Stagehand Browser points at the MCP server package that still exists (the previous one was removed from npm, so launching it always failed) and asks for the model key it actually uses. In the workflow editor's AI tools, "cancel run" can now genuinely cancel a running workflow instead of always reporting nothing was running after asking you to approve it, and "auto layout" honours the top-to-bottom/right-to-left direction you ask for instead of silently laying out left-to-right. Claiming a Pet daily-quest reward no longer burns the quest when the reward can't be granted — it stays claimable and can be retried.

More built-in plugins that silently did nothing now work. `/ocr <path>` and the OCR tool's file-path mode run instead of always erroring, and OCR now honours the provider, languages and format you configured rather than ignoring them; the tool also stops offering the agent an attachment-id source nothing in the app can supply. The Zhihu content pipeline no longer runs green every morning while saving nothing: its ranking step uses your configured model routing instead of falling back to a placeholder echo, its hot-list step runs unattended so the scheduled run isn't left waiting on a confirmation dialog nobody sees, and a step that can't read the previous step's output now fails visibly instead of reporting success with zero rows saved. The two external-agent example plugins actually register their contributions when installed, and the LSP test plugin ships the server binary its manifest points at.

Plugin slash commands now use the name the plugin declares. Typing `/browser`, `/stagehand`, `/sandbox`, `/skill` or `/record-skill` works — previously the declared name was ignored and only an internal id like `/playwright.attach` or `/skill.list` resolved, which nothing told you. Command aliases work at all for the first time (they were registered under a name no one could type). Screenshot, Playwright, Stagehand, E2B Sandbox, Anthropic Skills and Skill Recorder now declare their commands in their manifest, so those commands also appear in the command palette, are listed as contributions on the plugin's detail page, and are cleaned up properly when the plugin is disabled. Workspace Tools now refuses to read outside the folder you have open — `workspace_read_file` could previously be pointed at any file on your machine, including SSH keys.
