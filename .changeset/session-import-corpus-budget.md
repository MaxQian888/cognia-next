Fix the external-agent session-history import freeze on large histories: Codex and the portable sources (Cline, Cursor, Copilot CLI, Qwen Code) re-walked, re-read, and re-parsed their entire corpus once per imported session, and the Codex scan parsed every rollout a second time just to filter children — O(selected × corpus) work that hard-froze the renderer on multi-GB histories. Corpus parsing is now cached per scan input (one pass per run), the children filter uses summary-level parent ids, Claude transcripts are read once instead of twice, team/task artifacts are read once per run, directory walks use `readDir` entry types instead of a `stat` IPC per entry, and fs-watch single-file events stay single-file instead of triggering a corpus rescan. Filesystem reads now run through bounded 8-lane concurrency with periodic main-thread yields so large scans stay responsive instead of monopolizing the renderer, watch-triggered imports are serialized through a path-coalescing queue so an actively-writing agent can no longer spawn concurrent imports racing the same file, directory walks descend subdirectories in parallel, and the Codex summary scan JSON.parses only the handful of lines it reads (session meta, first user message, head/tail timestamps) instead of every line — verified byte-identical to the old per-line parse on real rollouts.
