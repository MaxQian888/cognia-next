Projects can run their agents in a container image of their choice (ADR-0182). A project environment's new "Runtime environment" panel picks an image from the deployment's catalog, or approves the one the repository declares in `.cognia/workspace.json` or `devcontainer.json`, and shows what the next run would do before it happens. Each run is readied where its environment puts it: a run that needs a sandbox it cannot get is refused with a reason instead of silently running unsandboxed. The agent settings show the sandbox the server actually gave each run, with its image digest, isolation tier and user. Tenant administrators get a new "Image catalog" settings page to add, edit and revoke images on servers that run the sandbox pool. The compose deployment gains an optional `docker-compose.runtime-environment.yml` overlay and a smoke script for it. Everything is off unless an operator enables the pool and a project opts in; deployments and projects that do neither run exactly as before.
