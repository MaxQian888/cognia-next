Plugin scaffold produces an installable project again. `cognia plugin new --kind ts` previously emitted a `package.json` depending on `@cognia/plugin-sdk` and `@cognia/plugin-ui` at `^0.1.0` — neither is published to any registry, so `pnpm install` failed outright and no third-party author could get past the first step. The scaffold now vendors the TypeScript declarations it needs (SDK, UI kit, and the `provider-types` / `provider-core` surface the SDK's public types reach into) and resolves them through `tsconfig.json` `paths`, declaring only real published packages as dependencies. Runtime is unchanged: both `@cognia/*` specifiers stay external and the host supplies its own instances.

Also fixes scaffold gaps that the broken install had been masking: `src/panel.tsx`, `src/panel.css` (referenced by `plugin.json`'s `styles`) and `src/panel.test.tsx` were never written despite `src/index.ts` importing them; Jest's `testMatch` skipped `.tsx` tests entirely; and the build script declared no externals at all, so a scaffolded plugin bundled its own React — including the jsx-runtime subpaths a bare `--external:react` would not have covered — and threw `Invalid hook call` the moment one of its components rendered in the host tree. The externals now mirror the loader's shared-module whitelist exactly, plus `react-dom`, which is externalised on purpose: it is not a shared module, so leaving it unbundled turns reaching for it into the loader's explicit "not available to plugins" error instead of a second reconciler quietly rendering into a detached tree.
