Stop the system-wide selection toolbar monopolising focus and the input stream, and give it real perception.

Opening the language list called `WebviewWindow::set_focus`, which routes through tao and activates the whole application — so the document you had just selected text in deactivated, its highlight greyed out, and your keystrokes stopped reaching it. The window was already reclassed to a non-activating `NSPanel`, so the fix is to take the keyboard through the panel (`show_and_make_key`) and hand it back on the way out. That conversion is also now awaited rather than fire-and-forget: it could previously lose a race against the first reveal and briefly put an ordinary, activating `NSWindow` on screen, and a failure only logged a warning, leaving the toolbar stealing focus for the rest of the session. It now fails `start` instead. The toolbar also gets its own panel role, because the reveal-generation bookkeeping is keyed by role and sharing the pet's would have let closing the pet cancel a toolbar reveal.

Every left-button release anywhere on the desktop used to spawn a task that slept 60ms, read the accessibility selection, and on failure slept another 120ms and read again — plus, on macOS, an `osascript` fork for the focused window. A plain click cannot have produced a selection, so it now costs nothing: releases are classified as drag, multi-click or neither, and the app-blocklist check moved ahead of the read so password managers and disabled apps pay nothing at all.

Selections are now observed rather than polled. macOS gains a real `AXObserver` (`subscribe_events` was a stub there), so `AXSelectedTextChanged` and `AXFocusedUIElementChanged` drive the toolbar directly; Windows gets the matching UIA `TextSelectionChanged` wiring behind a new opt-in `text-selection-changed` event kind. Keyboard selection therefore raises the toolbar for the first time — after a 350ms settle so it does not strobe under a moving caret, with an upper bound so ⌘A over a document does not trigger it, and dismissing the moment the selection empties. Apps that post nothing keep working through the click path.

When accessibility exposes no text at all — images, PDF viewers, Java apps, remote desktops — the drag region is captured and read with OCR. Three gates must all pass first, and a missing Screen Recording permission skips the fallback silently: macOS answers that with a picture of the desktop minus every window's contents, so OCR would otherwise have returned your wallpaper as "the selection". Region capture also converts global logical points into monitor-local pixels, which it previously did not — the crop was doubly wrong on Retina and wrongly positioned on any secondary display.

`pick_at_point` on macOS is a true `AXUIElementCopyElementAtPosition` hit-test instead of returning the focused window's metadata regardless of the point.

Four contextual actions join the six stable ones: open link, email, search and convert. They appear only when the selection matches, are capped so the capsule still shows six buttons, and evict from the tail so the generic buttons never shift. `⌥⇧1`–`⌥⇧6` stay bound to the original six whatever is on screen. Payloads from the overlay are treated as untrusted: Rust re-parses the URL and refuses any scheme but http(s), builds the `mailto:` itself, and encodes the search query against its own engine table. Link and email actions are withheld from OCR text, where a misread domain is a real risk, and every action is withheld from a secure text field. The capsule now springs out of the selection rather than fading in.
