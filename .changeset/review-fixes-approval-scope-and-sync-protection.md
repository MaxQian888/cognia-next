Fixes from a review of the external-agent and account work. A permission request raised by a paired device stays that device's to answer: the record of where it came from used to be erased by the next ordinary send on the same session, after which any device holding a remote-control grant could answer it, repeatedly, with no context. Retiring a context and forgetting which requests were remote-scoped are now two different things. An invitation-accept operation is bound to the invitation that opened it, so a pending one cannot be replayed carrying a different, already-redeemed token and land an identity-provider membership for an organization nobody was invited to. The contact directory and connector callback bindings are encrypted at rest now that they reach paired devices, where the classification heuristic had read their names and called them metadata. A companion that loses its event socket no longer reports itself subscribed from the previous socket's acknowledgements, which is what let a spawn race its own subscription and read an empty stream. External agents ask whether an agent process can start _here_ rather than anywhere, so a browser paired to a Host is no longer offered the desktop-only runtime install controls. A failed execution, session or permission response is reported against its agent instead of setting state nothing renders, and a failed slash command no longer surfaces only as an unhandled rejection. The session a conversation owns is read from the one store that includes sessions the agent opened itself, and sessions belonging to an agent process that died are forgotten rather than offered back for reuse. The pair recovery screen lists the hosts of the account it would actually switch, instead of every local profile's hosts with buttons that refuse them.
