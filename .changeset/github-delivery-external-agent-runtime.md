Let a GitHub Delivery issue loop run on a configured External Agent instead of only the built-in Claude sidecar. The `action.github.run_issue_loop` node gains an **AI runtime** field: leave it on the built-in runtime to keep today's Claude Agent SDK behaviour, or point it at any External Agent (Codex, Claude Code, …) you have already set up. There is no silent fallback — if the selected agent is missing, not executable, or lacks tool execution, file writes, multi-turn, or session resume, the run fails with that reason instead of quietly reverting to the sidecar.

The driver that actually ran is now reported everywhere it was previously hard-coded as `claude-code`: the delivery event log, the failure record, and the "Generated by cognia GitHub Delivery" line in the pull-request body.

External agents run under the same confinement the sidecar already had, decided fail-closed per request and never remembered: permission escalation and bypass modes are refused, shell commands must prove a working directory inside the cloned workspace and are matched against the issue-loop ruleset, file reads and writes must resolve inside the workspace and outside `.git/`, replayed permission requests are rejected, and anything else is denied. Prompts pass the outbound PII gate before they leave the machine.

Also closes a hole in that ruleset for both drivers: remote Git operations could be smuggled past the deny list by wrapping them in a shell (`sh -c "git push"`, `powershell -Command …`, and the other five spellings), which is now refused.
