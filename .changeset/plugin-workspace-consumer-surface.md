Plugins can now obtain and read a repository. `ctx.workspace` had a registration half and no consumer half: a plugin could contribute a workspace backend and read back one it had registered itself, but nothing anywhere let it acquire a checkout — `ctx.git` is locked to the repo bound in Source Control and has no clone, and `ctx.fs` is confined to the plugin's own data directory. `acquire` / `walk` / `read` / `changedSince` / `release` close that gap: a remote is cloned into the plugin's own cache under guard rails (https only, host allow-list, no embedded credentials, shallow, timed, size bounded), and a local path is accepted only inside a workspace the user has already opened. Three host primitives that did not exist back it — a recursive gitignore-aware walk (the file tree's lister is one level deep by design and the search walker caps at 200 hits), reading a file at an arbitrary revision, and a guarded clone — plus a normalizer that accepts `owner/repo`, an https or ssh URL, or a path, which nothing in the app could do before. The walk refuses credential files (`.env`, `id_rsa`, private keys) outright rather than trusting each plugin to skip them, and reports both what it withheld and whether a cap truncated it, so a caller cannot mistake a truncated listing for a small repository.
