Provider sign-in: every provider that needs an API key now says where to get one, the check that a key works no longer refuses good keys, and OAuth token refresh works for the first time.

Pasting an API key was the login for almost every provider, but it was an unlabelled password field: nothing said where a key comes from, and nothing checked that the pasted value worked, so a wrong key surfaced later as an opaque chat failure far from its cause. Providers now offer "Get a key", which opens their own console page, and "Verify", which runs the cheapest call that proves the key is accepted. The result is three-way on purpose: a key the provider rejected is reported differently from one we could not check, because being offline says nothing about the key and reporting one as the other either throws away a working credential or accepts a typo silently. Almost none of this is hand-written per provider. The catalog already records each provider's console page and base URL, so the console link and a token-free `GET /models` probe are derived from what is there, and the four first-party providers whose SDKs default their base URL name their probe explicitly.

OAuth refresh is repaired. The old path POSTed to `/api/oauth/<id>/refresh`, a Next.js route that does not exist in a static export, so it returned 404 on every shell. It was also unreachable, reading its refresh token from a storage key nothing ever wrote, and the code exchange discarded the refresh token in the first place. Refresh now runs against the provider's own token endpoint from a declarative spec, the exchange keeps the refresh token, and a background sweep renews credentials shortly before they expire so every existing reader of a provider key stays correct without changing. A provider that refuses a renewal is blocked through the shared credential ledger rather than re-asked on the next sweep, and a revoked grant latches until the user signs in again.

Also adds an RFC 8628 device-code engine, with the provider interval honored, `slow_down` widening the cadence for the rest of the flow, and both an expiry deadline and a hard attempt cap. No shipped provider declares that flow yet, because each one that publishes it requires a registered OAuth application.

Every provider that requires a key now has somewhere to send the user for one. A coding-plan relay is a deployment of a vendor, billed to that vendor's account and opened with that vendor's key, so an entry that names no console of its own now inherits the vendor's, which covers the Chinese coding plans that previously showed a Verify button above a key box that never said where the key comes from. Anything the catalog still cannot place precisely falls back to the vendor's platform page and is labelled "Open console" rather than "Get a key", because that page is a correct place to start and is not a key page.

Verification no longer convicts a key on a refusal that was never about the key. A 403 means the credential authenticated and was then refused one particular thing, which is routine for a perfectly good key on a plan-gated, region-gated or model-gated provider, so it now counts against the key only when the provider's own words name the credential, in English or Chinese. The other half of the same problem is that the free `GET /models` probe does not exist on the relays that borrow Anthropic's wire format, so twenty providers could only ever answer "could not verify"; when that probe reports no such endpoint, the check now asks once more in the shape those providers do implement.

Fixes an OAuth provider declared in the catalog rendering no login at all: the converter that turns a catalog entry into a provider copies fields by name, and both fields the login depends on were missing from that list. The one shipped OAuth provider survived only because an inline duplicate happened to shadow it, and that catalog entry pointed its callback at `/api/oauth/openrouter/callback`, a route the static export deletes, which would have answered 404 after the user had already approved. A test now refuses any callback path under `/api/`.
