Agent runs now resolve their host from the host profile instead of the desktop marker, so Squads and teammates on the headless brain and agent turns driven from a paired phone or browser run on the real sidecar instead of degrading to a tool-less completion. The sidecar no longer exits when one send fails (a HostState send for an external-agent session used to take every live session down), keeps its command idempotency ledger across a finished turn so a retried send is not re-run, and the desktop refuses to spawn a torn `target/debug/_up_/sidecar` copy. Unattended plugin, Bot and scheduled turns answer permission asks immediately and end as `needs_approval` naming the tools instead of silently denying or hanging for five minutes. On companions, a host-owned external run waits for the event topic to be acknowledged before starting, the phone's direct send carries the session's resolved options, and the desktop's run cockpit sends pause, stop and steer to the remote host that is actually running the turn. Workflow triggers and crash-resume now reach the native workflow state on both hosts: the bridge sends `{ input }` the way the Rust commands read it (the bare object had been refused on every persist and every trigger registration, so the mirror stayed empty and cron, webhook and file-watch triggers were never registered), and on the headless brain the same calls travel the internal plane to cognia-server, which now serves the fourteen workflow mirror commands to the brain and refuses them to paired devices. An issue run started from an IM card carries its thread, so a Squad whose plan needs approval asks in that thread instead of failing its gate as unattended, and a thread with a bound session gets a carded run that reports back to it. A paired phone or browser can now change the model of a running session in place: the live session-control and session-level SDK calls are execution-plane commands the host's sidecar answers (they were declared client-only, so the companion refused them before any request left the device), and the composer's model picker asks the host profile rather than the desktop marker before driving the live switch. The SDK capability lists, the live context-window readout, the MCP live-session card and the SDK session manager ask the same host question, so a companion sees the running session's real models, context usage and MCP health and can manage the host's SDK transcripts, instead of hiding all four behind the desktop marker.
