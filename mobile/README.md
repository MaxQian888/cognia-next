# mobile/ — Capacitor 7 Mobile Shell

Capacitor 7 wraps the Next.js static export (`out/` at the repo root) into a
native iOS / Android app. The same `out/` directory feeds Tauri (desktop) and
Capacitor (mobile) — `pnpm build` generates it once.

## Layout

| Path                  | Purpose                                          | Owner      |
| --------------------- | ------------------------------------------------ | ---------- |
| `package.json`        | Workspace manifest + Capacitor CLI deps          | M3.1 (#41) |
| `capacitor.config.ts` | `webDir: "../out"`, `appId: "com.cognia.mobile"` | M3.1 (#41) |
| `ios/`                | Xcode project — generated by `cap add ios`       | M3.2 (#42) |
| `android/`            | Gradle project — generated by `cap add android`  | M3.3 (#43) |

The `ios/` and `android/` directories are gitignored until M3.2 / M3.3 land
each platform. Removing a platform's line in `.gitignore` is the signal that
platform's scaffold is committed.

## Common workflows

Run from the repo root.

| Goal                                        | Command                      |
| ------------------------------------------- | ---------------------------- |
| Install / refresh deps                      | `pnpm install`               |
| Build static export + sync to all platforms | `pnpm mobile:sync`           |
| Open iOS project in Xcode                   | `pnpm mobile:open:ios`       |
| Open Android project in Android Studio      | `pnpm mobile:open:android`   |
| Add iOS platform (one-time, M3.2)           | `pnpm -F mobile add:ios`     |
| Add Android platform (one-time, M3.3)       | `pnpm -F mobile add:android` |

`pnpm mobile:sync` chains `pnpm build` (regenerates `out/`) → `cap sync`
(copies `out/` into the platform dirs and refreshes native deps). Always run
this after editing TypeScript sources before opening Xcode / Android Studio.

## Talking to a desktop server

The mobile shell is a _client_. It pairs with a desktop server (Tauri app
running with the companion HTTP server enabled — see Settings → Companion
on the desktop) over LAN. Pairing flow lands in M3.4 (#44):

1. Desktop generates a 5-minute pair JWT and shows a QR.
2. Phone navigates to the in-app onboarding screen (`/(mobile-onboard)/pair`)
   and enters `baseUrl` + the pair JWT (real QR scan ships in M4.5).
3. Phone POSTs `/api/v1/auth/pair`, receives a 90-day device JWT, persists
   it in the OS keystore (Keychain / Android Keystore).
4. Subsequent RPC calls go through `CompanionTransport`
   (`lib/tauri/transport-companion.ts`) using the device JWT as a Bearer
   token; events arrive over `/ws/v1/events` with seq-based replay.

For now (M2.8 deferred TLS to M2.9), pairing runs over plain LAN HTTP.

## What this workspace does NOT contain

- Mobile-specific UI components (Sheet shell, safe-area, typography) — M4.
- `usePlatform()` hook replacing `isTauri()` gates — M4.1 (#45).
- Push notifications / FCM / APNs registration — M4.6 (#50).
- TestFlight / signing assets — M5 (#53/#54/#55).

The shell is intentionally minimal: native platform projects + the Capacitor
config that points them at the shared static export. All mobile-specific
logic lives in `lib/`, `app/`, and `components/` of the root workspace and is
gated by `isCapacitor()` (`lib/tauri.ts:19-27`).
