# Shared conversation batching experiment — 2026-10-07

User path: syncSharedSession receives paged shared conversation events and commits the complete encrypted local projection, event cache, account-sync capture and durable cursor.
Primary workload:1024 new message events, each with4KiB text. Guard workloads:one created message; one message created, corrected twice and redacted (four retained events).
Primary metric:time from calling public syncSharedSession until resolution after durable transaction commit. Fixture creation and post-commit verification excluded.
Runtime:isolated native Chromium IndexedDB/WebCrypto, actual CogniaDB schema and middleware, encrypted account cipher active, account capture armed. Client is deterministic in-process fixture with200-event pagination; no real network. Search markSessionDirty is stubbed to count scheduling, so background search-index rebuild is excluded and disclosed. No other application state/crypto/capture behavior should be stubbed.
Before source edit:freeze baseline module, run one warmup and one measured baseline feasibility sample. Final acceptance:one warmup each then ten alternating baseline/current measured samples per workload, same process and conditions. Compare medians and MAD. Require>=10% median improvement AND delta>2*larger MAD. Guard workloads:reject>10% slowdown beyond2MAD. No CI wall-clock threshold.
Correctness gates:every event retained; messages fully decrypted and exact parts checked; repeat corrections/redaction version and final metadata correct; event/projection cursors equal full sequence; account outbox/field clocks preserve all required intermediate writes (repeated message outbox rev); underlying raw messages/field clocks encrypted. Stable row counts and client response byte counts. Track message mutation calls/rows for attribution.
Allowed mutations:only files under this report directory; temporary browser bundle/server origin18748 and dedicated agent-browser sessioncognia-shared-perf. Parent owns production code/tests. Existing browser profiles and personal IndexedDB untouched. Synthetic unique account databases removed after samples.

Hook-enabled workload is a correctness/no-regression guard, not an accelerated claim. Full CogniaDB schema bundle includes dormant Node-only dynamic dependencies; mark node:* external and use ESM chunk splitting instead of stubbing their application functions. Any invoked unsupported host import fails visibly.

Additional pre-measurement guard:16 distinct messages with a creating hook that mutates metadata. Verify16calls and every hook mutation persisted; no throughput improvement claim for the hook fallback. Search removal exports throw if unexpected usage occurs.
