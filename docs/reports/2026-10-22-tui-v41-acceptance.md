Current-source routing already supplied `buildAgentsRunDispatch`, contrary to the initial controller-fallback diagnosis, but the factory never prepared the TUI-owned lazy sidecar. A successful main chat turn hid this cold-start defect. Evidence: original `run-3/advanced-v2`, new deferred preparation/cancellation regressions and repaired actual PTY `run-22`.
2. **Layout, mouse and selection changes cannot persist.** The TUI calls `persist("layout"|"mouse"|"selection", value)`, but `cli/src/config/mutate.ts` omits all three from `SETTABLE_KEYS`. The actual PTY reports “couldn't save to config”; the isolated config remains unchanged. The first fullscreen-to-scrollback transition also left the screen blank until a resize in this run, preventing the immediate switch-back check. Evidence: `run-3/advanced-results.json`, `run-3/settings-results.json`, and the corresponding failure screens.
3. **The current CLI build gate fails.** `node scripts/build/build-cli.mjs --js-only --outdir .cache/tui-v41-2026-10-22/cli` emits JavaScript, then exits 1: `build-cli: undeclared runtime dependencies: @opencode-ai/sdk`. The generated bundle initially could not resolve `undici` from the cache directory. A test-only symlink to `cli/node_modules` supplied the normal CLI runtime dependencies. Existing native helper binaries were reused; no Cargo/Tauri build was run. Execution of the emitted bundle is not a passing packaging build.

## Failed trials and corrected test assumptions

- Initial emitted-bundle startup failed on `undici`; preserved as `run-1`. `run-2` was interrupted at an unapproved `working_set` call accidentally induced by a “remember” prompt. The completed-conversation fixture was corrected to explicitly forbid tools. Interrupted partial context did not resume like a completed turn; no successful partial-turn resume is claimed.
- Initial panel predicates used guessed title capitalization. Later checks use observed current titles, a fresh rendered frame and a cleared composer. Bare `/provider` and `/limits` open subcommand palettes; their command text alone is not a passing controller check. Final replacements exercise explicit subcommands.
- The initial deny prompt allowed the model to call an unloaded deferred tool, then prohibited retry. That was not an approval-denial test. The corrected case first loads `sandbox_write`, then verifies the actual detail pager and Deny selection.
- After files-only rewind, the first model answer reused old tool output without calling `read`. Disk bytes were already correct. The explicit new-read control returned `ORIGINAL_REWIND`, so a stale read cache was **not** established. The spontaneous reuse of stale evidence remains a model behavior limitation.
- A freshly resumed TUI has no live sidecar session before a turn. After small live turns, the default retained tail still covers the entire conversation (about 12k tokens), so manual compaction correctly does nothing. Those no-op trials do not establish compression failure or successful compression. The final fixture reads previously unread real source ranges and verifies upstream prompt usage exceeds the retained-tail precondition.
- The initial goal predicate expected only `completed`; the real configured acceptance gate intentionally parks a satisfied goal as `paused + awaitingAcceptance`. The corrected test verifies that state and explicit stop instead of disabling the gate.
- Offline harness regressions cover secret redaction across PTY chunks, excluding old tool calls, slash-input false positives, subagent facts scoped to successful results, and rejecting budget-stop suffixes. Failed/blocked selected checks return a nonzero exit status.
- Long wrapped input exposed a single-line assumption in the reused character-by-character driver. Long questions now use bracketed paste with a fresh rendered acknowledgement and an exact full-prompt persistence assertion. The source-context run exercised this path. An intentional dependency-negative run exits 1, preserves its blocked result, sends zero inference and restores terminal modes.
