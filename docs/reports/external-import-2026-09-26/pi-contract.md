# Pi conversion experiment

Pre-registered on 2026-09-26 before production edits. Baseline revision:
`5d48f846142312c8d344083b5240d32400b36946` (Pi files clean).

- Path: Pi JSONL file read → `parsePiSession` → imported conversations.
- Hypothesis: constructing the complete parent index once per alternate leaf
  makes heavily branched imports unnecessarily quadratic.
- Workloads: 12,010 linear entries; 10 shared entries followed by 1,000 branches
  with 12 entries each. Fixed timestamps and 128-character text. Real temporary
  files, warm filesystem cache, identical generated bytes in both builds.
- Compare bundled production functions in the same Node process, alternating
  baseline/candidate order, two warmups and 12 measured samples per variant.
  Time includes file reading and complete conversion; serialization/hash checks
  occur outside the timer. GC before each sample; record RSS and heap deltas.
- Primary: branched conversion median; keep only >=10% improvement exceeding
  twice the larger MAD. Guard: linear workload must not regress by >10% beyond
  noise; entire serialized output hashes must match for every sample.
- Correctness: retain v1 fallback, duplicate IDs, cycles, dangling parents, leaf
  ordering, tool outputs, usage, private state loss notes and truncated lines.
- Scope: subsystem timing on generated fixtures, not Tauri IPC, Dexie writes,
  authenticated external runtime, cold disk, or UI end-to-end timing.
