Pre-registered before editing the owned production memory handler. Other shared-tree changes are preserved.

- User path: companion `syncMemories` receives a JSON delta with real V1 encrypted memory envelopes, decrypts with native WebCrypto, applies through the full CogniaDB schema with account-content encryption, and bounds the offline cache.
- Primary metric: elapsed milliseconds from invoking actual `syncMemories` through its returned successful outcome. Includes transport JSON parsing, actual `openMemorySyncRowV1`, row encryption/storage, pruning, and cursor/scope handling. Fixture wire encryption and DB seeding are outside timing.
- Hypothesis: a native IndexedDB count can avoid loading/decrypting cached payloads when <=1,000 records, without altering overflow eviction ordering.
- Primary fixture: 800 existing distinct records + 200 incoming new records; each memory text is 4,096 ASCII bytes, cache reaches exactly 1,000. Native AES-GCM storage encryption and actual V1 wire envelopes, synthetic generated profile DEK injected through existing `loadDek` dependency. Account sync capture is not armed.
- Guard workloads: 1,000 existing + 200 incoming (overflow 1,200, retain 1,000); empty cache + one incoming 4KiB memory; 800 existing + empty delta.
