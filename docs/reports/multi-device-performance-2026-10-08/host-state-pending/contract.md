# HostState pending projection experiment — 2026-10-08

Registered before production optimization and baseline pilot. Source baseline saved byte-for-byte in baseline-host-state-service.ts.txt.

User path: a companion receives a HostState session snapshot, persists confirmed state, replays its pending durable actions, updates the local draft/session and publishes visible state. Primary metric is elapsed milliseconds of the public installHostStateSync call through completion (local fixture snapshot/status responses, real client apply, full CogniaDB, native Chromium IndexedDB and real account encryption). A subsequent ordered live event through the installed transport callback is a secondary guard measurement.

Primary workload: 2048 terminal outbox rows (alternating sent/rejected/conflicted/deadlettered), each with a 4096-character payload; eight active rows mixing pending/sending, tied clientSeq across statuses, other protocol/channel, and malformed actions. Guard: zero terminal rows with the same active rows. One warmup and ten measured samples per variant/workload, alternating baseline/result order. Fresh encrypted fixture database each sample; seed and verification excluded; browser process/module state warm. Baseline and current source compiled together with esbuild production definitions, same dependencies and runtime. No cache cleaning.

Decision: primary median improvement >=10% and absolute delta >2*max(baseline MAD,result MAD). Small-queue and live-event guard median regression must be <=max(5% of baseline, 2ms, 2*larger MAD). No p95 claims. Report raw samples, median/MAD, queue decrypt counts, wire bytes and normalized output digest. Incoming snapshot/event counts and bytes must match, complete pending queue must remain unchanged, confirmed snapshot/durable session/draft/templateBinding and visible state must equal deterministic expected projection. Lock and cancellation are separate untimed guards using canonical production lockAccountContentCipher and stop during resync. No timing thresholds in CI.

Real paths: schema, encryption middleware, HostState validation/reducers, snapshot/event apply and all persistent writes are unchanged. Transport is an injected local fixture with no network latency; search index scheduling throws if unexpectedly reached (fixture uses draft/rename actions and has no optimistic queued messages). UI rendering, physical devices, WAN, backend lease/service and delivery are unmeasured. Any additional runtime stub or deviation must be disclosed before final timings.

Environment: same local macOS Apple Silicon machine as preceding reports; record Chromium UA/hardwareConcurrency. Browser runs in isolated agent-browser session against loopback static server. Agent-owned timings serialized with parent; no timer starts until coordinated. Allowed writes: only this report directory, temporary compiled browser bundle, isolated test browser DBs, normal build caches. No production edits by harness owner. Each database is removed in finally.

Owning table policy audit before pilot: mobileOutboundQueue is metadata-only, so its payload is structured-cloned/filtered but not content-encrypted even in an encrypted account DB. Queue decryption count should remain zero. hostStateChannels, sessions and chatDrafts use their actual schema encryption policies. Raw fixture checks queue equality and draft encryption; no claim of avoided queue decryption.

Baseline guard correction before source comparison: initial locked-install guard expected no confirmed row, but the unchanged implementation persists metadata-only hostStateChannels before its first encrypted draft read fails. The fixture now asserts this exact pre-existing partial-confirmation state, unchanged encrypted session/draft/outbox, lock rejection and unsubscribe. This is not a transactionality improvement claim. Initial diagnostic error retained in initial-guard-assumption-error.json.
