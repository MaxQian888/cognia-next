## Candidate and deferred work

The current dispatcher clones an already-owned JSON array immediately before calling a borrowed `append(&[Value])`. This is the one native candidate under measurement; removing it does not change SQLite statements, durability, locking or scopes.

The degraded `SqliteAppStore` message mutations separately autocommit message and parent revision writes. An explicit transaction could reduce commit count and improve failure atomicity, but it is outside this experiment and does not address primary app chat. No performance claim or source change is made for it.

Existing native manual benchmarks in `agent_session_store/mod.rs` cover list-session and restore/backup contention. Their prior results are historical, not this run's baseline. Full transcript load remains proportional to total content because the SDK asks for a complete transcript; silently truncating it is invalid.

## ADRs consulted

- ADR-0116: host-authoritative session state, ordered semantic receipt and replay boundary.
- ADR-0215: account E2E sync core and current six-table scope; snapshots/compaction still separate work.
- Current native module comments reference ADR-0067 / ADR-0196 for crate ownership, ADR-0090 for SDK mirror, ADR-0059 for headless data-plane selection.

No real user database, credentials or message content was accessed.
