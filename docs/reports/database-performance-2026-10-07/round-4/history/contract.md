# Scoped workflow failure history experiment — 2026-10-08

User path: workflow editor RunsTab mounts DeadLetterPanel with workflowId. Its Dexie live query calls listDeadLetters(workflowId), currently reading and decrypting all failed runs before discarding other workflows. Primary metric is that complete storage function until the complete returned rows resolve; UI paint is outside this boundary.

Hypothesis: for a truthy workflowId, query the existing [workflowId+status] compound index with exact equality [workflowId, "failed"]. Keep the current acknowledgement/workflow predicate and stable startedAt sort. Empty or absent workflowId retains the original global status query. No schema, cache, transaction, write, retention, migration, public API, snapshot projection, or legacy-field normalization changes.

Research: ADR-0011 establishes persisted immutable run snapshots and editor history; current schema already includes [workflowId+status]. The owning workflowRuns table policy is encrypted-content. Browser/terminal history lists already use indexed bounded queries; workflow dashboard aggregation would require a broader change. Proposed production ownership is lib/db/workflows.ts and its existing test only, subject to root coordination.

Harness: native Chromium 151 IndexedDB, Dexie 4.4.6 defaults, production/minified esbuild; real account cipher and encrypted-content middleware, matching current workflowRuns indexes. Select the exact exported listDeadLetters function from a frozen full-source AST; inject only getDb. This avoids booting unrelated publication/write paths. No handwritten replacement query. Apple M4 Pro 14 cores / 48 GiB, macOS 26.5.2; no power/thermal controls. Root serializes timing windows. Seed synthetic databases separately from timed reads; do not delete application caches.

Fixed fixtures: primary 1000 total runs across 20 workflows, 200 failed total with 10 in selected workflow; payload includes a frozen workflow snapshot with 2 KiB description, error and trigger fields. Other statuses are succeeded/running/cancelled. Guardrails: 20 rows in one workflow with 4 failures; 200 all-failed rows in selected workflow; same 1000-row global query; nonexistent workflow. Include acknowledged and unacknowledged records in each fixture; return exact same complete objects/order. Two warmups plus 12 recorded calls per fixture; sequential before/after same browser and isolated DB. Record median, MAD, max and all raw samples. Retain only primary gain >=10% AND absolute gain >2*max(beforeMAD, afterMAD). No guardrail regression beyond max(10% baseline, 1 ms). No CI wall-clock assertions.

Native checks cover empty/absent/nonexistent workflow, acknowledgedAt undefined/null/zero, same-time stable primary-key ties, missing/negative startedAt, mixed status and missing workflowId legacy rows, liveQuery entering/leaving scope and acknowledgement updates, locked cipher rejection. Regression test must fail on original broad query and pass candidate; preserve co-located tests. Root coordinates final workflow repository/panel/RunsTab suites and broader checks.
