## Implemented behavior

- Search and selectable link results carry their originating `accountBinding`. Provider, query, account and authorization epoch jointly identify visible results. Account/query changes hide old results before the next debounce; cancelled requests cannot repopulate a later A→B→A selection. The popover rejects stale bound results for keyboard and pointer selection.
- Google account metadata uses the authoritative host state. Fetch/search check the expected authorization before and after token acquisition and after the provider response. Normal refresh preserves the picker epoch; Begin, Commit and Disconnect invalidate an old authorization lineage. Invalidate also fails when tokens disappear even if the epoch is unchanged. Existing Google storage keys, command names and event ownership remain intact.
- Staging checks account membership before fetch, after fetch and immediately before attachment commit. It passes cancellation through, subscribes to account invalidation, and rejects obsolete session/composer generations and unmounted destinations. A superseded failed verification cannot cancel a newer valid verification.
- `RemoteDocContent.completeness` describes semantic losses as well as budget truncation. Shared normalization retains legacy `truncated` compatibility, adds a visible model-facing marker, rejects empty text and stays stable when applied twice. The UI distinguishes partial content from ordinary truncation. Body content still enters the existing untrusted File → attachment preparation → fail-closed PII dispatch path.
- New-provider citations include opaque account scope without persisting epochs. Existing Lark/Google citation identifiers remain compatible. No new cloud provider is registered.
- The existing native `proxy_http_request` byte bridge accepts an optional strict download policy. It preserves raw bytes, caps actual data at 20 MiB or a lower caller limit, bounds the operation at 60 s including semaphore wait/DNS/redirects/body, and permits two concurrent strict downloads. Declared size and each received chunk are checked.
- Strict requests require GET, HTTPS, an explicit origin grant and public-only DNS answers pinned to the connection at each hop. They remove Host/Referer and strip cross-origin bearer/cookie headers. Proxy routes with remote DNS are rejected rather than bypassed. Errors omit signed URLs; returned headers are restricted. An older native host, browser or Capacitor cannot silently ignore the policy.
- Buffered requests negotiate `requestAdmissionVersion: 1` and wait for `proxy_http_prepare` before dispatch. The host returns a unique per-attempt token; cancellation, claim and cleanup affect only that token. Missing, cancelled, expired or reused claims fail before I/O. Reservations are bounded at 256, with a 30 s unclaimed lifetime; active requests retain their guard until completion or future drop. Strict downloads now require `downloadPolicyVersion: 2` plus admission v1. Ordinary callers can use an older host only when the admission capability is absent, retaining that legacy host’s cancellation behavior; explicit unknown versions reject.
- The production consumer is Tauri HTTPS link-preview image reading, using its existing lower image-size limit and same-origin redirect grant. Ordinary proxy requests retain their existing byte ceiling and oversize error message, including the video-job non-retryable classification.

## Design refinements supported by source

The current attachment citation binding and `attachments.add` commit are synchronous. There is no `await` between the final guard and these mutations. P0 adds an asynchronous `beforeCommit` account check followed by the synchronous destination/identity guard; it does not add a speculative receipt/rollback framework. Pending preparation and verification tests preserve concurrently added local attachments. If commit becomes asynchronous later, isolation and rollback by exact attachment IDs become required.

There is already a lossless binary bridge; the text-only connector HTTP path is not the only native transport. P0 extends that existing owner instead of inventing a Microsoft command without a Microsoft account. The future account/drive/item-bound Graph command, tenant domain grants and bounded Office/PDF parsing remain provider-phase work.

Google conformance is fixed before any common auth-core extraction. With no second native provider yet, extracting a credential framework would add unused ownership. Lark currently supplies adapter-ID binding and membership checks, without a native same-adapter reauthorization epoch; P0 does not claim that additional guarantee.
