# Agent convergence: adversarial research and design boundaries

Research date: 2026-10-23, Asia/Shanghai. Status: research complete; implementation and live acceptance are not part of this report.

This dated report addresses convergence after the Warehouse Ledger campaign. It does not rewrite the historical [compaction comparison](./2026-10-21-agent-compaction-comparison.md) or [TUI acceptance record](./2026-10-22-tui-v41-acceptance.md). Only research artifacts were added. No production source was edited, no model-provider acceptance calls were made, and neither typecheck nor Tauri was run.

## Decision under examination

Reduce investigation and verification that make no useful progress while preserving correctness, explicit user constraints, legitimate rereads, independent acceptance, cancellation, and resumable incomplete work.

The following shortcuts are **not justified**: prohibiting reads of previously seen paths; caching test success by command alone; permanently freezing completed findings; removing every Plan tool based solely on model-reported completion; replacing existing budgets with a new small request/time cap.

## Reassessment of run 97

The [recorded campaign](../../.cache/tui-v41-2026-10-22/run-97/project-results.json) has 74 provider attempts: V1 implementation 22, restored-context recall 1, Explore 9, Plan 8, V2 implementation 18, explicitly requested follow-up verification 14, manual summary 1, and post-summary recall 1. Request intervals total 1104.158 seconds; stage wall time totals 1236.016 seconds. One HTTP 504 consumes 120.049 seconds. These are different accounting units from individual tool calls or another SDK's turns.

The prior analysis needs these qualifications:

- Plan made 14 read calls covering 13 paths previously read by Explore. That proves overlap, **not that all those calls were useless**. Required source details, retained context, truncation, freshness and the purpose of each read must be assessed. Anthropic explicitly uses overlapping reads in its own workflow [S1].
- Nine model-invoked full-suite executions, including six after the implementation stopped changing in their respective phases, identify candidates for consolidation. They do not prove six forbidden actions: fixtures, environment, exit-status collection, flakiness and proof layers can differ. Running a suite twice only to display different filtered views can usually be consolidated while retaining the actual exit status.
- Follow-up verification found and repaired the real `__proto__` SKU defect and added regressions. Removing that phase to improve the headline request count would remove useful evidence.
- The nine recorded main-agent tool errors are heterogeneous: five sandbox writes, three malformed patches and one command-policy refusal. Five parallel failed writes are not five sequential retries after observing an error. Error count alone does not establish a recovery loop.
- The only model-summary compaction is attempt 73, after implementation and verification. The recorded post-summary recall made no new tools. This trace does not establish a compaction-induced research loop, nor does its keyword-based observer prove every constraint or fact survived.
- Run 97 included a development User Timing diagnostic intervention. It is not a clean production performance baseline. No percentage speedup or ideal request count can be inferred from it.

The parent implementation also has a session-local read-before-edit requirement: child reads do not authorize parent writes. That makes some parent rereads necessary even when source content is unchanged. [Local tracker](../../sidecar/src/tools/state/read-tracker.ts)

Gemini's inspected client also has a 100-turn recursion ceiling; Goose documents a configurable autonomous-turn default of 1000 [S10, S11]. These are counterexamples to "all hard limits are inherently wrong", not proposed Cognia defaults. A resource boundary must report an incomplete result when the task is unfinished.

OpenAI native Responses compaction returns opaque state with protocol-specific handling [S12]. It is not an interchangeable text-summary mechanism for an arbitrary OpenAI-compatible provider. None of the external sources establishes an optimal compression ratio, request count or test count for this Cognia task.

### Read-only function probes

The actual `progress-checkpoint.ts` module was imported with Node's type stripping; no source/test files were written. Two pure calls produced:

```text
same ID: done(Path A) + pending(Path B contradicts A)
  -> old done item unchanged; new evidence and question absent; ready=true

one model-reported done item with summary="" and evidence=[]
  -> ready=true
```

The first proves deterministic correction loss in the supplied case. The second proves the readiness predicate does not require supporting facts; it does not mean every empty-evidence research task is invalid. The dangerous step is using that predicate as authority to remove all tools. These probes do not establish the frequency of either case in live sessions.

## Revised policy: smallest justified change

1. **Repair concrete tool contracts first.** Extend existing tool/result/failure owners rather than create another error system. Give malformed patches a precise argument failure. Distinguish a missing target, missing parent, unavailable executable, policy refusal and uncertain partial execution. Keep sandbox confinement; creating parents or using another tool requires the same authorization. Never route around rejection. Prefer clear valid examples and actionable feedback over guessing ambiguous edits.
2. **Make handoff sufficient, not exhaustive.** Retain the task, applicable earlier user constraints, findings, reusable symbols, gaps and source references. Expose what detail is absent/truncated and how to retrieve it. Plan may reread for source detail, conflicting evidence, freshness, a new receiving context or read-before-edit. Ask for a concise purpose when repetition is suspicious; do not block by path or require an explanation on every ordinary read. Extend the current handoff seam before proposing a universal research cache.
3. **Separate historical progress, active validity and authorization.** Keep established findings, but represent explicit corrections or reopened questions without erasing history. Bind any delivery decision to current task/revision and unresolved original requirements. An ordinary model status should orient drafting; it should not alone make further evidence retrieval impossible. A blocked-gap report can be a valid research deliverable while the implementation objective remains unfinished.
4. **Consolidate verification without caching correctness.** Reuse visible evidence as context and avoid rerunning a deterministic suite solely to reformat logs. Preserve independent acceptance and checks requested by the user. Changed tests/fixtures/dependencies/environment, nondeterminism, restart/recovery and new failure hypotheses justify repetition. If equivalence cannot be established, retain verification. Do not build a command-hash cache or universal dependency fingerprint from this single trace.
5. **Improve existing loop feedback, retaining its authority.** Augment observed repetition with outcomes, relevant changes and remaining questions where evidence is available. First explain the stagnation signal and allow a different approach or the existing approval route. Preserve the current permission guard and execution-budget authority. Any later stop must explicitly distinguish stagnation, cancellation, refusal and budget exhaustion from completion. Upstream thresholds are heuristics, not semantic proof and not defaults to copy.
6. **Keep budgets and continuation truthful.** Preserve explicit limits and the unified governor. Save completed/partial findings, unresolved criteria, failures and the next useful action at safe boundaries. Resume must carry those results while rechecking changed external state and permissions. Fixing waste does not justify a new role-specific 20-round or five-minute cap. Persistent evidence-based completion is also the center of the official Codex Goals design [S13].

Content hashes may be useful for a narrowly scoped stale-read check, but the inspected evidence does not justify a new cross-agent, persistent cache/ledger spanning every tool, environment and permission. Observation reuse must never transfer authorization.

## Falsification and acceptance required before shipping

These are proposed checks, not tests executed in this research.

| Case                                                                                                    | Required result                                                                                                                                                              |
| ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Same-ID completed item receives explicit conflicting evidence                                           | Keep prior history and the new conflict; prevent stale-state forced delivery.                                                                                                |
| Source changes after a checkpoint, or a resume adds a new required question                             | Refresh only affected findings; allow necessary tools; retain unrelated completed work.                                                                                      |
| Model omits a required workstream or emits unsupported `done`                                           | Do not treat its list alone as complete coverage or verified success.                                                                                                        |
| Earlier user says no installs / preserve independent acceptance; later planning command is short        | Both children receive applicable constraints, without sending unrelated conversation history.                                                                                |
| Explore read is truncated, only covers part of a file, or is absent from the receiving context          | Allow targeted retrieval/continuation; do not report a full-read cache hit.                                                                                                  |
| Parent needs a session-local read before editing a child-inspected file                                 | Keep the read-before-edit safety contract.                                                                                                                                   |
| Invalid patch and sandbox missing-parent cases                                                          | Actionable typed failures; valid correction succeeds under unchanged permissions; no blind replay.                                                                           |
| Second file write fails, or a command times out after writing                                           | Report known/unknown effects; inspect/reconcile before retry; no false all-or-nothing claim.                                                                                 |
| Tool action is refused or user cancels                                                                  | No alternate-tool bypass or automatic restart of that action.                                                                                                                |
| Same test command after fixture/environment change; deliberate flakiness run                            | Permit useful repetition; retain true exit status and requested proof layer.                                                                                                 |
| Identical reads/polls see changed external state; semantically repeated queries use different arguments | Do not confuse signature equality with progress or inequality with novelty.                                                                                                  |
| Real project with default compaction and a separate stress-compaction configuration                     | Preserve original constraints and selected facts, perform subsequent useful work, and naturally deliver the required result. Inspect structured outputs, not keywords alone. |
| Selected execution budget exhausts mid-investigation, then explicit resume                              | Persist a visibly incomplete result and recover useful progress; allow changed-source corrections. No reset to a new investigation, no silent success.                       |
| A legitimate task requires more than 20 calls under its selected budget                                 | Continue normally; an independent observer verifies actual completion.                                                                                                       |

Use the same task/fixtures, build mode, model configuration, handoff and acceptance contract for paired experiments. Separate parent/child/summary requests, transport retries, tool outcomes, model wait/stream time, tool time, approvals and independent observer time. Report correctness and completion alongside requests, tokens, time and cost. Preserve failed trials. Run 97's diagnostic/dev timings are not a control arm for an untouched production build. A request reduction that loses the `__proto__` regression or required independent checks is a failed optimization.
