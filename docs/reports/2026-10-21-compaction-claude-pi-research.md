## Findings that change the design discussion

- There is no validated universal percentage to copy. Pi separates a token reserve from a token-sized recent tail. Claude Code's current default depends on model/session configuration; “Claude always compacts at 95%” is not an accurate current description. [Pi settings and trigger](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/src/core/compaction/compaction.ts#L120-L270), [Claude defaults](https://code.claude.com/docs/en/model-config#default-auto-compact-thresholds).
- Summary quality, request fit, and generation completion are different concerns. At the inspected Pi revision, the reserve parameter does **not** cap summary generation; a length-stopped summary is rejected. [Pi generation](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/src/core/compaction/compaction.ts#L581-L754).
- Compaction continuity includes deterministic state. Claude documents disk rehydration and reminders about running tasks. Pi persists a summary boundary and cumulative file metadata rather than asking prose to carry everything. [Claude rehydration](https://code.claude.com/docs/en/context-window#what-survives-compaction), [Pi storage](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/src/core/session-manager.ts#L91-L106), [Pi file metadata](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/src/core/compaction/utils.ts#L7-L94).

## Claude Code: documented behavior

### Trigger and response reservation

Current documentation says unset auto-compact windows generally compact at the model limit, with exceptions: cloud sessions compact as they approach it; non-extended Opus/Sonnet 4.6 use the 200K boundary; native 1M models compact at about 967K. A gateway alias can instead inherit an assumed window. Explicit windows can be selected per model through `/autocompact`, with settings, CLI, and environment overrides. These are documented product defaults, not a recommended Cognia policy. [Model configuration](https://code.claude.com/docs/en/model-config#context-window-and-auto-compaction).

`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` can lower the trigger percentage but cannot raise it, and applies only to sessions that compact proactively. `CLAUDE_CODE_MAX_OUTPUT_TOKENS` controls most generation requests; raising it reduces effective context available before compaction. Thus output allowance affects request headroom, but this documentation does not expose an exact universal arithmetic formula. [Environment reference](https://code.claude.com/docs/en/env-vars).

### Clearing, summary, and continuation

Claude documents clearing old tool output before summarizing if necessary. Requests and important code fragments are retained, while early detailed instructions can be lost. `CLAUDE.md` can contain compact instructions, and `/compact` accepts a focus. This establishes layered management rather than one indiscriminate transcript rewrite; it does not disclose the exact clearing threshold or summary schema. [How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works#when-context-fills-up).

After compaction, the system prompt remains applicable; root instructions, auto memory, and plans reload. Files read/edited in the session are re-read up to five, ordered by recent modification; a file above 5,000 tokens returns as a reference. Invoked skills have separate 5,000-token individual and 25,000-token aggregate budgets. Running background commands/subagents continue, with reminders to prevent duplicates. Path-scoped and nested instructions reload on demand. These are distinct restoration channels, not guaranteed details in the generated summary. [What survives compaction](https://code.claude.com/docs/en/context-window#what-survives-compaction).

The cited page also says summary generation inherits the session's thinking setting as of v2.1.198. This says how the summary is generated; it does not prove old private thinking is serialized into the summary input. [Context window](https://code.claude.com/docs/en/context-window#what-survives-compaction).

### Hooks and failure containment

`PreCompact` receives manual/auto origin and custom instructions, and can block. Blocking a proactive compaction leaves the conversation running; blocking recovery from an already returned context-limit error makes the request fail. `PostCompact` exposes the generated summary and cannot alter the result. `SessionStart` hooks matching `compact` can add context afterward. [Hooks reference](https://code.claude.com/docs/en/hooks#precompact), [post-compaction](https://code.claude.com/docs/en/hooks#postcompact), [rehydration](https://code.claude.com/docs/en/context-window#what-survives-compaction).

Claude documents a thrashing stop: repeated immediate refills following successful compactions eventually produce an error rather than another automatic attempt. Recovery includes smaller reads, focused compaction, separate-context research, and clearing when history is dispensable. The official page does not establish the precise counter or reduction-ratio criterion. [Troubleshooting](https://code.claude.com/docs/en/troubleshooting#auto-compaction-stops-with-a-thrashing-error).

## Pi: source-backed mechanisms

### Three budgets must remain separate

The default reserve is 16,384 tokens, recent-tail target 20,000. The trigger is strict `contextTokens > contextWindow - reserveTokens`; tail size is absent from that trigger. Usage accounting takes native total usage when available, otherwise input/output/cache components, then estimates trailing messages. Invalidated pre-edit/pre-compaction usage must not be treated as current context. [Token accounting and trigger](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/src/core/compaction/compaction.ts#L120-L270).

Current Pi docs explicitly distinguish this reserve from summary generation: generation uses the model output limit and can be reduced so input plus output fit. Model-specific reserve/tail settings resolve independently, while invalid supplied integers raise errors. Overrides are keyed by exact provider/model ID; these defaults are a configurable operating point, not evidence of optimal quality. [Pinned compaction reference](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/docs/compaction.md#when-it-triggers), [per-model settings](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/docs/compaction.md#per-model-overrides).

### Tail and active-task preservation

The retained suffix is token-estimated, not “last N messages.” It walks backward and selects a valid boundary; it never starts on a tool result. A large user-message span can be split at an assistant boundary, with a separate prefix checkpoint preserving its request and work so far. Tool batches can force the retained suffix above the nominal target. Upstream tests explicitly cover oversized trailing results and repeated-compaction boundaries. [Cut algorithm](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/src/core/compaction/compaction.ts#L430-L505), [split-span contract](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/docs/compaction.md#split-user-message-spans), [tests, inspected but not executed](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/test/compaction.test.ts#L298-L410).

The normal checkpoint schema distinguishes goal, constraints/preferences, completed/current/blocked progress, decisions, ordered next actions, and critical context. Updates merge the earlier checkpoint with new messages; a split-span prefix has its own request/progress/continuation fields. Exact paths, symbols, and errors receive explicit preservation instructions. This is a prompt contract, not a validated JSON schema or proof against model omission. [Summary prompts](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/src/core/compaction/compaction.ts#L507-L577), [prefix prompt](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/src/core/compaction/compaction.ts#L931-L943).

### File evidence and serialization

Pi deterministically extracts built-in `read`, `write`, and `edit` paths from assistant tool calls and nested codemode calls. Modified paths are the union of writes/edits; read-only paths exclude that union. Metadata is appended independently of prose. This is observed tool activity, not a complete filesystem audit: arbitrary shell edits and unknown tool schemas are not covered by this extractor. [Extraction and formatting](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/src/core/compaction/utils.ts#L7-L94).

Serialization uses role labels and includes visible text and tool arguments. Each tool result keeps its first 2,000 characters plus an omission marker; thinking is omitted. Consequently a checkpoint can miss important material late in a large result; file metadata is a recovery aid, not proof its findings survived. Default file lists accumulate across built-in compactions/branch summaries; hook-generated summaries own their custom metadata. [Serialization](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/src/core/compaction/utils.ts#L96-L183), [cumulative metadata](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/docs/compaction.md#cumulative-file-tracking).

### Persistence, failure, and continuation

Compaction appends an entry containing summary, retained-boundary ID, before-token count, optional metadata/usage, and current system message. Projection uses the latest checkpoint plus its retained suffix, leaving raw historical entries available. This separates durable history from the model's current view. [Entry schema](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/src/core/session-manager.ts#L91-L106), [projection](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/src/core/session-manager.ts#L470-L578), [append](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/src/core/session-manager.ts#L1261-L1292).

Pi checks context before new prompts and between tool batches/next responses. Overflow or an eligible early length stop gets one compact-and-retry attempt. Manual compaction first aborts active work and does not automatically resume that interrupted turn. Recovery keeps failed attempts in raw history but omits them from projection; cancellation/failure appends no checkpoint or internal retry. Queue semantics remain distinct from retrying a completed answer. [Lifecycle implementation](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/src/core/agent-session.ts#L2780-L3275), [recovery ordering](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/docs/compaction.md#overflow-and-length-recovery-ordering).

The generation layer rejects provider errors, length-stopped checkpoints, and attempted tool calls. It retries transient summary-call failures through the configured policy, disables prompt-cache writes for one-off summaries, and retains cancellation signals. A nonempty partial summary therefore does not automatically become the replacement history. [Summary validation and call wrapper](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/src/core/compaction/compaction.ts#L581-L754).

Extensions can cancel or replace a checkpoint using prepared spans, previous summary, file operations, and settings. Events distinguish manual/threshold/overflow and expose `willRetry`; success and failure/abort have separate events. Custom implementations must supply their own valid retained boundary and metadata semantics. [Typed extension contract](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/src/core/extensions/types.ts#L784-L821), [custom result type](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/src/core/extensions/types.ts#L1511-L1515), [official custom-model example](https://github.com/earendil-works/pi/blob/cae9fd28a2d3d515c83ea495093e3768cc8efab6/packages/coding-agent/examples/extensions/custom-compaction.ts).

## Anthropic API: relevant, separate capabilities

| Capability           | Documented behavior                                                                                                                                                                                                                       | Evidence                                                                                                                                |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Tool-result clearing | Server-side chronological clearing, default trigger 100K input tokens and retention of three uses; optional minimum removal, excluded tools, and input clearing. Placeholders replace removed results; the client keeps its full history. | [Context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing#configuration-options-for-tool-result-clearing) |
| Threshold compaction | Beta `compact_20260112`, default input trigger 150K, minimum 50K. Uses the requested model. Custom instructions replace the default. Can pause after the summary, allowing application-controlled continuation.                           | [Threshold compaction](https://platform.claude.com/docs/en/build-with-claude/compaction-threshold)                                      |
| On-demand compaction | The application requests a server-written summary and swaps in the returned block; the current overview recommends this path where available. It can support keep-tail and background workflows.                                          | [Overview](https://platform.claude.com/docs/en/build-with-claude/compaction)                                                            |
| Keep-tail            | The application chooses the cut; there is no keep-tail parameter. Old messages go to compaction, then the returned block precedes the exact retained suffix. Each tool call/result must remain on the same side.                          | [Keep recent turns](https://platform.claude.com/docs/en/build-with-claude/compaction-keep-recent-turns)                                 |

Tool clearing can invalidate prompt-cache prefixes, and `clear_at_least` is an explicit tradeoff. Editing statistics and the counting endpoint expose post-edit token use. This supplies a measurable alternative to summarizing every old tool response, but is provider-specific. [Editing, counting, and cache behavior](https://platform.claude.com/docs/en/build-with-claude/context-editing).

The threshold API separately reports compaction iteration usage; top-level usage excludes compaction iterations. Preserving old thinking after replacing history can require removing invalid thinking blocks, while the on-demand keep-tail path has its own validity conditions. Neither API should be emulated by blindly copying old reasoning blocks into a new prompt. [Threshold usage/limitations](https://platform.claude.com/docs/en/build-with-claude/compaction-threshold#understanding-usage), [keep-tail thinking validity](https://platform.claude.com/docs/en/build-with-claude/compaction-keep-recent-turns#keep-thinking-valid-in-the-kept-turns).

## Relevance to the inspected Cognia tree

The current working tree is concurrently dirty. The read-range carryover and augmented shared prompt below are **unvalidated draft patches written earlier in this same task**, not verified baseline or shipped mechanisms. The root adversarial review rejected the draft coverage mechanism's budget, provenance, and source-version behavior; their presence in saved files is not evidence of correctness or approval:

- The inspected AI SDK compactor defaults to six recent messages and serializes bounded tool payloads. Its draft read-range carryover must be reviewed for replacement or repair before reuse; it must not be treated as trustworthy execution evidence. [Local draft](../../sidecar/src/runtimes/ai-sdk/compaction.ts).
- The draft shared prompt asks for goals, decisions, constraints, completed investigations, failed searches, remaining questions, and the next action. Its effectiveness has not been established; wording alone would not address tail sizing, summary truncation, or runtime state rehydration. [Shared prompt draft](../../lib/ai/generation/summarizer.ts).

The following are design inferences, not upstream benchmarks or an implementation proposal:

1. **Separate admission/headroom, retained-tail size, and summary generation limits.** A low generation cap does not safely substitute for context reservation; copying Pi's exact numeric defaults does not establish fit for Cognia's providers.
2. **Prefer a token-targeted suffix with tool-pair invariants.** Message counts are unstable when one message contains a huge result. Still handle oversized indivisible batches, where a target cannot be a hard maximum.
3. **Carry task state outside free-form prose.** Goals, pending operations, verified findings, read ranges, and active background jobs serve different recovery roles. Claude's file re-read strategy and Pi's path lists are different mechanisms with different costs and completeness limits.
4. **Validate replacement before publishing its boundary.** A truncated but nonempty summary is not demonstrated safe. Review existing `finishReason: length` handling, aborts, concurrent appends, and tool pairing before claiming a checkpoint is valid.
5. **Test continuation, not just size reduction.** Replay a long ongoing investigation; require the next step to continue from verified results, preserve the original task, avoid duplicate active work, and remain recoverable after a failed summary call.

No source reviewed establishes that one schema, one percentage, or one recent-tail number is best across workloads. The user currently asks for research before proceeding; these findings do not approve adopting an upstream strategy. Implementation acceptance would need offline transcript fixtures plus separate real-provider evidence.
