# ADR-0234 Phase 2 — provider framework, plugin API, VNC on desktop

Design source: [ADR-0234](../content/docs/en/adr/0234-a-remote-desktop-is-a-provider-binding-brokered-by-the-host.md) §1, §3–§6 and Phase 2. User decisions (2026-10-18): the entry point is a **Remote desktop section in the devices console**; VNC supports **VncAuth and None only**, every other security type is refused by name at probe time.

Phase 2 is the desktop shell only. Companion transports, the `cognia.rfb` channel and phone/Web clients are Phase 3. Commands are `target: "client"`, `transports: ["internal"]`.

## Facts relied on (verified 2026-10-18)

- `cognia-secrets::keyring_secrets::{get,set,clear}(namespace, key)`; headless needs `secret_store::init_headless` first (already done by the server for managed desktops). `keyring` is `directOnly`: never depend on it directly.
- `cognia-net::egress::is_forbidden_dest_ip` / `is_metadata_ip` are pure; there is no shared resolve-and-pin helper.

- `cognia_core::fs_atomic::atomic_write_with_mtime_check` is the public atomic writer.
- Desktop data root `<app_data>/cognia/` (`src-tauri/src/startup/services.rs`), headless `<data_dir>/` (`cognia-server.rs`). Pass the root explicitly.
- New Tauri commands need: `protocol/companion-commands.json` (+ `companion-resources.json` resource, verbs from `companion-verbs.json`), `protocol/headless-command-dispositions.json` (`local-only`), `generate_handler!` in `src-tauri/src/lib.rs`, a `tauri-host` feature on the crate enabled from `src-tauri/Cargo.toml`, `pnpm companion-api:gen`, and the ACL file regenerated by `src-tauri/build.rs`. `list` verbs need `pagination: "page-token"`.

In-tree frontend plugins are listed in `plugins/browser-builtins.json` and bundled by esbuild to CommonJS.

- Production builds use webpack (`next build --webpack`). noVNC 1.7.0 is ESM with top-level await, which esbuild cannot emit as CommonJS; **pin `@novnc/novnc@1.6.0`** (CommonJS, RFB over WebSocket).

## Rust — `crates/cognia-remote-desktop`

1. **Endpoint classification** in `cognia-net::egress`: `pub enum DestClass { Public, Private, Forbidden }` and `pub fn classify_dest(ip: &IpAddr) -> DestClass` (Forbidden: loopback, unspecified, link-local, multicast, broadcast, metadata; Private: RFC1918, CGNAT, ULA; IPv4-mapped addresses classified by their IPv4). Unit-tested beside `is_forbidden_dest_ip`.
2. **`target`**: Host store `remote-desktop-targets.json` (`{ version: 1, targets }`, ≤256 targets, ≤8 bindings each, ≤64 KiB per binding config, atomic write, 0600, symlink refused). `RemoteTarget { id, name, bindings, createdAt, updatedAt }`; `Binding { id, providerId, adapter: "vnc"|"none", priority, enabled, endpoint: { host, port, pinnedIp, class, confirmedAt }, viewOnly: bool, config: Value }`. Credentials in `keyring_secrets` namespace `remote-desktop`, keys `<bindingId>:control` / `<bindingId>:view`, never in the JSON, never returned.
3. **Pinning**: save resolves the host (`tokio::net::lookup_host`, 5 s timeout), refuses if any resolved address is Forbidden, pins the first address, and requires `confirm: true` for every endpoint (Private: LAN; Public: plaintext over the internet). Connect dials only `pinnedIp:port`. Probe re-resolves; a changed resolution is refused as `remote_desktop_endpoint_changed` until saved again.
4. **`rfb` adapter** (VNC): server side reads `RFB 003.00x\n` (3.3/3.7/3.8), answers min(server, 3.8); 3.7+/3.8 reads the type list (count 0 → reason ≤4 KiB → refusal). Chooses VncAuth (2) when a password is supplied and offered, else None (1) when offered and no password is required; anything else refuses with the offered type numbers. VncAuth: DES-encrypt the 16-byte challenge with the first 8 password bytes, zero-padded, each byte bit-reversed. SecurityResult per version rules; failure reason surfaced. Client side (toward noVNC): sends `RFB 003.008\n`, accepts the client's 3.3/3.7/3.8 reply, offers only None, sends SecurityResult OK where the version requires it, then pipes bytes both ways. 15 s handshake budget. `probe()` connects, reads version + types, disconnects without authenticating.
5. **`bridge`**: per session a loopback `axum` WebSocket listener on `127.0.0.1:0`, path `/rd/<256-bit hex ticket>`, accepts exactly one upgrade (constant-time ticket compare; Origin absent or one of the app origins), unused listener expires after 30 s. After upgrade it runs the adapter against the pinned address with the session's credential, then forwards binary frames ⇄ TCP with bounded buffers (1 MiB frame cap). Selects the `binary` subprotocol when offered. All tasks are owned (JoinHandle kept, aborted on close) — no detached tasks.
6. **`session` broker**: `open(targetId, bindingId, mode, takeover)`: binding enabled, endpoint confirmed, credential present for the mode. `view` is allowed only for `viewOnly` bindings with a stored view password (server-enforced); otherwise refused `remote_desktop_binding_cannot_be_read_only`. `control` requires `takeover: true` and the per-target `ControlLeaseCore` lease (principal `local-owner`; busy refuses). Sessions renew every 5 s; no renew for 15 s, `close`, release, or target/binding change/delete closes the bridge from the Host side. ≤8 concurrent sessions per Host. Returns `{ sessionId, url, mode, expiresAt, lease? }`.
7. **Audit**: extend the allowlist with `remote_desktop.target.save|delete`, `remote_desktop.credential.set|clear`, `remote_desktop.endpoint.confirm`, `remote_desktop.session.open|close|failed` and `target_kind = "external"`. Never hosts' passwords; host and port are not logged either (target/binding ids only).
8. **Tauri commands** (`tauri-host` feature): `remote_desktop_target_list` (page-token paging), `remote_desktop_target_save`, `remote_desktop_target_delete`, `remote_desktop_credential_set` (value or null to clear), `remote_desktop_target_probe`, `remote_desktop_session_open`, `remote_desktop_session_renew`, `remote_desktop_session_close`. State managed in desktop startup. Protocol entries + resources + dispositions + generated contract + ACL as listed above.
9. **Egress gate**: add a Rust rule for `TcpStream::connect` to `scripts/gates/check-network-egress.mjs` (+ test), allowlist the bridge with a new reason only if none fits (prefer existing `transport-impl`), and allowlist existing hits with accurate notes.

## Frontend

10. **Runtime point** `provider.remote-desktop` → binding `lib/remote-desktop/provider-registry.ts:registerRemoteDesktopProvider`, permission `remote-desktop:provide` (new, catalog + descriptions, tier `confirm`). SDK `defineRemoteDesktopProvider` + capability entry; regenerate the contract; update `extension-point-consumers.md`.
11. **Provider definition**: `{ id, nameKey, integrationMode: "embedded", adapter: "vnc" | "none", capabilities, configFields, viewer }`. Phase 2 implements `embedded` only; `native`, `web-console`, `external-app` are typed, refused by the registry with a named error, and shown as unavailable (ADR rule: dormancy on all three axes). Viewer: a React component for in-tree first-party plugins only; any other plugin must supply a webview viewer.
12. **Plugin API** `ctx.remoteDesktop.registerProvider(def)` returns a disposer; host side `lib/plugin/api/remote-desktop-api.ts`, guarded; cleanup on plugin unload.
13. **Third-party viewer bridge**: the webview host gains a transfer list; the page opens the Host WebSocket and relays bytes over a `MessagePort` transferred to the iframe. The iframe never sees the URL or ticket.
14. **First-party plugin** `plugins/remote-desktop-vnc/` (listed in `browser-builtins.json`): registers the VNC provider with a React viewer using `@novnc/novnc@1.6.0` loaded client-only; `viewOnly` mirrors the session mode (the Host is the boundary); scale-to-fit, clipboard off.
15. **Devices console**: section `remote-desktop` on the local desktop row (`lib/devices/section-plan.ts`): target list, add/edit wizard (provider → name/host/port → probe shows protocol and security types → endpoint confirmation text for LAN vs internet → control password, optional view-only password → save), delete, open. Viewer page `app/devices/remote-desktop/page.tsx?target=&binding=&mode=`: toolbar (take control / release, fit, fullscreen, disconnect), session status, Host-side refusals mapped to messages. All strings i18n'd (en + zh-CN).
16. **Changeset** `minor`.

## As built (2026-10-18)

Deviations from the plan above, each pinned by tests:

- **Takeover.** `control` without `takeover` succeeds when nobody controls the target and is refused `remote_desktop_control_busy` while someone does; `takeover: true` preempts the current controller (its session ends with reason `preempted`, audited as `remote_desktop.lease.takeover`). The viewer asks before taking over and offers view-only where the binding allows it.
- **Delete is idempotent.** `remote_desktop_target_delete` on a missing target is a no-op, per the ADR-0175 `delete` verb.
- **Credential lifecycle.** Credentials are cleared before the store is written (a failed clear aborts the save or delete, so no secret outlives its binding). Turning view-only off, switching to adapter `none`, or removing a binding clears its secrets. Binding ids are minted by the Host only.
- **Probe is two-step.** `{ kind: "draft", confirm: false }` resolves and classifies without connecting; `confirm: true` connects and reads the RFB offer. `{ kind: "saved" }` refuses `remote_desktop_endpoint_changed` when the name no longer resolves to the pinned address (membership, so round-robin reordering is not a change).
- **noVNC 1.6.0 is not top-level-await free.** `lib/util/browser.js` awaits a WebCodecs H.264 probe at module scope. `patches/@novnc__novnc@1.6.0.patch` starts the flag `false` and publishes the probe result when it settles; `rfb.js` reads it live when sending encodings.
- **Egress gate.** The new `tcp-connect` rule found 18 existing raw sockets; each is allowlisted with a reason, and the new `user-endpoint` reason covers SSH forwards and the remote desktop bridge and probe. The relay's loopback WebSocket is allowlisted as `loopback`.
- **Third-party viewers.** `PluginWebviewHost`'s per-frame poster accepts a transfer list; `lib/remote-desktop/port-relay.ts` owns the loopback WebSocket and hands the page a `MessagePort` (binary frames, `{ type: "closed" }` / `{ type: "close" }`, 1 MiB cap).

Not verified yet: a real TigerVNC server (with and without a view-only password) and a desktop smoke of the devices section and viewer.
