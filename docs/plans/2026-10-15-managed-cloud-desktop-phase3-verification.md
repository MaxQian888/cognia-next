## Implemented behavior

- **Original admission authority:** `delivery_admission.rs` consumes the closed source declaration before spawn, derives owner/Host/device from authenticated native context, normalizes the authorized repository, stores secret values only in the Host store, and persists `SourceStore` before remote work. Delivery records reference the unique source ID and verify task/repository/branch consistency. Legacy records remain readable but cannot authorize handoff.
- **Run identity distinction:** the Host mints the durable authoritative `codingRunId`; the original conversation's `originRunRef` is an immutable owner-admitted reference, not an authorization claim about a browser-owned run. The diagnostic child stores `parentRunId` pointing to the Host run, plus the original reference, conversation/task/source/delivery IDs. Phase 4 must preserve this distinction when projecting existing execution history. No terminal parent run is reopened or completed.
- **Revocation:** source tombstones survive restart and refuse late admission. Conversation deletion uses the ADR-0213 canonical pre-delete barrier while the original Host links still exist. New sessions persist their exact source Host before spawn. Wrong/offline/replaced Hosts refuse; successful revokes persist progress across multiple Hosts. Native task deletion performs its existing state/device authorization before revoking source authority.
- **Metadata UI:** the existing managed desktop settings mount delivery selection and an explicit proposal form. Host-checked immutable delivery/revision, mode, criteria and selected relative paths produce an estimate only. The proposal always returns `executionEnabled:false`; there is no spending/execution RPC. Account/Host changes invalidate pending responses.
- **Read-only source:** `GitProxy::start_read_only` refuses receive-pack discovery and POST before contacting upstream. The original branch-limited publishing mode remains. Git credentials are resolved only on the source Host. Read-only proxy logs omit repository URL and branch.
- **Pinned reconstruction:** fetch/import resolves the exact recorded commit; a moving branch cannot change it. Recovery files are confined to the trusted recovery directory, opened without following symlinks, bounded to 512 MiB, hashed, and checked for required objects. Private staging reserves disk capacity, monitors cumulative size and cleans up on cancellation/deadline. Blocking filesystem work runs outside async workers.
- **Acceptance inputs:** up to 100 selected files, 8 MiB each and 32 MiB aggregate, read from pinned Git objects. Reject traversal, duplicates, secrets/profile paths, symlinks, special files and overwrite. Source transfer includes Git history; the UI/operator explicitly describe that selected-file filtering is not history sanitization.
- **Guest install:** a fixed embedded Python installer uses protected envd process/stdin transport with both authentication layers. It checks hashes and exact HEAD, uses an exclusive operation directory, and runs only an explicitly selected `npm run <script>` in the checkout with a clean environment as `cua`. No implicit dependency installation, arbitrary shell, source preview tunnel or credential forwarding is added.
- **Native diagnostic:** `managed-desktop-operator handoff-smoke` requires the existing explicit paid-smoke flag, a bounded private request file and per-quote typed approval. It claims an operation durably before work, persists the child binding and transfer/full-manifest digests, reauthorizes source and desktop around transfer, and always requests desktop cleanup. An interrupted/duplicate operation never silently creates a second desktop. It writes no screenshot, acceptance verdict, human approval, qualification receipt, share link, merge or original-task completion.
- **Image identity:** recipe revision 3 adds Git/nodejs/npm and checks those executables. The computer-server remains fixed at 0.3.46 and the published image must still be digest pinned. Old recipe qualification cannot authorize the new image.
