# Per-workspace port allocation (W4): design research

Date: 2026-10-16. Source: read-only Codex (gpt-6-astra) research job over `dev`; `observed` claims cite code, `inferred` claims are design proposals. Companion to `2026-10-16-agent-sandbox-workspace-gap-analysis.md`.

## Summary

建议在 cognia-task-workspace 的 SQLite 中新增独立端口租约表，由实际执行 Host 按工作目录解析身份、原子分配连续端口块，并在各进程启动边界注入 COGNIA_PORT、COGNIA_PORT_COUNT、PORT。默认归档保留租约，删除与 provisioning 回滚释放，启动时协调恢复。需同时覆盖 Rust managed workspace、桌面 session 文件夹和用户项目 checkout；容器端口必须按网络命名空间处理。已完成只读研究，未修改文件、未运行测试。详细事实、注入位置和实施顺序如下。

## Open questions

- 产品是否接受给用户自己的 checkout、Permanent/Imported 环境和桌面 session 文件夹也分配端口？建议全部覆盖，并按实际物理 root 去重；若只做 registry managed，需要明确这些入口不在首期保证范围。

- 默认端口范围尚未确定；blockSize 可定为 10。归档保留会持续占用逻辑容量，需要确定范围大小、耗尽提示以及是否提供显式释放闲置归档租约的操作。

- 同机多个 Cognia 数据目录、桌面进程与独立 terminal-host 应通过哪个单一 Host 服务协调租约？当前证据显示它们存在进程边界，不能仅靠一个进程内 Mutex 保证全机唯一。

- 远端 E2B/Kubernetes、SSH 目标是否纳入首期端口保证？尚未进行目标环境 bind/forward 实测；需要明确 runtime namespace、恢复后的稳定性和 preview/forwarding 契约。

- 是否要求 Cognia 自身的 pnpm dev/Tauri dev 也自动使用租约？目前启动脚本固定 3000，这需要与端口基础能力一起纳入验收范围。

## Decisions (2026-10-16)

- **Coverage:** managed registry workspaces, desktop session folders and user project checkouts all get leases. Leases are deduplicated by canonical physical root; multiple aliases of one physical root share one block.
- **Range:** the default is 41000–48999 with a block size of 10 (800 blocks), configurable in `WorkspaceLifecyclePolicy` as `portRangeStart`, `portRangeEnd` and `portBlockSize`, all with serde defaults. Changing the range affects only new leases.
- **Lifecycle:** a lease is allocated before setup scripts run, or lazily on first execution for existing workspaces. Archive keeps it. Delete, prune and provisioning rollback release it, and the Settings UI offers an explicit release for idle archived leases. Boot reconcile repairs links and reports duplicates or out-of-range leases without reassigning them.
- **Authority:** the task-workspace SQLite ledger, with allocation inside `BEGIN IMMEDIATE`, which SQLite serialises across processes. Allocation probes IPv4 and IPv6 loopback binds for every port in a candidate block and skips blocks another app holds. A port that becomes occupied after allocation is reported, never reassigned or killed. Separate Cognia data directories are not coordinated beyond the probe, and the docs say so.
- **Namespaces:** containers and remote runtimes receive the same block values inside their own network namespace. The ports are not published or forwarded automatically, so the lease never opens a host port. SSH targets are out of scope.
- **Exhaustion:** this is an explicit error naming the setting. There is no silent fallback to 3000.
- **Not in scope:** making Cognia's own `pnpm dev` / Tauri dev scripts read the lease.
