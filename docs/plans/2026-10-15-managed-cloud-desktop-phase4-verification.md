## Implemented behavior and ownership

- **Encrypted Host authority:** `crates/cognia-automation/src/cua_sandbox/managed/evidence.rs` persists an AES-GCM authenticated index and images using a Host secret-store key. Bindings retain owner/Host, source/conversation/task, Host coding run and original run reference, immutable delivery revision/commit, manifest digest, desktop ID/generation and criteria. New storage is necessary because the existing recording and media namespaces have different ownership, capture and retention contracts.
- **Bounded evidence:** only checkpoint/failure PNG/JPEG artifacts are retained, with at most 100 capture reservations, 100 MiB aggregate and 8 MiB per image; decoded dimensions are bounded to 4096 per axis and allocation to 64 MiB. Capacity reservations precede publication; interrupted reservations remain accounted for and staging is reconciled. No continuous recording, default sharing, library promotion or automatic evidence backup/export. `crates/cognia-companion/src/backup.rs` excludes the evidence root before traversal/staging.
- **Independent decisions:** agent verdicts require the bound agent principal and complete criterion evidence; required missing/corrupt images cannot produce a pass. Human approvals carry their own principal, timestamp, idempotency key and expected revision. They never overwrite the agent verdict, merge code, complete the source task or reopen a terminal parent. Diagnostic system outcomes are a third, explicit field.
- **Authenticated result API:** `crates/cognia-companion-rpc/src/managed_desktop_results.rs` registers nine closed-schema commands through existing local/remote/headless dispatch. Caller-supplied owner, decision principal, pixels and paths are rejected. Native capture uses the bound desktop generation and rechecks source/authority. Mutations recheck admission after acquiring the evidence file lock. HTTP evidence replies carry `Cache-Control: no-store` on both Host API surfaces.
- **History and views:** `lib/execution/managed-desktop-results.ts` projects a child verification artifact into existing execution history, using opaque references/counts rather than image bytes or bearer URLs. `RunDetailPane` and the existing source-conversation overview mount the result view. Conversation lookup survives parent-event pruning. The captured account/Host transport invalidates stale responses; image integrity is verified before displaying revocable object URLs. The user opens screenshots explicitly. Independent approval and confirmed acceptance-only deletion reuse the same view.
- **Canonical conversation/acceptance deletion:** `lib/automation/managed-desktop-result-deletion.ts` extends the ADR-0213 path through `session-archive-writes.ts`, `sessions.ts` and retention. Schema v244 adds an account-local, content-free outbox, excluded from sync and portable backup, with no ordinary tombstone TTL. Existing guards run first. Native prepare freezes evidence; the Dexie transaction couples history deletion, acceptance projection cleanup and committed outbox state. Rollback aborts the prepared intent. Offline preparation remains durable and visibly pending; it does not claim remote bytes are already erased.
- **Multi-Host and native task deletion:** cleanup commits evidence deletion, revokes the recorded source Host, re-reads Host-derived task IDs, and invokes canonical task deletion on each owning Host. Renderer gateway links cannot supply task deletion authority. Task-only deletion persists owner/Host and the original optional device constraint before its destructive future; ambiguous failure remains prepared. Restart replay uses the canonical execution backend, never infers success from missing local HOME files, and commits only after backend success. Account changes cannot reinterpret a prepared operation as another owner.
- **Cleanup independent of enablement:** desktop and headless startup reconcile native deletion intents, artifact/staging removal and desktop destruction. Provider cleanup failure is separate from byte cleanup and retains a minimal durable target. Renderer retention and the settings cleanup panel replay/report pending outbox work. Archive retains evidence. Committed scopes fence late capture, verdicts, registration and browser re-import.
- **Reachable diagnostic, dormant production:** the existing explicitly authorized `handoff-smoke` can register a binding, retain a real checkpoint, record an inconclusive system outcome and request cleanup. Its plaintext receipt contains only version, opaque ID, state and cleanup status. Production acceptance/delegated agent control remains hard-disabled; this phase does not fabricate a successful agent run or a qualification receipt. Live preview, cross-Host transfer and project-triggered paid acceptance remain dormant on contract/UI/test axes.
