## Problem frame

Remove role-specific shipped caps (O1), preserve terminal status across the runtime/executor/dispatcher boundaries (O2), and reuse the existing explicit continuation protocol with saved partial findings for foreground and background tasks (O3). Continuation re-dispatches the original task and recorded findings; it does not replay a complete native session. Automatic retry must not buy more budget after exhaustion (C1).

## Research-informed rewrite (2026-10-21)

This section supersedes the rejected-draft implementation status above. The user authorized implementation and real-provider reacceptance, while explicitly forbidding Tauri startup and typecheck. The optional cross-model review remains skipped.

Implemented behavior:

- Standalone workspace port RPC may legitimately return an empty overlay. Real sandboxed ripgrep now exercises that host response; malformed partial allocations still fail closed.
- Removed the global32K reservation draft. Recognized built-in DeepSeek models use documented output defaults:8K with thinking disabled,64K with thinking enabled,128K for max/xhigh. Explicit output limits survive. Main Anthropic reservation includes actually generated thinking; summary reservation omits top-level reasoning that its adapter request never sends and ignores another protocol's options.
- Unconfigured summary generation uses up to16384 output tokens, bounded by the selected model output ceiling and one quarter of its context window. This quarter-window policy is a Cognia default heuristic, not a provider requirement. Explicit provenance prevents a stored cap (including16384) from being reclassified as a default; retrying a larger model recomputes the default rather than retaining a previous small-model cap. Positive explicit summary/tool caps, custom prompts, strategies and message counts remain authoritative. Unconfigured tool-result clipping is disabled;0 is supported and explained in settings. Existing persisted values are treated as explicit, with no speculative migration of legacy500-token or6-message settings.
- Unconfigured recent history uses a token suffix bounded by min(12000,10% of resolved input budget), expanded to keep tool pairs legal. Previous checkpoints inform incremental AI summaries as separate prior_context; unchanged facts stay in the frozen prefix, new output records progress and an original-goal/constraints anchor. Recursive chunks also receive that background; regeneration merges old checkpoints once. Extractive incremental behavior is preserved.
- Summary requests check the estimated full input, including prior context, against the summary model's resolved input budget before billing/dispatch. This uses a token estimate, not an exact tokenizer guarantee. Invalid, empty, truncated or failed chunk/merge results retain history. Publication checks complete size, shrinkage and pairing with concurrent appends; an identical rejected snapshot does not buy another automatic summary. New evidence or explicit force permits retry.
- Budget-stop capture retains a redacted text checkpoint bounded to32768 characters alongside the existing first/latest tool evidence. It labels the checkpoint an untrusted model summary, not verified execution. The discarded read-coverage appendix is absent.

Focused validation:725 Jest tests in6 suites,123 sidecar tests in7 files and108 AI SDK runtime-caller integration tests (956 total); scoped ESLint/Prettier plus i18n build/check/lint.
