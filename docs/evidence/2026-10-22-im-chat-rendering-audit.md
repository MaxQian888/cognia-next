### New findings

1. **P1 — Lark thread recalls do not match the stored row.** Create uses a thread/root conversation key (`lark/parse.ts:699-705`), and the live adapter defaults `replyInThread` to true (`lark/index.ts:641,700-702`). Recall builds an unthreaded key (`lark/parse.ts:595-619`); bus lookup demands exact conversation scope (`bus.ts:1600-1613`). Independent in-memory execution with checked-in `dm-text.json` produced stored `lark:audit:oc_dm_chat_001:om_dm_001` versus recall `lark:audit:oc_dm_chat_001`; `reply-thread.json` produced stored `lark:audit:oc_group_chat_002:om_thr_001` versus recall `lark:audit:oc_group_chat_002`. Both fail the lookup predicate. Legacy unscoped rows and genuinely flat sessions are counterexamples. This affects text as well as cards/media.

2. **P1 — Recall can leave the old rich body visible even when lookup succeeds.** `bus.ts:1730-1737` adds `deletedAt` and replaces parts with `[deleted]`, but spreads the full old metadata. `message-renderer.tsx:1060-1068` still renders `inboundA2UI`, without testing `deletedAt`. A flat Lark interactive-card conversation avoids finding 1 and reaches this path. This is source-confirmed; the new database/full-renderer Jest probes did not run because of ENOSPC.

3. **P2 — Malformed rich payload can take down the conversation pane.** Renderer directly reads `block.body.map` and `node.kind` (`inbound-a2ui-renderer.tsx:64,74`). Lark `textOf` trusts truthy content (`inbound-to-a2ui.ts:52-58`), so object content can reach React as a child. A read-only in-memory transpile + SSR harness using actual source reproduced missing body → reading map, null node → reading kind, and object-valued Lark Markdown → `Objects are not valid as a React child`. The later React error is outside dispatcher try/catch. No single-message error boundary was found; Inbox has a pane-level boundary. These are malformed/synthetic inputs, not proof that a live platform emitted them.

4. **P2 — Character mention handling bypasses fallback Markdown even without a mention.** `message-list.tsx:181-182` builds a character map. Any nonempty named-character map creates a regex (`message-renderer.tsx:604-613`); user parts then always take the plain-span branch (`2202-2209`) before MarkdownRenderer (`2237-2246`). The branch does not first require an actual match. This affects ordinary user/IM fallback text when such characters exist. It does not apply to assistant parts, which receive a null mention pattern, or renderers without a character map. Source-backed; no new DOM assertion ran.

Installed Next image prop computation passed the platform schemes directly to src. These checks do not load images in a real browser.

No new Jest pass is claimed. Unexecuted temporary test/config copies were removed; the first round's 8 suites / 84 tests remain historical results only.
- Current shell still runs Node v24.19.0 against a manifest requiring >=26.0.0. No real-provider, browser, native or mobile acceptance ran.
- Adjacent observation held out of the confirmed rendering findings: synthetic partial Discord MESSAGE_UPDATE can throw when author is missing; the live-provider legitimacy of that shape and gateway-loop consequence need separate verification.

Revised next-phase order, pending user confirmation: (1) recall matching and rich-body invalidation on deletion/edit; (2) native-envelope boundaries and per-message validation/failure isolation; (3) media presentation, text mirrors, Markdown and deduplication; (4) ordinary URL navigation. Callback execution remains a separate product decision. No original claim was silently promoted to live-provider acceptance.
