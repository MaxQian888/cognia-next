### F1 — History rows silently disappear

SnowLuma's `sanitizeMessageEventForApi` removes `post_type` and `self_id` from history rows. Cognia `fetchHistory` directly calls `parseV11Event`, which returns null unless the row has the live-event envelope (`post_type === "message"`). A one-message SnowLuma-shaped API response produces zero normalized history events.

Repro: `Expected length: 1; Received length: 0; Received array: []`.

Impact: history can appear empty even when the server successfully returned messages. Fixing only cursor fields does not solve this. A history-specific normalization path must supply authoritative self identity and preserve incoming/outgoing direction, peer identity and recall semantics; do not blindly treat every self-sent history row as inbound AI input.

### F2 — Both history cursors use the wrong contract

Cognia serializes `message_seq`; SnowLuma's group/friend history actions declare `message_id`, defaulting to zero. The upstream action parser iterates declared fields and ignores `message_seq`. SnowLuma expects its signed message identifier, not the raw sequence number. Cognia also advances from the oldest row's `message_seq`, so renaming a field alone is insufficient.

Repros:

- Group: expected `message_id: -123456`; received `{group_id: 200001, count: 20, message_seq: -123456}`.
- Friend: expected `message_id: -123456`; received `{user_id: 200001, count: 20, message_seq: -123456}`.

Impact: after F1 is fixed, pagination can refetch the latest page or stop without loading older data. SnowLuma's anchored history includes its anchor, so adapter pagination also needs overlap/dedup and progress tests against the upstream contract.

### F3 — SnowLuma reactions and files are suppressed

The implementation probe normalizes `SnowLuma` to `snowluma`, but grants features only to NapCat/Lagrange/LLOneBot. It therefore persists `features: []` for SnowLuma. `effectiveCapabilities` suppresses `send.reaction` and `send.file`; `assertReactionSupported` refuses reaction RPCs. The upstream v2.2.0 action registry includes `set_msg_emoji_like`, `upload_group_file` and `upload_private_file`.

Repro: expected capabilities containing `send.reaction` and `send.file`; both absent after a successful SnowLuma version/identity probe.

Impact: the tool capability surface understates supported SnowLuma functions. This does not mean every direct file send fails: the serializer also supports a v11 file segment. A fix should preserve honest feature gating and test both capability exposure and actual outgoing action shape. Selecting NapCat as the UI hint does not repair runtime probing.

### F4 — Temporary private replies lose their source group

SnowLuma emits `message_type: private`, `sub_type: group`, with the source in `sender.group_id`. Cognia's `OneBotV11Sender` omits this field and the parser stores `conversationRef.groupId` only for group messages. The private serializer sends only `user_id` and `message` even if group context were supplied.

Repro: expected `group_id: 200001`; received `{user_id: 300001, message: [...]}`.

Upstream chooses `sendGroupTempMessage` only when an explicit source group references an existing peer-opened temp session. Without that field it selects normal friend C2C. This proves a routing mismatch; actual QQ rejection/delivery was not exercised. Fix parser retention and serializer routing together, including same-user/multiple-source-group and non-friend regressions.
