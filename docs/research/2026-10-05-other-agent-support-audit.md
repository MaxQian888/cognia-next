# Other external agent support audit

Date: 2026-10-05. Scope: the current shared working tree, all 20 non-Pi runtime catalog entries, and the generic A2A adapter. This is a source/protocol audit with focused tests, not certification of every installed agent or authenticated provider. The findings below preserve the original audit snapshot; the remediation section records subsequent implementation and verification.

## Remediation (2026-10-05)

The implementation extends the existing shared session contracts and host transport. Vendor adapters supply their native semantics; the same controls consume capabilities locally and through the paired-host RPC plane.

| Area                     | Implemented correction                                                                                                                                                                                                                                                                                            |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Shared session targeting | Steering requires the chat-linked native session ID and refuses an ambiguous target.                                                                                                                                                                                                                              |
| Shared operations        | Typed entry/turn fork boundaries, archive/unarchive, normalized history, queue/runtime controls and background subscriptions reuse the manager and capability-driven UI contracts.                                                                                                                                |
| Codex                    | Common rename, turn-boundary fork, history entries and archive/unarchive map to current app-server methods. Active and archived native threads are discovered after restart; restoring an archived row explicitly unarchives without automatically resuming execution.                                            |
| ACP                      | Explicit null clears metadata. | OpenCode                 | V1/V2 command and instruction paths pass through the outbound gate; common rename/history/fork/queue operations and persistent event subscriptions use native capabilities. V2 state, retry, compaction and command updates are projected.                                                                        |
| A2A                      | Terminal tasks are retired while conversation context survives; omitted streaming capability uses the non-streaming method. Artifact snapshots preserve append/replacement/completion and binary payloads through collected results and chat file parts. Cancellation retires a task only on server confirmation. |
| Aider                    | Cold manifest discovery, consistent warm/cold resume and updated instructions. Inline/workspace images use confined binary filesystem operations with size limits and cleanup of runtime-owned files.                                                                                                             |

### Deliberate boundaries

- OpenCode native shell remains explicitly unsupported through the common shell capability: its native route inserts output into model context before Cognia can apply the outbound gate. Exposing that route as safe shell support would be inaccurate. A provider hook or an equivalent enforceable exclusion boundary is required.
- The generated CLI host API exposes the new session query/mutation commands. Existing TUI integration handles slash commands and background events/approvals; a complete advanced-operation TUI menu is not claimed.
- Existing user-configured package-runner commands are preserved. New defaults require an installed executable; setup guidance and executable identity/version consent remain in force.
- DSH's actual installed process was exercised with isolated runtime state and a loopback model/MCP fixture, not an authenticated cloud model. These checks do not raise certification for every ACP vendor.
- Caller-local MCP URLs still cannot be forwarded to a different host without a reverse transport.

## Original audit result (before remediation)

Support is not complete. The main gaps are session identity, operations implemented under vendor-specific names but invisible to the common interface, incomplete event projection, and runtime version certification. Missing Pi-specific operations are not automatically defects in other agents.

## Intentional limits and items not to implement blindly

- DSH's current SDK wire still exposes initialize, prompt, and shutdown rather than separate native tree/rename/export or per-tool approval/cancel RPCs. Process cancellation is an integration constraint to handle explicitly. [Wire types](https://raw.githubusercontent.com/deepseek-ai/deepseek-harness/master/packages/sdk/protocol/src/types.ts).
- Aider's CLI is the stable scripting entry point; its Python API has no compatibility guarantee. Preserve existing sandbox and command restrictions when adding attachments or history indexing. [Scripting](https://aider.chat/docs/scripting.html).
- Paired-host caller-local MCP mounts need a reverse tool transport. Forwarding localhost addresses to another host is incorrect; the existing refusal in `remote-execute.ts:156` is intentional.
- ACP Next Edit Suggestions is now marked **To be removed**; filling the dormant draft integration would not improve current compatibility. [Upstream status](https://agentclientprotocol.com/rfds/next-edit-suggestions).
- Codex rollback is deprecated upstream and is not a priority for a new common UI. Codex external-message submission has distinct low-trust semantics; it must not become an ordinary user-message alias. Named permission-profile comments also need reconciliation with actual legacy sandbox behavior, without weakening policy.

## Fresh verification

- **29 runtime test suites passed: 1,233 tests passed, 1 skipped.** A2A alone: 42 passed. The remaining ACP, Codex, OpenCode, DSH, Aider and remote-runtime suites: 1,191 passed, 1 skipped.
- Tests ran serially with a 2 GiB Node heap and a 65-second process-group bound. The aggregate run emitted Jest's delayed-exit/open-handle warning, then exited successfully. No coverage run.
- Current-source probes reproduced wrong-session steering, ignored ACP null clears, A2A terminal-task retention, artifact replacement metadata loss, and inline-file payload loss. A focused OpenCode method probe captured the unguarded command argument using synthetic data and a stub SDK boundary.
- Local `codex --version` and `codex app-server generate-json-schema --experimental` established version/API evidence without starting a provider session.
- Existing tests passing does not cover these new counterexamples. In particular, some A2A/Aider tests intentionally assert the current degraded projection or image rejection.
- Not run: full typecheck/build, browser UI acceptance, authenticated provider calls, package upgrades, or an installed-process test for every vendor. Unit suites and extracted-source probes are not substitutes for those checks.

## Recommended implementation order

1. Correct common session targeting, outbound instruction/command safety, metadata clearing and artifact state semantics. Add behavioral regressions for two simultaneous chats, terminal-task continuation, replacement artifacts, binary content and warm/cold resume.
2. Extend existing common operation contracts only where native semantics require it: archive lifecycle, typed fork boundaries, inbox item operations and background event ownership. Preserve explicit unsupported states and capability negotiation.
3. Map Codex/OpenCode methods onto those contracts, then fill Aider attachment/indexing behavior and DSH's coordinated version migration. Validate each adapter against its real upstream version.
4. Connect shared UI/CLI and paired-host RPCs to the same contracts, including permission decisions, cancellation, persistence and event subscriptions. Do not create vendor-only parallel controls.
5. Add contract fixtures for each supported version and then run real-process/provider acceptance before raising catalog certification. Resolve the three unpinned launch waivers with vetted pinned distributions.
