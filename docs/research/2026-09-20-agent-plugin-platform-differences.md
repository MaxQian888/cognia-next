# Agent plugin platform differences

Research snapshot: 2026-09-20. Scope: official documentation and current local conversion code. These findings support product discussion; they are not a claim that converted bundles have passed live native-host acceptance. Documentation describes current capabilities, not the minimum supported installed version. Version-specific adapters require pinned fixtures and native-host smoke tests.

## Platform contracts

| Platform       | Native package and capabilities                                                                                                                                                  | Conversion implications                                                                                                                                                                                                                                                                                                                                             |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Claude Code    | `.claude-plugin/plugin.json`; skills, agents, hooks, MCP, LSP, monitors, themes; user configuration and runtime path variables                                                   | A rich declarative package, not merely Markdown. Tool identities, activation metadata, hook results and persistent state need explicit mappings.                                                                                                                                                                                                                    |
| Codex          | Portable Agent Plugins 1.0 root `plugin.json`, `skills/`, `mcp.json`; OpenAI-specific `extensions.com.openai`; legacy `.codex-plugin/plugin.json` compatibility; lifecycle hooks | Distinguish portable format from legacy Codex format. Hooks use `PLUGIN_ROOT`/`PLUGIN_DATA`, with Claude aliases. Do not assume a `CODEX_PLUGIN_ROOT` binding. Plugin-agent behavior needs version/source verification: the official examples repo mentions agents/commands, but the package guide does not establish a compatible Claude-agent execution contract. |
| Gemini CLI     | `gemini-extension.json`; native `skills/`, TOML commands, `hooks/hooks.json`, `agents/` (preview), `policies/`, context, settings and themes                                     | Native skills should preserve resources. Hooks, agents and policies are convention-discovered outside the manifest. Installation settings can supply environment variables, with sensitive settings stored in keychain.                                                                                                                                             |

## Confirmed local gaps at the pre-implementation snapshot

The converter currently exposes only `cognia`, `claude-code`, `codex`, and `gemini-cli` as bundle ecosystems. Support elsewhere for external-agent execution or individual configuration synchronization is not equivalent to complete plugin conversion.

In particular, the existing `lib/ai/agent/external/renderer-tool-host.ts` hosted-tool route is a separate delivery mode: exposing Cognia-hosted tools to an external agent does not make the Cognia plugin a standalone native package. Current examples such as `deep-research` (tools/commands/skills/configuration), `cognia-documents` (tools/importers/exporters), and `github-devin-bot` (bot) exceed the converter's allowed declarative capability set. A product should present hosted use and standalone export separately, including whether Cognia must remain running.

1. **Gemini capabilities are silently omitted.** A local `tsx` fixture containing `gemini-extension.json` with name/version, `skills/review/SKILL.md`, and `hooks/hooks.json` imports with `capabilities: []`, `structured` fidelity, and no warning/blocker. The converter reads context, commands and MCP but does not inventory convention-based capabilities. Policies and agents need detection too. The current native-skill-to-command export and resource-skill rejection reflect an obsolete limitation, not Gemini's documented capability.
2. **Bundled MCP implementation files disappear on export.** A Cognia stdio preset referring to `${COGNIA_PLUGIN_ROOT}/servers/index.js`, with that file present, exports to Claude with only `.claude-plugin/plugin.json` and `.mcp.json`. The report is `structured` without warnings. The generated config points to a missing executable. Resource dependency closure must include MCP/hook scripts and supporting assets, not only skill directories.
3. **Skill activation policy is lost.** A Claude skill with `disable-model-invocation: true` imports as an inline skill without an invocation policy and without warnings. Keeping prompt text does not preserve who can activate the skill. The same audit should cover allowed tools, fork context, model routing, argument behavior and frontmatter fields.
4. **Hook runtime compatibility is overstated.** A hook-only command plugin is reported compatible with browser/Tauri/mobile: `finalizeForeignConversion` determines runtime need from MCP and skill filesystem needs, omitting hooks. This is a metadata mismatch; actual execution requires separate host-specific verification.
5. **Hook conversion is asymmetric.** Command hooks can import into Cognia, but export's allowed capability set excludes `command-hooks`. The platform supports hooks; this is a missing adapter, not absence in the destination.
6. **Configuration fields are blanket-blocked.** Export rejects MCP preset fields with a message that target formats cannot prompt users. Gemini settings and Claude user configuration offer native mechanisms, although field types, secret storage and lifecycle differ. They need field-level projection rather than a universal unsupported statement.
7. **Codex root-token mapping lacks a documented contract.** Code emits `${CODEX_PLUGIN_ROOT}`. Current official plugin-hook documentation specifies `PLUGIN_ROOT`, `PLUGIN_DATA`, and Claude compatibility aliases. Verify every component separately; substituting a token globally across content and executable config is insufficient.
8. **Portable root manifests need separate detection.** Agent Plugins uses root `plugin.json`, also used by Cognia. Schema/shape detection and ambiguity handling are necessary before adding portable imports. Legacy Codex exports remain documented compatibility, so legacy format alone is not proof of a broken package.
9. **Whole-bundle MCP import bypasses the existing secret parameterization.** A synthetic `API_KEY` in a Claude `.mcp.json` env block survives in generated Cognia `plugin.json`, with empty preset fields and no warnings. `convertMcpDocuments` uses normalized drafts directly, whereas single-MCP `buildMcpPreset` calls `sanitizeMcpConfig`. No real credentials were used or inspected in this reproduction. Packaging for redistribution needs a shared credential/configuration policy, including retained original source files.

Local evidence supplied by the parent audit: `lib/plugin/convert/ecosystem.ts` around lines 326, 418, 1139, 1399 and 1465, plus `lib/plugin/convert/skill-source.ts` `buildSkill`. These line numbers describe the working-tree snapshot and may move. No implementation changes were made for this research.

## Recommended decisions for discussion

- Treat conversion as a capability report and transformation, with separate statuses for native preservation, adapter-required, explicit semantic downgrade, unsupported, and unverified. Package-level `structured` is not enough.
- Make import/export profiles depend on platform, version and surface (CLI, desktop, cloud), plus installed optional extensions. Pi-with-MCP-extension is different from Pi core.
- Preserve a portable skill/MCP core where genuinely equivalent; retain target-specific extensions for agent lifecycle, hook contracts, UI, secrets and policies. Do not rewrite Cognia UI/WASM/Python/JS activation code into prompts and call it converted.
- Detect all declared and conventional source capabilities before conversion. Unknown behavior must be reported; unsupported policy/hook behavior must never disappear silently.
- Validate hook event names, tool-name matchers, input/output payloads, block/continue semantics, timeout/failure behavior and trust rules independently. For example Gemini `BeforeTool` and Claude `PreToolUse` are not made equivalent by renaming the key. [Gemini hook reference](https://geminicli.com/docs/hooks/reference/)
- Establish complete-bundle acceptance fixtures: install/load, explicit and automatic skill invocation, resource reads, MCP startup and tool call, hook firing/blocking, secret configuration, update/reload and uninstall cleanup. Mock conversion success is only structural evidence.
- Prioritize silent loss and broken bundle resources first; then restore Gemini native skills and add versioned hook/config adapters; only then expand bundle targets to OpenCode/Pi/Cursor/Copilot/Kimi/Devin.

## Evidence limits

Focused verification: `pnpm exec jest lib/plugin/convert/ecosystem.test.ts --runInBand --silent` passed 1 suite / 37 tests. Additional in-memory `tsx` fixtures reproduced items 1–4 and 9 and inspected returned manifests/file maps. Passing existing tests does not cover those missing behaviors. `ecosystem.ts` already had uncommitted changes before the audit; conclusions describe the current working tree, not a published release. This research added only this note.

No native agent installation, authentication, plugin installation or external service call was performed. Absence of an advertised component in a page is recorded as unverified, not proof that the platform lacks it. Platform metadata can change independently of this repository; native support should be checked against a pinned release before implementation. Agent Plugins compatibility does not imply all vendor-specific extensions or runtime variables behave identically.

## Implementation after approval on 2026-09-20

The shared converter, desktop dialog, inspection/apply tools and Rust CLI now expose all eleven targets
(including Cognia and the portable Agent Plugins format). Foreign-to-foreign conversion uses the canonical
pipeline. Native package generation and Cognia-hosted tools have separate delivery outcomes; neither
claims installation or runtime verification. Cloud output is blocked pending a verified route.

| Area                  | Implemented behavior                                                                                                        | Remaining boundary                                                                                                                    |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Skills                | Native Gemini Skills; all target Skill package shapes; text/binary resources, root Skills and invocation metadata preserved | Unsupported tool policies, dynamic execution, model/fork controls and target-specific invocation rules explicitly block               |
| MCP                   | Sanitized credentials, preserved runtime payload, Gemini installation settings, target config projection                    | Pi needs an extension; OpenCode needs portable local command semantics; other targets' interactive fields require adapters            |
| Hooks                 | Validated Claude/Codex import and Claude native export; shell hooks require desktop runtime                                 | Codex/Gemini export and new vendors' hook contracts require dedicated adapters; Gemini hooks/agents/policies are detected and blocked |
| Runtime contributions | Tool-host alternatives identified for existing Cognia external-agent adapters                                               | UI, bot lifecycle, storage and arbitrary JS/WASM/Python runtime stay in Cognia; no standalone runtime rewrite                         |
| Writing               | Source-bound expiring plans, concurrent-use guard, output overlap protection, explicit warning acknowledgement              | Writing files is not plugin installation or authentication                                                                            |
| Reports               | Shared capability statuses, native/hosted split, surface and verification state; structured CLI failures preserved          | No pinned native-host version certification                                                                                           |

The initial gap list above records the audit baseline; it is not a description of the updated working tree.
Focused verification after the fixes passed 27 Jest suites / 1,020 tests. The standalone embedded-converter
test executes from a temporary directory without repository dependencies and verifies binary resource
preservation and dotenv removal. Coverage checks were explicitly skipped at the user's request.
