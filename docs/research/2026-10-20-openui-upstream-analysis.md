## What OpenUI owns

OpenUI Lang is a model-to-application UI language, with component definitions, generated prompts, a streaming parser, an interpreter, and framework renderers. A React application can adopt only `@openuidev/react-lang` plus its core dependencies. The model provider, existing chat shell, and hosted service can remain application-owned. `defineComponent` binds a name, Zod props definition, description, and trusted React renderer; `createLibrary` collects these and exports a prompt/spec/JSON Schema. `Renderer` takes `response`, `library`, and `isStreaming`, with host callbacks for actions, state, parse results, and errors. These APIs do not require replacing the surrounding chat state architecture. [Library source](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/lang-core/src/library.ts), [React renderer](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/react-lang/src/Renderer.tsx), [official overview](https://www.openui.com/docs/openui-lang/overview).

Typical wire text is a program such as:

```text
root = Card([title, chart])
title = TextContent("Revenue")
chart = BarChart(["Jan", "Feb"], [Series("Revenue", [10, 12])])
```

Arguments are positional and derive meaning from component schema key order. References allow the root/layout to arrive before referenced components. This is a different representation and evolution contract from a JSON component list; preserving or deliberately versioning argument order matters during catalog changes. [Evolution guide](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/docs/content/docs/openui-lang/evolution-guide.mdx).

The streaming parser caches completed statements, parses a pending tail with auto-closing behavior, and can accept either appended chunks or the accumulated response through `push`/`set`. Replacing a response resets stale parser state. The renderer uses this incremental parser, maintains a store, evaluates state bindings, and preserves the last successful component output through render errors. This is source-inspected behavior, not a measured speed or memory improvement in Cognia. [Parser](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/lang-core/src/parser/parser.ts), [state hook](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/react-lang/src/hooks/useOpenUIState.ts), [renderer](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/react-lang/src/Renderer.tsx).

## Relationship to A2UI: there is now a package, but it is a profile

The upstream project explicitly describes [`@openuidev/a2ui`](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/a2ui/README.md) as an **experimental A2UI v1.0 profile**. It preserves lifecycle/envelope concepts while replacing component lists with OpenUI Lang statement strings. Its runtime schema accepts exactly `version: "v1.0"`; `createSurface.components` and `updateComponents.components` are nonempty arrays of nonempty strings. No standard JSON component-object-to-Lang adapter is exported by this package. This is not proof of compatibility with Google's current JSON catalog payloads or Cognia's custom messages. [Protocol schema](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/a2ui/src/protocol-schema.ts), [exports](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/a2ui/src/index.ts).

```json
{
  "version": "v1.0",
  "updateComponents": {
    "surfaceId": "main",
    "components": ["root = Stack([title])", "title = TextContent(\"Hello\")"]
  }
}
```

The framework-neutral client owns surface lifecycle, protocol validation, component statement merging, JSON-pointer data-model updates, capabilities metadata, actions, and function RPC. A newer assignment replaces a statement by ID; `statementId = null` deletes it. `A2UIRenderer` subscribes to one surface, hydrates Lang/form state from the data model, and renders through React Lang. By default its `Query`/`Mutation` tool provider emits A2UI `callAgentFunction` and waits for matching `agentFunctionResponse`; a host can override that provider. [Client](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/a2ui/src/client.ts), [statement merge](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/a2ui/src/statement-patch.ts), [React bridge](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/a2ui/src/Renderer.tsx).

Implementation limits relevant to an adapter:

- `mapAction` may need to restore Cognia action names, context, and source IDs. Missing source IDs fall back to `root`.
- `sendDataModel` controls opt-in data-model metadata; the host transport decides where that metadata goes.
- Incoming agent-to-renderer function calls require an explicit matching catalog and an `agentOnly`/`rendererOrAgent` registration. A shorthand function registration is not agent-callable.
- A pending `callAgentFunction` has no built-in timeout in this client. It settles on a response, surface deletion, or client disposal. Host transport cancellation/timeout semantics remain integration work.

These are source-specific properties, not a complete security audit. [Client source](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/a2ui/src/client.ts), [adapter source](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/a2ui/src/Renderer.tsx).

### Published-package compatibility probe

To separate upstream source inspection from actual published-package behavior, npm tarballs for `a2ui@0.5.0` and `lang-core@1.0.1` were downloaded and extracted under `/tmp/cognia-openui-published-probe-20261020`. Existing workspace `zod` and `ci-info` modules were linked only into that temporary directory. No install lifecycle scripts ran and no Cognia manifest or dependency tree changed. Node loaded the published CJS module and called `agentToRendererMessageSchema.safeParse`:

| Fixture                                                              | Observed result  |
| -------------------------------------------------------------------- | ---------------- |
| `version: "v1.0"`, nested `updateComponents`, Lang statement strings | `success: true`  |
| Same v1.0 envelope, component **objects**                            | `success: false` |
| `version: "v0.9"`, nested `updateComponents`, component objects      | `success: false` |
| Flat `{ type: "updateComponents", surfaceId, components: [...] }`    | `success: false` |

The v1.0-object case isolates the component representation mismatch from the version mismatch. These probes validate envelope acceptance only; they are not rendering, runtime, or interoperability acceptance tests. Registry artifacts: [a2ui](https://registry.npmjs.org/@openuidev/a2ui/latest), [lang-core](https://registry.npmjs.org/@openuidev/lang-core/latest).

A second published-core probe defined a component with `text: z.string().min(5)` and `count: z.number().min(10)`, generated its JSON Schema using `createLibrary`, and parsed complete programs. `root = Box("x", 1)` produced a root and no errors despite violating both minima. `root = Box(123, "bad")` produced `type-mismatch` errors and no root; `root = Box()` produced `missing-required` errors and no root. This confirms useful structural validation while demonstrating that “Zod schema validates props” must not be interpreted as complete Zod constraint enforcement in the renderer. No component was mounted in this probe.

## What the linked shadcn example actually demonstrates

The example is a complete demonstration application, not a drop-in React rendering package or production data backend. Its source registers **59 component entries**, including helper/data nodes such as `Series`, `Slice`, `Point`, and `Col`; this is a static count of the `components` array and should not be compared directly to Cognia's catalog count. Its README's “45+” is approximate. It covers cards, text, tables, charts, forms, tabs, accordions, calendar, dialogs, drawer, and follow-ups. [Library registry](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/examples/design-systems/shadcn/src/lib/shadcn-genui/index.tsx), [README](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/examples/design-systems/shadcn/README.md).

Its stack is Next.js 16.2.6, React 19.2.3, Tailwind 4, Zod 4, and local shadcn primitives. The page mounts `AgentInterface`, with `fetchLLM`, `openAIAdapter`, `openAIMessageFormat`, and the custom library. The sample stores threads in memory and sends the full conversation each turn. The Next POST route calls `https://api.thesys.dev/v1/embed` using server-side `THESYS_API_KEY`; its current default model is `google/gemini-3.6-flash-free`. The generated library spec is read with Node `fs`/`path` on the server. [Manifest](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/examples/design-systems/shadcn/package.json), [page](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/examples/design-systems/shadcn/src/app/page.tsx), [POST route](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/examples/design-systems/shadcn/src/app/api/chat/route.ts), [cloud prompt](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/examples/design-systems/shadcn/src/lib/cloud-prompt.ts), [model configuration](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/examples/design-systems/shadcn/src/lib/env.ts).

Published `react-ui@0.18.1` and `react-headless@0.18.1` declare a `zustand: ^4.5.5` peer dependency. A host using Zustand 5 must resolve that separately if adopting those packages; it is not evidence that the core renderer requires a downgrade. Published `react-lang@1.0.1` has no Zustand peer. [React UI registry metadata](https://registry.npmjs.org/@openuidev/react-ui/latest), [headless registry metadata](https://registry.npmjs.org/@openuidev/react-headless/latest), [React Lang metadata](https://registry.npmjs.org/@openuidev/react-lang/latest).

Weather, stock, and web-search tools deliberately return mock data. Pagination emits a conversational “Go to page N” action; it is not a real data-pagination integration. Dialog confirmation likewise continues a conversation. Forms have actual state hooks and validation contexts, but domain persistence and authenticated side effects remain host work. Its custom Button accepts the legacy action object shape, unlike the newer `Action`/`@Run` examples in the generic language documentation. Therefore a rich demo screenshot does not establish complete production business wiring. ## React, static export, Tauri, and security implications

**The renderer is separable from the sample server.** Adopting React Lang inside an existing client-rendered message is architecturally compatible with static assets; copying the sample `/api/chat` route and its filesystem prompt loader into Cognia's static export is not. The latter needs a real backend. An integration can instead generate the prompt from an application-owned library and pass output from Cognia's existing inference pipeline into `Renderer`. This is an architectural inference from the public interfaces, not a completed Cognia build or Tauri acceptance result. [Renderer interface](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/react-lang/src/Renderer.tsx), [sample server](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/examples/design-systems/shadcn/src/app/api/chat/route.ts).

**State and tools need deliberate ownership.** The runtime supports `$variables`, form state, `Query`, `Mutation`, built-in transformations, and composed actions. Queries are evaluated after streaming settles; mutations run through action execution. A passed `toolProvider` can be a function map or MCP-like client. This is application code executing host capabilities, so Cognia's own authorization, tool confirmation, tenant/session isolation, PII redaction, cancellation, and persistence boundaries cannot be replaced by schema validation. Start a rendering experiment with no tools, then adapt controlled host tools separately. [State/action/query hook](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/react-lang/src/hooks/useOpenUIState.ts), [query/mutation docs](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/docs/content/docs/openui-lang/queries-mutations.mdx).

**Trusted components reduce arbitrary-code exposure, but do not constitute a sandbox.** The inspected parser/interpreter resolves registered component and function/action names, rather than evaluating model text as arbitrary JavaScript. The component implementation is still trusted host code. The parser's validation implements structural/type/enum/default checks over exported JSON Schema; it is not a general execution of every original Zod refinement. The shadcn example's image source and action URL schemas are plain strings. `A2UIRenderer` defaults OpenUrl to `window.open(url, "_blank", "noopener,noreferrer")` without a scheme allowlist in that adapter. Reuse Cognia's URL/media policy and native opener rather than taking sample behavior as a desktop security policy. [Interpreter](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/lang-core/src/runtime/evaluator.ts), [schema validator](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/lang-core/src/parser/validation.ts), [image component](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/examples/design-systems/shadcn/src/lib/shadcn-genui/components/image.tsx), [action schema](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/examples/design-systems/shadcn/src/lib/shadcn-genui/action.ts), [A2UI URL handler](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/a2ui/src/Renderer.tsx).

**Development and installation have extra behavior.** React Lang auto-mounts inspection tools in `NODE_ENV === "development"`; the devtools loads its browser build from jsDelivr. Core package installation includes opt-out install telemetry; `OPENUI_TELEMETRY_DISABLED=1` or `DO_NOT_TRACK=1` disables it. Runtime telemetry is explicitly opt-in with `OPENUI_RUNTIME_TELEMETRY_ENABLED=1`, sampled on supported server runtimes, and excludes browser/worker environments. These installation/development properties warrant integration configuration; they do not mean ordinary renderer use sends chat data to OpenUI. [Development bootstrap](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/react-lang/src/devtoolsBootstrap.ts), [CDN loader](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/devtools/src/cdn.ts), [install telemetry](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/lang-core/src/telemetry/install.ts), [runtime telemetry](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/lang-core/src/telemetry/runtime.ts), [flags](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/packages/lang-core/src/telemetry/shared.ts).

## Decision implications and unresolved evidence

The strongest adoption unit is a **versioned OpenUI message renderer and application-owned component library**, while keeping the current inference/chat/business ownership. The linked shadcn library provides useful component composition and schema examples, but Cognia should reuse its own primitives and internationalization. Full replacement would additionally migrate wire protocols, generated prompts, stored history, surface IDs/data models, editor/plugin/MCP contracts, action semantics, and tool policy. The new A2UI profile may preserve a multi-surface lifecycle, but does not remove the protocol/catalog conversion work.

Upstream's token-efficiency benchmark uses saved samples across seven scenarios and multiple representations. Its reliability benchmark is a separate vendor-run evaluation; neither measures Cognia's current catalog, providers, prompts, streaming transport, or existing JSON parser. Treat those as hypotheses for local paired evaluation, not a guaranteed percentage reduction or acceptance rate. [Token benchmark methodology](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/docs/content/docs/openui-lang/benchmarks.mdx), [reliability documentation](https://github.com/thesysdev/openui/blob/9823ec05d4b29bc78d101676dc16b44fe17f1830/docs/content/docs/openui-lang/reliability.mdx).

Before choosing replacement, compare representative Cognia tasks on identical providers and model settings: renderable-result rate, first useful UI latency, completion latency, prompt plus response tokens, corrective retries, client parse/render cost, form/action round trips, stored-message replay, static-export behavior, and real Tauri URL/tool flows. Unknown at this stage: Cognia-specific improvement magnitude, full feature parity, compressed bundle cost, long-stream resource behavior, full upstream test status, and production security acceptance.
