# Repository integration repair results

Date: 2026-10-01, Asia/Shanghai.

The user authorized rechecking and fixing the defects in the [original audit](2026-10-01-repository-integration-audit.md). The repair extends existing issue, account, sync, review, and delivery paths. It does not add a second issue board, PR viewer, account store, or job queue. GitLab adapter implementation remains a separate capability gap.

## Confirmed findings and resulting behavior

| Finding                                                        | Repair and regression boundary                                                                                                                                                                                                                                                                                                                                                                        |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1: issue writes choose the wrong host/account                 | Reuse `githubReadAccountsFor` for the target repository. The current issue resource model represents public GitHub repositories, so GHES credentials cannot redirect those writes. The confirmation dialog passes the displayed account ID; a removed/disabled account fails instead of falling back to another. Issue runs also recheck account availability before starting.                        |
| F2: cached PR points at a different repository                 | Publication checks provider, repository, and host against the newly resolved root binding before sending anything.                                                                                                                                                                                                                                                                                    |
| F3: milestone identity collides across repositories/workspaces | IDs now include host and repository. Cycle lookup is constrained to workspace, container, and binding. Matching legacy rows migrate in place, preserving local cycle IDs; ambiguous rows are not reassigned. Unscoped legacy milestone IDs are rejected for outbound edits.                                                                                                                           |
| F4: failed reads erase cached issues                           | Only successful complete listings can prune the mirror. HTTP 404, other failed responses, invalid response bodies, and failures on later pages propagate without cache mutation.                                                                                                                                                                                                                      |
| F5: capped imports permanently skip older issues               | The shared reader follows pagination in creation order and fails the entire read at the safety limit instead of publishing partial rows or advancing the watermark. Incremental reads overlap the last timestamp by one second. Query-ambiguous row ETags are no longer reused by the mirror. Regression fixtures include more than 1,000 raw records, PR filtering, and updates sharing a timestamp. |
| F6: Project items join by issue number alone                   | The GraphQL query carries content type and repository identity. Iterations map only to Issues belonging to the bound repository.                                                                                                                                                                                                                                                                      |
| F7: unsupported iteration edit is reported as synchronized     | Reject iteration changes before queuing any part of the patch. Clearing/replacing an existing iteration is also refused; configured Projects are rechecked, and incomplete/error responses cannot authorize the write. The existing sync error path retains the unsynchronized change. This repairs false success; it does not implement iteration mutation.                                          |
| F8: GHES-only account leaves review controls disabled          | Authentication resolves per repository root, using its host-specific client. The shared review UI gates each root's controls with that result.                                                                                                                                                                                                                                                        |
| F9: push always selects origin                                 | Preserve the resolver's actual selected remote and pass it to the existing Git push command. Missing remote identity fails explicitly.                                                                                                                                                                                                                                                                |
| F10: UI review omits exact-head/dedup behavior                 | Extract the existing plugin publication policy into `plugins/github-delivery/src/review.ts` and call it from both the plugin and UI. Require the cached head SHA, recheck it remotely, and send top-level `commit_id`. The UI adds a stable per-bundle marker for reconciliation; retries retain the bundle ID. Draft COMMENT reviews remain supported by the UI without changing the Bot policy.     |

The new shared publisher file is justified by two existing callers: the delivery plugin and the review provider. It moves the existing policy out of the plugin entry point so the UI can reuse it without importing plugin initialization. Its transport remains injected, and it adds no Node/server dependency to the static-export frontend. Existing bilingual UI keys are reused.

## Remaining boundaries

- No authenticated GitHub/GHES/GitLab write, browser/Tauri journey, native Git push, webhook ingress, or actual merge was exercised. Component tests are not live UI acceptance.
- Existing incomplete caches from the old 1,000-record cap need the existing full **Sync now** flow once. Reads exceeding 100,000 raw API records fail explicitly; resumable import is not implemented.
- GHES issue resources, GitLab/Gitea/Bitbucket issue/MR adapters, editable Project iterations, complete planning pagination, native remote issue hierarchy/dependencies/types, and the broader PR-management gaps remain as recorded in the original audit.
- Review retry preserves already successful repository legs. It rebuilds current editable content for retried legs; it is not a frozen snapshot of the original entire bundle.
- Live acceptance needs a disposable repository URL, an account connected through Cognia, the intended runtime, and the permitted test-write scope. For self-hosted services, include instance version and tier. Do not paste tokens into chat.
