# Model catalog governance — 2026-10-19

The shipped catalog retained retired models in ordinary model pickers and used
outdated recommendations. This change updates recommendations and applies the
same lifecycle policy to the chat picker, CLI, routing option source, and
Catalog v2. Existing modules are extended; no persistence schema is added.

## Selection and compatibility rules

| Purpose               | Active   | Preview  | Deprecated | Retired                       |
| --------------------- | -------- | -------- | ---------- | ----------------------------- |
| New selection         | Yes      | Yes      | No         | No                            |
| Automatic routing     | Yes      | No       | No         | No                            |
| Existing explicit pin | Preserve | Preserve | Preserve   | Preserve storage; unavailable |
| Historical lookup     | Yes      | Yes      | Yes        | Yes                           |

Saved provider defaults, enabled-model lists, and CLI per-provider model choices
are treated as deliberate choices. Older settings do not record whether a value
was chosen manually or inherited from an older release. The change therefore
does not guess at their origin or migrate them silently. Retired GUI pins remain
visible as disabled rows with a suggested replacement; the CLI offers eligible
new choices while retaining its stored pin. Historical model IDs and display
metadata remain available. No conversation records are rewritten.

Provider-scoped retirement notices in `packages/provider-types/src/model-catalog.ts`
remain after upstream removes a model. Current catalog metadata and saved discovery
are combined conservatively: an old `active` discovery cannot reopen a retired
model. A direct API retirement does not retire a separately available aggregator
offering, even when they share a canonical model.

Catalog v2 overlays current bundled recommendations and lifecycle notices in its
read index, including when loading an older persisted revision offline. The raw
revision remains unchanged. Legacy aliases keep the original target and expose
the replacement separately. New recommendations do not rewrite historical IDs.

listed models.

## Request compatibility

The new defaults also require model-aware reasoning settings. GPT-6 keeps `max`
and rejects the older `minimal` value; saved unsupported values map to supported
levels. Gemini 3.8 Flash uses `thinkingLevel` instead of a token budget. Claude
5.5 uses adaptive thinking with explicit effort and omits unsupported sampling
parameters. Older model behavior is retained. Tests use the installed SDKs with
injected fake fetches to check serialized request bodies without paid inference.

## Follow-up baseline audit — 2026-10-19

This audit uses the refreshed 232-provider / 9,056-model baseline, revision
`sha256:18db5390f959fdfb55d183e7c21ddfcd5c4f1e1b176ceaeb31ded0bf54d2d3de`.
It covers 81 built-in providers (70 cloud, 11 local), their default model rows,
coding recommendations and packages, relay presets, and separate image, video,
and captioning defaults. The findings below record the state before the
authorized follow-up fixes. Remediation is recorded after the audit sources.
No persisted settings or conversations are migrated.

### Confirmed lifecycle omissions

- The built-in xAI list still contains `grok-3`, and the lifecycle notice registry
  has no xAI entry. xAI's official notice retires that ID on 2026-05-15 and
  redirects requests to `grok-4.3`, with different pricing. Preserve history and
  explicit configuration, but do not present it as a fresh model choice.
- Google image generation still defaults to `gemini-3.1-flash-image-preview` in
  `lib/ai/media/image-generation-sdk.ts`. Google's official schedule lists its
  shutdown on 2026-06-25 and recommends `gemini-nano-banana-2.1`. The refreshed
  models.dev shard still includes the old ID, so presence alone is insufficient.
- Google's video default is `veo-3.1-generate-preview`, whose published shutdown
  date is 2026-10-22. It is an upcoming migration, not a retired model as of
  2026-10-19. The published successor is `gemini-omni-1.1-flash`; its request
  contract must be checked before changing the default.
- Captioning still defaults to `gemini-2.5-flash`. Google restricts 2.5 access to
  projects that have used those models previously and recommends 3.5 Flash-Lite
  or 3.8 Flash for new projects. The model is not retired, but it is unsuitable
  as an unconditional new-project fallback.
- Perplexity still recommends Sonar Pro through the legacy chat surface.
  Official documentation says Sonar Chat Completions support ended on
  2026-09-27; synchronous and streaming requests are reformulated into Agent API
  requests. This requires a transport migration review, not merely a model ID
  replacement or a blanket retired classification.

### Baseline mapping and test coverage gaps

`models-dev-id-map.ts` omits four built-in providers that the new baseline tracks:
`sambanova`, `volcengine`, `ai21`, and `commandcode`. Conversely, `github` still
maps to `github-models`, a provider absent from the refreshed baseline. Do not
replace it with `github-copilot`: those are separate products.

Two defaults are absent from an otherwise present provider shard:

| Provider   | Current default   | Baseline observation                                   |
| ---------- | ----------------- | ------------------------------------------------------ |
| AI21       | `jamba-1.5-large` | Absent; official current API endpoint is `jamba-large` |
| Volcengine | `doubao-pro-256k` | Absent; shard lists current Seed models                |

Absence is a verification gap, not proof that requests fail. Local models,
account deployment IDs, and relays also cannot be classified from absence alone.

The existing baseline tests skip unmapped providers and missing shards. Their
active-offering test builds from the manual catalog, which marks missing IDs
active by default. Those tests can pass while these gaps remain.

defaults to `glm-5-turbo`, while the separate `zhipuai-coding-plan` shard lists
GLM 5.3 models instead. MiniMax's current default is not marked for coding, while
the old M2/M2.1 rows are.

### Capability and parameter drift

Eight default model rows differ from models.dev in 13 explicitly configured
capability or limit fields (excluding prices and missing optional fields):

| Provider     | Static metadata                   | Baseline metadata                |
| ------------ | --------------------------------- | -------------------------------- |
| DeepSeek     | 384,000 output                    | 393,216 output                   |
| Mistral      | 256,000 context                   | 262,144 context                  |
| SiliconFlow  | 128,000 context / 16,384 output   | 164,000 / 164,000                |
| Moonshot     | No vision / zero context          | Vision / 262,144 context         |
| Perplexity   | No vision / tools / 16,384 output | Vision / no tools / 8,192 output |
| Zhipu        | 128,000 output                    | 131,072 output                   |
| Qwen         | Vision                            | Text-only                        |
| Hugging Face | 128,000 context / 16,384 output   | 262,144 / 66,536                 |

The Moonshot and Bedrock default rows also omit `supportsTemperature: false`
despite that explicit upstream constraint. Current inference parameter filtering
depends on that flag. The synchronous chat metadata resolver reads manual
metadata and saved discovery, not the models.dev cache, and Catalog v2 prefers
manual capability and limit fields. Refreshing the baseline therefore does not
repair these values by itself. Manual values need correction or explicit,
reviewable overrides; a newer catalog must not silently override user metadata.

Other absent media IDs remain unverified: models.dev does not exhaustively cover
all image/video APIs. Do not convert those absences into retirement notices.

### Follow-up remediation

Provider mapping now includes AI21, SambaNova, Volcengine, and CommandCode.
GitHub Models remains a manual provider without a false mapping to Copilot.
Baseline tests fail for missing tracked shards/defaults, stale coding
recommendations, drift in explicitly configured default capabilities/limits,
and coding-package IDs absent from their subscription catalog. Perplexity's
`preset/fast` has an explicit tested contract exception: it selects a
server-managed configuration rather than a models.dev model ID.

The reviewed defaults above replace stale recommendations while retaining older
definitions. Moonshot keeps its cheaper K2.7 Code default with corrected metadata
and optional K3. Zhipu keeps its free default, with current GLM 5.3 coding-plan
choices. OpenCode Zen uses K2.7 Code on its current OpenAI endpoint: Claude 5.5
requires a different wire family. Google Argon is an additional choice beside
Flash; its official synchronous output limit is a reviewed baseline override.

Capability mismatches and unsupported-sampling flags are corrected. Synchronous
metadata resolution uses the primed baseline as a fallback; reviewed bundled
values beat older caches, and saved discovery/user custom metadata retain their
precedence. Offered reasoning tiers and execution share model-specific tables.
Gemini 4 uses thinking levels, vendor efforts normalize only at dispatch, and
toggle-only models expose no unsupported effort control. Stored preferences are
not rewritten.

Retired xAI/Google IDs are excluded from new choices. Sonar is deprecated while
explicit legacy calls retain Chat Completions. Perplexity Agent uses Responses;
the shared fetch adapter translates presets, citations, incremental UTF-8 SSE,
and cache usage for the installed SDK. Renderer, core/CLI, sidecar, and twin
factories preserve explicit API flavors and custom gateway paths.

Google image/video defaults use Nano Banana 2.1 and Omni 1.1 Flash through
Interactions-compatible adapters. Video retains restartable operation IDs,
polling, cancellation, timeouts, errors, and model-specific options. Explicit
Veo choices retain their adapter. Captioning uses the cheaper Flash Lite
fallback with supported minimal thinking. Retired pins remain in storage/history
but cannot start new inference. Verification uses fake fetches, without paid
provider completions.

The user requested skipping full repository typecheck. Follow-up validation uses
focused tests, lint, request serialization, and package checks. Browser checks
are blocked by the existing development server returning HTTP 500 with `ENOSPC`.
No unrelated caches or user files were deleted.

Final follow-up verification: 31 Jest suites / 671 tests and 81 sidecar tests
passed. Targeted provider-core/provider-types type checks, focused ESLint,
Prettier, i18n checks, and whitespace checks passed. Read-only PII, static-export,
i18n, and test/wiring reviews passed. The PII review found one secondary image
prompt path in provider options; deep value/key admission checks and three
zero-provider-call regressions closed it before the final run.
