# Kimi integration follow-up

Date: 2026-10-01. Native version verified: `@moonshot-ai/kimi-code@2.1.1`. This report follows the [coverage audit](2026-10-01-kimi-integration-coverage.md) and separates implemented behavior, native authenticated evidence, and remaining upstream/product boundaries.

## Changes

| Area                         | Result                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Forked sessions and MCP      | Kimi ignores MCP options in `session/fork`. Cognia closes and restores the newly created fork with fresh session-scoped MCP authorization. Forks created from the desktop without explicit execution options are rebound before the next prompt. Failed rebinding removes the new fork from local execution state without closing the parent. Unsupported workspace changes are rejected.                              |
| Desktop authentication       | The external-agent manager mounts terminal login, live output, explicit login-link opening, cancellation and confirmed logout. Operation guards prevent overlapping execution/session mutations. Startup failures, delayed terminal creation and agent switching are handled; stale operations cannot launch authentication against a different selected agent.                                                        |
| Native session deletion      | A negotiated native-delete action is wired through the hook and manager with confirmation. Failed RPCs preserve the row and active session. Successful deletion clears only matching active state. Bounded Kimi tombstones prevent the native asynchronous index from immediately resurrecting a deleted row. Native deletion does not delete a Cognia transcript or project files.                                    |
| Installation and maintenance | Settings show exact commands and confirmed visible-terminal actions for pinned installation/restoration, native upgrade and npm uninstall. Package mutations require disconnected Kimi connections and a local POSIX terminal. Commands preserve the configured working directory and state root, safely quote arguments, and omit secret environment values. Terminal launch is not reported as installation success. |
| Native management            | Existing terminal transport opens native diagnostics, TUI and web management. Migration and native session export recipes are available; export excludes the global diagnostic log. Subscription quota and extension management use native surfaces. Goal, Swarm and native Undo use the TUI. These are user-operated native handoffs, rather than embedded ACP panels.                                                |
| Question forms               | Native multi-select `items.anyOf` schemas without an explicit `items.type` are normalized into the existing shared form. Choice values, labels, minimum/maximum selections and malformed schemas are validated.                                                                                                                                                                                                        |
| Context compaction           | Native `/compact` acknowledges only that a background job started. Cognia therefore disables managed compaction completion for Kimi ACP and rejects that route before starting work. The advertised native command remains available with its native response; Cognia does not infer completion from token changes or `/tasks`.                                                                                        |

The installation remains a system npm package. Restoring the reviewed pin is an explicit package command, not a managed-runtime rollback receipt. Native web retains its loopback and bearer-authentication defaults. Clipboard/terminal commands do not copy API keys or subscription tokens.

## Native verification

The expanded [smoke script](../../scripts/smoke/kimi-acp-smoke.ts) ran through Cognia's native macOS sandbox with the installed CLI. Scratch projects, fixture MCP servers and probe sessions were owned by the test and cleaned up. The authenticated run reused the existing subscription; it did not log out, switch accounts or reinstall packages.

- [Account-free result](kimi-completion-evidence/completion-account-free.json): authentication-required behavior, negotiated capabilities, model/thinking/mode options, session creation/list/fork/close/load/resume/delete, and both explicit and deferred fork rebinding. stdio, HTTP and SSE servers were connected after the fork.

Forked sessions called stdio, HTTP and SSE tools with fixture-side receipts.
- The authenticated compaction evidence establishes **trigger acknowledgement only**. Background completion and failure cannot be observed through the current ACP mapping, so they are not claimed as passing checks.

The [browser harness evidence](kimi-completion-evidence/interaction-evidence.json) exercises real authentication and management components with stubbed native terminal, opener and clipboard boundaries. Login output/link/cancel/completion and confirmed logout passed. Each package action displayed its exact command, cancellation launched no terminal, confirmation launched exactly one reviewed recipe, and active selected/other Kimi connections disabled package actions. Copy recipes, native web launch and session export also passed. See the [package confirmation](kimi-completion-evidence/package-install-confirmation.png) and [connection guard](kimi-completion-evidence/package-connected-disabled.png) screenshots. These verify UI interaction, not real authentication/package mutation or a packaged desktop application.

## Validation

The final focused Jest run passed **676 tests across 11 suites**, covering the ACP adapter, manager, hook, authentication and session UI, management helpers/card/inspector, and shared elicitation normalization/form/dialog. Existing React `act()` warnings remain in the test output; there were no failing assertions. No coverage threshold was applied.

ESLint with zero tolerated warnings and Prettier passed for the 19 changed source/test/smoke paths. `i18n:build`, `i18n:build:check`, `lint:i18n` and scoped `git diff --check` passed. Translation key parity had zero drift, and referenced keys existed in both locales.

Scoped TypeScript checking still reports the existing `TS2554` errors at `lib/workflow/publish/publication-lifecycle.ts:348` and `:538` (eight arguments where three to seven are expected). No changed Kimi-source diagnostic was reported. A full production/package build is not established.

## Remaining boundaries

- Kimi ACP does not expose subscription quota or native plugin lifecycle APIs. Native web/TUI management is available from Cognia, but embedded quota/plugin/Skill/agent/hook administration has not been implemented or authenticated end-to-end. The separate Server API documents quota and plugin routes; it cannot establish the status of an in-process ACP compaction job.
- Current native ACP does not advertise audio and does not implement `providers/*`, `nes/*`, `document/*` or `elicitation/complete`. Additional directories apply to newly created sessions, not arbitrary fork/load/resume workspace changes.
- No native multi-account selector or complete live Plan-review workflow is established. Native Goal/Swarm/Undo remain TUI operations, not Cognia ACP commands.
- Real packaged desktop interaction and package install/upgrade/uninstall execution remain unverified. Component/browser harness checks and authenticated native protocol checks are separate evidence.
