# Agent prompt management: competitor evidence

Extraction date: 2026-10-20 (Asia/Shanghai). Scope: Claude Code, Gemini CLI, and OpenCode. This evidence supports the Cognia comparison; it does not claim behavioral evaluation or model-quality differences.

Official documentation was searched and opened directly. OpenCode implementation claims are pinned to the actual `v1.19.3` tag commit, `e3c4eb242585dcd77be1a867391b7c25fd47ce52`, released on 2026-10-16. GitHub's release `target_commitish` is a different commit and was not treated as the tag. The current `dev` branch has a newer directory layout; findings about the pinned stable implementation must not be generalized to it. [Release](https://github.com/anomalyco/opencode/releases/tag/v1.19.3).

## Claude Code: observations

1. **The customization operation is explicit.** Append retains the default prompt; replace removes it. The docs recommend append for extra rules while retaining coding behavior. The default records the initial system prompt for later requests and resumed sessions until compaction; `--system-prompt-snapshot off` requests rebuilding. The snapshot option requires v2.1.257 or later, and the docs describe additional version-dependent exceptions. This is lifecycle behavior, not a promise that all prompt-related resources are frozen. [CLI reference](https://code.claude.com/docs/en/cli-reference#system-prompt-flags).

2. **Scope and composition are separate concepts.** `CLAUDE.md` files concatenate; later/closer text does not constitute a deterministic policy override. Path-specific rules reduce unnecessary context, and the docs warn that contradictory instructions can produce inconsistent choices. `/context` identifies loaded memory files; `/doctor prompt-audit` checks stale and conflicting instructions on v2.1.283+. [Memory](https://code.claude.com/docs/en/memory).

3. **Resources have different execution semantics.** Skills are discoverable task procedures, with bodies loaded only when invoked; subagents have their own prompt and separate context. Current docs describe live detection of skill/subagent file changes, subject to directory and mode exceptions. They also state that `/agents` no longer opens the interactive CRUD wizard after v2.1.197. A generic editor cannot safely assign one activation rule to every resource. [Skills](https://code.claude.com/docs/en/skills), [Subagents](https://code.claude.com/docs/en/sub-agents).

4. **Output styles are a useful warning against ambiguous labels.** Styles influence session-wide role, tone, and format, but a custom style on the full prompt also removes built-in software-engineering instructions unless `keep-coding-instructions: true`. That flag has no effect on the shorter prompt. Switching a loaded style applies from the next message; editing its file during a terminal session requires restarting. Hooks handle guaranteed actions; a style does not enforce them. [Output styles](https://code.claude.com/docs/en/output-styles).

## Gemini CLI: observations

1. **Full replacement is supported, but made visible.** `GEMINI_SYSTEM_MD` does not merge the default. `GEMINI_WRITE_SYSTEM_MD` exports the built-in prompt, and the terminal indicates custom-system-prompt mode. Templates can explicitly insert available skills, subagents, and tool names through documented substitutions. The docs distinguish stable operational instructions in `system.md` from project/persona guidance in `GEMINI.md`. [System prompt override](https://geminicli.com/docs/cli/system-prompt/).

2. **Instruction inspection is a first-class workflow.** Global and workspace instructions are supplemented by just-in-time context up to a trusted root. `/memory show` displays the assembled hierarchical instruction content; `/memory reload` rescans it. This is an exact preview of that instruction layer, not proof of a complete final transport request including all tools, history, and system content. [GEMINI.md](https://geminicli.com/docs/cli/gemini-md/).

3. **Skills preserve discovery and ownership.** The documented priority is built-in < extension < user < workspace, with same-name definitions selecting the higher tier. Metadata is discovered first; activation asks for consent and adds the body to history plus access to bundled resources. Commands support list, enable/disable, linking, and refresh. Replacing this with unconditional template expansion would change both context cost and activation behavior. [Skills](https://geminicli.com/docs/cli/skills/).

4. **Agents include execution controls beyond prose.** Definition files carry a system-prompt body plus model, tools, turn limit, and timeout. They run in independent context loops; `/agents` supports interactive management. Tool policies can target a subagent and enforce allow/deny/confirmation decisions. The policy docs explicitly say workspace policy files are currently disabled; user/admin policies should be used. A comparison should not mistake documented configuration shape for a fully supported runtime feature. [Subagents](https://geminicli.com/docs/core/subagents/), [Policy engine](https://geminicli.com/docs/reference/policy-engine/).

## OpenCode: observations

1. **The shipped baseline is model-aware in the pinned stable version.** `SystemPrompt.provider(model)` selects among GPT, GPT-6, Codex, Claude, Gemini, Kimi, Trinity, Meta, and fallback templates using model IDs and selected provider IDs. This is a concrete source-level mechanism; it does not establish which template gives better results. [Stable system.ts](https://github.com/anomalyco/opencode/blob/e3c4eb242585dcd77be1a867391b7c25fd47ce52/packages/opencode/src/session/system.ts#L26-L48).

2. **A custom agent prompt also replaces the baseline here.** `LLMRequestPrep.prepare` chooses `agent.prompt` or the provider template, then adds runtime system sections and user system text. For OpenAI OAuth the assembled text is passed through `options.instructions`; other ordinary paths use system-role messages. Plugin transformation runs after initial composition. This shows why Cognia must expose both operation and actual transport result; it does not prove competitors universally preserve the default baseline. [Stable request.ts](https://github.com/anomalyco/opencode/blob/e3c4eb242585dcd77be1a867391b7c25fd47ce52/packages/opencode/src/session/llm/request.ts#L58-L118).

3. **File interoperability does not imply identical resolution rules.** OpenCode supports `AGENTS.md`, Claude instruction fallbacks, configured instruction files/globs/URLs, and several compatible skill directories. Rule docs describe first-match behavior within specified categories; skill bodies load on demand and denied skills are hidden and rejected. A single account/workspace/session ordering cannot be assumed to describe every resource. [Rules](https://opencode.ai/docs/rules/), [Skills](https://opencode.ai/docs/skills/).

4. **Agent management includes capabilities.** JSON and Markdown agents can customize built-ins as well as define new agents. The documented `opencode agent create` flow chooses global/project storage, generates a prompt, and selects permissions before saving a definition. This confirms a management workflow, not a full graphical prompt lifecycle product. [Agents](https://opencode.ai/docs/agents/).

## Implications to test against Cognia

These are design deductions from the evidence above, not findings about Cognia source:

- Keep the requested full management UI, while distinguishing baseline, additive guidance, task procedure, output style, subagent definition, and generated runtime context. Different adapters can share discovery, provenance, diff, editing, and history without sharing replacement semantics.
- Make append versus replace an explicit operation. A short persona routed into a full-replacement API can remove operational guidance; whether that reduces quality requires a controlled evaluation.
- Model/provider/runtime compatibility belongs in the contract. A portable resource ID alone cannot ensure equivalent instructions or tool behavior across GUI, CLI, sidecar, and delegated runtimes.
- Show the ordered instruction sources and the actual active revision. Include conditions, prompt budgets, loading triggers, overrides that did not apply, and activation timing. Distinguish a layer preview from the complete model request.
- Preserve on-demand Skills and scope-aware instructions. Versioning every string does not solve irrelevant context, contradictory policies, or incorrect task activation.
- Keep permissions, sandboxing, output schema validation, and tool restrictions enforced outside editable prose. Full editing need not mean that prompt text can reconfigure capabilities implicitly.

## Limits and unknowns

- Live official documentation is mutable and is not necessarily synchronized to the installed product version. Version qualifiers above come from the pages; no competitor was installed or exercised for this comparison.
- Claude Code's full shipped prompt contents and model-dependent selection were not reconstructed from unofficial prompt dumps. Only official documented customization semantics are asserted.
- The OpenCode stable code is pinned; its development branch already has different composition files. Do not describe that branch using the stable paths or declare its behavior unchanged.
- Gemini custom-system-prompt hot reload and OpenCode instruction/agent live reload were not established. No claim of support or absence is made.
- This investigation verifies prompt-management mechanics. It does not measure adherence, task success, token overhead, latency, safety, or GUI usability; those need reproducible flows and evaluations.
- No universal absence claim about graphical prompt editors, cloud registries, version history, or enterprise products follows from these documentation pages.
