**EX-01 — Verified local ingestion gap:** [`core-files/read.ts:145`](../../sidecar/src/tools/builtin/core-files/read.ts:145) reads the complete file, decodes it and splits every line before applying the 256 KiB result cap. `offset` and `limit` do not bound source bytes loaded. A large file can therefore consume substantially more memory and time than the result size suggests. The handler at line 66 also does not accept `ToolHandlerExtra.signal`. Proposed acceptance: instrument reads of a large fixture, require bounded bytes for the first page, and abort a pending read without completing unnecessary scanning. This is a source finding; no large-file OOM experiment was run.

**EX-02 — Verified local notebook aggregate gap:** [`read.ts:79`](../../sidecar/src/tools/builtin/core-files/read.ts:79) returns rendered `.ipynb` output before the ordinary text window/cap. [`read-media.ts:141`](../../sidecar/src/tools/builtin/core-files/read-media.ts:141) clamps each cell and its output, but walks every cell and joins every result without an aggregate output/cell limit. A notebook with many bounded cells can still generate an arbitrarily large tool result. Proposed acceptance: hundreds of cells exceed the aggregate cap, return a continuation hint and honor cancellation. Per-cell caps already exist and must be preserved.

## File mutation, matching and concurrent cancellation

pi's current `edit` accepts a list of unique, non-overlapping replacements against the original content; it serializes the operation with a shared mutation queue, preserves BOM/EOL and checks abort after awaited operations. Its comment explicitly explains why rejecting immediately from an abort listener would release the queue before an in-flight write finishes. [Edit](https://github.com/badlogic/pi-mono/blob/73f8de80bc87021375f8b525292ac07492253002/packages/coding-agent/src/core/tools/edit.ts#L159-L215), [write](https://github.com/badlogic/pi-mono/blob/73f8de80bc87021375f8b525292ac07492253002/packages/coding-agent/src/core/tools/write.ts#L61-L88), [queue](https://github.com/badlogic/pi-mono/blob/73f8de80bc87021375f8b525292ac07492253002/packages/coding-agent/src/core/tools/file-mutation-queue.ts).

OpenCode routes edit/write through `FileMutation`, uses process-shared transaction locks, and makes the final locked write uninterruptible. Its edit leaf computes a diff before permission review, rejects zero or ambiguous matches, and preserves BOM/line endings. The service explicitly states that external writers can still race; its TODOs disclose missing rollback, watcher/LSP integration and crash recovery. Those TODOs are limitations of that snapshot, not capabilities Cognia should be assumed to lack. [Edit](https://github.com/anomalyco/opencode/blob/16c338372a67121819248db970c9f287ccb450a9/packages/core/src/tool/plugin/edit.ts#L225-L319), [mutation boundary](https://github.com/anomalyco/opencode/blob/16c338372a67121819248db970c9f287ccb450a9/packages/core/src/file-mutation.ts#L59-L153).

Cognia already supplies read-before-overwrite/freshness tracking, shared serialization for `write`/`edit`/`multi_edit`, BOM/EOL preservation, fuzzy match reporting, a post-edit snippet and bounded diagnostic feedback. `multi_edit` prepares its sequence in memory before one write, which is a useful existing guarantee. [Write](../../sidecar/src/tools/builtin/core-files/write.ts), [edit](../../sidecar/src/tools/builtin/core-files/edit.ts), [text IO](../../sidecar/src/tools/builtin/core-files/text-io.ts), [read tracker](../../sidecar/src/tools/state/read-tracker.ts).

**EX-03 — Verified local mutation cancellation gap:** `execWrite`, `execEdit` and `execMultiEdit` do not receive/check `ToolHandlerExtra.signal`, and [`text-io.ts:72`](../../sidecar/src/tools/builtin/core-files/text-io.ts:72) runs a queued callback even if its caller has since been interrupted. An already queued mutation can therefore proceed after interruption. The kernel explicitly documents the signal as the interruption mechanism; the confinement middleware forwards it without adding cancellation checks. [Kernel](../../sidecar/src/tools/kernel/define.ts:14), [middleware](../../sidecar/src/tools/middleware/confinement.ts:25). Proposed acceptance: hold the file queue, enqueue a second write, abort it, release the first and verify the second never starts its write. Keep the lock until any already-started filesystem operation settles; returning an abort early must not reintroduce interleaving. This is not a promise that a committed filesystem write can be rolled back.

**Comparison dimension — mutation helpers outside the core lock:** [`file_append` and `file_binary_write`](../../sidecar/src/tools/builtin/file-extras/file-write.ts) enforce credential restrictions but call filesystem writes without participating in the core mutation lock/read tracker. This is a concrete coordination difference, not proof that append or intentional binary overwrite must require prior text reads. Test concurrent helper/core edits and define which operations share a serialization boundary before changing policy.

**Comparison dimension — multi-edit semantics:** pi applies disjoint edits against the original file, whereas Cognia applies edits sequentially against the previous result. Both are legitimate contracts; importing a peer's matching algorithm without preserving that distinction would change behavior. Tests should distinguish sequential dependency, overlapping ranges, repeated matches, no-op edits and failure before the single final write.

## Shell execution, output and process lifecycle

Codex separates interactive resumable processes from completion-only calls. The latter link cancellation tokens and terminate on cancellation/timeout; its exec subsystem caps retained output at 1 MiB, limits active unified-exec processes to 64 and uses a head/tail buffer that preserves omission metadata. [Exec limits](https://github.com/openai/codex/blob/8196bcdc189ad2c189d631b321fa54b8e09b9bb0/codex-rs/core/src/unified_exec/mod.rs#L68-L77), [one-shot lifecycle](https://github.com/openai/codex/blob/8196bcdc189ad2c189d631b321fa54b8e09b9bb0/codex-rs/core/src/unified_exec/oneshot.rs#L37-L118), [buffer](https://github.com/openai/codex/blob/8196bcdc189ad2c189d631b321fa54b8e09b9bb0/codex-rs/core/src/unified_exec/head_tail_buffer.rs#L9-L80).

pi's bash links timeout/abort to process-tree cleanup and retains a clipped preview plus the full output path. Cline's SDK executor uses process-group kill on POSIX, `taskkill.exe` on Windows, explicit signal-termination reporting and a 10 MiB cap for detached logs. These are examples of distinct limits for model output, in-memory retention and retained disk logs. [pi bash](https://github.com/badlogic/pi-mono/blob/73f8de80bc87021375f8b525292ac07492253002/packages/coding-agent/src/core/tools/bash.ts#L99-L162), [pi accumulator](https://github.com/badlogic/pi-mono/blob/73f8de80bc87021375f8b525292ac07492253002/packages/coding-agent/src/core/tools/output-accumulator.ts), [Cline SDK bash](https://github.com/cline/cline/blob/ca7402c5abced42da9c7c50500b7a9bae82cb6fa/sdk/packages/core/src/extensions/tools/executors/bash.ts#L773-L847), [detached log cap](https://github.com/cline/cline/blob/ca7402c5abced42da9c7c50500b7a9bae82cb6fa/sdk/packages/core/src/extensions/tools/executors/bash.ts#L692-L706).

Cognia's core [`bash`](../../sidecar/src/tools/builtin/core-files/bash.ts) already implements signal propagation, process-tree termination, timeout escalation, bounded in-memory head/tail previews, output spill and session background-shell controls. These are existing capabilities, not missing work inferred from the external references. Cancellation must be checked on the selected host-backed versus local execution path, rather than inferred from a tool's name.

**EX-04 — Verified local cancellation inconsistency:** [`shell_execute_advanced`](../../sidecar/src/tools/builtin/shell-advanced/index.ts:77) invokes the process helper with timeout and a 4 MiB capture cap but does not consume `ToolHandlerExtra.signal`. [`webclone/run.ts:254`](../../sidecar/src/tools/builtin/webclone/run.ts:254) also has no execution signal; its timeout calls `child.kill("SIGKILL")` rather than the core shell's process-tree termination. Thus a hard timeout exists, but user interruption is not wired through these handlers. Whether webclone leaves descendants behind requires a real process-tree reproduction; that consequence is a risk, not a demonstrated leak. Proposed acceptance: abort each running tool and verify bounded settlement plus no surviving owned descendants on each supported platform.

**EX-05 — Verified local webclone output bound gap:** [`run.ts:291`](../../sidecar/src/tools/builtin/webclone/run.ts:291) appends every stdout chunk to one string until child exit. Its stderr cap checks the previous string length before adding the entire next chunk, so one chunk can overshoot the stated bound. A 180-second job deadline does not bound accumulated output bytes. Proposed acceptance: injected stdout/stderr chunks exceed the cap, UTF-8 boundaries remain valid, and the result either preserves a bounded final envelope or fails explicitly instead of growing capture indefinitely. No hostile-page or real-engine memory test was run.

**Comparison dimension — lifecycle accounting:** define live process count, idle retention, session disposal, output-spill disk retention, terminal-REPL ownership and polling cursor behavior across all execution families. A per-result display cap alone establishes none of these. Codex's numerical limits are examples, not target defaults for Cognia.

## Web access and SSRF

OpenCode's current `webfetch` leaf accepts only HTTP(S), checks URL permission, imposes a request timeout, validates MIME types and calls a bounded response-body collector. The collector enforces actual streamed bytes even if `Content-Length` is missing or false. [Webfetch](https://github.com/anomalyco/opencode/blob/16c338372a67121819248db970c9f287ccb450a9/packages/core/src/tool/plugin/webfetch.ts#L70-L159), [collector](https://github.com/anomalyco/opencode/blob/16c338372a67121819248db970c9f287ccb450a9/packages/core/src/tool/http-body.ts#L4-L32). The inspected leaf is not sufficient evidence of DNS/IP pinning or private-network protection in the complete OpenCode transport; no claim of that protection is made here.

Cognia's webclone already validates the entry target and calls a shared `@cognia/network-guard` policy for resource fetches and every redirect. It defaults private hosts to denied, and the tool exposes an explicit `allowPrivateHosts` input. [Tool entry](../../sidecar/src/tools/builtin/webclone/run.ts:334), [guard](../../sidecar/webclone/src/ssrf-guard.ts), [transport](../../sidecar/webclone/src/fetcher.ts:94). This is stronger leaf-level evidence than merely restricting URL schemes; it does not by itself prove DNS-rebinding resistance or that a model-supplied private-host override matches the intended authorization policy.

**Comparison dimensions requiring end-to-end proof:** private DNS answers and DNS rebinding; IPv4-mapped IPv6; redirect reauthorization; credential forwarding across origins; request count and aggregate resource bytes; cancellation during DNS/body decoding; and whether private-host override is reserved for authorized host policy. Assess these against the owning network package and real transport, not a peer feature checklist. A webclone snapshot tool also differs from a general web reader/search tool; availability elsewhere in Cognia must be traced before calling it absent.

## Subagents, tasks and approvals

Codex exposes distinct spawn/wait/interrupt operations. Its wait implementation uses bounded timeouts, subscribes to activity and can wake for messages, steering or timeout. OpenCode's subagent implementation checks recursion depth (default 1), agent availability/mode and explicit permission; interruption of a blocked child joins session interruption and job cancellation. [Codex spawn](https://github.com/openai/codex/blob/8196bcdc189ad2c189d631b321fa54b8e09b9bb0/codex-rs/core/src/tools/handlers/multi_agents_v2/spawn.rs), [wait](https://github.com/openai/codex/blob/8196bcdc189ad2c189d631b321fa54b8e09b9bb0/codex-rs/core/src/tools/handlers/multi_agents_v2/wait.rs#L50-L111), [interrupt](https://github.com/openai/codex/blob/8196bcdc189ad2c189d631b321fa54b8e09b9bb0/codex-rs/core/src/tools/handlers/multi_agents_v2/interrupt_agent.rs), [OpenCode subagent](https://github.com/anomalyco/opencode/blob/16c338372a67121819248db970c9f287ccb450a9/packages/core/src/tool/plugin/subagent.ts#L114-L150), [child cancellation](https://github.com/anomalyco/opencode/blob/16c338372a67121819248db970c9f287ccb450a9/packages/core/src/tool/plugin/subagent.ts#L234-L251).

Cognia's [`TaskCreate`/`TaskGet`/`TaskList`/`TaskUpdate`](../../sidecar/src/tools/builtin/core-files/tasks.ts) are a session task graph, not child-agent execution. Their presence proves task bookkeeping, not spawn/cancel/recovery. Conversely, the absence of spawn from [`builtin/registry.ts`](../../sidecar/src/tools/builtin/registry.ts) does not prove the application lacks subagents: provider-native and other registered tool surfaces must be audited separately. The external lifecycle contracts supply acceptance dimensions for those owners: parent/child authorization, depth/concurrency budget, wait interruption, cancellation propagation, terminal state, restart recovery and final-result retention.

Approval and confinement are also different boundaries. Codex's orchestrator coordinates initial permission, sandbox selection, network approval and retry authority; escalating after sandbox denial is reviewed as a new authority. OpenCode edit includes a computed diff in its permission metadata. Cline's inspected desktop approval helper denies when IPC configuration is absent or the approval times out. [Codex orchestrator](https://github.com/openai/codex/blob/8196bcdc189ad2c189d631b321fa54b8e09b9bb0/codex-rs/core/src/tools/orchestrator.rs), [OpenCode edit preview](https://github.com/anomalyco/opencode/blob/16c338372a67121819248db970c9f287ccb450a9/packages/core/src/tool/plugin/edit.ts#L271-L286), [Cline approval](https://github.com/cline/cline/blob/ca7402c5abced42da9c7c50500b7a9bae82cb6fa/sdk/packages/core/src/runtime/tools/tool-approval.ts#L28-L126).

Cognia collection applies confinement before tool presentation; wrappers check tool paths and carry the process scope to execution. That source ordering is useful existing evidence, but it does not establish the complete approval flow for AI SDK, Anthropic-native, generated `run_code`, host-backed process and MCP paths. [Registry](../../sidecar/src/tools/builtin/registry.ts:208), [confinement](../../sidecar/src/tools/middleware/confinement.ts). Compare these boundaries with explicit denied/approved calls and nested/generated invocations; do not infer safe execution from a category toggle or keyword-based shell check.

**EX-06 — Reproduced local nested-tool authorization bypass:** the registry applies presentation before the AI SDK adapter filters `allowedTools`/`disallowedTools`. Presentation captures the original category-enabled definitions and calls `def.handler(parsed.value)` directly, so a nested eligible read does not re-enter its own permission gate. The run-code comment claiming that every nested call preserves permissions is therefore not true for this wiring. [Captured definitions and direct dispatch](../../sidecar/src/tools/middleware/presentation.ts:28), [post-presentation filtering](../../sidecar/src/tools/adapters/ai-sdk.ts:432), [outer-only gate](../../sidecar/src/tools/adapters/ai-sdk.ts:174), [claimed contract](../../sidecar/src/tools/builtin/run-code/index.ts:5).

A controlled executable check used the real `buildAiSdkTools` adapter, a temporary ordinary text file, and these settings:

```js
permissionMode: "bypassPermissions",
permissionRuleset: {
  "mcp__cognia-tools__read": "deny",
  "mcp__cognia-tools__run_code": "allow",
},
allowedTools: ["run_code"],
disallowedTools: ["read"],
execution: { composition: { toolPresentation: "both" } },
```

With native presentation and no palette filtering, the same deny rule rejected direct `read.execute` with `denied by permission ruleset: mcp__cognia-tools__read`. With the settings above, the returned tool map contained only `run_code`, yet source `return await cognia.read({file_path:"fixture.txt"})` returned the fixture marker and `callsUsed: 1`. Thus both an explicit read deny and exclusion from the final tool palette were bypassed by the nested call. The probe exited successfully and removed its temporary directory.

The child launcher was `/usr/bin/env` in that isolated test process, matching the repository's existing presentation-test fixture. This exercises the real child protocol and adapter dispatch; it does **not** validate a real OS sandbox or change production sandbox configuration. The bypass occurs in the parent broker and does not depend on the child having direct filesystem access.

Protections that remain: the outer `run_code` call still passes its gate; supervisor eligibility permits only metadata-declared programmatic read-only tools; disabled categories are absent; nested argument parsing still runs; pre-existing confinement wrappers still enforce supplied process roots; code execution has its own budgets; and the final outer result still passes the model-output PII check. These mechanisms do not apply a per-read deny rule. Nested per-tool approval/profile/ruleset checks, per-tool adapter deadline, output review and abort forwarding are not re-entered. Proposed acceptance: the scenario above must fail before reading; allowed nested reads should retain schema/confinement/output guarantees; deny rules must win in both `code` and `both` presentations.

## Verification status and follow-up

This note verified public commit identities, fetched pinned primary code, read local implementations and inspected call-boundary signatures. It additionally ran the controlled local adapter/child-protocol check for `EX-06`. It did not run external agents, external test suites, real OS-sandbox acceptance, browser/native product flows, adversarial networking, production workloads or memory-stress tests. `EX-01` through `EX-05` are static source findings with proposed reproducible acceptance checks; `EX-06` has local executable evidence; other comparison dimensions remain unproven. The companion audit is responsible for merging overlapping findings and recording further local executable evidence.

Prioritize cancellation and resource bounds across existing tools before expanding the tool catalog. Preserve Cognia capabilities already present: read freshness, format preservation, multi-edit preparation, process-tree cancellation in core bash, confinement before presentation and per-target webclone guards.
