### Node and Bun are different delivery paths

Desktop resolves `agent-host.mjs` first, then the legacy `claude-host.mjs` fallback. Its shared supervisor resolves a Node executable, checks the version, and launches Node with the script path. The desktop facade obtains its executable from the managed Node runtime. Headless resolves its script from `COGNIA_SIDECAR_SCRIPT`. Sources: [desktop resolution](/Users/bytedance/Project/cognia-next/src-tauri/src/claude/sidecar.rs:14), [desktop executable](/Users/bytedance/Project/cognia-next/src-tauri/src/claude/host.rs:54), [shared spawn](/Users/bytedance/Project/cognia-next/crates/cognia-sidecar/src/supervisor.rs:534), [headless resolution](/Users/bytedance/Project/cognia-next/crates/cognia-companion-rpc/src/sidecar_runtime.rs:60).

CLI development spawns `node <script>`. A packaged CLI self-executes its executable with `COGNIA_ROLE=sidecar`; the CLI supports both pkg and Bun standalone detection. The Bun builder rewrites role modules to import sidecar launchers into the Bun executable. Thus the desktop's current agent host remains Node, while a Bun standalone CLI runs the bundled sidecar role under Bun. Sources: [packaged-runtime detection and spawn](/Users/bytedance/Project/cognia-next/cli/src/runtime/bootstrap.ts:148), [Bun role bundling](/Users/bytedance/Project/cognia-next/scripts/build/build-cli-bun.mjs:178).

### Consumers outside the directory

The sidecar has production callers beyond its own package. Tauri ships launchers, TS sources, dependencies, auxiliary compiled hosts and broker artifacts as resources. The renderer/provider packages import selected public isomorphic provider modules directly, and Node MCP transport imports the egress guard. These are real source dependencies, so moving their files also requires updating those consumers. Sources: [Tauri resources](/Users/bytedance/Project/cognia-next/src-tauri/tauri.conf.json:51), [provider-core](/Users/bytedance/Project/cognia-next/packages/provider-core/src/core/client.ts:29), [gateway](/Users/bytedance/Project/cognia-next/lib/gateway/mint-session-ticket.ts:22), [MCP transport](/Users/bytedance/Project/cognia-next/lib/mcp/transport.ts:265), [public surface](/Users/bytedance/Project/cognia-next/scripts/gates/sidecar-architecture.json:97).

The broker build has an alternate caller: both Tauri `beforeDevCommand` and `beforeBuildCommand` explicitly build the extension, although root `prebuild` does not. Aggregate `sidecars:build` and CI also include it. This is connected wiring, not evidence of a missing desktop build step.
