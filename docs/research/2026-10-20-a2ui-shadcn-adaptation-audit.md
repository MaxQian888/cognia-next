# Cognia A2UI shadcn adaptation audit — 2026-10-20

Research-only snapshot of the shared checkout. No product source, dependencies or commits changed. This document complements the protocol/generation audit; it does not repeat its ingestion/edit findings.

## Decision

Strengthen the existing A2UI implementation first. The 68 catalog names all have renderer entries and editor factory cases, but this proves name-level wiring only. Several established components expose fields that do not take effect or cannot round-trip state. Adding the remainder of shadcn by file count would hide the more consequential work.

The local `components/ui/` directory has **71 top-level production `.tsx` files**, excluding tests/stories and all `__mocks__`. These include animated icons, providers and product loading helpers, so 71 is not a count of 71 independently model-worthy shadcn widgets. The classification is 44 directly reused sources, 7 capability candidates, 2 compositions, 1 composition gap, 2 alternative implementations, 4 host helpers and 11 icon helpers. Full mappings are below and in [the machine-readable inventory](2026-10-20-a2ui-shadcn-adaptation-inventory.json).

Current shadcn docs expose framework variants; the local Combobox is Base UI while many local controls remain Radix. Follow the **vendored local API**, not a global assumption that every control is Radix or every control should migrate to Base UI. Official current composition examples support the Combobox/InputGroup findings. No local upstream reinstall/update is justified by this audit. The [current upstream component index](https://ui.shadcn.com/docs/components) also lists Code Block, Trace, Attachment, Bubble, Marker, Message, Message Scroller and Questionnaire, which are not top-level files in this local UI directory. This is a separate upstream inventory question: Cognia already has richer chat/Markdown/AI Elements feature paths, so absence from components/ui alone does not establish that the product lacks each capability or that A2UI needs a one-to-one wrapper.

## Findings and evidence

Priorities describe concrete product impact; disabled UI is not an authorization/security boundary. `P1` should be repaired before claiming reliable generated forms. `P2` is the next strengthening batch. A source-only finding is labeled as such.

### S01 — P1: FormGroup validation/submission is built but disconnected

`components/a2ui/form/a2ui-form-group.tsx:36` creates `useA2UIForm` and an `onSubmit` closure. The rendered `fieldset` at line 58 has no submit handler; line 73 renders children without handing them `setValue`, `getFieldProps`, blur handling or validation state. The returned `handleSubmit` is never used. Thus ordinary A2UI child edits go into surface data while this form hook retains its independent empty values; the declared `validationRules`/`onSubmit` integration cannot run through this component. Existing external button/action flows may still submit data; the defect is specifically the advertised FormGroup form-state integration.

The hook's `ValidationRule` also accepts `RegExp` and custom functions (`hooks/a2ui/use-a2ui-form.ts:26-31`), and the local wrapper accepts `onSubmit` function. These are host APIs, not a valid JSON wire contract. The central `types/artifact/a2ui.ts` union has no `A2UIFormGroupComponent` interface; it relies on the broad custom-base fallback. **Source-verified; existing tests mock the hook and assert rendering/aria state, not a submission.**

Repair with a JSON-safe schema, surface-model-owned values and a real submission event/action route. Choose whether FormGroup is a form or a fieldset within a declared form; avoid invalid nested forms. Validate before dispatch and surface field errors through the same paths read by field wrappers.

### S02 — P1: disabled semantics differ across wrappers and the renderer leaks bindings

`components/a2ui/a2ui-renderer.tsx:272` writes `disabled: isDisabled ? true : component.disabled`. A false-resolving `{path}` remains an object. `TimePicker`/`DateTimePicker` cast that object to boolean in JSX rather than resolving it, and `InputOTP` forwards it directly under a narrowed boolean-only interface. A cast does not change runtime values: the native input becomes disabled even when the data-model value is false.

Conversely, `form/a2ui-combobox.tsx:67` never passes base `disabled` to Root/Input/Trigger; `form/a2ui-toggle-group.tsx:50,63` only forwards option-level disabled. A disabled ToggleGroup remains editable and writes data. Several other interactive containers also ignore the base field; the first repair should define leaf/container semantics, normalize the boolean once, and guard actions as well as DOM affordances where required.

**Behavior probes with real primitives:** disabled Combobox has `inputDisabled:false`; disabled ToggleGroup button is enabled and emits `['/value',['a']]`; TimePicker with `{path:'/disabled'}` resolving false has `inputDisabled:true`. These are isolated leaf probes; the renderer expression is source evidence for why this same false-bound object reaches the leaf.

### S03 — P2: Combobox omits the actual popup and filtering contract

`form/a2ui-combobox.tsx:67-87` renders Trigger, Input and List directly under Root, omitting `ComboboxContent`. The vendored `components/ui/combobox.tsx:85` provides Portal/Positioner/Popup as Content. The normal source consumer at `components/workflow/editor/inspector/forms/shared/entity-picker.tsx:143` uses it. The leaf also omits the Root items collection and branches empty text on the original options length rather than filtered results.

**Behavior probe:** before opening, two role=option elements are already in the inline DOM and there are zero `combobox-content` popup elements. Existing three Combobox tests only inspect labels/placeholders/selected text. Repair using local Base UI composition and verify closed/open DOM, keyboard selection, query filtering, zero matches, path updates, reset and disabled options. Do not expose Base UI's entire object/callback API through JSON.

### S04 — P2: declared binding props do not provide controlled state

- `navigation/a2ui-sheet.tsx:38,42` and `navigation/a2ui-drawer.tsx:37,41`: open binding is authoritative, but `onOpenChange` only changes internal state, never the bound path. A false-bound sheet cannot open through its trigger; a true-bound sheet cannot close through its normal interaction. Truthiness also treats literal `false` as absence.
- `layout/a2ui-collapsible.tsx:27,31`: resolves `open` but passes it to `defaultOpen`, so updates after mount do not apply and user changes never write to the model.
- `layout/a2ui-tabs.tsx:22-30`: `activeTab` is read only into `useState` initializer; later model updates are ignored and tab clicks do not write the bound path.
- `navigation/a2ui-pagination.tsx:59-65`: currentPage is read from a binding but changes only emit an optional action. Without an action handler that updates data, the page does not advance. Decide and document whether this is intentionally action-controlled or should write back.
- `Sidebar.collapsed` is a boolean/default, not a declared path; using `defaultOpen` is a separate default-state limitation, not the same binding promise.

**Behavior probes:** false-bound Sheet trigger produces no dialog and no data writes; `open:false` opens a dialog (treated uncontrolled); Tabs path one→two still selects One; Collapsible path false→true stays `aria-expanded=false`. Drawer shares the source pattern but was not separately behavior-probed. Preserve explicit `default*` semantics for genuinely local defaults; distinguish controlled literal, controlled path and absent/uncontrolled.

### S05 — P2: InputGroup exists by name but cannot express the local shadcn composition

`form/a2ui-input-group.tsx:17` is only a generic child renderer inside `<InputGroup>`. No A2UI contract expresses InputGroupInput/InputGroupTextarea, addon alignment, group text or specialized buttons. Ordinary A2UI TextField adds a wrapper div and local `<Input>` (`form/a2ui-textfield.tsx:37,47`), so it is not the specialized direct input required by local InputGroup. The primitive relies on direct-child selectors and `data-slot="input-group-control"` (`components/ui/input-group.tsx:21,131-147`).

This is a **source-verified composition gap**, not a claim that every InputGroup subcomponent needs its own catalog name. Prefer one purposeful compound descriptor with control + prefix/suffix/addon slots, or teach child adapters an explicit group context. Verify focus, error ring, keyboard behavior and mobile sizing using real DOM/browser screenshots.

### S06 — P2: component contracts are scattered and several declared props are ignored

All 68 factory cases exist; nested child collections and required trigger IDs are now recognized by `lib/a2ui/component-tree.ts`, and inspector property replacement protects those graph references. This is real existing work to retain. The factory supplies trigger bundles for Popover/HoverCard/Drawer/Sheet/DropdownMenu/ContextMenu.

However:

- `Button.icon`/`iconPosition` are declared (`types/artifact/a2ui.ts:186-187`) and iconPosition has inspector enum metadata, but `form/a2ui-button.tsx:46-54` renders only loading glyph and text.
- `Sidebar.groups[].items[].icon` is declared but `navigation/a2ui-sidebar.tsx:66-70` renders only labels. `Tabs.tabs[].icon` is also not consumed by the tab renderer.
- `Dialog.closable` is declared but `layout/a2ui-dialog.tsx` never reads it; the primitive close affordance remains independent.
- `Chart.clickAction` makes chart glyphs show a pointer, but only the Bar branch attaches `onClick` (`data/a2ui-chart.tsx:97-121`); Pie/Area/Scatter/Radar/Donut/Line do not dispatch it.
- `lib/a2ui/prompts.ts:92,105-107` teaches Alert.description (renderer expects message), Table.rows (expects data), Chart.type/options (expects chartType/xKey/yKeys). Many of the 68 components receive no standard prompt reference at all. MCP `componentSchema` only requires id/component with arbitrary extra fields (`lib/a2ui/mcp-tool-schemas.ts:27-35`). The custom-agent catalog section lists extra names but does not repair standard component contracts.
- The inspector lists present JSON props plus known enums (`workspace/property-inspector-panel.tsx:99-102`); it can edit arbitrary JSON, but cannot discover every optional non-enum property absent from a starter descriptor. Full props editing is not the same as a schema-complete UI.

**Source-verified.** Build one declarative catalog contract for accepted JSON props, bindings, child slots, action payloads, defaults, examples and optional editor metadata; derive prompt/MCP/runtime validation from it where practical. Keep existing modules and avoid an independent replacement registry. Implement declared props or explicitly deprecate them; do not promise all upstream shadcn props.

### S07 — P2: overlay trigger composition and accessibility need a focused pass

Popover/HoverCard/DropdownMenu/Tooltip use `asChild` on an extra span, with the rendered button nested inside. Trigger attributes/ref belong to the span rather than the actual control. Clicking can bubble and work, but focus/keyboard trigger semantics need direct-child forwarding or a dedicated trigger adapter. Tooltip can accept multiple children yet represents them as one span trigger.

`overlay/a2ui-tooltip.tsx:25` adds a TooltipProvider per component even though `components/runtime/app-runtime.tsx:159,211` already provides one. This violates the current repository provider contract. Delay can be passed at the Tooltip Root according to the local Radix API. Drawer/Sheet render a Title only if supplied, unlike Dialog's hidden fallback; generated descriptors must retain an accessible title even when visual title is omitted.

Combobox/InputOTP/ToggleGroup labels are plain Label nodes without htmlFor/aria-labelledby wiring, and the Combobox/DatePicker fallback strings remain hard-coded English in TSX. Include accessible names and next-intl defaults in the same targeted adapter pass. **Source-verified; no browser/native keyboard acceptance ran.** Do not infer an exploit or full keyboard failure from markup alone; use actual Tab/Enter/Space/Escape/focus-return checks to choose the fix.

### S08 — P2: Toast is a rendered side effect with no stable lifecycle

`display/a2ui-toast.tsx:26-66` emits a fresh sonner toast whenever message, variant, duration, description or onAction identity changes. It has no stable toast id and no cleanup/dismiss/update route. Loading toasts can outlive deletion of their surface; streamed message updates or remounts can produce duplicate notifications rather than updating one. **Source-verified; not behavior-probed.** Tie toast ids to surface/component identity and update/dismiss them through the surface lifecycle. Preserve deliberate transient notifications rather than making every stream patch a new alert.

### S09 — P2: Table selectedRows is write-only and select-all omits its action

`data/a2ui-table.tsx:83` starts local `selectedRowKeys` empty and never resolves `component.selectedRows`. The latter is used only to find a write-back path (`:230-234`). Restored/model-controlled selection therefore is not reflected, despite being declared `A2UIArrayOrPath<string>`. Row selection emits `selectAction`; `handleSelectAll` at line 245 writes data but does not emit the same action. **Source-verified; not behavior-probed in this audit.** Use the binding as source of truth when supplied and make row/select-all events consistent. Test restored state, remote updates, sorting/pagination and selection clearing.

### S10 — P2: date and datetime adapters need timezone round-trip tests

`form/a2ui-datepicker.tsx:62` serializes the selected local Date via `toISOString().split('T')[0]`; selecting local midnight 2026-10-20 in Asia/Shanghai serializes 2026-10-19. Format the selected calendar date in the local calendar rather than truncating its UTC instant. `form/a2ui-datetimepicker.tsx:27-33` displays an ISO instant with string slicing but writes a datetime-local string through local `new Date(...).toISOString()`, so the same UTC instant is not round-tripped as the same local displayed time. **Source-verified plus a deterministic `TZ=Asia/Shanghai` Date probe (date-only 2026-10-20→2026-10-19; local datetime 12:00→04:00 after serialization and restore), not a real Calendar interaction probe.** Explicitly define date-only vs zoned instant semantics and test Asia/Shanghai plus a negative offset and DST boundary.

## Validation performed

1. Existing focused suites ran through the repository entry point: `rtk pnpm test --runInBand --runTestsByPath` for Combobox, FormGroup, Sheet, ToggleGroup, component-definitions, component-properties and catalog. **7 suites / 199 tests passed**, no snapshots/coverage.
2. Separate isolated jsdom/RTL probes loaded the real local primitives through `tsx/cjs`, with only the A2UI data context/child renderer replaced to inject deterministic state. They observed the defects above; they are **not new passing regression tests**, not full-surface integration or browser acceptance. Script/results are in the chat artifact folder linked below. DOM-geometry observers were stubbed because jsdom has no layout.
3. Source inventory cross-checked 68 renderer entries, 68 editor factory cases and 71 production top-level UI sources. File-level imports identify reuse; they do not certify every composed subcomponent or indirect dependency.

No coverage, full suite, typecheck, lint, build, real model generation, browser or Tauri acceptance ran for this research-only document. Any subsequent implementation needs co-located behavioral regressions and browser/native verification appropriate to its scope.
