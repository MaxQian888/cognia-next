# CCSwitch Interop

Cognia reads **CC Switch v4.0.18, SQLite schema 21**. The external database stays read-only. An older or newer schema produces an explicit error instead of guessed columns or empty successful results. Upgrade CC Switch itself to migrate its database; Cognia does not migrate it.

## Supported records

All eleven current app types are browsed: `claude`, `claude-desktop`, `codex`, `gemini`, `grokbuild`, `opencode`, `openclaw`, `hermes`, `pi`, `mcode`, and `agy`.

| Record | Behavior |
| --- | --- |
| Providers | Decode current per-app credentials/endpoints and model names, including Codex TOML and OpenCode V2. Identity is `(app_type, id)`. |
| MCP servers | Read `server_config`; import through Cognia's existing skip/overwrite/duplicate flow. A URL-only config defaults to HTTP. |
| Prompts | Preserve app identity and import selected content as new prompt presets. |
| Skills | Read installed `SKILL.md`, parse frontmatter and optional `agents/openai.yaml`, and persist scripts/references/assets with the skill. |
| Quota metadata | Import recognized declarative templates as disabled sources for review. Never execute CC Switch JavaScript. |

GrokBuild `env_key` is exposed as a variable name; Cognia does not read an arbitrary environment variable named by an external database row. Managed authentication and non-Anthropic protocols remain browse-only for the bundled Anthropic SDK. CC Switch's proxy, terminal launchers, and OAuth account management stay in CC Switch.

## Module ownership

| Module | Responsibility |
| --- | --- |
| `crates/cognia-ccswitch/src/db.rs` | Read-only connection, exact schema validation, SQL queries |
| `crates/cognia-ccswitch/src/provider_config.rs` | Per-app JSON/TOML parsing; no credential lookup or execution |
| `crates/cognia-ccswitch/src/skill_files.rs` | Constrained installed-skill directory reads and file limits |
| `crates/cognia-ccswitch/src/types.rs` | Serialized record types |
| `crates/cognia-ccswitch/src/paths.rs` | Database redirects and device-local skill storage selection |
| `crates/cognia-ccswitch/src/commands.rs` | Tauri command entry points and existing external-agent writers |
| `crates/cognia-ccswitch/src/watcher.rs` | Database/WAL/SHM change events |
| `lib/ccswitch/provider.ts` | Composite identity, SDK compatibility and model registration |
| `lib/ccswitch/switch-plan.ts` | Pure preview of settings and external-agent patches |
| `lib/ccswitch/switch.ts` | Apply the reviewed plan and report individual external-agent outcomes |
| `lib/ccswitch/subscription-switch.ts` | Activate an existing vault account or adopt local Claude login |
| `lib/ccswitch/active-provider.ts` | Match credentials and project drift without writes |
| `lib/ccswitch/client.ts`, `hooks.ts`, `import.ts` | IPC, shared watcher lifecycle, and existing domain import adapters |

Rust tests live beside their implementation in `#[cfg(test)]` modules; TypeScript tests are co-located. `schema-v21.sql` is a test fixture taken from the tagged upstream table definitions, not a production migration.

## Paths and installed skills

Database resolution uses this order:

1. Cognia's `CC_SWITCH_HOME` test/debug override.
2. `ccswitchSync.manualDataDir` saved in Cognia.
3. CC Switch's flat `app_paths.json` key `app_config_dir_override`.
4. `~/.cc-switch/cc-switch.db`.

Every reader and watcher uses the saved manual directory. Skills normally live under the resolved database directory's `skills/`. CC Switch's device-local `~/.cc-switch/settings.json` can select `skillStorageLocation: "unified"`, in which case the source is `~/.agents/skills/`.

Skill paths must stay within the selected root. Traversal, symlink escapes, special files, and bundles exceeding the shared native reader's limits are rejected. The limits are 50 resource files, 2 MiB per file, 32 nested directory levels, and 500 directories. An unavailable bundle remains visible with import disabled; Cognia does not silently import a partial resource set.

## Explicit switching

The dialog previews changes before applying them. Compatible Anthropic cards can update Cognia's settings and sidecar. Keyless official Claude cards require a usable Anthropic login; failed activation leaves the switch unapplied. Managed OAuth cards are not treated as official Claude merely because they lack an API key.

The existing external-agent writers operate only after explicit selection and confirmation. Claude propagation clears a competing `ANTHROPIC_AUTH_TOKEN` before setting the selected API key. Propagation is limited to Claude Code and the Anthropic credential entry in OpenCode. Codex/Gemini are not compatible destinations for the bundled Anthropic switch. OpenCode updates credential storage only; its separate endpoint configuration is not rewritten, as the preview indicates. This is not equivalent to CC Switch's full native per-app switching.

Active badges use composite references such as `ccswitch:claude:default`. Credential matching trims whitespace and trailing URL slashes, prefers an explicitly stored matching identity, and keeps other app types from being mistaken for the bundled SDK's provider.

## Verification scope

Focused Jest and Rust tests cover schema rejection, all eleven app formats, read-only database access, composite identities, import payloads, watcher ownership, and failed activation. An isolated snapshot of local records can be checked without modifying the external database.

A frontend running against an older native process does not verify a changed Rust reader. Restart a rebuilt Cognia desktop host and use a real schema-21 CC Switch installation for final native acceptance. Do not infer that counts alone prove MCP configurations or skill bodies are readable.
