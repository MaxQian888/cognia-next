## Context

Slices ① and ② of the tracker (Dexie v170 / v171: projects, issues, events, counters, labels, GitHub mirror, `/issues` `/projects` `/workspace` routes) shipped with the **types, i18n keys and UI placeholders of slice ③ already present** — `canRun`, the four `run_*` / `artifact_linked` event kinds, the `agent-team` / `agent-task` source ids, the "N agents working" tile, the "My agents" view — but nothing produced them. This is the repository's recurrent "built but dormant" pattern, and an audit against the original intent (the Multica plan, ADR-0066/0086/0111/0113/0018, the shipped changesets and message bundles) listed the gaps precisely:

- "N agents working" was a hard-coded `0`; "My agents" had an empty `agentKeys` and could never match.
- Two declared federated sources had no adapter; `canRun` had no consumer; `lib/issues/run/` did not exist.
- `/workspace` linked to Settings instead of opening the one workspace editor (`WorkspaceManageDialog`), and showed neither trust state nor running agents.
- No ⌘K provider, no ADR (the type file cited one that did not exist), no assignee picker, `WorkItemRefV1.kind` had no `"issue"`.
- Slice ③ as a whole — notifications, IM cards, filing from chat — was unbuilt.
- Adjacent workspace/team gaps: `WorktreeCreate` / `WorktreeRemove` had four declarations and zero producers; Agent Teams created before v86 had no `projectId` and leaked across workspaces; a dormant `lib/terminal/collaboration` share model (see ADR-0133); a stale `project-store` docblock; an e2b workspace-backend shim whose `else` branch was unreachable and whose lookup used the wrong id prefix.

Non-goals, unchanged from slice ①/②: GitHub Projects v2 / milestones, bidirectional field sync, per-project custom columns, saved views, mobile writes, free-text tag refactor, an MCP bridge, an IM `/issue` slash command, a Managed Workspaces page (deliberate debt), external-agent assignees.

## Decision

### 1. Terms and invariants

`Workspace = Project` (`types/plugin/_compat.ts`), which owns `WorkspaceRoot[]`, `IssueProject[]`, `Issue[]` and `AgentTeam[]`. An issue's **assignee** is an `IssueActor`: `human`, `agent` (= a `Character` id) or `team` (= an `AgentTeam` id); anything else is refused by the picker and the IM handler. The board's six columns are fixed. Human moves go through `lib/issues/state-machine.ts`; **the runtime owns `in_progress`** — a human can never move an issue there, a run does; a settled run parks the issue at `in_review`, never `done`; a cancelled run returns it to `todo`. `applyRuntimeIssueStatus` (`lib/db/issues.ts`) is the only writer of runtime transitions.

### 2. Execution bridge — `issueRuns` (Dexie **v174**) and `IssueRunAdapter`

`lib/db/issue-runs.ts` adds the `issueRuns` table (`&id, issueId, [issueId+status], projectId, [projectId+status], adapterId, kind, targetId, status, startedAt, updatedAt`) — the **issue side is the single source of truth** for "which runs belong to this issue"; execution engines are never widened with an `issueId` column, so a new engine binds without a schema bump (`AgentTeamTask.metadata.issueId` is a reverse convenience only). Claimed as v174 rather than v172 because two concurrent branches hold v172 (ADR-0130) and v173; Dexie tolerates the gap.

`lib/issues/run/registry.ts` defines `IssueRunAdapter { id, kind, canRun(issue, project) → verdict, start(issue, ctx) → IssueRun, cancel(runId) }` with `registerIssueRunAdapter` / `listIssueRunOptions` / `startIssueRun` (refuse-or-dispatch; **dispatch failures throw**, they are never swallowed). Three adapters ship: `agent-task` (`createAgentTask` → `runAgentTaskNow`, settled from a `liveQuery` on `agentTaskAttempts`), `agent-team` (`createTask({ metadata: { issueId } })` + `agentTeamManager.start`, settled at the single completion sink `team-completion-linkage.ts`, artifacts from delivery nodes / child-run workspace paths), and `github-loop` (only when the project holds a `github-repo` resource; runs `executeIntegrationAction("runIssueLoop")` under the `awaiting_approval` gate; desktop only). `running.ts` exposes `listRunningIssueIds()` and `viewerAgentKeys()` (all Characters + AgentTeams as `agent:<id>` / `team:<id>`), which is what makes "My agents" mean *every* agent/team assignee in a single-user app.

### 3. Federated sources

`lib/issues/sources/{agent-task-source,agent-team-source}.ts` implement the two declared `IssueSourceAdapter`s **read-only** (`READ_ONLY_ISSUE_CAPABILITIES`), mapping engine states through one table (`agent-status-map.ts`: `pending→backlog`, `blocked/claimed→todo`, `in_progress/paused→in_progress`, `review→in_review`, `completed→done`, `failed/cancelled→canceled`) and deep-linking back to the native page. Federated rows render on the board by default with a source badge and a toolbar source facet; a row that carries an `issueId` (metadata or `issueRuns.targetId`) is badged "from KEY-1".

### 4. UI

`issue-console.tsx` reads the live viewer (`viewerAgentKeys`) and running set; a new `assignee-picker.tsx` (Characters + AgentTeams + me + unassigned) is wired into create and detail; `run-issue-dialog.tsx` is the `canRun` consumer (mode = local AgentTask default / AgentTeam / GitHub loop) and the detail panel shows run history, artifacts and cancel. `/workspace` mounts `WorkspaceManageDialog` directly (one editor, two entry points), shows trust state per root (`lib/db/trusted-workspaces.ts`) and a live agents-working tile. ⌘K gains `lib/global-search/providers/issues.ts` (kind `issue`); `WorkItemRefV1.kind` gains `"issue"`.

### 5. Notifications and IM (slice ③)

`lib/issues/notify.ts` projects issue events onto the Notification Center (`NotificationSource` `issue`, command `issue.open`) for: assigned / reassigned, run succeeded / failed, arrival at `in_review` / `done` / `canceled`, and comments by someone other than the viewer. A `liveQuery` watcher with a fixed watermark plus a seen-set never skips events; when the issue originated from an IM conversation (`Issue.origin = { kind: "im", conversationKey, messageId? }`) or a conversation is bound to the project (`ConversationOverrideRow.issueProjectId`) the same event is pushed back over IM through the governed queue, gated by the conversation's proactive-push opt-in and `hasNoLeakingPii`.

IM cards (`lib/issues/im/card.ts`) are pure A2UI builders: exactly the **legal human moves** (never `in_progress`), a **Run** button when an engine can take the issue, and an **Open** link; a numbered mirror serves button-less channels. Buttons carry `bindingKind: "issue_action"` + payload via `bindingHintFields` (shared by the Discord / Telegram / Slack / WeCom / Lark mappers) so a click reaches `lib/issues/im/callback-handler.ts` (a `ConnectorBus` short-circuit before `tool_approve`) instead of a model turn. Move / run buttons stay re-clickable; only the create-confirmation card is consume-once. Filing from chat is the built-in skill `issue.create` (write level, `hitlSurface`): the confirmation card lists ≤ 5 projects, the conversation's remembered choice first, and **nothing is written until a project button is pressed**; `issue_list_projects` resolves names. Lark and Slack inbound now carry `replyTo` so quote-to-issue works there as it did on Telegram / Discord. New audit kinds: `issue.card_action`, `issue.card_action_denied`, `issue.im_pii_blocked`.

### 6. Adjacent workspace / team gaps closed in the same change

- **Worktree hooks fire** (ADR-0111 decision 9, wording revised there): the Registry emits through `WorktreeLifecycleSink` (Rust) and `lib/git/commands.ts` fires after `git_worktree_add/remove` (TS) — two producers because the Registry does not sit in front of the Agent Team allocator or the source-control panel. Observational only.
- **Pre-v86 AgentTeams** get `projectId = DEFAULT_PROJECT_ID` (persist v7 `backfillTeamProjectIds`, applied in `migrate` and in `activateAgentTeamAccountStorage`); `updateTeam` stamps it; the mode selector drops its `!t.projectId` escape hatch.
- **e2b**: `resolveWorkspaceBackendByKind` (exact id, then `:<kind>` suffix) replaces the `"e2b"` lookup that never matched the registered `cognia-e2b-sandbox:e2b`; the `setE2BBackend/getE2BBackend` shim and the unreachable plugin branch are removed. `project-store` docblock corrected.

## Consequences

- Nothing on the tracker's surface is inert any more: every declared source, event kind, capability and view has a producer or a consumer, and the runtime/human boundary is enforced in one place.
- Engines stay ignorant of issues; adding one is an adapter plus a status-map row.
- IM is a first-class actor for issues without a new transport or a model digest turn on every click; PII never leaves without the gate.
- Two Dexie claims (v172, v173) by peers forced the gap to v174 — see the schema block comment.

## Verification

Per-stage co-located tests (adapters, sources, notify watcher, card builders, callback handler, skills, worktree sinks, persist migration); `pnpm i18n:build && pnpm lint:i18n` parity; scoped coverage ≥ 90 % on new modules. Full `test:coverage:changed --strict` and `tauri-smoke` could not be completed on the shared, disk-constrained box during this change and are recorded as outstanding.
