## Context

`lib/terminal/collaboration/{types,share-manager}.ts` described a collaboration model — invite objects with a `Math.random` token carried in a share URL, three roles (`controller` / `editor` / `viewer`), a private `CollabMessage` data-channel protocol — that **nothing imported** and that the host could not enforce: the durable host (`crates/cognia-terminal`) has exactly two lease roles (the controller and read-only viewers via `NotController`), authenticates remote clients per paired device with a single-use socket ticket plus the `terminal.open` capability, and already re-checks that capability every second while an attachment is live. Meanwhile the host already supported multiple attachments per session and a controller lease with take/release, but the renderer could not see **who** was attached: `SessionInfo` carried only `attachedClients` and `currentController`, and the host did not re-send the snapshot when the roster changed.

Options weighed in the grill: **A** — share to paired devices by granting the existing remote-terminal capability and reuse the host lease (no new transport, no tokens); B — a per-session invite token / link over the WAN signaling path; C — leave the model dormant. A was chosen: it is the only one the existing security boundary already enforces, and it needed no new frame kind or capability.

## Decision

1. **The host owns the roster.** `HostSessionInfo` gains `participants: Vec<SessionParticipant { client_id, device_id, local, role: controller | viewer }>` (serde `#[serde(default)]`, additive). `broadcast_participants` re-sends `HostEvent::SessionSnapshot` to every attachment after attach, detach, take-control, release-control and client disconnect. **No new `FrameKind`** — the wire compat invariant of ADR-0031 holds; older clients simply ignore the extra field and the extra unsolicited (sequence 0) snapshot.
2. **The bridge forwards unsolicited snapshots.** `terminal_host_bridge::channel_event_for` maps a sequence-0 `SessionSnapshot` frame to `HostChannelEvent::SessionSnapshot { session }` (replies to the desktop's own requests keep their sequence and are settled by the pending map). `HostSessionInfo` fixtures elsewhere gained the field.
3. **The renderer applies snapshots in place.** `BaseTerminalSession.applySessionSnapshot` replaces `info` field-by-field (same object identity — consumers hold `session.info`; keys the host dropped are removed) and fans out to `onInfo` listeners; `session.participants` is the typed accessor. `TerminalSession` handles the new `session_snapshot` channel event; `RemoteTerminalSession` routes sequence-0 `SessionSnapshot` frames through the same path. The session registry subscribes to `onInfo` and re-notifies, so `useSyncExternalStore` consumers update without polling. Nothing is persisted: the roster is live host state, so there is deliberately no terminal-store slice.
4. **Sharing = the per-device remote-terminal grant.** The Share dialog (`components/terminal/terminal-share-dialog.tsx`, dock **Share** button, desktop host only) lists the session's roster (device labels via the pairing table, controller/viewer badges) and every paired device with its grant as a switch. The grant flow — provision host descriptor → mirror to Dexie → flip the host, biometric-gated on enable, rollback on host refusal — was extracted from the paired-devices card into `hooks/companion/use-remote-terminal-grant.ts` so both surfaces are one implementation. Removing the grant is the "kick": the LAN/WAN adapters already recheck it every second and drop the attachment. The grant is **device-wide**, not per session; the dialog says so. When the host's `allowRemoteAccess` is off the dialog links to Settings → Terminal rather than flipping it (that switch also re-provisions the host).
5. **The chip reports sharing.** `TerminalSessionChip` adds a "Shared with N devices" state (re-expanding when a device attaches) and lists remote participants with their lease role in its popover; its release-control affordance keys off the roster's controller.
6. **The dormant model is deleted.** `types.ts`, `share-manager.ts`, `index.ts` and their test go; `lib/terminal/collaboration/roster.ts` is the pure renderer-side projection (`projectRoster`, `mergeDevicesWithRoster`, `participantLabel`, `deviceIdOfClient`) over `SessionInfo.participants` and the pairing table. There is no `editor` role because the host has none.

## Consequences

- Sharing rides the existing security boundary: paired device + single-use ticket + `terminal.open` + one-second recheck. No secret ever appears in a URL.
- Every window attached to a session sees roster and lease changes within one frame; the "Take control" / "Release control" affordances finally show who they are taking from.
- Per-session scoping is a non-goal of this ADR: a device with the grant may attach to any hosted terminal, exactly as before; if per-session grants are ever needed they belong in the ticket scope (`companion_api/api.rs`) and `ws_terminal.rs`, not in the renderer.
- PII gating does not apply — PTY bytes to a paired device are the existing trust boundary, unchanged.

## Verification

Host: `roster_is_broadcast_to_every_attachment_on_attach_detach_and_lease_moves`, `dropping_a_client_updates_the_roster_for_the_others` (crate suite green). Bridge: `unsolicited_session_snapshots_reach_the_channel_as_roster_refreshes`. Renderer: base-session snapshot tests, session / transport-ws snapshot dispatch, registry re-notify, roster projection, grant hook (ordering, rollback, gate), share dialog, chip roster, dock share button. Not done in this change: `tauri-smoke` on a real paired device (recorded as outstanding).
