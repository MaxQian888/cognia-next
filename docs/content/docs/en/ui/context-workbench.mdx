# Context Workbench

The Context Workbench provides a shared workspace on the right for resource-specific tools.
It combines navigation and layout.
Project, Canvas, Artifact, and Workflow retain their specialized capabilities.

## Surface parity

| Resource | Native panels kept in the Workbench |
| --- | --- |
| Project file | resource chat, comments, metadata/session controls, outline, diagnostics, Git review, proposal review, preview |
| Canvas document | AI actions/chat, suggestions, comments, collaboration, properties/formatting, outline, history, proposal review, preview/export, execution |
| Artifact | resource chat, comments, proposal review, preview, history, metadata, filesystem workspace, selection-to-AI |
| Workflow | specialized chat, comments, inspector, problems, runs, templates, settings, changelog |

Each host computes capabilities from the current resource and platform. A native panel may remain visible with an explanation when its backend is unavailable. A plugin panel is omitted when its declared capabilities or permissions are not satisfied.

## Navigation and layout

- Labeled tabs use a row across the right panel’s full width and show open panels by name. Use **Open panel** (`+`) to find another panel and the close button to dismiss a tab. The layout keeps the existing panel navigation and resource scope.
- Switch between **Labeled tabs** and **Compact icon rail** in the workbench; the choice is remembered. Tab mode collapses the entire right column, even when the saved icon-rail preference keeps icons visible in compact mode.
- Compact activity buttons group related panels. Arrow keys, Home, and End move through activities and grouped tabs with standard tab/tabpanel semantics.
- `narrow` uses the host's normal 360px width. `wide` uses about half of the host, clamped to 640–960px. `focus` is an accessible full-screen presentation that restores focus on Escape.
- Mobile renders a full-width Sheet and intentionally omits desktop-only width and focus controls.
- Pinning protects the selected panel from automatic reveals. Diagnostics, proposals, selection changes, and plugin requests update pending indicators until the user navigates explicitly or unpins.

## Task overview

**Task summary** sits in the title bar beside the layout toggles (shortcut
<kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>S</kbd>). It opens a compact card about the
current conversation:

- **Header**: the project and branch the task runs in, **Manage task** (session
  settings) and a menu.
- **Run progress**: the current step of the run's plan, with a step bar.
- **Waiting for you**: approvals and questions the task is blocked on; click to
  jump to the turn that asked.
- **Changes**: lines added and removed (or the file count when some files have
  no line counts); click to open the workspace panel.
- **Artifacts**: the artifacts this conversation made; one opens directly,
  several open the artifact list.
- **Sources**: the most-used kinds of source, **+** to manage sources and
  capabilities, and **View all** for the sources panel.
- **Sharing**: private or shared, the participants, and the shared-chat
  controls (connection status and **Request AI** in a shared room).

When the window leaves room beside the centred chat column, the card floats in
that gutter under the button and stays open; the button (or **Hide card** in
the menu) puts it away for this conversation. On a narrower window it opens as
a popover under the button instead. Either way the card never narrows the
conversation and never covers a banner. It does not open or close the right
panel, so it can sit beside whatever the panel shows.

Choose what the card shows from its menu: each row is **Always**, **When
present** or **Hidden**, and **Restore defaults** resets them. The choice
syncs with your other settings. **Open task overview** in the same menu opens
the full overview in the right panel. The rail's sources and workspace badges
use the same counts as the card.

In the full overview, capabilities start collapsed and results appear only when
available. The conversation title remains plain text. Search and navigation controls are grouped in the top-right toolbar; history,
workspace selection and navigation shortcuts remain available in **Navigation**.

The full overview includes open questions and subtasks, configured skills,
runtime capability snapshots, sharing controls and technical details. The card
and the overview read the same session state, so their counts always agree.

The overview keeps the existing `metadata` panel ID, so saved layouts and panel
shortcuts continue to work. Artifact properties remain a separate resource view.
Technical session fields remain available under **Technical details**.

Configured skills describe the next send; only a supported host snapshot can
confirm loaded or deferred runtime capabilities. Missing snapshots are shown as
unavailable. The results list is locked to the current conversation; input
citations are not counted as generated results. Open a result in its existing
artifact or workspace view to inspect or edit it.

## Split view

In `wide` or `focus` mode the layout menu offers **Split below**, which stacks a second panel under the one in front. Both panes stay live: each keeps focus, its own error boundary, and — for plugin panels — its own visibility signal.

- Drag the divider to change the ratio, or focus it and use the arrow keys (Shift for larger steps, Home/End for the extremes). Double-click resets it. The ratio is remembered per resource, between 20% and 80%.
- Selecting the panel already in the lower pane swaps the two and keeps each at the height it had, rather than replacing the one in front.
- Neither pane is rebuilt when the split opens, closes, resizes or swaps, so an embedded editor, browser or terminal keeps its state throughout.
- The mobile drawer, and any workbench too narrow for two panes, shows a single pane without disturbing the stored desktop layout — it returns when there is room again.
- `narrow` closes the split, because there is no room for two panes. Collapsing to the rail does not: the split is still there when you expand.

## Comments and resource sessions

All four resources use the shared comment model. Comments can target the whole resource, a text/line range, or Workflow nodes/edges. Threads retain edit/delete, replies, reactions, resolve/reopen, unresolved badges, revision metadata, and stale-anchor indication.

Each resource also owns one durable embedded AI session. Existing provider-bound context assembly, PII redaction, proposal-first editing, and review bridges remain in the specialized panel implementations.

## Rollback switches

The four host switches—`canvas`, `project`, `artifact`, and `workflow`—default on independently. Turning one off restores that surface's complete legacy sidebar without changing the other three. Legacy hosts remain for one minor release.
