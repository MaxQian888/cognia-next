# WebRTC transport

`TransportRtc` is the mobile/browser offerer. `CompanionTransport` selects the
route in this order:

1. healthy LAN HTTPS/WebSocket;
2. open WebRTC `cognia.v2` DataChannel;
3. authenticated HTTPS/WebSocket fallback when command metadata permits it.

The client never downgrades to a legacy signaling protocol.

## Pairing and signaling

The pairing response contains a public `RoomDescriptorV2` and a mobile role
private key. Capacitor stores the key in SecureStorage. A normal browser uses
a non-extractable WebCrypto key and an encrypted IndexedDB pairing blob.

`SignalingClient` connects to `/v2/signaling`, signs the server challenge with
ECDSA P-256, generates an ephemeral P-256 ECDH key, and subscribes for the
mobile role. SDP/ICE are encrypted with directional HKDF-SHA-256/AES-256-GCM
keys and signed over canonical length-prefixed fields. The relay cannot read
the encrypted body.

One serialized bounded send queue assigns increasing sequence numbers. The
receiver verifies the role/session/epoch, timestamp and signature before
advancing its replay state, then applies a bounded reorder window.

## Negotiation

The mobile creates one ordered reliable DataChannel named `cognia.v2`. ICE
received before the remote description is retained in order (256 entries, 30
seconds). Every async negotiation callback checks its epoch before mutating
the peer.

`awaiting-peer` is a normal state when the host is offline. Mid-session
recovery waits through a disconnected grace period, attempts ICE restart,
then rebuilds the peer and uses full-jitter bounded reconnect backoff.

## RPC and events

RPC uses:

```ts
{ id, method, params, idempotencyKey, protocolVersion: 2 }
```

The command manifest determines read/retry behavior. A write reuses one
idempotency key across RTC and HTTPS fallback. The host's persistent ledger
returns the prior result, `idempotency_conflict`, or
`idempotency_indeterminate`; it never blindly repeats an uncertain write.

Events carry a global `seq`. The client persists its cursor, sends
`event-resume`, filters duplicates/out-of-order delivery, and acknowledges
each delivered high-water mark. `resync_required` is explicit when replay
retention cannot cover the gap.

## Capacity and TURN

Physical frames are limited to 32 KiB and logical messages to 1 MiB.
Chunking allows eight concurrent reassemblies, 4 MiB memory, and a 15-second
deadline. Browser sending pauses above 1 MiB `bufferedAmount` and resumes at
256 KiB. Each peer permits 32 concurrent RPCs.

Static/BYO ICE servers are combined with short-lived provider TURN servers.
Credentials are refreshed before expiry. Configuration updates carry a
generation guard, so a late response from an obsolete provider cannot
overwrite newer settings. The selected candidate kind (`host`, `srflx`,
`prflx`, or `relay`) is exposed for connection status.
