## Per-record implementation review

The matrix below is the second-pass, record-by-record review requested after the catalogue audit. The verdicts mean:

- **Closed** — the current accepted/core scope has code, tests, and a reachable runtime or product surface; no missing function was confirmed.
- **Limited** — the core works, but a current platform or intentionally excluded capability remains.
- **Partial** — at least one described or deferred function is still absent, unwired, or only represented by a stub.
- **Rollout** — the implementation exists but remains experimental, default-off, dark-launched, or short of its stated GA gate.
- **Drift** — the implementation has moved past the ADR's status or follow-up text; the gap is documentation reconciliation rather than a confirmed missing user function.
- **Superseded / removed** — a later architecture owns the behavior or the product intentionally removed it.

An item marked Limited is not automatically a defect. It is included so product scope is explicit. Evidence paths name the current owner, not necessarily the historical path printed in the ADR.
