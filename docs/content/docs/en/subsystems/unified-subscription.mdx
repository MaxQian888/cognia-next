# Unified Subscription

<Status variant="stable">Stable · ADR-0025 · vault schema v4</Status>

<TLDR>
  Three subscription providers — Anthropic, Codex, OpenCode — share one account model, one vault format
  and one limits surface. The interesting piece is the **limits-source registry**
  (`lib/subscription/limits/registry.ts`): a flat ordered list where windowed sources come *before* the
  generic balance source, so the runner prefers a real utilization window and only falls through to a
  credit meter when no window applies. Aggregation (`limits/aggregate.ts`) queries every configured
  account and returns them with the active one pinned first — which is what both the TUI `/limits` panel
  and the desktop multi-provider view consume. Every seam is injected, so the same code runs offline in
  tests and in the CLI with a Node-`fetch`-backed `authedGet`.
</TLDR>

## Order is the design

A "limit" can mean two different things: a rolling utilization window (Anthropic, Codex) or a credit
balance (most OpenAI-compatible resellers). Presenting a credit meter when a real window exists would be
a downgrade, so the registry encodes the preference as list order — windowed sources first, the generic
balance source last. The runner walks the returned candidate list and stops at the first source that
yields a snapshot.

Plugin-contributed sources overlay in front of the built-ins, resolved through
`lib/plugin/registries/limits-source-registry.ts`. The registry itself is pure: a list plus a resolver
that returns *every* matching source rather than picking one, which keeps the fallback decision in the
runner where it can be tested.

## Account Center and credential boundaries

Settings → Subscription → Accounts is the only account CRUD surface. Claude, Codex, and OpenCode
provider pages keep provider-specific usage, probe, and routing controls; they do not duplicate account
mutation controls. “Active now” projects one credential into the provider runtime. “Default for new
sessions” is a resolver fallback and does not activate or rewrite a running tool.

The list and detail panes consume `AccountSummary` / `AccountDetail`, which cannot serialize access
tokens, refresh tokens, ID tokens, or API keys. Settings mutations are scoped operations: rename,
preference changes, credential replacement, identity-safe Codex reauthentication, and local removal.
Secret-bearing full-account resolution remains confined to runtime consumers and explicit encrypted
backup/export flows.

Vault schema v4 adds non-secret Codex identity facts and lifecycle state. Codex refresh is host-owned,
single-flight per account, atomically persists rotated access/refresh/ID tokens, and shares a lifecycle
lock with removal. A targeted reauthentication may replace an account only when the stored and incoming
workspace plus subject match. Legacy accounts without a verifiable fingerprint fail closed and must be
added separately. Terminal refresh errors persist `reauth_required`; transient network failures remain
retryable and do not invalidate the account.

<Callout type="warn">
  “Deactivate” only clears Cognia's active projection. “Remove from Cognia” only deletes the local vault
  entry and migrates Cognia references. Neither operation revokes an upstream token, logs out an external
  CLI, edits CCSwitch, or changes an external credential file/keychain entry. OpenCode and other external
  credential representations are read-only until the user explicitly creates a Cognia-managed copy.
</Callout>

The v3 → v4 migration is a pure payload migration: it derives an optional fingerprint only from the ID
token already present in the supplied vault payload. It performs no host discovery, keychain lookup,
configuration-file read, or network request.

## Export is encrypted with the backup primitives

`core/encrypted-package.ts` reuses the same crypto as the Dexie-wide backup in `lib/data/` —
PBKDF2-SHA256 at 600,000 iterations plus AES-GCM-256 — but ships a simpler envelope sized for just the
three provider vaults (`SUBSCRIPTION_PACKAGE_VERSION = "subscription-v1"`). The smaller payload keeps
backup files readable in tooling and makes it obvious which vaults are inside.

<Callout type="warn">
  Writes must go through the settings store, not straight to Dexie. Bypassing it leaves the in-memory
  store stale — a real bug that has been fixed once already in the ccswitch path.
</Callout>
