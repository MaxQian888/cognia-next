# Security Model

<Status variant="stable">allowlist.rs · rate_limit.rs · keyring.rs</Status>

<TLDR>
  Three small, independently unit-tested modules back the listener's defense in depth.
  `allowlist.rs` is an IPv4 CIDR matcher that masks the caller IP against each entry. `rate_limit.rs`
  is a mutex-guarded fixed-window counter (default 60/min, monotonic `Instant` clock, fails *open* on
  a poisoned lock). `keyring.rs` stores the bearer token and the outbound signing secret in the OS
  keyring under service `com.cognia.remote-control`, mapping `NoEntry` to `None`, and mints a 256-bit
  token from two UUIDv4s.
</TLDR>

## IPv4 CIDR Allowlist — `allowlist.rs`

`ParsedAllowlist` holds a `Vec<(Ipv4Addr, u8)>` of parsed (network, prefix) pairs. Garbage, IPv6,
and out-of-range prefixes are rejected at **parse** time (when the server spawns), not on the request
hot path. A bare IP with no slash defaults to a `/32` host route.

```rust
// allowlist.rs:37
fn parse_cidr(raw: &str) -> Result<(Ipv4Addr, u8), String> {
    // "127.0.0.1/32" → (127.0.0.1, 32); bare "192.168.1.1" → prefix 32
    // errors: "prefix is not a number", "prefix > 32", "address is not IPv4"
}
```

Matching is a linear scan; the first hit wins, and an empty list denies everyone. The core is a
straight prefix-mask compare — `prefix == 0` short-circuits to "match all":

```rust
// allowlist.rs:53
fn matches_cidr(addr: Ipv4Addr, network: Ipv4Addr, prefix: u8) -> bool {
    if prefix == 0 {
        return true;
    }
    let mask: u32 = (!0u32) << (32 - prefix as u32);
    let a = u32::from(addr) & mask;
    let n = u32::from(network) & mask;
    a == n
}
```

| Entry | Matches | Rejects |
| --- | --- | --- |
| `127.0.0.1/32` (default) | `127.0.0.1` | `127.0.0.2`, `10.0.0.1` |
| `192.168.1.1` (bare → `/32`) | `192.168.1.1` | `192.168.1.2` |
| `10.0.0.0/8` | `10.0.0.1` … `10.255.255.254` | `11.0.0.1` |
| `0.0.0.0/0` | everything | — |

The renderer mirrors this validation client-side with `validateCidrOrIp`
(`types/remote-control/index.ts:135`) so the Inbound tab can reject a malformed entry before it ever
reaches Rust — see [Renderer &amp; Settings](./renderer-and-settings).

## Fixed-Window Rate Limiter — `rate_limit.rs`

`FixedWindowRateLimiter` is a single `Mutex<RateLimiterInner>` holding `window_started_at: Instant`,
a `count`, and the `limit`. Because there is exactly one bearer token, a single global window is
equivalent to per-token limiting. The window is *fixed* (reset to `now()` once 60 s elapse), not
sliding, and the clock is monotonic `Instant`, immune to wall-clock changes.

```rust
// rate_limit.rs:40
pub fn try_acquire(&self) -> bool {
    let mut inner = match self.inner.lock() {
        Ok(g) => g,
        Err(_) => return true, // poisoned mutex must not lock users out
    };
    if inner.window_started_at.elapsed() >= Duration::from_secs(60) {
        inner.window_started_at = Instant::now();
        inner.count = 0;
    }
    if inner.count >= inner.limit {
        return false;
    }
    inner.count += 1;
    true
}
```

Two deliberate choices worth noting: a **poisoned mutex fails open** (returns `true`) so a panic
elsewhere can never permanently 429 a legitimate user; and the window resets *lazily* on the next
`try_acquire` after expiry rather than via a background timer, so an idle limiter costs nothing.

## OS Keyring Storage — `keyring.rs`

Both secrets live in the OS keyring through the `keyring = "3"` crate (`Cargo.toml:169`, with
`windows-native` / `apple-native` / `sync-secret-service` backends per platform). Service and account
names are constants:

```rust
// keyring.rs:11
const SERVICE: &str = "com.cognia.remote-control";
const TOKEN_ACCOUNT: &str = "inbound-token";
const SIGNING_SECRET_ACCOUNT: &str = "outbound-signing-secret";
```

The private `read` helper maps a missing entry to `Ok(None)` so "no token yet" is a normal value,
not an error:

```rust
// keyring.rs:19
fn read(account: &str) -> Result<Option<String>, String> {
    match entry(account)?.get_password() {
        Ok(v) => Ok(Some(v)),
        Err(keyring::Error::NoEntry) => Ok(None),
        Err(e) => Err(format!("keyring read failed: {e}")),
    }
}
```

Public wrappers (`read_token` / `write_token` / `clear_token` / `read_signing_secret` /
`write_signing_secret` / `clear_signing_secret`, `keyring.rs:44-67`) are the only surface the rest of
the module touches. Neither secret ever enters Zustand or Dexie.

### Token generation — 256 bits

A new bearer token is two UUIDv4s concatenated as 64 hex characters (256 bits of entropy):

```rust
// keyring.rs:70
pub fn generate_token() -> String {
    let a = uuid::Uuid::new_v4().simple().to_string();
    let b = uuid::Uuid::new_v4().simple().to_string();
    format!("{a}{b}") // 64 hex chars
}
```

This is invoked by `remote_control_rotate_token` (`commands.rs:41`), which persists the new token and
records its presence — see [State &amp; Commands](./state-and-commands).

## Threat Model

The single bearer token + `127.0.0.1` binding + IPv4 allowlist is sufficient against:

- a **co-resident user-mode process** that cannot read the OS keyring (defense: bearer auth);
- an **off-loopback network attacker** (defense: loopback binding + allowlist defaulting to
  `127.0.0.1/32`);
- **replay of a stolen webhook body** to a receiver (defense: the HMAC signature — once the outbound
  path is wired — plus constant-time inbound auth).

It is **not** sufficient against:

- a co-resident attacker who **can read the OS keyring** — no defense; the same exposure applies to
  any Cognia API key;
- a **malicious browser extension** inside the Cognia WebView (Tauri's default CSP applies);
- a **man-in-the-middle on outbound deliveries** — receivers should pin TLS and verify the signature.

<Callout type="info">
  Health (`GET /api/v1/health`) requires auth on purpose. The middleware gate runs on every route, so
  an unauthenticated scanner can't fingerprint the build by reading the embedded
  `CARGO_PKG_VERSION`.
</Callout>
