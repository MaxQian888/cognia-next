# State & Persistence

<Status variant="experimental" />

<TLDR>
  A2UI keeps state in **two independent layers**, and they do not call each other. The Zustand store
  (`stores/a2ui/a2ui-store.ts`) is the single ingest point for every server message and the source of
  truth at runtime. It persists the **complete 20 most recent ready surfaces** to `localStorage`
  (key `cognia-a2ui-surfaces`). The four Dexie tables
  (`a2uiApps`, `a2uiSurfaces`, `a2uiTemplates`, `a2uiEventHistory`) are a **separate durable layer**
  invoked from the renderer/hook layer, never from the store. On the Mini Apps route,
  `hydratePersistedApps()` restores missing runtime trees from saved `a2uiApps` rows through
  `restoreSurface`; legacy template-only instances retain deterministic regeneration as a fallback.
  Undo/redo lives in-memory only (50-entry stacks, 300 ms debounce).
</TLDR>

<StatGrid>
  <Stat label="Persistence layers" value="2" hint="zustand→localStorage (20 complete runtime surfaces) · Dexie (durable saved rows)" />
  <Stat label="localStorage LRU cap" value="20" hint="MAX_PERSISTED_SURFACES, ready surfaces only" />
  <Stat label="Undo history" value="50" hint="MAX_HISTORY_ENTRIES, 300 ms debounce" />

## Two Persistence Layers (read this first)

<Callout type="warn">
  The Zustand store and the Dexie `a2ui-*` tables are **two separate persistence layers**. Store
  `partialize` LRU-caps localStorage to the 20 most recent ready surfaces but preserves each complete
  component tree and data model. Dexie is **never imported by the store**; Save, hydration, metadata
  patches, and deletion cross the durable boundary in hooks. Writing the store does not write Dexie,
  but `useA2UIAppBuilder.hydratePersistedApps()` deliberately reads Dexie and calls the store's
  validated `restoreSurface()` action when a runtime surface is absent.
</Callout>

| Concern | Zustand store (`a2ui-store.ts`) | Dexie tables (`lib/db/a2ui-*.ts`) |
| --- | --- | --- |
| Medium | `localStorage` (zustand `persist`) | IndexedDB (Dexie) |
| Key / name | `cognia-a2ui-surfaces` (version 3) | tables `a2uiApps` / `a2uiSurfaces` / `a2uiTemplates` / `a2uiEventHistory` |
| Stores | 20 complete ready runtime surfaces, including components/dataModel | full saved rows: components, dataModel, rootId, audit |
| Scope | runtime truth + last-session restore | user-saved apps, panel/fullscreen surfaces, templates, audit trail |
| Cap / eviction | LRU 20 ready surfaces, sorted `updatedAt` desc | event-history trims to 1000 rows |
| Called from | every server message + UI action | renderer/hook layer (NOT the store) |
| Undo/redo | in-memory only (excluded from persist) | — |

## The Store as Message Entry Point

`useA2UIStore` (`a2ui-store.ts:212`) is created once via `create` and holds the entire runtime A2UI
state. Every server message — from any of the three dispatch paths — funnels through
`processMessage` (`351`).

## Undo / Redo

Undo/redo is **in-memory only** — `undoStacks` / `redoStacks` (`63-64`) are excluded from the
persist `partialize`. A snapshot captures `components` + `dataModel` (`A2UIHistoryEntry`, `30`).

- `pushSnapshot` (`500`) is **debounced 300 ms** (`HISTORY_DEBOUNCE_MS`, line `509`) so rapid edits
  collapse into one history step.
- Stacks are capped at `MAX_HISTORY_ENTRIES = 50` (`38`).
- `updateComponents` (`266`) and `updateDataModel` (`298`) push a snapshot before mutating.
- `undo` (`540`) / `redo` (`580`) restore a snapshot; `canUndo` (`620`) / `canRedo` (`624`) gate the UI.

## localStorage Persist Config

The zustand `persist` config (`641-702`):

| Aspect | Line | Behavior |
| --- | --- | --- |
| `name` | persist config | `cognia-a2ui-surfaces` — **localStorage**, not Dexie |
| `version` | persist config | `3` |
| `migrate` | persist config | → `normalizePersistedSurfaces` |
| `onRehydrateStorage` | persist config | re-normalize surfaces, re-derive `activeSurfaceId` |
| `partialize` | current store persist block | LRU cap with complete surfaces (below) |

`partialize` is the load-bearing part:

1. LRU-cap to `MAX_PERSISTED_SURFACES = 20`.
2. Keep **only `ready` surfaces**, sorted by `updatedAt` descending.
3. Preserve each selected surface **in full**, including `components`, `dataModel`, and `rootId`.
4. Persist `{ surfaces: persistedSurfaces, activeSurfaceId }`; undo/redo stacks are excluded.

The LRU means the store can rehydrate recent surfaces directly. Saved surfaces outside that window are
restored from `a2uiApps` by `hydratePersistedApps()`; only legacy template instances without a durable
row use deterministic template regeneration. A renderable local surface wins over a durable row so
hydration cannot overwrite unsaved runtime edits.

## The Four Dexie Tables

The durable layer lives in `lib/db/`. These tables were first introduced in Dexie `version(13)`
(`schema.ts` version-13 block); the **current** schema version is `version(118)`. Table classes are
declared in `lib/db/schema.ts`.

### Durable-layer invariants

- **Built-in protection** — single upsert, bulk upsert, metadata patch, and delete all reject attempts
  to modify an existing `isBuiltIn` app. Bulk upsert is transactional, so an accompanying user row is
  not partially inserted. `deleteAllUserApps` and `deleteAllUserTemplates` retain built-ins.
- **Inline exclusion** — `upsertSurface` (`a2ui-surfaces.ts:20`) early-returns for
  `type === "inline"` (22): inline surfaces are runtime-only and never written to Dexie. Only
  `panel` / `fullscreen` (and `dialog`) surfaces are durable.
- **Event-history cap** — `a2ui-event-history.ts` caps at `MAX_ROWS = 1000` (`9`) and trims
  `TRIM_BATCH = 100` (`11`) oldest rows when exceeded; `appendEvent` swallows failures so audit never
  breaks a UI action.

## Schema Version Reality

<Callout type="info">
  The A2UI tables were **introduced in Dexie `version(13)`**, whose schema block contains the four
  A2UI table definitions. Their index strings have not changed since. The **current/latest** schema
  version is `version(118)`. "Dexie v13" therefore means the introduction version, not the live
  database version: cite v13 for "when the tables appeared" and v118 for the current schema.
</Callout>
