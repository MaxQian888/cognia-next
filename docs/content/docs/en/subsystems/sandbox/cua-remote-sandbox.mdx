# CUA remote sandbox

Cognia provides a Linux desktop inside a local Docker container. Open **Settings → Automation → Sandbox connections**, create a Docker connection, then provision/start it. The connection detail shows the desktop, file transfer and lifecycle actions. Docker must be running in the context available to the client-local Tauri host.

The implemented adapter is `docker:computer-server`. E2B Desktop, Cua Cloud and Lume are not enabled desktop providers. Imported configuration does not create a working adapter. Browser-only and companion clients do not acquire local Docker access merely by displaying these settings.

## Runtime and image

The default `cognia-cua-desktop:0.3.46-1` image is built on first provisioning from resources embedded in `crates/cognia-automation/src/cua_sandbox/image/`. It uses a digest-pinned Python base, native Debian Chromium, Openbox, Xvfb, xterm and `cua-computer-server==0.3.46`. First setup requires network access to the image/package registries and adequate disk space. The recipe supports ARM64 and AMD64; the recorded real-desktop acceptance was run on ARM64.

The root filesystem is read-only. Runtime directories use tmpfs; `/home/cua` uses an anonymous persistent volume. The default policy drops capabilities before explicitly restoring the small set needed by startup, enables no-new-privileges and limits process count. CPU and memory limits are optional. A configured workspace bind mount intentionally exposes that host directory to the guest.

This is Docker container isolation. The built-in Chromium disables its own inner sandbox to work with this container policy. Neither a microVM boundary nor isolation between applications inside the same guest is claimed.

The host publishes container port 8000 on an ephemeral loopback port. Each container receives a private token; every HTTP/WebSocket request requires `X-Cognia-Sandbox-Token`, and browser-origin requests are rejected. The native host recovers the token from Docker metadata. It is not sent to the renderer, guest applications or command environments. The server runs in the protected startup process so same-user guest processes cannot inspect its credential memory or environment.

Image identity and container policy are checked during adoption. An old unauthenticated or unattested image is rejected; it is not silently admitted with weaker checks. Preserve required files before deleting an old container to recreate it.

## Desktop observation and control

`SandboxDesktopViewer` refreshes authenticated screenshots at approximately 1 Hz. It is a screenshot viewer with keyboard/pointer control, not a video/audio stream. PNG/JPEG frames must decode completely within the image budget before they can create observation tokens.

The viewer starts read-only. Explicit takeover obtains an expiring control lease and blocks agent GUI mutations and shell execution. Keyboard chords, text/IME input, click, drag, double-click and wheel input use that lease. Closing the view, hiding the document, blur, capture failure and lease expiry release local control. A late lease response is also released instead of leaving an invisible controller.

Remote app sessions expose one exact application identity, `cognia.sandbox.desktop:<connectionId>`, representing the whole guest desktop. Observations, revisions and action tokens belong to that connection. Unsupported application/window/semantic accessibility operations fail instead of falling back to the host desktop. The pinned Linux server does not provide a usable semantic accessibility tree.

## Binary file transfer

The file-transfer panel handles one regular file at a time, up to **8 MiB**, including empty files and non-UTF-8 data. Upload selection is read in bounded chunks. Downloads validate decoded size and SHA-256 before opening the shared save workflow. The ordinary agent text-file interface remains separate and retains its smaller transport limit.

An upload targets an absolute guest path whose parent directory already exists. It never overwrites an existing destination. The guest helper rejects symlink traversal and uses an unnamed temporary file followed by atomic publication. If the filesystem does not support this mechanism, upload fails explicitly; no weaker named-partial-file fallback is used. Downloads reject symlinks, directories, FIFOs and devices.

Every transfer carries both the connection ID and the exact expected container ID. Inspection, identity checks and the transfer run under the connection lock, so replacement or lifecycle changes cannot redirect an operation to a different guest. Downloads can run while a human owns desktop control. Uploads release the viewer's prior lease, acquire a fresh lease after file selection, and recheck it immediately before dispatch. They invalidate old observation tokens and hold the mutation lock until execution finishes.

The save workflow checks that its initiating view is still current after the native save dialog and before writing. Closing or changing the target prevents later frontend steps; it does not claim to undo a backend mutation already dispatched. Known failures such as an existing destination allow retry. Unconfirmed process cleanup quarantines the connection until cleanup or a confirmed stop.

## Lifecycle and recovery

| Action | Behavior |
| --- | --- |
| Provision | Creates a retained container without starting it; adopts a compatible existing one. |
| Start | Starts or adopts the selected container and waits for authenticated capture readiness. |
| Suspend / resume | Uses Docker pause/unpause; memory remains resident. This is not a persistent snapshot. |
| Stop | Ends guest processes but keeps the container and its home volume. |
| Delete | Requires confirmation, removes the container and anonymous home volume; bind-mounted host files remain. |
| Check health | Inspects Docker state and checks supervised execution plus decoded desktop capture. Verified identity repairs missing placement; confirmed absence clears stale placement. |

App exit disconnects cached driver clients and releases local sessions; containers remain available for later adoption. A cold registry reconnects to a retained running guest. Start/resume readiness is bounded to 60 seconds; cold reconnect is bounded to 30 seconds.

File reads, transfers, desktop mutations and lifecycle changes coordinate through the same per-connection lock. A cancelled or unacknowledged mutation stays quarantined until its process cleanup is known or the container is confirmed stopped. A failed delete keeps the saved connection so teardown can be retried. Completing an old request after switching connections cannot close or update the newly selected detail view.

## Execution and transport

`lifecycle_execution.rs` and the embedded `exec_supervisor.py` provide bounded output collection, an absolute timeout, a renewable caller lease and descendant cleanup. Killing the host's `docker exec` process alone is not treated as proof that the guest command ended. Timeout is reported as completed only when cleanup is acknowledged. Generic execution retains its 1 MiB stream/input budgets; binary transfers use a separate bounded transport budget.

The execution bootstrap uses trusted absolute Python paths. Caller environment variables cannot replace its interpreter, inspect its protected framing process or inherit the desktop token. The WebSocket client serializes requests through a bounded queue; deadlines include queue time, and timed-out connections are closed to prevent mismatched late replies.

## Implementation map and verification

- `lib/sandbox/`: provider capabilities, lifecycle dispatch and runtime binding.
- `hooks/automation/use-sandbox-connections.ts`: persisted state, health reconciliation and retry ownership.
- `components/settings/automation/`: connection detail, viewer, transfer and deletion UI.
- `lib/automation/sandbox-client.ts`: typed client-local IPC.
- `crates/cognia-automation/src/cua_sandbox/`: image lifecycle, registry, desktop sessions, supervisor, file transfer and authenticated driver client.
- `src-tauri/src/lib.rs`, `protocol/companion-commands.json`: command registration and internal-only transport classification.

The current implementation extends ADR-0020 with retained lifecycle, authenticated remote sessions and file transfer. Earlier examples describing `ghcr.io/trycua/cua-xfce:latest`, unauthenticated WebSockets, or timeout that only kills the host CLI no longer describe this path.

Focused tests cover UI races, target binding, protocol boundaries and process cleanup. The opt-in `live_builtin_desktop_authenticated_lifecycle_and_real_input` test uses a disposable real guest for desktop input, binary round trips, no-overwrite behavior, pause/resume, cold reconnect and persistent restart. Mock/component tests are not native Tauri-window, installer or cloud-provider acceptance. The implementation report is `docs/plans/2026-10-03-sandbox-virtual-computer.md`.
