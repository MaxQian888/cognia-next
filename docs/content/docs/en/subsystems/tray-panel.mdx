# Tray Panel

<Status variant="beta">Beta · desktop · ADR-0225 phases 1–2</Status>

<TLDR>
  Left-clicking the tray icon opens a small always-on-top window: a header with the workspace scope
  and an overall status pill, a single column of **glance modules**, a pinned **delegate bar**, and a
  footer. The panel owns no data and runs nothing itself. The main window builds a content-free
  `GlanceSnapshotV1` while a panel holds a lease on it, and executes the panel's requests. Every
  module summarizes a subsystem and routes to it; the subsystem keeps its controls. Agent Fleet's
  approvals and per-task stop stay on the Island.
</TLDR>

## Layout

| Region       | What it holds                                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------------------------------- |
| Header       | Title, scope switch (all / current workspace), status pill (automation › awaiting › running › idle), refresh, settings, close |
| Glance stack | The visible modules of the stored layout, in order. Scrolls once the panel reaches its max height                     |
| Delegate bar | The primary tray action as one growing line, its other fields in an options menu                                    |
| Footer       | Edit, the preset switch, Open Cognia, and how fresh the snapshot is ("Updated 12s ago" / "Connecting…")             |
| Resize grip  | Drag, or ↑ / ↓ in 40 px steps, to set the max height (240–860 px)                                                   |

The window hugs its content: a `ResizeObserver` fits the native window to the card, never moving
its top-left. Sections are separated by hairlines inside one container, not boxed as cards.

## Modules

Every module is registered in `lib/glance/registry.ts` with its sizes, its snapshot slice and the
owner surface it routes to. A size a module does not support degrades to the nearest one it does.

| Module     | Sizes                         | Shows                                                                                       | Routes to                                    |
| ---------- | ----------------------------- | ------------------------------------------------------------------------------------------- | -------------------------------------------- |
| `fleet`    | compact · standard · expanded | Working / awaiting / failed counts and the top rows. **Read-only**                          | The Island, focused on the clicked row       |
| `usage`    | compact · standard · expanded | Tokens today / 7 days / 30 days, turns or spend, budget meter, provider shares              | Settings › Subscription › Usage              |
| `quota`    | compact · standard · expanded | Each credentialed source's windows as "used %", with ok / warn / exhausted / error / stale | Settings › Subscription                      |
| `agenda`   | compact · standard            | Next scheduled run, last outcome, unread notifications, connectivity                        | Scheduler item, notification center, devices |
| `activity` | compact · standard · expanded | Daily heatmap over 1 / 3 / 12 months, streaks, peak hour                                    | Settings › Subscription › Usage              |
| `quick`    | compact · standard            | The user's tray actions other than the primary (desktop host only)                         | Settings › Desktop to edit them              |
| `recents`  | compact · standard            | The last few conversations                                                                  | That conversation                            |
| `pet`      | compact · standard            | Pet needs, and feed / play / pet / sleep / clean                                            | The pet page                                 |

Presets (`balanced`, `usage-first`, `agent-ops`, `minimal`) live in `lib/glance/presets.ts`.
`normalizeGlancePanelSettings` is the only reader of stored layouts: unknown ids drop, duplicates
keep the first, missing modules are appended hidden, out-of-range heights clamp.

## Editing

The footer's **Edit** swaps the stack for the layout editor in place: drag a module by its grip (or
Space, then ↑ / ↓) to reorder it, pick its size, hide it, or add a hidden one back. Two panel-only
switches sit under the list: the delegate bar and the width step. Escape or **Done** leaves edit
mode; the panel stays open. Every edit is shown at once and sent as a request
(`set-layout`, `set-delegate-visible`, `set-width`); a failed request drops the panel back to the
stored layout and says why.

Any edit makes the layout **Custom**. The preset switch beside Edit resets the modules, their order
and sizes to a built-in preset (`apply-preset`) and leaves width, height, scope and module options
alone. Hiding the delegate bar moves the primary action into the quick actions, so it stays one
click away.

The editor is `components/glance/glance-layout-editor.tsx`, and every edit it can make is a pure
function in `lib/glance/layout-edit.ts`, shared with the settings editor.

## Data flow

```
tray-panel window                         main window
─────────────────                         ───────────
useGlanceConsumer ── glance://subscribe ──▶ GlanceSubscriptionRegistry (lease, TTL 60s)
   (renew every 20s while visible)                │
                                                  ▼
                                          useGlanceSources(active)
                                          builds only the visible slices
                    ◀── glance://snapshot ── GlancePublisherInitializer (debounced 120 ms)
send(request) ───── glance://request ────▶ executeGlanceRequest
                    ◀── glance://result ───
```

- **Leases.** A hidden panel ends its lease; an expired lease is pruned every 10 s. With no live
  lease the publisher computes nothing.
- **Ordering.** Snapshots carry an `epoch` (per publisher boot) and a `revision`; consumers keep only
  newer ones.
- **Content-free.** Slices carry counts, labels and ids, never prompt text, questions or
  permission payloads. Names are redacted and truncated before they leave the main window.
- **Action catalogue.** The quick actions and the delegate bar come from the snapshot too
  (`actions`), resolved from `AppSettings.trayPanelActions`. Until the first snapshot lands the quick
  actions say they are loading and the delegate bar is absent. `open`-triggered actions run once per
  reveal, on the first snapshot that arrives after it, so they always use the current catalogue.
- **Requests.** `parseGlanceRequest` validates every request strictly. Routes close the panel once
  the main window took them; light requests (scope, usage scope, spend, activity range, size,
  quota refresh / enable, pet care) keep it open. A request with no answer resolves to a timeout
  after 15 s, so no spinner hangs.

## Ownership rules

- The panel never runs a tray action itself. Native actions go to Rust; the rest go to the main
  window over `tray-panel://run`, exactly as before.
- Fleet is a summary. Clicking a row calls `requestIslandFocus`, which opens the Island (parking the
  focus until it mounts) and pins that row so its approvals and answers are on screen.
- "Show notifications" opens the status-bar notification center (`requestNotificationCenter`),
  falling back to Settings › Notifications when no bell is mounted.
- Quota readings come from the `providerLimits` table in the main window. A login discovered on disk
  routes to Settings › Subscription to be adopted; a disabled vault account can be turned on inline.
- ADR-0165 opt-ins hold: spend is hidden until the user shows it, and the all-tools usage scope asks
  for consent first. Quota and other account-wide figures are never filtered by workspace.

## Settings

Settings › Desktop › Tray panel holds the full editor:

- **Modules**: the same layout editor as edit mode, the preset switch, the delegate bar switch, and a
  live preview beside them. The preview renders the real modules over this window's own data at the
  configured width and max height. It is built passively (no quota refresh, no login discovery) and
  is `inert`, a picture rather than a second panel.
- **Panel layout**: width step (320 / 380 / 460 px), max height, default scope, and whether the
  delegate bar takes focus on open.
- **Actions**: the action catalogue editor.

The layout is `AppSettings.trayPanelLayout` and the catalogue `AppSettings.trayPanelActions`, both in
sync category `desktop-only`, so they are backed up and account-synced without a Dexie migration, and
an open panel repaints from the next snapshot.

### Migration

Before ADR-0225 the catalogue lived in the Tauri store under `trayPanel.actions.v1`, because the
panel window read it directly. `TrayPanelInitializer` imports it once into settings when settings
have loaded (never after a failed load) and deletes the pref only after the save landed, so an
interrupted import runs again. If settings already hold a catalogue (synced from another desktop),
settings win and the pref is dropped. `resolveTrayPanelActions` (`lib/tray-panel/catalogue.ts`)
repairs whatever it reads: malformed or duplicate entries are dropped, retired native effects
rewritten, and built-ins a newer build added folded back in.
