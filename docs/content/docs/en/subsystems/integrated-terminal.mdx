# Integrated Terminal

<Status variant="stable">Stable · ADR-0031 → 0033</Status>

<TLDR>
  The terminal is a real PTY, not an emulator over a command runner. Which pipe carries it is decided by
  `selectTerminalTransport()` (`lib/terminal/pick-transport.ts:31`): a Tauri desktop gets the in-process
  `tauri-channel`, Capacitor mobile gets `ws` over LAN/mDNS, and a desktop driving a remote Cognia host
  retargets to the host's `/ws/v1/terminal`. Prompt boundaries, exit codes and cwd changes come from
  **OSC 633** shell-integration sequences parsed in Rust (`crates/cognia-terminal/src/osc633.rs`), which
  validates a per-spawn nonce so a hostile process inside the terminal can't fabricate prompt decorations.
  Agents get their own door — `headless-exec` plus a per-tab trust gate (`lib/terminal/agent-trust.ts`).
</TLDR>

## Transport selection

```ts
type TerminalTransportKind = "tauri-channel" | "ws" | "webrtc" | "unsupported"
```

Two entry points, deliberately separate. `selectTerminalTransport()` returns the single highest-priority
transport for callers that don't want fallback logic — the dock's "+ New" button on desktop.
`selectTerminalTransportChain()` returns an ordered list the spawn orchestrator walks, trying the next
transport when the previous one returned `null` or threw.

| Shell | Transport | Notes |
| --- | --- | --- |
| Tauri desktop | `tauri-channel` | in-process PTY, no remote ambiguity |
| Desktop → remote host | `ws` | targets the host's `/ws/v1/terminal` ([ADR-0082](../adr/0082-remote-development-remote-host)); inert until a remote host is activated, so a plain desktop is unaffected |
| Capacitor mobile | `ws` | LAN / mDNS |
| Browser | `unsupported` | the chain returns `[]` and the dock does not mount |

`webrtc` is declared in the union but is **planned, not wired** — the chain extends to `["ws", "webrtc"]`
once the Rust desktop peer and the TS client are connected through the rendezvous. `terminalAvailable()`
(`lib/terminal/pick-transport.ts:66`) is what components use to decide whether to mount the dock at all.

## Shell integration is nonce-validated

VS Code's `ESC ] 633 ; <C> ; <args> BEL` family is what turns a dumb byte stream into a structured session:
prompt boundaries, command pre/post-exec, and cwd changes. PTY output streams through
`Osc633Parser::feed`, which yields the raw bytes back **unchanged** — the terminal still needs them in
scrollback for fonts and colours — and separately surfaces a typed `IntegrationEvent` when a complete
sequence is recognised.

The security property is the per-spawn nonce stamped into `$COGNIA_TERM_NONCE`. The parser validates it, so
a hostile process running *inside* the terminal cannot emit its own OSC 633 sequences to fake prompt
decorations. Unrecognised sequences are dropped rather than guessed at.

## Sharing a session with a paired device

A hosted session can be watched — or driven — from a paired phone or another Cognia
([ADR-0133](../adr/0133-terminal-session-sharing)). There is no share link and no second transport:
the device attaches to the same durable host over the companion `ws`/WebRTC adapters and takes part
in the host's **controller lease** — one controller at a time, everyone else read-only, "Take
control" / "Release control" from the session chip. The dock's **Share** button (desktop host only)
opens a dialog with the host's live participant roster and a switch per paired device for its
remote-terminal grant; the grant is device-wide (every terminal on the host), and removing it drops a
live attachment within a second because the adapters recheck it continuously. The host re-broadcasts
the session snapshot whenever a client attaches, detaches, or the lease moves, so the chip
("Shared with N devices") and the dialog update without polling. `lib/terminal/collaboration/roster.ts`
is the pure renderer-side projection of that roster.

## Agents don't get a free shell

An agent reaching the terminal passes two gates. `headless-exec.ts` is a separate, non-interactive surface
with its own registry (`headless-session-registry.ts`), so an agent run never silently inherits an
interactive tab. To drive an *interactive* tab it must first clear `requestAgentTrust()`
(`lib/terminal/agent-trust.ts:50`), which is keyed per chat session **and** per tab —
`agentTrustPluginId(chatSessionId, tabId)` — so trust granted in one tab does not leak into another.
`isAgentTrusted()` is the read side of that gate.
