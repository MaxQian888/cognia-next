# Authoring and SDK

Authors declare only `manifest.ide`:

```ts
ide: {
  schemaVersion: 1,
  targets: ["monaco", "pro-ide"],
  requirements: {
    codeApiVersion: "1.128.0",
    brokerProtocol: "^1.0.0"
  },
  contributions: {},
  providers: [],
  executables: [],
  protocols: { lsp: [], dap: [], mcp: [] },
  agents: []
}
```

The generator locks the live Code 1.128 extension schema and every referenced
schema in `packages/plugin-sdk/contract/code-1.128-contribution-schemas.json`.
Exact upstream digests and provenance are checked before generation. The
resulting `code-1.128-ide.json` catalog hash is part of broker negotiation and
proxy activation. The generated public JSON Schema is self-contained and has
no external references.

The build emits TypeScript types/helpers, JSON Schema, normalized
engine-neutral IR, exhaustive conformance fixtures, and proxy contribution
metadata. An unclassified stable contribution or provider fails generation.
Legacy `vscode*` author fields are normalized with field-level deprecation
diagnostics for one major; generated SDK output uses only `manifest.ide`.

Global IDs are rewritten to `cognia.<pluginId>.*`. Language model tools are
the exception: VS Code drops a tool whose name does not match `/^[\w-]+$/`, so
a tool named `inspect` becomes `cognia_<pluginId>_inspect` (dots in the plugin
id become `_`). A tool name may contain only letters, digits, `_` and `-`, and
must stay within 64 characters once namespaced, the limit model APIs put on
function names. Duplicate, reserved, or externally occupied IDs reject the
entire activation transaction. Static
assets are canonical plugin-relative files. A plugin cannot provide an
extension entrypoint.

Proxy VSIX output is deterministic and content-addressed. Its Ed25519-signed
descriptor binds plugin id/version, manifest hash, platform version, catalog
hash, executable resource hashes, and VSIX digest. `codeserver_build_proxy`
only stages the artifact; `codeserver_activate_proxy` promotes it after a live
handshake. The activation marker, not the artifact cache, is authoritative on
restart.

Stable provider coverage includes language features and virtual filesystems;
views, trees, status, decorations, webviews and custom editors; terminals,
tasks, SCM, debug, tests, notebooks and comments; authentication, URI handling
and storage; Chat participants, language-model tools, MCP definitions, and the
stable contribution families in the locked catalog.

## Provider handlers

Every provider names an exported `handler` of the plugin's single Cognia
runtime. The broker calls it as `handler(operation, ...args)`: the operation
first, then the VS Code arguments serialized to JSON (a `Uri` as its
components, a `TextDocument` as `{ uri, languageId, version, isDirty }`, bytes
as a content handle). Answers come back the same way and the broker turns them
into VS Code values.

| Family | Operations |
| --- | --- |
| Language features (hover, completion, code lens, links, inlay hints, …) | `provide`, and `resolve` where VS Code resolves lazily |
| `call-hierarchy` / `type-hierarchy` | `prepare`, then `incoming`/`outgoing` or `supertypes`/`subtypes` |
| `source-control` | `initialize`; `status` returns `{ groups: [{ id, label, resources: [{ uri, tooltip }] }] }`; `originalResource` gives the quick-diff base; `commit` receives the input box text |
| `test-controller` | `resolve` (no item: the root tests) and `run` with `{ profile, include, exclude }`; return `{ results: [{ id, state, message?, durationMs? }], output? }`, and every included test the run does not mention settles as skipped |
| `notebook-serializer` | `deserialize` (bytes) returns `{ cells }`; `serialize` receives `{ cells }` and returns the file's text |
| `notebook-controller` | `execute` per cell returns `{ outputs: [{ items: [{ mime, text }] }] }`; `interrupt` |
| `webview-view` / `custom-editor` | `resolve` returns `{ html }`, which must carry a Content-Security-Policy; `message` for posts from the page |
| `chat-participant` | `request` returns `{ stream: [{ method, arguments }], result }` |
| `language-model-chat-provider` | `provideLanguageModelChatInformation`, `provideLanguageModelChatResponse` (messages arrive as `{ role, name?, content: [typed parts] }`; answer with `{ stream: [{ $type: "LanguageModelTextPart", value }] }`), `provideTokenCount` |
| `language-model-tool` | `prepare`, `invoke` returning `{ content: [typed parts] }` |
| `file-system` | `stat`, `readDirectory`, `readFile`, `writeFile`, `createDirectory`, `delete`, `rename`, `copy` |

A selector or a language server that names one of the plugin's own languages
is pointed at its namespaced id; a built-in id such as `typescript` is kept.
A language server gets exactly the VS Code features it claims in its
`initialize` capabilities, with its own trigger characters.

`plugins/pro-ide-fixture` declares one provider of every family above and is
the reference for these shapes. `pnpm test:pro-ide:e2e` drives it through a
real code-server, and `pnpm audit:pro-ide-perf` checks that run against the
performance gates.
