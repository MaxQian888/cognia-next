# MCP Server (Tauri Side)

<Status variant="stable">M3 Delivered · axum + bearer auth</Status>

<TLDR>
`src-tauri/src/mcp_server/` is the HTTP transport implementation for External Bridge: axum listens on `127.0.0.1:<port>`, bearer tokens are compared in constant time using the `subtle` crate to prevent timing attacks, and after authentication JSON-RPC requests are fed line-by-line to a long-lived Node sidecar (`node cognia-mcp.js`), with responses read line-by-line and written back. The entire pipeline is sequential (a single mutex serializes stdin/stdout), isomorphic to the MCP SDK's `StdioServerTransport`. Four Tauri commands — `mcp_server_start`, `stop`, `restart`, and `status` — expose the lifecycle to the React frontend. HTTP body is limited to 1 MiB, `/healthz` requires no authentication, and `/mcp/sse` returns 501 in Phase 1 (SSE deferred to Phase 2).
</TLDR>

## When to Use

- External coding agents (Cursor, Claude Desktop, custom HTTP clients) accessing Cognia knowledge over HTTP instead of stdio.
- Multiple agents connected to Cognia simultaneously — HTTP mode lets a single Cognia instance serve multiple clients (sidecar is serial, but the HTTP layer accepts connections concurrently).
- When you need an explicit "network reachability" switch beyond token and scope — users can disable the HTTP service to cut off traffic.

## When Not to Use

- Cross-machine access — binds to `127.0.0.1` only; no TLS, no cross-host authorization.
- Running in web mode — the Tauri Rust process does not exist; web users must use stdio with an external sidecar package.
- Do not call `lib/external-bridge/mcp-server/server.ts` directly — inside the Rust process, only the sidecar can run TypeScript handlers.

## Control Flow

### Startup (`mcp_server_start`)

<Steps>
<Step>Frontend React clicks Start in Settings → calls `tauri-control.ts:startMcpServer({ port, token, settings, sidecarPath })`.</Step>
<Step>Tauri routes to `commands.rs:mcp_server_start`, passing `State<McpServerState>` and four parameters.</Step>
<Step>`McpServerState.start` guard: empty token → `TokenMissing`; `settings_json` parse failure → `InvalidSettings`; already running → `AlreadyRunning(port)`.</Step>
<Step>`SidecarProcess::spawn(sidecar_path, settings_json)` launches `node <path>`, setting env:<br/>  • `COGNIA_BRIDGED=1`<br/>  • `COGNIA_BRIDGE_SETTINGS=<JSON>`<br/>Uses `kill_on_drop(true)` to ensure the child process is killed on Drop.</Step>
<Step>`spawn_server(port, token, sidecar)` binds `127.0.0.1:<port>` (`0` lets the OS choose), builds the axum router, and `tokio::spawn`s the listener task. Returns `ServerHandle { bound_port, shutdown: watch::Sender }`.</Step>
<Step>Stores `(handle, sidecar)` in `McpServerInner.server`, updates `status` to `running: true, port: bound_port, started_at`, and returns `bound_port` to TS.</Step>
</Steps>

### A Single `/mcp` Request

<Steps>
<Step>External agent sends `POST /mcp` + `Authorization: Bearer <token>`.</Step>
<Step>`RequestBodyLimitLayer(1 MiB)` wraps the outer layer.</Step>
<Step>`auth_middleware`: `/healthz` is bypassed; for all other paths, extracts `Bearer …` from the header and compares against `state.token` using `subtle::ConstantTimeEq`. Mismatched length returns 401 immediately; content comparison is constant-time.</Step>
<Step>After auth, handler `mcp_post` converts the body to a UTF-8 string; empty body → 400.</Step>
<Step>`state.sidecar.round_trip(&request_str)` — acquires the `Mutex<SidecarIo>` lock, writes `stdin.write_all(line + "\n")` + `flush()`, then `stdout.read_line` reads one line. Empty response means the sidecar has exited → `SidecarIo`.</Step>
<Step>The response string is parsed with `serde_json::from_str` as `Value` and forwarded transparently to the client (avoids field loss from double-serialization when the SDK adds extension fields). Sidecar failure → 502 Bad Gateway.</Step>
</Steps>

### Stop (`mcp_server_stop`)

<Steps>
<Step>`McpServerState.stop` acquires the inner lock, and `Option::take` removes `(handle, _sidecar)`.</Step>
<Step>`handle.shutdown.send(())` notifies the axum graceful shutdown future; the listener task finishes processing in-flight requests before exiting.</Step>
<Step>`_sidecar: Arc<SidecarProcess>` goes out of scope → `kill_on_drop` triggers → Node child process is killed.</Step>
<Step>`status` is reset to `McpServerStatus::default()` (`running: false`).</Step>
</Steps>

`restart` = fault-tolerant `stop` + `start`, performed atomically; the frontend does not need to race two IPC calls itself.

## Sidecar Process Model

### Option A: Long-Lived + Serial

The design comment in `sidecar.rs` explicitly chose the "persistent sidecar + mutex" pattern, neither "spawn once per request" nor "multi-process multiplexing":

```rust title="src-tauri/src/mcp_server/sidecar.rs"
pub struct SidecarProcess {
    request_lock: Arc<Mutex<SidecarIo>>,
    /// Kept alive so `kill_on_drop` fires when we are dropped.
    _child: Child,
}
```

Rationale:

- The MCP SDK's `StdioServerTransport` is inherently sequential; multiplexing yields zero benefit.
- A single mutex prevents byte interleaving on stdin/stdout from two concurrent axum handlers.
- Long-lived lifetime means the Node V8 engine, handler modules, and Dexie adapter are initialized only once, keeping p50 latency stable.

### Child Process Environment

| Variable                 | Source                       | Purpose                                                  |
| ------------------------ | ---------------------------- | -------------------------------------------------------- |
| `COGNIA_BRIDGED`         | Fixed `"1"`                  | `standalone-entry.ts` uses this to select bridged mode   |
| `COGNIA_BRIDGE_SETTINGS` | JSON from `mcp_server_start` | Injected once; changing scope requires a service restart |

Note: stderr uses `Stdio::inherit()`, so sidecar `console.error` output flows directly into the Tauri main log.

### Test Hook

`sidecar.rs:spawn_echo_for_tests` spawns an inline node `-e "..."` that echoes stdin → stdout line-by-line, used for integration tests in `http_server.rs` and `mod.rs`. When Node is unavailable, tests return early with a skip — CI does not hard-depend on Node.

## HTTP Endpoints

| Method | Path       | Auth   | Behavior                                                                               |
| ------ | ---------- | ------ | -------------------------------------------------------------------------------------- |
| GET    | `/healthz` | None   | `{ "ok": true, "version": "<CARGO_PKG_VERSION>" }`                                     |
| POST   | `/mcp`     | Bearer | One line of JSON-RPC in, one line of JSON-RPC out                                      |
| POST   | `/mcp/sse` | Bearer | Phase 1 placeholder → 501 + `{ error: "SSE streaming is not implemented in Phase 1" }` |

```rust title="src-tauri/src/mcp_server/http_server.rs"
const BODY_LIMIT_BYTES: usize = 1024 * 1024;   // 1 MiB

let app = Router::new()
    .route("/healthz", get(healthz))
    .route("/mcp", post(mcp_post))
    .route("/mcp/sse", post(mcp_sse))
    .layer(from_fn_with_state(state.clone(), auth_middleware))
    .layer(RequestBodyLimitLayer::new(BODY_LIMIT_BYTES))
    .with_state(state);
```

## Error Model

`McpServerError` is derived with `thiserror`, serialized as a single string for easy React toast consumption.

| Variant                   | Meaning                                                          |
| ------------------------- | ---------------------------------------------------------------- |
| `AlreadyRunning(port)`    | A service is already running on the given port                   |
| `NotRunning`              | Service is not running when `stop` or `status` is called         |
| `Bind { port, source }`   | TCP bind failure (port in use, insufficient permissions)         |
| `InvalidSettings(reason)` | `settings_json` is not valid `ExternalBridgeSettings`            |
| `TokenMissing`            | Token is an empty string                                         |
| `SidecarSpawn(reason)`    | Failed to spawn `node <path>` (node not in PATH, script missing) |
| `SidecarIo(reason)`       | stdin/stdout read/write failure, or sidecar abnormal exit        |

## Security Considerations

- **Binding surface**: `127.0.0.1` only, no TLS. Phase 1 assumes the attacker can already run code on the user's machine; it does not protect against sniffing by other local processes (OS-level namespace isolation requires capabilities system support).
- **Bearer token**: 32-byte random hex (64 characters), compared with `subtle::ConstantTimeEq` to prevent timing attacks. The token is generated on the frontend with `crypto.getRandomValues` and stored in IndexedDB in plaintext. Token rotation is done via service restart + settings change.
- **Body limit**: 1 MiB (MCP envelopes may be larger than remote-control's 8 KiB; tests include `assert!(BODY_LIMIT_BYTES > 8 * 1024)` as a self-check).
- **CSRF**: MCP is JSON-RPC over POST with an Authorization header; no form replay risk exists.
- **DoS**: Sidecar is serial → a single slow request blocks subsequent ones; axum body limit + handler timeout (determined by the sidecar internally) are the main safeguards.

## Known Limitations / Open Issues

- **SSE not implemented**: `POST /mcp/sse` returns 501; clients can only use single-request-single-response. The MCP SDK already supports SSE; Phase 2 will wire it up.
- **Missing IP allowlist**: All local processes can access; additional netns isolation is needed for Linux containerized deployments.
- **Sidecar restart policy**: Currently, if the sidecar crashes, HTTP still accepts connections but `round_trip` returns `SidecarIo` errors; automatic restart is left for a future version.
- **Token persistence**: Stored in plaintext in IndexedDB. Planned migration to OS keyring once the bridge supports remote access (see the `keyring` crate usage in `lib/anthropic-subscription` for reference).
- **Cross-platform sidecar path**: Currently `external-bridge-section.tsx` falls back to `homeDir/.cognia/cognia-mcp.js`; Phase 2 npm plugin packaging will switch to a resource path under the Cognia installation directory.
- **Multiple sidecars**: Currently one HTTP service maps to one sidecar. To expose Cognia to multiple isolated scope sets (e.g., "read-only wiki" and "read + twin" clients simultaneously), a sidecar pool or multi-server refactor is needed.
- **Test coverage**: Integration tests require `node` on PATH; when Node is missing in CI, all round-trip tests early-return. Unit tests mock `subtle::ConstantTimeEq` to cover the auth branch.
