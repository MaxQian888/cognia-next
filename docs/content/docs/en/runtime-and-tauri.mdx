# Runtime model & Tauri integration

Cognia ships a single React codebase that runs in two modes:

- **Web mode** — `pnpm dev` opens the app at [http://localhost:3000](http://localhost:3000) in your browser.
- **Desktop mode** — `pnpm tauri dev` opens it inside a Tauri webview with full OS access.

Most components work identically in both modes. The few that don't go through `lib/tauri.ts`.

## The `isTauri()` gate

```ts
// lib/tauri.ts
export function isTauri(): boolean {
  return typeof window !== "undefined" && "__TAURI_INTERNALS__" in window
}
```

Use it to guard any code path that calls a Rust command:

```tsx
import { isTauri, openExternal } from "@/lib/tauri"

function ExternalLink({ href, children }: Props) {
  if (isTauri()) {
    return <button onClick={() => openExternal(href)}>{children}</button>
  }
  return <a href={href} target="_blank" rel="noreferrer">{children}</a>
}
```

In SSR (Next.js server components), `isTauri()` always returns `false` because `window` is undefined. Wrap Tauri-dependent UI in a client component (`"use client"`).

## The single-invoke rule

**Only `lib/tauri.ts` and its sub-modules under `lib/tauri/` may call `invoke()`.** Every Rust command gets a typed wrapper:

```ts
// lib/tauri.ts
export async function greet(name: string): Promise<string> {
  return invoke<string>("greet", { name })
}
```

Why this rule:

- One place to add request validation, error mapping, and telemetry.
- Business code stays portable — easy to mock in tests.
- Refactors of the Rust API only touch `lib/tauri.ts`.

If you find a stray `invoke()` outside this folder during code review, move it.

## Adding a new IPC command

<Steps>
  <Step>
    ### Define the command in Rust

    Add it to `src-tauri/src/commands.rs` (or a domain-specific module like `src-tauri/src/scheduler/commands.rs`):

    ```rust
    #[tauri::command]
    pub async fn my_command(arg: String) -> Result<String, String> {
        Ok(format!("got {arg}"))
    }
    ```

    <Callout type="info" title="Conventions">
      - Return `Result<T, E>` so Tauri serialises errors as a string the JS side can `catch`.
      - Use `String` not `&str` for arguments — Tauri owns its own buffers.
      - For long-running work, take `tauri::Window` and emit progress events.
    </Callout>
  </Step>
  <Step>
    ### Register it in `lib.rs`

    ```rust
    .invoke_handler(tauri::generate_handler![
        commands::greet,
        commands::my_command,
        // ...
    ])
    ```
  </Step>
  <Step>
    ### Add a typed wrapper in `lib/tauri.ts`

    ```ts
    export async function myCommand(arg: string): Promise<string> {
      return invoke<string>("my_command", { arg })
    }
    ```

    Or place it in a sub-module under `lib/tauri/` if the surface is large
    (e.g., everything scheduler-related lives in `lib/tauri/scheduler.ts`).
  </Step>
  <Step>
    ### Write the test

    <Tabs groupId="lang" persist items={["TypeScript", "Rust"]}>
      <Tab value="TypeScript">
        Sibling `lib/tauri.test.ts`. Mock `@tauri-apps/api/core`:

        ```ts
        jest.mock("@tauri-apps/api/core", () => ({
          invoke: jest.fn(),
        }))
        ```

        Then assert the wrapper passes the right command name + args.
      </Tab>
      <Tab value="Rust">
        Inline `#[cfg(test)] mod tests {}` block:

        ```rust
        #[cfg(test)]
        mod tests {
            use super::*;
            #[tokio::test]
            async fn handles_basic_input() {
                let r = my_command("hello".into()).await.unwrap();
                assert_eq!(r, "got hello");
            }
        }
        ```
      </Tab>
    </Tabs>
  </Step>
</Steps>

### About the bundle identifier

<Callout type="error" title="Don't rename without a migration">
  `identifier` is `com.reactquickstarter.desktop` — a legacy value carried over
  from the original starter. Tauri uses this string to derive the **per-user app
  data directory**. Changing it would orphan every existing installation's
  settings, vector store, and chat history.

  **For 99% of contributors, leave `identifier` alone.**
</Callout>

Tauri-derived per-user data directory by platform:

| Platform | Path |
| --- | --- |
| Windows | `%APPDATA%\com.reactquickstarter.desktop\` |
| macOS | `~/Library/Application Support/com.reactquickstarter.desktop/` |
| Linux | `~/.local/share/com.reactquickstarter.desktop/` |

If you must rename it, plan a migration:

<Steps>
  <Step>### Read from both old and new identifiers on first run</Step>
  <Step>### Copy data to the new path</Step>
  <Step>### Tag the migration in `settings` so it only runs once</Step>
</Steps>

### Content Security Policy

The CSP in `app.security.csp` controls what the webview is allowed to load. The shipped policy permits `'self'`, `wasm-unsafe-eval` (Monaco), `blob:` (workers + iframes), and inline styles (Tailwind).

When you add a feature that calls a new HTTPS origin from the browser (e.g., a model provider, telemetry endpoint, OAuth provider), add the origin to `connect-src`. Otherwise the request is blocked silently in production builds.

```jsonc
"csp": "... connect-src 'self' ipc: http://ipc.localhost ws: wss: https://api.example.com; ..."
```

### Window chrome

`decorations: false` + `titleBarStyle: "Overlay"` + `hiddenTitle: true` give Cognia a custom-drawn title bar. The drag region is set in CSS (`-webkit-app-region: drag`) and the close/min/max buttons are drawn in React (see `components/desktop/`).

## Tauri plugins in use

Registered in `src-tauri/src/lib.rs`. Each has corresponding `tauri-allowlist` entries in `src-tauri/capabilities/default.json` that limit what the JS side can do.

| Plugin | Used for |
| --- | --- |
| `single-instance` | Second launches focus the existing window and forward args (CLI workspace path, deep-link URL). |
| `deep-link` | Registers `cognia://` URL scheme. Mac/Linux receive URLs as launch args; Windows uses single-instance forwarding. |
| `autostart` | Optional "launch on login". Off by default. |
| `global-shortcut` | Registers system-wide shortcuts; user-configurable. |
| `cli` | Parses `--workspace <path>` and `-n` (new chat) flags from launch args. |
| `store` | Persists settings the Rust side cares about (the JS side uses Dexie). |
| `updater` | Disabled by default (see `src-tauri/UPDATER.md`). |
| `dialog`, `fs`, `notification`, `clipboard-manager`, `opener`, `os`, `process` | Standard OS access. |
| `log`, `window-state` | Logging, persistent window position/size. |

The first second-instance hook is set up **before** any other plugin, per Tauri docs:

```rust
builder = builder.plugin(tauri_plugin_single_instance::init(|app, args, cwd| {
    // focus existing window, forward args
}));
```

## Lifecycle and shutdown

`src-tauri/src/lib.rs` wires:

- **App ready** — initialise `SidecarState` (lazy, started on first `claude_send`), register hooks, schedule the readiness ping.
- **Window close** — kill the sidecar (`kill_sidecar`) before exiting so we don't orphan a Node process.
- **Single-instance second launch** — focus the existing window, forward `args` and `cwd`.

If you add a long-running native task, register it in `lib.rs` and clean it up on `RunEvent::ExitRequested`.

## Permission model

Cognia ships a **default-allow-list** stance (Tauri 2 capabilities). The capability files under `src-tauri/capabilities/` define which APIs are accessible from which window labels. The default policy:

- Only the `main` window has Tauri API access.
- Filesystem ops are scoped to specific roots (`$APPDATA`, `$DOWNLOADS`, …); raw paths are rejected.
- Shell exec is gated through `lib/native/local-runtime.ts` + `src-tauri/src/shell.rs`, which whitelists trusted workspaces (`lib/db/trusted-workspaces.ts`).

Plugins request additional capabilities through the plugin manifest (see [Plugin system](./plugin-system)).
