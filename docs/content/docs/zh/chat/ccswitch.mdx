# CCSwitch 互操作

Cognia 读取 **CC Switch v4.0.18、SQLite schema 21**。外部数据库始终只读。旧版或更新的 schema 会明确报错，不再猜测列名或返回看似成功的空数据。数据库升级由 CC Switch 自身完成，Cognia 不迁移外部数据库。

## 支持的数据

浏览当前全部 11 类应用：`claude`、`claude-desktop`、`codex`、`gemini`、`grokbuild`、`opencode`、`openclaw`、`hermes`、`pi`、`mcode`、`agy`。

| 数据 | 行为 |
| --- | --- |
| Providers | 解析当前各应用的凭据、端点及模型名称，包括 Codex TOML 和 OpenCode V2；身份使用 `(app_type, id)`。 |
| MCP servers | 读取 `server_config`，复用 Cognia 的跳过／覆盖／复制导入流程；仅含 URL 的配置默认使用 HTTP。 |
| Prompts | 保留应用身份，将选中内容导入为新的提示词预设。 |
| Skills | 读取已安装的 `SKILL.md`，解析 frontmatter 和可选的 `agents/openai.yaml`，同时持久化脚本、参考资料和资源。 |
| 额度元数据 | 将已识别的声明式模板导入为停用来源，等待检查；不执行 CC Switch JavaScript。 |

GrokBuild 的 `env_key` 仅以变量名返回，Cognia 不根据外部数据库中的任意名称读取环境变量。对于内置 Anthropic SDK，托管认证和其他协议的卡片仅供浏览。代理、终端启动器及 OAuth 账号管理仍由 CC Switch 负责。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `crates/cognia-ccswitch/src/db.rs` | 只读连接、精确 schema 校验、SQL 查询 |
| `crates/cognia-ccswitch/src/provider_config.rs` | 各应用 JSON／TOML 解析，不查找或执行凭据 |
| `crates/cognia-ccswitch/src/skill_files.rs` | 限定根目录的技能文件读取及文件限制 |
| `crates/cognia-ccswitch/src/types.rs` | 序列化数据类型 |
| `crates/cognia-ccswitch/src/paths.rs` | 数据库重定向及设备本地技能存储位置 |
| `crates/cognia-ccswitch/src/commands.rs` | Tauri 命令入口及已有的外部 agent 写入器 |
| `crates/cognia-ccswitch/src/watcher.rs` | 数据库／WAL／SHM 变化事件 |
| `lib/ccswitch/provider.ts` | 复合身份、SDK 兼容性、模型注册 |
| `lib/ccswitch/switch-plan.ts` | 设置及外部 agent 补丁的纯预览 |
| `lib/ccswitch/switch.ts` | 执行已确认的计划，分别记录外部 agent 结果 |
| `lib/ccswitch/subscription-switch.ts` | 激活 vault 账号或采用本地 Claude 登录 |
| `lib/ccswitch/active-provider.ts` | 只读凭据匹配与漂移判断 |
| `lib/ccswitch/client.ts`、`hooks.ts`、`import.ts` | IPC、共享监听生命周期及已有领域导入适配 |

Rust 测试与实现在同一文件的 `#[cfg(test)]` 模块中，TypeScript 测试也与源文件相邻。`schema-v21.sql` 来自上游版本标签中的建表定义，只用于测试，不是生产迁移。

## 路径及已安装技能

数据库按以下顺序定位：

1. Cognia 的测试／调试覆盖变量 `CC_SWITCH_HOME`。
2. Cognia 保存的 `ccswitchSync.manualDataDir`。
3. CC Switch 扁平 `app_paths.json` 中的 `app_config_dir_override`。
4. `~/.cc-switch/cc-switch.db`。

所有读取器及监听器都使用已保存的手动目录。技能默认位于数据库所在目录的 `skills/`。CC Switch 的设备本地 `~/.cc-switch/settings.json` 若选择 `skillStorageLocation: "unified"`，则读取 `~/.agents/skills/`。

技能路径必须位于选定根目录内。路径穿越、符号链接逃逸、特殊文件及超出共享原生读取器限制的包会被拒绝。限制为 50 个资源文件、每文件 2 MiB、32 层子目录及 500 个目录。不可读取的技能仍展示，但禁止导入，不会静默导入缺少资源的半个包。

## 明确确认的切换

对话框先预览变化，再执行。兼容的 Anthropic 卡片可以更新 Cognia 设置及 sidecar。没有 API key 的官方 Claude 卡片需要可用的 Anthropic 登录；激活失败时不应用切换。托管 OAuth 卡片不会仅因缺少 API key 而被误判为官方 Claude。

已有的外部 agent 写入器只在明确勾选并确认后执行。Claude 写入会先清理竞争的 `ANTHROPIC_AUTH_TOKEN`，再设置选定 API key。传播仅限 Claude Code 和 OpenCode 的 Anthropic 凭据项；Codex/Gemini 不是当前 Anthropic 切换的兼容目标。OpenCode 只修改凭据存储，不改写独立的端点配置，预览会提示这一限制；不能等同于 CC Switch 完整的各应用原生切换。

活动标记使用 `ccswitch:claude:default` 一类复合引用。凭据匹配会清理首尾空格及 URL 尾部斜杠，优先选择显式保存且匹配的身份，避免把其他应用类型误认成内置 SDK 当前供应商。

## 验证范围

针对性的 Jest 与 Rust 测试覆盖 schema 拒绝、11 类应用格式、数据库只读、复合身份、导入数据、监听所有权及激活失败。可以在隔离的本地数据快照上检查记录，不修改外部数据库。

旧原生进程加载新前端不能证明 Rust 读取器已生效。最终原生验收需要重建并重启 Cognia 桌面宿主，使用真正的 schema-21 CC Switch 数据库。不能仅凭计数认定 MCP 配置或技能正文可读。
