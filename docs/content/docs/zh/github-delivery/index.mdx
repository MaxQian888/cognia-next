# GitHub Delivery — 概览

## 它解决什么

cognia 已经有工作流、插件、调度器和连接器,但没办法直接在 GitHub 上做事:开 PR、
评审、合并、打 release —— 这些动作要么靠 GitHub Actions,要么手动操作。
GitHub Delivery 把这些操作搬进同一个可视化编辑器里,让用户可以:

- 在 PR 一开/一推时让 AI 写 review,并按置信度选 `APPROVE` / `COMMENT` / `REQUEST_CHANGES`。
- 在 Issue 一开时按 bug / feature / question 分类并自动打标签。
- 在 Issue 被 `cognia:claim` 标签触发后,克隆代码、跑 Claude Code、推分支、开 PR。
- 在每次合并主干后自动生成 Conventional Commits changelog,打 tag,发 release。
- 在 CI 失败时让 AI 解释失败原因,并把结论评论到对应 PR。

所有写操作都先经过 [policies](./policies) 门:CI 是否绿、是否有人审批、当日 merge 配额、
分支保护正则、作者白名单、安静时段。

## 关键概念

<Callout type="info">
  **核心层 vs 插件壳。** 所有"通用 GitHub 知识"(类型、Octokit 工厂、HMAC 验签、 Conventional Commits
  parser)放在 `lib/github/`。所有"运行时连接到当前 cognia 实例"的部分(Dexie 表读写、secrets
  API、连接器适配器)放在 `plugins/github-delivery/`。这样核心层可以被任何插件复用,插件壳可以被替换 /
  多实例。
</Callout>

### NormalizedGhEvent

webhook 和 polling 两条入口都被规范化为同一个 `NormalizedGhEvent`
(见 [`lib/github/types.ts`](https://github.com/) 第 161 行),
下游只面对一种形状。

```ts title="支持的 11 个事件类型"
type NormalizedGhEventKind =
  | "pull_request.opened"
  | "pull_request.synchronize"
  | "pull_request.closed"
  | "pull_request.review_requested"
  | "issues.opened"
  | "issues.closed"
  | "issues.assigned"
  | "issues.labeled"
  | "issue_comment.created"
  | "check_run.completed"
  | "release.published"
```

### guardedExecutor

13 个节点都是 `guardedExecutor` 的薄包装(见 `plugins/github-delivery/src/workflow/shared.ts`)。
统一处理:repo 解析、Octokit 获取、policy-gate 调用、HITL 审批分支、审计写入、错误回放。
作者只写 Octokit 请求本身。

```mermaid
flowchart LR
    P[step.params] --> R[resolve repoFullName]
    R --> A{action 非 null?}
    A -- 否 -- 只读 --> Run[run<br/>octokit.request]
    A -- 是 --> G[checkPolicy]
    G -- allow --> Run
    G -- deny<br/>needsApproval --> HITL[draft-bridge<br/>Inbox 草稿]
    HITL -- approve --> Run
    HITL -- reject --> Skip[output.skipped = true]
    G -- deny<br/>常规 --> Skip
    Run --> Audit[recordAudit]
    Audit --> Out[output]
```

### Dexie 命名空间

按 ADR-0011 + M0 的"插件 Dexie 表"约定,所有表存为 `github-delivery:<name>`。
插件代码通过 `ctx.dexie.table<T>(name)` 访问;外部代码(例如 `/github-delivery`
看板)直接以全名访问 `db.table("github-delivery:workOrders")`。

| 命名空间内名 | 全名                         | 主键 + 索引                                                                |
| ------------ | ---------------------------- | -------------------------------------------------------------------------- |
| `repos`      | `github-delivery:repos`      | `&fullName, credentialMode, createdAt`                                     |
| `workOrders` | `github-delivery:workOrders` | `++id, [status+repoFullName], issueNumber, prNumber, createdAt, updatedAt` |
| `events`     | `github-delivery:events`     | `&deliveryId, [repoFullName+seenAt], kind, source`                         |
| `audit`      | `github-delivery:audit`      | `++id, [repoFullName+at], runId, &[runId+stepId+at]`                       |

## UI 入口

| 位置                                                     | 用途                                                                                                    |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `Settings → GitHub Delivery`(`?section=github-delivery`) | 5 个 Tab:Repos / Credentials / Policies / Audit / Usage(`?ghTab=...`)                                   |
| `/github-delivery` 独立页面                              | 6 列看板,以 `workOrders` 表为数据源(Open / In progress / PR opened / Awaiting review / Merged / Failed) |
| Inbox(`/inbox/...`)                                      | `pull_request.opened` / `review_requested` 等事件以 InboundMessage 形式呈现                             |
| Workflow 编辑器                                          | 节点搜索栏输入 "github" 即可看到 13 个 `action.github.*` + 1 个 `trigger.github.webhook`                |

## Web 模式降级

| 能力                 | 桌面(Tauri)           | Web                                             |
| -------------------- | --------------------- | ----------------------------------------------- |
| 节点执行(Octokit)    | 完整支持              | 完整支持(浏览器 fetch)                          |
| Webhook 触发器       | 完整支持(Rust 接收器) | **不可用**(无 Rust);UI 上有 "desktop only" 提示 |
| 轮询触发器           | 支持                  | 支持(只在 webview 存活时跑)                     |
| 凭据存储             | OS keyring + Dexie    | Dexie 加密 blob                                 |
| cloudflared 一键暴露 | 桌面 only             | 不可用                                          |
