# 用量与配额

<TLDR>
GitHub App 给的是 **5K 调用/小时 per installation**,PAT 是 **5K/小时 per token**。
cognia 给所有 Octokit 实例统一挂 `@octokit/plugin-throttling` 和 `@octokit/plugin-retry`,
触发主速率限制时最多重试 3 次,触发次级速率限制时只观察不阻塞。Usage Tab 在 M4 阶段
仅占位,实时配额历史(`GET /rate_limit` 周期采样)是 ADR-0018 的开放问题。
</TLDR>

## GitHub 速率限制基线

| 凭据         | 限额                  | 备注                                                                                  |
| ------------ | --------------------- | ------------------------------------------------------------------------------------- |
| GitHub App   | 5000 调用 / 小时 / installation | 每 installation 独立桶,适合给多个仓库/团队同时跑;企业版可更高                |
| PAT(经典)  | 5000 调用 / 小时 / token | token 创建者的所有应用共用一个桶                                                  |
| PAT(fine-grained) | 5000 调用 / 小时 / token | 同上                                                                          |
| Search API   | 30 调用 / 分钟         | cognia 当前不直接走 search 端点;若以后接入 PR 搜索需要注意                            |
| Secondary rate limit | 不公开数值;按"短时间高并发同一资源"触发 | Octokit 插件会消费 `retry-after` 而不重试                          |

`GET /rate_limit` 端点本身**不计入配额**,可以放心轮询。

## Octokit 工厂的统一配置

源代码:`lib/github/octokit-factory.ts`。每次构建 Octokit 实例时:

```ts title="lib/github/octokit-factory.ts(节选)"
const ThrottledRetriedOctokit = Octokit.plugin(retry, throttling)

return new ThrottledRetriedOctokit({
  auth: <token>,
  authStrategy: createTokenAuth,
  userAgent: "cognia-github-delivery/1.0",
  throttle: _throttleHandlers(opts.onWarning),
})
```

`_throttleHandlers` 返回两个回调:

| 回调                       | 何时调                                              | cognia 的策略                                                            |
| -------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------ |
| `onRateLimit`              | 主速率限制(剩余 0 / reset)                        | log 一条 warn 到 `ctx.logger.warn`,返回 `retryCount < 3` —— 最多重试 3 次 |
| `onSecondaryRateLimit`     | 次级限制(`retry-after` 头)                        | log warn,**不**自动重试 —— Octokit retry 插件会按官方建议等 retry-after  |

`@octokit/plugin-retry` 的默认行为是对**幂等动词**(GET / HEAD / PUT / DELETE)进行最多 3 次
指数回退重试。POST / PATCH 不自动重试 —— 这恰恰是 cognia 想要的:`mergePr` / `createRelease`
等是非幂等,失败重跑会重复"做事"。`guardedExecutor` 会把它们的失败回放成 audit 行 + step error,
而不是隐式重试。

## 节流事件如何浮到用户面前

| 通路              | 输出                                                                                |
| ----------------- | ----------------------------------------------------------------------------------- |
| `ctx.logger.warn` | 桌面 / Web 控制台 + Settings → Diagnostics 的实时日志面板                          |
| Audit 行         | 节流不写 audit(audit 只记策略决定);速率失败被 Octokit 重试或抛错时,会在 step error |
| Run 详情页       | step error 显示完整 HTTP 状态 + body                                                |

## Usage Tab 当前实现

`components/settings/github-delivery/tabs/usage-tab.tsx`(M4 阶段)只显示静态卡片:

- "API 配额采样图(M4 占位)" —— 路线图卡片,引导用户去看
  [ADR-0018 的开放问题](/zh/adr/0018-github-delivery#留待的开放问题)。
- "今日 Octokit 调用次数(估算)" —— 从 audit 表 `[repoFullName+at]` 上 `today` 起拉所有行,
  每个非"read-only"行计一次(粗估)。

完整实现(规划中):

<Steps>
<Step>
**周期采样 `GET /rate_limit`.** 通过现有调度器跑一个 `github-rate-limit` 任务(每 5 分钟),
把 `core / search / graphql` 三个桶的 `limit / remaining / reset` 写到一张新表
`github-delivery:rateLimitSamples`。
</Step>
<Step>
**Usage Tab 30 日图表.** 用 sparkline 渲染最近 30 天的 `remaining` 曲线;在 reset 点画竖线。
</Step>
<Step>
**预测耗尽时间.** 用最近 60 分钟的"调用/分钟"窗口估算,展示 ETA。
</Step>
</Steps>

## 建议的限速策略

针对工作流场景,把 5K/h 当成 ~80/分钟来分配:

| 节点                                     | 调用次数(典型)            | 建议触发频率                                       |
| ---------------------------------------- | --------------------------- | -------------------------------------------------- |
| `action.github.reviewPr` / `reviewPrInline` | 1 GET files + 1 POST review | PR opened/synced;高频仓建议加 debounce            |
| `action.github.generateChangelog`        | 1 GET compare(单页;若 > 250 commits 翻页) | 每次 release;不在每个 push 上跑          |
| `action.github.runIssueLoop`             | 1 GET issue + 1 POST PR + 1 POST labels | 用 `cognia:claim` 标签触发,人控触发频率   |
| webhook                                  | 0(GitHub 推过来)           | n/a                                                |
| polling                                  | 1 GET events / repo / 5 min(条件 GET 时是 304) | 配额无忧                            |

## 多仓部署的取舍

| 你的情况                              | 建议凭据 |
| ------------------------------------- | -------- |
| 1 个个人仓库,几个轻量自动化         | PAT      |
| 多个个人仓库共用 token                | PAT,注意限额是共享的 |
| 一个组织 10 个仓库                    | GitHub App,每个仓 5K/h 独立桶 |
| 多组织 / SaaS 多租户                  | 每租户独立 App + installation,审计粒度到 installation |
