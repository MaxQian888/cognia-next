# 上下文工作台

Context Workbench 是资源专属工具共用的右侧工作区，统一管理导航与布局。Project、Canvas、Artifact 和 Workflow 各自已有的专用能力均保留，**不会被替换或删除**。

## 轻量摘要与标签导航

**任务摘要** 按钮位于标题栏、布局切换按钮旁（快捷键 <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>S</kbd>），打开当前对话的紧凑摘要卡片：

- **卡片顶部**：任务所在的项目与分支、**管理任务**（会话设置）和菜单。
- **运行进度**：本次运行计划的当前步骤和步骤条。
- **等你处理**：任务正在等待的审批与提问，点击跳到提问的那一轮。
- **改动**：新增与删除行数（部分文件没有行数时只显示文件数），点击打开工作区面板。
- **产物**：这次对话生成的产物，只有一个时直接打开，多个时打开产物列表。
- **来源**：使用最多的几类来源，**+** 管理来源与能力，**查看全部** 打开来源面板。
- **共享**：私有或已共享、参与者，以及共享对话控件（共享房间中显示连接状态和 **请求 AI 回复**）。

聊天列两侧有足够空间时，卡片悬浮在按钮下方的空白处并保持显示；再次点击按钮或菜单中的 **隐藏卡片** 会为当前对话收起它。窗口较窄时，卡片改为在按钮下方弹出。两种方式都不会压缩聊天区，也不会遮挡横幅；卡片不会打开或关闭右侧面板，可以和面板中的任何内容并排显示。

在卡片菜单中可以设置每一行 **总是**、**有内容时** 或 **隐藏**，**恢复默认** 可重置，设置会随其他设置同步。同一菜单中的 **打开任务概览** 会在右侧面板打开完整概览。侧栏的来源与工作区角标和卡片使用同一组计数。

完整概览中能力默认折叠，有结果时才显示结果区。卡片与完整概览读取同一份会话状态，计数始终一致。

会话标题保持普通文本，搜索与导航入口统一位于右上角工具栏；历史、工作区选择与导航快捷入口移入 **导航** 菜单。

工作区默认在右侧面板顶部使用占满面板宽度的文字标签栏，通过 **打开面板**（`+`）选择其他面板，并可关闭已打开的标签。可以切换为 **紧凑图标栏**，偏好会被保存。文字标签模式关闭时会收起整个右侧栏；切回图标模式后，原有“保持图标栏显示”偏好仍然有效。

## 能力完整性

| 资源 | Workbench 中保留的原生面板 |
| --- | --- |
| Project 文件 | 资源聊天、评论、元数据/session 控制、outline、diagnostics、Git review、proposal review、preview |
| Canvas 文档 | AI actions/chat、suggestions、评论、collaboration、properties/formatting、outline、history、proposal review、preview/export、execution |
| Artifact | 资源聊天、评论、proposal review、preview、history、metadata、filesystem workspace、selection-to-AI |
| Workflow | 专用聊天、评论、inspector、problems、runs、templates、settings、changelog |

每个 host 根据当前资源与平台计算真实 capabilities。原生面板在 backend 不可用时可继续显示并解释原因；插件面板缺少声明的能力或权限时直接不提供。

## 导航与布局

- Activity 按钮对相关面板分组。方向键、Home、End 可在 activity 与组内 tab 间移动，并遵循标准 tab/tabpanel 语义。
- `narrow` 使用 host 的常规 360px 宽度；`wide` 约占 host 一半，并限制在 640–960px；`focus` 是可访问的全屏展示，按 Escape 后恢复焦点。
- 移动端渲染全宽 Sheet，不显示仅桌面有意义的宽度与 focus 控件。
- 桌面窗口较窄时，打开的右侧面板会保证对话区至少 420px 宽，分三步让出空间：先把自身缩到最小宽度（工作区为 480px，其他为整行的四分之一）；仍不够时，会话列表折叠成图标栏；再不够时，面板浮在对话上方并加暗色遮罩，按 Escape 或点击遮罩关闭，焦点回到原处。折叠是临时的，不会改动你保存的侧栏设置；如果你手动重新展开会话列表，它会保持展开，改由面板浮起，直到窗口重新变宽。因窗口变窄而缩小的面板，在窗口变宽后会恢复原来的宽度。
- Pin 会保护当前面板不被自动 reveal 覆盖。诊断、proposal、selection 与插件请求只更新 pending 指示，直到用户显式导航或取消 pin。

## 分屏视图

在 `wide` 或 `focus` 模式下，布局菜单提供**向下分屏**，把第二个面板堆叠在当前面板下方。两个窗格都是活的：各自保留焦点、各自的 error boundary，插件面板还各自收到可见性信号。

- 拖动分隔条调整比例，或聚焦它后使用方向键（Shift 步长更大，Home/End 到两端），双击复位。比例按资源记忆，范围 20%–80%。
- 选中已经位于下方窗格的面板会交换两者，并保持各自原有的高度，而不是替换前台的那个。
- 开分屏、关分屏、拖比例和交换主次都不会重建任何一个窗格，因此内嵌的编辑器、浏览器或终端全程保留状态。
- 移动端抽屉，以及任何窄到放不下两个窗格的工作台，都只显示单窗格，且不会改动已保存的桌面布局——空间足够时它会回来。
- `narrow` 会关闭分屏，因为没有空间容纳两个窗格；收起到图标栏则不会，展开后分屏仍在。

## 评论与资源会话

四类资源共用评论模型。评论可锚定整个资源、文本/行区间，或 Workflow 节点/边。线程保留编辑/删除、回复、reaction、resolve/reopen、未解决徽标、revision 元数据与 stale-anchor 指示。

每个资源同时拥有一个持久化内嵌 AI session。现有 provider-bound 上下文组装、PII 脱敏、proposal-first 编辑与 review bridge 继续由专用面板实现。

## 回滚开关

`canvas`、`project`、`artifact`、`workflow` 四个 host 开关相互独立且默认开启。关闭其中一个只恢复该业务面的完整旧右侧栏，不影响另外三类资源。旧 host 保留一个小版本。

生命周期、持久化、评论与插件决策参见 [ADR-0083](../adr/0083-context-workbench)。


## 任务概览

在会话的 Workbench 中打开 **检查 → 任务概览**，可以查看状态、执行模式与环境、待解决问题和子任务、技能配置、运行时能力快照与具体结果。管理设置、模式和环境复用聊天已有组件。

概览保留 `metadata` 面板 ID，兼容已保存的布局与快捷入口。产物属性仍是独立的资源视图；原会话字段保留在“技术详情”中。

技能配置表示下次发送的配置，已加载或延迟加载的能力以支持该功能的主机快照为准；没有快照时明确显示不可用。结果列表限定当前会话，不将输入引用计为生成结果。点击结果可进入已有产物或工作区界面查看和编辑。
