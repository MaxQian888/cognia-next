# 账号同步设备登记

<Status variant="beta">第 2 阶段 · 密钥与设备 · ADR-0215 · 受构建开关控制</Status>

<TLDR>
  登录官方账号的人拥有一个同步空间。加入空间的每台设备都持有自己的密钥，当前纪元的空间密钥会封装给每台设备和同步恢复密钥。服务端只保存带签名、只追加的设备列表和封装后的密钥：它可以拒绝服务，但无法在设备不察觉的情况下添加设备、读取密钥或隐藏移除操作。已登记的设备随后同步什么，见[账号同步数据](./account-sync-data)（第 3a 阶段）。
</TLDR>

## 首台设备

在已登录官方账号的配置文件上，*设置 → 账号 → 同步设备*会在此人还没有空间时提供**设置同步**。设备生成自己的密钥、同步恢复密钥和第一个纪元密钥，并用自己的密钥和恢复密钥共同签署创世条目。在此人证明已保存恢复密钥之前不会上传任何内容：可以输入随机位置的四个字符，也可以下载恢复套件并确认已妥善保存。只有服务端接受创世条目之后，设备才保留自己的密钥。如果另一台设备先完成了设置，这台设备会改为请求那台设备批准。

**同步恢复密钥**不是配置文件恢复密钥：前者向同步空间添加设备，后者解锁本地配置文件。界面中总是使用完整名称。

## 添加设备

<Steps>
  <Step>新设备发起请求：提交对随机数的承诺、自己的密钥，以及分别封装给每台已登记设备的名称。</Step>
  <Step>已登记的设备显示“有新设备想要同步”（通知、账号页面、设备控制台）。此人打开后选择继续：该设备提交自己的随机数。</Step>
  <Step>新设备揭示自己的随机数，批准方对照承诺进行检查。</Step>
  <Step>双方都显示一个六位代码，由两个随机数以及批准所绑定的全部内容计算得出。此人比较后点击**代码一致**。</Step>
  <Step>批准方将设备追加到列表中，附上转录的哈希，并把当前密钥封装给它；新设备只接受已验证列表能证明的内容。</Step>
</Steps>

服务端只能在双方各自确定之后才看到两个随机数，因此无法挑选密钥或随机数让代码相同；伪造的设备列表同样会改变代码。

**没有其他设备时**，**使用同步恢复密钥**会在一个原子批次中添加此设备并轮换密钥，然后提示更换恢复密钥。

## 管理设备

设备列表显示每台设备的名称（在设备上解密）、加入方式和列表的**指纹**。两台设备显示的指纹不同，说明服务端向它们展示了不同的列表。在这里，设备可以**移除**另一台设备、**轮换密钥**或**更换同步恢复密钥**。每个操作都开启一个新纪元，被移除的设备或旧恢复密钥永远拿不到它的密钥。

被移除的设备只有在已验证列表中找到针对自身的有效签名移除条目后，才删除自己的密钥。它会保留被哪台设备、在何时移除的记录并告知此人；本地数据不受影响。服务端单纯的拒绝不会删除任何内容。

## 设备会拒绝什么

- 带签名的列表没有承诺过的纪元密钥。
- 比之前验证过的列表更短或不同的设备列表。设备会报告完整性问题，并且不做任何更改。
- 转录或批准者与请求不符的批准。

## 构建开关

该功能默认休眠。当 `NEXT_PUBLIC_COGNIA_ACCOUNT_SYNC=1`（预发布构建）或在 `next dev` 下（除非该变量为 `0`）时启用。关闭时，不挂载、不轮询、不连接同步服务，账号概览会显示“账号同步：此版本未提供”。同步服务地址为 `NEXT_PUBLIC_COGNIA_SYNC_URL`（默认 `https://sync.cognia.cn`；预发布 `https://sync-staging.cognia.cn`）。

## 已知限制

- 请求保存在新设备的内存中，重新加载会放弃该请求，直到它过期。
- 无界面宿主在自己的终端里登记（`cognia-agent account-sync`），带着已有数据加入的设备会被询问合并还是替换：两者都见[账号同步数据](./account-sync-data)。
