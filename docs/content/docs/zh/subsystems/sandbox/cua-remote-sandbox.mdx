# CUA 远端沙箱

Cognia 在本地 Docker 容器中提供 Linux 桌面。进入 **设置 → 自动化 → 沙箱连接**，创建 Docker 连接，然后创建并启动实例。连接详情提供桌面画面、文件传输与生命周期操作。Docker 必须在客户端本地 Tauri Host 使用的 context 中运行。

当前实现的适配器是 `docker:computer-server`。E2B Desktop、Cua Cloud 与 Lume 尚未作为桌面 provider 启用。导入配置不会自动获得可运行的适配器。浏览器或 companion 客户端也不会因为显示这些设置而获得本地 Docker 权限。

## 运行环境与镜像

默认镜像 `cognia-cua-desktop:0.3.46-1` 在首次创建时，通过 `crates/cognia-automation/src/cua_sandbox/image/` 中嵌入的资源构建。镜像使用固定 digest 的 Python 基础镜像、Debian 原生 Chromium、Openbox、Xvfb、xterm 与 `cua-computer-server==0.3.46`。首次准备需要访问镜像和软件包仓库，并有足够磁盘空间。构建配方支持 ARM64 与 AMD64；记录中的真实桌面验收运行于 ARM64。

根文件系统只读，运行时目录使用 tmpfs，`/home/cua` 使用匿名持久卷。默认策略先移除 capabilities，再显式授予启动所需的小范围权限；同时启用 no-new-privileges 并限制进程数。CPU 和内存上限可配置。配置 workspace bind mount 会有意向 guest 开放对应宿主目录。

隔离边界是 Docker 容器。内置 Chromium 为适配此容器策略关闭了其内部沙箱。本实现不宣称 microVM 隔离，也不隔离同一 guest 内的不同应用。

宿主将容器端口 8000 发布到随机 loopback 端口。每个容器有独立私有 token，所有 HTTP/WebSocket 请求都必须携带 `X-Cognia-Sandbox-Token`，带浏览器 Origin 的请求被拒绝。原生 Host 从 Docker 元数据恢复 token；它不会进入 renderer、guest 应用或命令环境。服务在受保护的原始启动进程中运行，同 UID 的 guest 进程不能读取其凭据内存或环境。

接管保留容器时会验证镜像身份与容器策略。缺少鉴权或身份信息的旧镜像会被拒绝，不会自动降低验证要求。删除旧容器并重新创建前，必须先保留仍需使用的文件。

## 桌面观察与控制

`SandboxDesktopViewer` 约每秒刷新一帧鉴权截图。这是支持键鼠操作的截图查看器，不是音视频流。PNG/JPEG 必须在图片预算内完整解码成功，才能生成观察 token。

查看器默认只读。显式接管会获取带有效期的控制 lease，并阻止 Agent GUI 修改与 shell 执行。组合键、文本/输入法输入、点击、拖拽、双击和滚轮均使用此 lease。关闭视图、隐藏文档、失焦、截图失败或 lease 过期都会释放本地控制权。晚到的 lease 响应也会释放，避免出现不可见的控制者。

远端 app-session 只公开一个精确应用标识 `cognia.sandbox.desktop:<connectionId>`，代表整个 guest 桌面。观察、revision 与动作 token 绑定到该连接。不支持的应用、窗口或语义 accessibility 操作会失败，不会回退到宿主桌面。固定版本的 Linux server 不提供可用的语义 accessibility 树。

## 二进制文件传输

文件面板一次处理一个普通文件，最大 **8 MiB**，支持空文件和非 UTF-8 数据。上传选择按有界分块读取；下载在进入共用保存流程前验证解码大小和 SHA-256。普通 Agent 文本文件接口保持独立，仍受较小的传输预算约束。

上传使用 guest 绝对路径，父目录必须已经存在，且不会覆盖已有目标。guest helper 拒绝 symlink 路径遍历，先写入无名称临时文件，再原子发布。文件系统不支持该机制时会明确失败，不会回退到较弱的具名部分文件方案。下载拒绝 symlink、目录、FIFO 和设备文件。

每次传输同时携带 connection ID 与预期的精确 container ID。检查、身份验证和传输都持有该连接的锁，容器替换或生命周期变化不能将操作导向另一个 guest。人工接管桌面时仍可下载。上传会释放查看器的旧 lease，在文件选择结束后获取新的 lease，并在真正派发前再次验证；同时使旧观察 token 失效，直到执行完成前一直持有修改操作锁。

保存流程在原生保存对话框返回后及实际写入前，检查发起视图是否仍有效。关闭或切换目标会阻止后续前端步骤，但不宣称撤销已经派发的后端修改。目标已存在等已确认失败允许重试；无法确认进程清理时，连接会进入隔离状态，直到清理确认或容器被确认停止。

## 生命周期与恢复

| 操作 | 行为 |
| --- | --- |
| 创建实例 | 创建保留容器而不启动；已有兼容容器可以被接管。 |
| 启动 | 启动或接管选定容器，等待鉴权截图通道就绪。 |
| 暂停 / 恢复 | 使用 Docker pause/unpause，内存仍然驻留，不是持久快照。 |
| 停止 | 结束 guest 进程，保留容器及 home 卷。 |
| 删除 | 需要确认，删除容器与匿名 home 卷；bind mount 的宿主文件仍保留。 |
| 检查健康 | 检查 Docker 状态、受监管执行与完整解码的桌面截图。验证通过的身份用于补全 placement；确认实例不存在时清除过期 placement。 |

退出应用会断开缓存的 driver client 并释放本地 session；容器保留，之后可以重新接管。新的 registry 能重新连接仍在运行的 guest。启动/恢复就绪等待最多 60 秒，冷连接恢复最多 30 秒。

文件读取、传输、桌面修改与生命周期操作通过同一连接锁协调。取消或未确认的修改保持隔离状态，直到进程清理已知完成或容器已确认停止。删除失败会保留连接记录，便于重试清理。切换连接后，旧请求完成不会关闭或修改新选中的详情。

## 执行与传输通道

`lifecycle_execution.rs` 与嵌入的 `exec_supervisor.py` 提供有界输出收集、绝对超时、可续约的调用者 lease 和子孙进程清理。仅终止宿主 `docker exec` 进程不算 guest 命令已退出；只有收到清理确认，才返回已完成清理的 timeout 结果。通用执行保留 1 MiB 输入/输出流预算，二进制传输使用独立的有界预算。

执行 bootstrap 使用可信的 Python 绝对路径。调用者环境变量不能替换解释器、查看受保护的 framing 进程或继承桌面 token。WebSocket client 通过有界队列串行请求，deadline 包含排队时间；超时后关闭连接，避免晚到响应匹配错误请求。

## 实现位置与验证

- `lib/sandbox/`：provider 能力、生命周期派发与 runtime 绑定。
- `hooks/automation/use-sandbox-connections.ts`：持久状态、健康检查协调与失败重试归属。
- `components/settings/automation/`：连接详情、桌面、传输及删除界面。
- `lib/automation/sandbox-client.ts`：客户端本地 IPC 类型封装。
- `crates/cognia-automation/src/cua_sandbox/`：镜像生命周期、registry、desktop session、supervisor、文件传输与鉴权 driver client。
- `src-tauri/src/lib.rs`、`protocol/companion-commands.json`：命令注册与 internal-only 传输分类。

当前实现扩展 ADR-0020，增加保留生命周期、鉴权远端 session 与文件传输。早期关于 `ghcr.io/trycua/cua-xfce:latest`、无鉴权 WebSocket 或 timeout 只终止宿主 CLI 的示例，已不再描述这条路径。

定向测试覆盖 UI 竞争、目标绑定、协议边界与进程清理。显式启用的 `live_builtin_desktop_authenticated_lifecycle_and_real_input` 测试使用一次性真实 guest，验证桌面输入、二进制往返、不覆盖已有文件、暂停恢复、冷重连和重启持久化。Mock/组件测试不等于原生 Tauri 窗口、安装包或云 provider 验收。实施记录位于 `docs/plans/2026-10-03-sandbox-virtual-computer.md`。
