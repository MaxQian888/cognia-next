# Cognia CLI

<Status variant="stable">cognia-cli 0.1.0 · 二进制 `cognia` · MSRV 1.82</Status>

<TLDR>
  `cognia` 是一个独立的 Rust crate（`crates/cognia-cli/`，约 8.5k 行 + UI 层），在 `cognia plugin …`
  下提供 **14 个插件子命令** —— scaffold（`new`）、validate（`lint`，60 个诊断码）、build（`build` ——
  WASM 走 cargo-component，TypeScript 走 esbuild，Python/hybrid/VS Code-extension 走 existing-entry
  打包）、sign（`keygen`/`sign`/`verify`，对原始 bundle
  字节做 Ed25519）、inspect（`info`，支持 `.zip` bundle 或 unpacked 目录）以及 live-develop
  （`dev`，250 ms 去抖的 watch → rebuild → hot-reload）。`install` 同时支持 `.zip` bundle 和
  unpacked 目录。`status`/`install`/`uninstall`/`list`/`reload`/`dev` 命令通过一个 **仅 loopback 的 axum bridge**
  （`src-tauri/src/cli_bridge/server.rs:28`）触达运行中的桌面端 —— 该 bridge 绑定到临时的
  `127.0.0.1` 端口，经由 `<config_dir>/cognia/cli-endpoint.json` 发现，并由一个每次启动生成、以
  常量时间比对的 64-hex dev token 门控。渲染端从 Plugin DevTools 完成检测、下载（SHA-256 + 可选的
  Ed25519 验证）和启动 CLI。顶层工具还覆盖 `cognia acp`、`cognia release-key` 与
  `cognia release-verify`。
</TLDR>

CLI 的存在是为了让插件作者能在 GUI **之外** 工作：拓印一个起步项目，用文件监听的 dev 循环迭代并对运行中的
cognia 做 hot-reload，最终产出一个已签名、可验证的 `.zip` bundle。它可以独立于应用安装
（`cargo install --locked --path crates/cognia-cli`），并独立于宿主进行版本管理。本节逐模块记录
**当前实现**；面向用户的安装指南见 [CLI Prerequisites](../../dev/cli-prerequisites)。

## 命令表面

插件作者操作嵌套在 `cognia plugin <cmd>` 下
（`TopCommand::Plugin`，位于 `crates/cognia-cli/src/main.rs`），旁边还有 `cognia acp`、
`cognia release-key` 和 `cognia release-verify` 这样的顶层工具命令。全局 flag 处处生效：
`--color auto|always|never`、`--no-color`、`-q/--quiet`、`-v/--verbose`（最多 `-vv`）、
`-y/--yes`（预确认每个 prompt；CI 必需）。Verbose 模式会为人类运行在
stderr 打印一条解析后的命令诊断；`--quiet` 和每个命令的 `--json` 都会抑制它。

| 命令 | 作用 | 模块 | 是否与应用通信？ |
| --- | --- | --- | --- |
| `new [name] [--dir DIR] [--kind wasm\|ts\|python\|hybrid\|vscode-extension] [--author NAME] [--author-email EMAIL] [--description TEXT] [--with-keygen true\|false] [--json]` | 拓印一个起步项目（TTY 上为交互式 wizard） | `cmd_new.rs` + `template.rs` | 否 |
| `lint [--path .] [--json]` | 60 个诊断码的 manifest 校验；出错时 exit 1 | `cmd_lint.rs` | 否 |
| `build [--path .] [--out P] [--skip-build] [--json]` | Lint → cargo-component / esbuild / existing-entry 打包 → zip | `cmd_build.rs` / `build_ts.rs` / `packaging.rs` | 否 |
| `info <bundle.zip\|directory> [--detailed] [--json]` | Manifest、文件表、bundle 签名状态或目录 `not-applicable`、`cognia:api-version` | `cmd_info.rs` | 否 |
| `keygen [--out-dir .cognia] [--json]` | Ed25519 密钥对 → `.cognia/plugin.{private,public}.b64` | `cmd_keygen.rs` | 否 |
| `sign <bundle> --key <priv> [--out sig] [--json]` | 对原始 zip 字节签名；未传 `--out` 时写入 `<bundle>.sig` | `cmd_sign.rs` | 否 |
| `verify <bundle> [--public-key b64] [--signature sig] [--json]` | 用 `author.publicKey` 或显式公钥验证 `.sig` | `cmd_verify.rs` | 否 |
| `install <bundle.zip\|directory> [--json]` | 预检冲突 → POST bundle 或 unpacked 目录安装 | `cmd_install.rs` | **是** |
| `uninstall <id> [--purge-data] [--json]` | 确认后移除（purge 会警告：单向 Dexie 抹除） | `cmd_uninstall.rs` | **是** |
| `list [--json]` | 打印运行中桌面端 bridge 的已安装插件快照 | `cmd_list.rs` | **是** |
| `reload [--plugin-id ID] [--path P] [--json]` | 按已安装插件 id、重建后的 bundle 或 unpacked 目录触发 hot-reload；`--bundle` 仍兼容旧脚本 | `cmd_reload.rs` | **是** |
| `status [--json]` | 探测 `/api/v1/dev/health`；JSON 不含 token，bridge 不可用时返回非零 | `cmd_status.rs` | **是** |
| `dev [--path .] [--reload-url URL] [--once] [--json]` | Watch → 去抖 250 ms → rebuild → POST reload；`--once` 只构建/重载一次后退出，并可输出 JSON | `cmd_dev.rs` | **是**（无连接时优雅降级） |
| `embed-version <wasm> <ver> [--out wasm] [--json]` | 重新注入 `cognia:api-version` 自定义段 | `main.rs::cmd_embed_version` + `packaging.rs` | 否 |
| `release-key [--json]` | 查看内置 CLI release 公钥、fingerprint、placeholder 状态和签名策略 | `cmd_release_key.rs` + `release_key.rs` | 否 |
| `release-verify <artifact> --checksums <checksums.txt> [--artifact-name NAME] [--signature PATH] [--json]` | 离线校验下载得到的 CLI release 产物是否匹配 `checksums.txt` 与 release-key 策略 | `cmd_release_verify.rs` + `release_key.rs` | 否 |

## 一次端到端的作者会话

```mermaid
sequenceDiagram
  participant A as Author
  participant C as cognia CLI
  participant FS as Plugin dir
  participant B as Bridge (axum, desktop)
  participant R as Renderer

  A->>C: cognia plugin new hello --kind ts
  C->>FS: stamp 10-file scaffold + patch plugin.json
  A->>C: cognia plugin dev
  C->>C: load cli-endpoint.json (baseUrl + devToken)
  loop every save (debounced 250 ms)
    FS-->>C: notify event (src/ · plugin.json · package.json)
    C->>C: cmd_build (lint → esbuild → zip)
    C->>B: POST /api/v1/dev/plugins/reload {bundle_path, plugin_id}
    B->>B: install_inner — extract zip, register PluginRecord
    B-->>R: emit plugin-hot-reload {plugin_id, via:"install"}
    R->>R: unload + reload plugin artifact
  end
  A->>C: cognia plugin sign … --key .cognia/plugin.private.b64
  A->>C: cognia plugin verify …
  A->>C: cognia plugin status --json
  C->>B: GET /api/v1/dev/health
  A->>C: cognia plugin install target/cognia/hello-0.1.0.zip
  C->>B: GET /plugins/installed (collision preflight)
  C->>B: POST /plugins/install {bundle_path}
  B-->>R: emit cli-bridge:plugin-installed
  A->>C: cognia plugin install .
  C->>B: GET /plugins/installed
  C->>B: POST /plugins/install-directory {source_dir}
  B-->>R: emit cli-bridge:plugin-installed
```

## 一张表看清安全态势

| 关注点 | 机制 | 位置 |
| --- | --- | --- |
| 对 bridge 的远程访问 | 在任何处理之前硬性 `is_loopback(addr)` 拒绝（403 `remote_blocked`） | `src-tauri/src/cli_bridge/server.rs:94`、`mod.rs:189` |
| Token 窃取 / 重放 | 32 个随机字节 → 64-hex `X-Cognia-Dev-Token`，每次启动应用轮换，常量时间比对 | `mod.rs:115`、`server.rs:127` |
| Endpoint 文件暴露 | `cli-endpoint.json` 在 Unix 上以 `0o600` 写入 | `mod.rs:128-150` |
| 超大负载 | 4 MiB `RequestBodyLimitLayer` | `server.rs:81` |
| 安装时的 zip-slip | 解压时拒绝路径穿越条目（已测试） | `handlers.rs:592-608`、`handlers.rs:741-766` |
| 目录安装逃逸 | Load-unpacked 目录复制会跳过 symlink，并要求所选 source dir 内存在 `plugin.json` | `handlers.rs:439-477`、`handlers.rs:569-588` |
| Bundle 真实性 | 对原始 zip 字节做 Ed25519，作者密钥位于 `plugin.json author.publicKey` | `signing.rs:61-82` |
| CLI 二进制真实性 | 始终 SHA-256；一旦替换占位密钥即进行 Ed25519 release-key 校验 | `download.rs:200-309`、`release_key.rs:25` |

<Callout type="info" title="bridge 不是 companion API">
  CLI bridge（临时 loopback 端口、每次启动的 dev token）是一个独立于移动配对 companion API（端口 7890，
  JWT 鉴权）的监听器。按设计，两者都不为插件 endpoint 提供 LAN/WAN 触达 —— 见
  [Companion API](../companion-api)。
</Callout>
