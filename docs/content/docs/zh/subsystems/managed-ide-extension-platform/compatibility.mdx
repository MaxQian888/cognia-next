# 兼容性与发布门禁

| Host | Architecture | 结果 |
| --- | --- | --- |
| Linux | amd64 / arm64 | 支持 |
| macOS | amd64 / arm64 | 支持 |
| Windows | 任意 | `unsupported_platform`；无 npm fallback |

本发布固定 code-server `4.128.0` 与 Code `1.128.0`。升级必须完成 upstream
catalog diff、schema import digest 更新、generator 修改、compatibility fixture
和真实 E2E 审批。远程 host 必须预加载匹配二进制；不匹配返回
`CODESERVER_UPGRADE_REQUIRED`。

Proposed/internal VS Code API、remote-authority、extension-management API、
Windows host，以及 managed profile 中的第三方 `extensionDependencies` 都返回
结构化兼容错误，不会 silent no-op。

Stable release 需要 catalog-entry conformance、malformed/oversized frame、
cancellation race、stale generation、reconnect、path/ticket security、profile
isolation、deterministic proxy/update rollback、offline artifact、双 major
negotiation，以及本地/配对真实 LSP、DAP、MCP、SCM、test、notebook、
webview/custom editor 与 Chat E2E。

性能门禁为：cold readiness 回归不超过 20% 且 2 秒；idle RSS 回归不超过 20% 且
150 MiB；本地空 broker RPC p95 不超过 30 ms；远程 relay 排除物理 RTT 的额外开销
p95 不超过 75 ms；声明容量内 control/lifecycle event 零丢失。

真实二进制 E2E（`pnpm test:pro-ide:e2e`）通过真实 code-server 跑通上述每个家族，
并在同一次运行中测量：cold readiness、host 进程树的 idle RSS、200 次空 broker
RPC、100 次 relay 与直连请求的对比，以及 200 个 lifecycle event 的突发（在
companion event bus 256 的 broadcast 容量内），要求全部按序到达。
`pnpm audit:pro-ide-perf` 将该次运行与所在平台已提交的基线
（`scripts/gates/pro-ide-perf-baseline.json`）比较；用 `--write-baseline` 记录
基线。CI 在改动该链路的 PR 和每晚全量运行中执行两者。在提交 Linux 基线之前，
CI 只强制绝对门禁，两项回归门禁报告为 skipped。

远程 telemetry 必须 opt-in 且只含聚合数据。源码、路径、prompt、参数、环境、
secret 与 content handle 永不进入 telemetry。
