# Companion API

<Status variant="beta">beta</Status>

<TLDR>
  Cognia 的原生 Rust 运行时提供两套契约。配对设备通过短期 DPoP 凭据访问公开的
  `/api/*` 与 `/ws/*`；无渲染 Brain 通过仅限 loopback 的 24 小时 service token 访问
  `/internal/*`。两者共享 Rust RPC dispatcher，但属于不同信任边界，并分别生成 OpenAPI。
</TLDR>

## 两个 surface，一个 dispatcher

| Surface | 路由 | 调用方 | 鉴权 | 规范 |
| --- | --- | --- | --- | --- |
| 配对设备 | `/api/*`、`/ws/*` | 移动端与受管设备 | 设备密钥、DPoP access token、socket ticket | `docs/api/mobile-companion-api.openapi.yaml` |
| Headless service | `/internal/*`、`/ide/content*` | 本机无渲染 Brain 与受管 IDE | loopback service token | `docs/api/headless-service-api.openapi.yaml` |

公开命令是 `KNOWN_COMMANDS` 的子集：descriptor 必须以 `execution` 或 `host-admin` 为 target，
并声明支持 HTTP transport。service 命令不会进入公开 spec。Headless spec 包含全部 dispatcher
命令，因为 Brain 是本机执行权威。

## 规范公开路由

| 用途 | 路由 |
| --- | --- |
| 健康与就绪 | `GET /healthz`、`GET /livez`、`GET /readyz` |
| 设备初始化 | `POST /api/auth/device/challenge`、`POST /api/auth/device/register` |
| 短期凭据 | `POST /api/auth/token` |
| WebSocket ticket | `POST /api/auth/socket-ticket` |
| RPC dispatch | `POST /api/_rpc/{name}` |
| 身份 | `GET /api/whoami` |
| 事件流 | `GET /ws/events?ticket=…&since=…` |
| 终端与浏览器 socket | `/ws/terminal/*`、`/ws/browser/{session_id}` |

`/api/v1/*` 与 `/ws/v1/*` 仅用于已发布客户端的显式弃用兼容。新客户端必须采用规范路由和
DPoP 流程。

## 自动生成契约

路由目录、命令 manifest 与 Rust allowlist 是生成输入：

```bash
pnpm companion-api:gen
pnpm companion-api:check
pnpm companion-api:lint
```

仓库 artifact gate 会运行 `companion-api:check`；Rust 测试还会把两份具体 RPC 路径清单与
dispatcher 逐项比较，因此路由、descriptor 或 allowlist 变化不会让已提交 OpenAPI 静默过期。
