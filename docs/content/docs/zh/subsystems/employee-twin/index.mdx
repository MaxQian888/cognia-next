# 员工数字孪生

<Status variant="beta">Beta · schema v70</Status>

<TLDR>
  员工数字孪生把一个人的文档、聊天导出与代码蒸馏成四类资产 —— **知识索引**（RAG）、**风格画像**（少样本语气）、
  **Playbook 库**、以及 **角色 / 技能草稿**。发送时 `applyTwinContext`
  （`lib/twin/runtime/apply-twin-context.ts:170`）只对用户消息嵌入一次，执行混合检索（向量 + BM25/RRF）并可选做词法重排，
  挑选风格少样本，组装四段式系统提示 —— 现已直接接入 `resolveSendOptions`（`lib/claude/build-options.ts:625`）。
  PII 在任何嵌入或 LLM 调用 **之前** 就被替换为 `<KIND_NNN>` 占位符；逆向映射以 AES-GCM-256 加密落盘
  （`lib/twin/ingest/redaction-key.ts:255`）。
</TLDR>

**员工数字孪生** 是 Cognia 最深的定制化层。它把用户的文档、聊天导出与代码蒸馏成：

- **知识索引**（RAG）—— 发送时检索最相关的片段。
- **风格画像** —— 采样用户的文字，让助手用 ta 的语气书写。
- **Playbook 库** —— 由蒸馏 agent 抽取出的重复工作模式。
- **角色 + 技能草稿** —— 自动合成，进入人工审核队列，审核通过前绝不进入正式选择器。

完整设计原由见 [ADR-0003](../../adr/0003-employee-digital-twin)。本节逐模块记录 **当前实现**。

## 多孪生是设计前提

"孪生"是一等的 registry 行（`Twin`，`types/twin/index.ts:480`），但绑定是 **软** 的：角色通过
`Character.twinId` 启用，并通过 `Character.twinSettings` 调参。

`DEFAULT_TWIN_SETTINGS` 位于 `types/twin/index.ts:445`。多个角色可共享一个孪生，单个 Dexie 数据库可承载多个孪生
（自己 / 导师 / 前任）—— 每个孪生作用域的行都带 `twinId`。registry（`lib/db/twins.ts`）负责创建 / 重命名 / 克隆 /
归档，以及 **级联删除**（`deleteTwin`，`lib/db/twins.ts:110`）：抹除每张孪生作用域表、解绑引用它的角色、删除两个 cron
任务、并删掉远程向量集合。

## 隐私红线

<Callout type="warn" title="任何数据离开渲染端前先脱敏">
  ingest 的第 3 阶段（`redact`，`packages/redact/src/index.ts:227`）在 chunk 被嵌入或发给任何 LLM **之前**，
  就把 11 类 PII 替换为 `<KIND_NNN>` 占位符。只有 `contentRedacted` 会进入嵌入器
  （`lib/twin/ingest/embed.ts:48`）或远程向量负载（`lib/twin/ingest/persist.ts:137`）。逆向映射以 AES-GCM-256
  加密落盘，原始文本从不持久化。
</Callout>

| 关注点 | 缓解位置 |
| --- | --- |
| chunk 中的 PII | `redactText` 在嵌入/LLM 前脱敏；只发送 `contentRedacted`（`redact.ts:227`） |
| 静态逆向映射 | AES-GCM-256，密钥在 OS keyring（Tauri）或 AES 加密存于 Dexie（web）（`redaction-key.ts`） |
| 草稿中的幻觉 PII | 两层守卫 —— 落库时再脱敏（`distill/job-runner.ts`）+ 编辑时深度扫描（`draft-pii-guard.ts:54`） |
| 云端外发 | 桌面端向量后端默认 **原生 sqlite-vec**；仅在用户选用时才走云（`twin-runtime-settings.ts:50`） |
| 丢钥 vs 首次运行 | SHA-256 密钥指纹闩，遇异常抛 `RedactionKeyMismatchError` 而非静默换钥（`redaction-key.ts:177`） |
