# Agent SDK (ctx.agent)

<Status variant="experimental" />

<TLDR>
`ctx.agent` 是聊天 Agent 的可嵌入对应物。除注册类方法（`registerTool` / `registerSkill` / `registerSubagent` …）外，它现在暴露了带类型的运行循环：`run(prompt, options)`（一次性）与 `runStreamed(prompt, options)`（typed 事件的异步可迭代）。二者都包装 `lib/ai/agent/agent-executor.ts:executeAgent` —— 默认纯文本，设置 `toolsEnabled` 时经桌面 sidecar 走工具循环（由 `agent:control` 权限把关）。运行支持结构化 JSON 输出（`outputFormat`）、可改写参数的 `canUseTool` 许可门，以及按名调用任意宿主/插件工具的 `invokeTool(name, args)`。旧的 `executeAgent(config)` 作为已弃用的兼容垫片保留。
</TLDR>

## 为什么需要它

插件本就能注册工具与 subagent，但唯一能*运行*一个 agent 回合的方式是无类型的 `ctx.agent.executeAgent(config: Record<string, unknown>)`：没有类型契约、不能向插件流式回传、没有结构化输出、无法对工具调用参数做许可/改写，也无法在插件代码内调用宿主工具。Agent SDK 补齐了这些缺口，其可嵌入 Agent 形态借鉴自 VS Code Language Model API、Anthropic Claude Agent SDK（`query()`）、Cursor SDK 与 OpenAI Agents SDK。

## run —— 一次性

```ts
const result = await ctx.agent.run("总结发布说明", {
  appendSystem: "简洁作答。",
  outputFormat: {
    type: "json_schema",
    schema: { type: "object", properties: { summary: { type: "string" } } },
  },
})
result.text        // 原始助手文本
result.object      // 请求 outputFormat 时解析出的 JSON
result.parseError  // 解析失败时被设置（绝不抛出）
result.channel     // "text" | "sidecar"
result.agentId     // 取消句柄
```

`run` 以 `PluginAgentRunResult` 解析。Provider 解析走与聊天 Agent、`ctx.ai.chat` 相同的 `lib/ai/provider-consumption.ts` 路径 —— `run` 是具备工具循环能力的 agent 化超集，`ctx.ai.chat` 仍是轻量的原始补全。

## runStreamed —— 实时事件

```ts
const run = ctx.agent.runStreamed("研究这个主题", { appendSystem: "引用来源。" })
for await (const event of run) {
  if (event.type === "text-delta") process.stdout.write(event.delta)
  if (event.type === "tool-call") console.log("调用", event.toolName)
}
const result = await run.result   // 最终 PluginAgentRunResult
run.cancel()                      // 中途中止
```

`runStreamed` 返回 `PluginAgentRun` —— `text-delta` / `tool-call` / `tool-result` / `result` 事件的异步可迭代，外加 `result` promise 与 `cancel()`。流式事件由 `lib/claude/run-and-capture.ts` 中唯一的 assistant-block 解析循环（经其 `onEvent` 钩子）发出 —— 没有第二份事件解析器。

## 结构化输出

设置 `outputFormat: { type: "json_schema", schema }`。一条 JSON-only 指令（`buildJsonInstruction`，来自 `lib/workflow/nodes/ai/structured.ts`）会被追加到系统提示，最终文本以 `parseStructured` 解析。解析值落在 `result.object`；解析失败落在 `result.parseError`，绝不抛出。这复用了仓库既有的 JSON-mode 惯用法，在两个通道上行为一致 —— 没有原生 `generateObject`，也没有 JSON-Schema→Zod 转换器。

## canUseTool —— 允许 / 拒绝 / 改写

许可门对齐 Claude Agent SDK 的 `canUseTool`：返回 `allow`（可带 `updatedInput` 以**改写**参数）或 `deny`（带回传给模型的 message）。

```ts
import { createPiiRedactionGate } from "@cognia/plugin-sdk"

await ctx.agent.run("...", { toolsEnabled: true, canUseTool: createPiiRedactionGate() })
```

对工具运行（sidecar）而言，许可门应答 sidecar 既有的 `permission_request` 往返，并经 `approveTool` 回传改写后的 `updatedInput` —— 端到端复用可改写契约。内置的 `createPiiRedactionGate()` 把每个字符串参数过一遍 twin 摄取脱敏器（`packages/redact/src/index.ts`），以占位符替换而非硬拒。运行级门与每工具 `canUseTool` 组合：工具级门先跑，其改写后的输入流入运行级门，任一方 `deny` 即短路。

> **覆盖范围限制。** 被权限规则集自动放行的宿主工具不会发出 `permission_request`，因此许可门只拦截 ask 档的宿主工具；插件自有的内联工具始终受门把关。

## invokeTool —— 按名调用宿主工具

```ts
const page = await ctx.agent.invokeTool("web_fetch", { url: "https://example.com" })
```

`invokeTool` 经统一的 `lib/plugin/core/invoke-plugin-tool.ts` 接缝（归属校验 + 权限档 + 惰性激活）并返回工具结果。需要 `agent:control` 权限。

## 生命周期钩子（Package A）

`run` / `runStreamed` 接受每次运行的 `hooks`，对齐 Claude Agent SDK 的 PreToolUse / PostToolUse / Stop：

```ts
await ctx.agent.run("...", {
  toolsEnabled: true,
  hooks: {
    onPreToolUse: (name, input) =>
      name === "Bash" ? { behavior: "deny", message: "禁止 shell" } : { behavior: "allow" },
    onPostToolUse: ({ toolName, result }) => ({ updatedToolOutput: redact(result) }),
    onStop: ({ text, channel, usage }) => log(`完成于 ${channel}`),
  },
})
```

- **`onPreToolUse`** 接入与 `canUseTool` 相同的门链，**最后**执行（工具级 → 运行级 → 钩子）；任一 `deny` 胜出，改写沿链流转。
- **`onPostToolUse`** 观察每个工具结果，并可返回 `updatedToolOutput` 以**改写**模型所见。输出改写仅在结果于进程内物化处生效 —— **ai-sdk 通道与进程内 MCP 工具**；原生 Anthropic 工具（Bash / Read / Edit / Grep）在 SDK 子进程内执行，仅可**观察**。捕获循环对每个工具只触发一次（ai-sdk 通道走 review，否则走 observation）。
- **`onStop`** 完成时触发一次，在**两个通道**上都触发（优雅降级：工具钩子在文本通道不触发，但 `onStop` 触发）。

输出改写走一条新的可选 sidecar 往返（`tool_result_review` → `tool_result_decision`，对应 `claude_tool_result_decision` Rust 命令），仿照 `permission_request`；仅当存在 `onPostToolUse` 钩子时启用。无新权限 —— 钩子搭乘 `agent:control`。

## Guardrails（Package B）

输入/输出守卫**环绕**运行（OpenAI Agents SDK 风格）。触发 tripwire 会以带类型的 `PluginGuardrailTripwireError` 中止。

```ts
import { defineGuardrail, createPiiOutputGuardrail } from "@cognia/plugin-sdk"

ctx.agent.guardrails.register(
  defineGuardrail({
    id: "no-secrets",
    type: "output",
    run: ({ output }) => ({ tripwireTriggered: /sk-[a-z0-9]+/i.test(output) }),
  })
)

await ctx.agent.run("...", { guardrails: ["no-secrets", createPiiOutputGuardrail()] })
```

运行的 `guardrails` 可混用内联守卫对象与经 `ctx.agent.guardrails` 注册的守卫 id。输入守卫在回合前跑，输出守卫在最终文本上跑。守卫与通道无关（文本通道上完整生效），搭乘 `agent:control`。

## 编程式调度（Package C）

```ts
const review = await ctx.agent.dispatchSubagent("code-reviewer", "审查这个 diff")
const team = await ctx.agent.runTeam("team-id", { ultracode: true })
```

- **`dispatchSubagent(idOrDef, prompt, opts)`** 解析已注册 subagent（或内联定义），将其作为一次性工具运行回合执行 —— subagent 的 `{prompt, model, tools, maxTurns}` 映射到执行器。（subagent 在宿主无直接调用入口，这是忠实的"运行该 subagent"路径。）
- **`runTeam(teamOrConfig, opts)`** 以既有 id 或临时 config 无头运行 Agent Team，复用 `agentTeamManager.start`（实时 store 绑定、已配置运行时依赖、每团队 inflight 守卫）。

二者均需 **`agent:dispatch`** 权限（非危险）。无 sidecar 时降级为纯文本子运行 / 队员。

## 会话（Package D）

插件自有的持久多轮会话：

```ts
const session = await ctx.agent.sessions.create({ characterId, maxTokens: 50_000 })
await session.send("开始分析")
await session.send("现在与上季度对比")  // 续上对话
const history = await session.history()
await session.end()
// 稍后 / 重载后：
const resumed = await ctx.agent.sessions.resume(session.id)
```

会话是一条持久 `ChatSession`。每次 `send` 续上之前的对话 —— sidecar 上走原生 SDK resume（经持久化的 `sdkSessionId`），文本通道上回放转录。回合写入 Dexie，使 `history()` 在重载后仍可用。`create` / `resume` 复用既有的 `session:write` / `session:read` 权限。可选的累计 `maxTokens` / `maxBudgetUsd` 预算（Package F）在耗尽后拒绝 send（`PluginBudgetExceededError`）。

## 上下文与记忆（Package E）

```ts
import { defineContextProvider } from "@cognia/plugin-sdk"

ctx.agent.context.registerProvider(
  defineContextProvider({ id: "recent-decisions", provide: async () => "近期决策：…" })
)
const shared = await ctx.agent.context.readSharedMemory("team-id")        // agent:shared-memory:read
const chunks = await ctx.agent.context.queryTwinMemory(characterId, "q")  // twin:read
```

- **上下文提供器**贡献环境文本，追加到插件发起的每次运行的系统提示（与通道无关；抛错的提供器被跳过）。
- **`readSharedMemory(teamId)`** 返回团队共享记忆黑板的 ACL 可读 operator 视图（受 `agent:shared-memory:read` 把关）。
- **`queryTwinMemory(characterId, query)`** 对员工数字分身做 RAG 检索，复用 `tryBuildTwinDeps` + `applyTwinContext`（PII 在摄取期已审过）；未绑定/不可用时降级为 `[]`（受 `twin:read` 把关）。

## 健壮性（Package F）

运行整形旋钮（无新方法、无新权限）：

```ts
await ctx.agent.run("...", {
  fallbackModel: "claude-haiku-4-5",  // 主模型出错时用它重试一次
  maxTurns: 8,                        // maxSteps 的别名（maxSteps 优先）
  trace: true,                        // 发出每次运行的 agent-trace plugin-hook span
})
```

`fallbackModel` 在主运行失败时对一次性运行重试一次（流式运行不重试 —— 重试会重复发事件）。`trace` 经 `lib/agent-trace/emitter.ts` 向追踪面板发出 `plugin-hook` span（开始/结束 + 用量 + 错误）。

## 权限

| 面 | 权限 |
| --- | --- |
| `toolsEnabled` 运行 · `invokeTool` | `agent:control` |
| 钩子 · 守卫 · fallback/budget/trace | `agent:control`（搭乘既有运行） |
| `runExternalAgent` | `agent:dispatch-external` |
| `dispatchSubagent` · `runTeam` | `agent:dispatch` |
| `sessions.create` / `sessions.resume` | `session:write` / `session:read` |
| `context.readSharedMemory` | `agent:shared-memory:read` |
| `context.queryTwinMemory` | `twin:read` |

纯文本运行、上下文提供器/守卫的**注册**、以及 `onStop` 不设门。新权限在 `lib/plugin/core/validation.ts` 与 Rust `crates/cognia-cli/src/cmd_lint.rs` 白名单中同步（有 parity 测试）。

## 作者辅助

`@cognia/plugin-sdk` 再导出 `defineAgentTool()`、`defineGuardrail()`、`defineContextProvider()`（带类型直通，可定义运行时 provider 对象，也可定义声明式 `manifest.contextProviders[]` 条目），以及 `createPiiRedactionGate()`（工具参数门）与 `createPiiOutputGuardrail()`（输出守卫）。直接 helper 子路径也可通过 `@cognia/plugin-sdk/define/<name>` 使用。

## Dogfood

内置 `cognia-web-tools` 插件的 `web_research` 工具端到端演练了整个面：先用 `ctx.agent.invokeTool("web_fetch", …)` 收集来源页，再用 `ctx.agent.runStreamed` 配合 `outputFormat`、`createPiiRedactionGate()`、一个输出**守卫**、一个 `onStop` **钩子**与 `trace` 做总结；激活时注册一个**上下文提供器**。见 `plugins/web-tools/src/index.ts`。
