# GitHub 评论 Bot

内置插件 `github-comment-bot`（`plugins/github-comment-bot/`）是一个 Bot：每个安装监听一个仓库的评论，回应你所允许的人发出的 `@` 指令。它运行在 Cognia **Host** 上，即桌面应用或无头 Host。配对的 Web 与移动端负责配置和审批，不会再运行第二份。

它不自建任何基础设施。GitHub 访问、webhook 与签名写入来自 **GitHub Delivery**。排队、租约、审批与重启恢复来自 Bot 控制平面（[ADR-0174](../adr/0174-the-bot-control-plane)）。检出使用 bot-run 工作区，回答由外部 Agent 运行时生成。解析与上下文辅助函数放在共享包 `@cognia/github-bot-kit` 中，`github-devin-bot` 也在使用。

## 指令

以触发词开头写一行，每条评论只接受一个指令。

| 指令                        | 效果                                                                  |
| --------------------------- | --------------------------------------------------------------------- |
| `@bot ask <问题>`           | 只读 Agent 根据仓库与讨论串作答。                                     |
| `@bot review [重点]`        | 对 Pull Request 做只读评论式评审，锁定在确切的 head 提交；不会批准或要求修改。 |
| `@bot status [任务]`        | 列出该讨论串的任务及状态，不调用模型。                                |
| `@bot cancel [任务]`        | 取消该讨论串最新的（或指定的）任务，包括待决的发布决定。              |
| `@bot help` 或只写触发词    | 显示用法。                                                            |
| `fix`、`retry`              | 尚未开放，回复固定提示。                                              |

触发词后的自由文本按 `ask` 处理。写在代码、引用、HTML 注释里或句子中间的提及不算指令。保留动词（`merge`、`approve`、`release`、`exec`、`deploy`）会被拒绝。

编辑指令会替换之前的版本；删除指令会取消对应任务。超过**指令时效**（默认 24 小时）的指令只会收到“已过期”回复，不会执行。轮询和重投的 webhook 可能带回旧评论，时效限制就是为此设置的。

## 配置

1. 安装并启用 **GitHub Delivery**，连接一个 GitHub 账号。推荐使用 **GitHub App** 账号：Bot 会以 `<app>[bot]` 身份回复，触发词默认为 `@<app-slug>`。
2. 在 Bots 页面安装 **GitHub 评论 Bot**，把它的 `github` 凭据槽绑定到该账号。
3. 在安装设置中填写：
   - **仓库**：`owner/repo`，没有默认值。
   - **允许的作者**：可以指挥 Bot 的 GitHub 数字用户 ID。至少填一个，否则谁都无法使用。
   - **触发词**：App 账号可以留空。个人令牌账号必须填写，因为它的登录名属于一个真实的人。
   - **发布模式**：`automatic`（默认）或 `approval`，见[发布](#发布)。
   - **外部 Agent**、**回答超时**、**指令时效**、**轮询间隔**。
4. 在安装的“路由”区选择**模型路由**。**Cognia 模型**让模型流量经过网关，网关逐请求做敏感数据检查，费用上限是硬限制。**Agent 自己的登录**是一种明确的取舍：只有 Host 对提示词的脱敏生效，费用上限只在两次调用之间检查。
5. 启用触发器。webhook 能到达本机时，启用 **GitHub comments**。**Poll comments** 无论如何都要启用：没有公网 webhook 时它是兜底，有 webhook 时它每五分钟补查一次。
6. 运行 **Check setup**（第一个手动触发器），查看结果。

## 就绪检查

Bot 每次运行都会重做便宜的检查。**Check setup** 做全部检查，包括经绑定账号的一次真实检出。阻断问题会让运行以“需要配置”结束，并显示在安装上；告警不会阻断，Bot 以较窄的形态继续运行。

| 代码                        | 类型 | 含义                                                       |
| --------------------------- | ---- | ---------------------------------------------------------- |
| `repository_missing`        | 阻断 | 未配置仓库。                                               |
| `allowlist_empty`           | 阻断 | 没有任何作者可以指挥 Bot。                                 |
| `trigger_required`          | 阻断 | 个人令牌账号未设置触发词。                                 |
| `trigger_conflict`          | 阻断 | 本机另一个安装已在同一仓库响应同一触发词。                 |
| `no_ingress`                | 阻断 | webhook 和轮询触发器都未启用。                             |
| `permission_probe_failed`   | 阻断 | 绑定账号无法读取仓库，或账号健康检查失败。                 |
| `private_clone_unavailable` | 阻断 | 经绑定账号的检出失败。                                     |
| `publication_grant_missing` | 告警 | 自动发布缺少 autopilot 授权，每条回复都要等人批准。        |
| `pii_boundary_unverified`   | 告警 | 路由为 Agent 自己的登录，模型请求不经网关逐请求检查。      |
| `executor_unavailable`      | 告警 | 尚未选择模型路由。                                         |

每个仓库只应由一个 Host 响应。同一 Host 上的第二个安装会被拒绝；两台独立的 Host 彼此看不到对方，所以要为每个仓库只指定一个 Host。迁移步骤：先关闭旧 Host 的触发器，等在途任务完成或取消，再在新 Host 上安装，最后把 webhook 指向新 Host。

## 发布

回答、回复、跟踪评论和评审都通过 GitHub Delivery 的代理动作写入，并先批准确切内容：

- **automatic**：由 Host 的策略决定。Bot 策略有 autopilot 授权且不要求写入审批时，直接发布；否则运行会等待人工批准。
- **approval**：每条回复都需人工批准。待批准项与其他 Bot 审批一样推送到配对端。

Bot 写的每条评论都带一个不可见的标记。Bot 不会回应自己的评论；响应丢失后重试的写入会找到之前的副本，不会重复发帖。

## 安全

- **谁可以用**：作者必须在白名单中，**且** GitHub 认定其有 write 权限。两项都按用户 ID 检查，分别在指令到达时、开始回答时、发布前各查一次。拒绝只记录在本地，不会在讨论串里公开。
- **运行什么**：Agent 在隔离、一次性的检出中工作，版本精确。结束后对检出做 diff，有任何改动就阻止发布（`readonly_violation`）。
- **发送什么**：上下文有上限（读取 2 MiB，选取 256 KiB / 24k token），并清除控制字符。在任何 Agent 看到之前，Host 会先做脱敏。
- **花费多少**：每个安装的 `maxConcurrentRuns` 与 `maxRunCostUsd` 都在运行时强制执行。运行详情页显示该运行的模型费用；没有已知价格的调用单独计数，不按零计算。

## 跟踪任务

每条指令都是一次 Bot 运行，出现在安装的“运行”区和 `/agent-runs` 中。详情显示：

- 来源评论与任务编号；
- 回答所针对的提交；
- 被省略的上下文；
- 结果与发布地址；
- 模型费用。

在讨论串里，`@bot status` 会列出同样的任务。
