# 配置治理

内置的 `config-governance` 插件（`plugins/config-governance/`，[ADR-0238](../adr/0238-agent-configuration-is-governed-by-evidence)）针对智能体加载的每条规则回答三个问题：

1. **该不该存在？** 审计找出过时、脆弱、冲突和失效的规则。
2. **是否被遵守？** 遵守情况检查在历史会话上回放规则。
3. **修改后是否更好？** 验证会比较改动前后的遵守情况和评测结果。

可以从侧栏（**配置治理**）、命令面板，或在对话中输入 `/governance` 打开。

## 审计

**概览 → 开始审计** 会读取所选工作区的每个配置面：指令文件（`CLAUDE.md`、`AGENTS.md` 及其分层）、`.claude/agents` 下的智能体文件、技能、角色、模板、自定义模式、预设、工作区指令和提示词覆盖。除非开启 **审计内置提示词**，否则会跳过你从未修改过的内置提示词。

对每个配置面，插件会对照仓库检查其中提到的路径和包脚本，用版本控制为每一行标注日期，并查找 Anthropic prompt-audit 方法中的模式（大写强调、思考脚手架、针对旧模型的变通写法、历史叙述、罗列触发示例、过长的技能）。然后对每个配置面调用一次模型，按你的 **目标模型** 进行评判；再调用一次，比较不同文件中针对同一事项的规则。

模型的回答在展示前会被校验：一条发现必须使用已知模式、引用真实存在的行号，并引用这些行上确实存在的文字。无法脱敏的文本从不发送给模型，该配置面只做本地检查。

## 发现

每条发现会显示位置、引用的证据、模式、理由、置信度和建议的处理方式。有把握的修改会附带差异对比。

- **选中建议的修改** 会选中普通修改。冲突和失效事实类修改标记为 **需手动选择**：它们依赖任何有提交权限的人都能写入的文本，因此需要你逐条选择。
- **应用所选** 会通过各自的所有者写入每个配置面。每个配置面的改动在写入前都需要你确认；审计之后被修改过的配置面会被拒绝写入。
- **保留这条规则** 表示这条规则应当保留；被保留的发现不再计入统计和报告。
- **在提示词中心打开** 会打开该配置面及其编辑器和修订历史。

## 遵守情况

**生成检查项** 会把与工具使用相关的规则转换为检查项（调用一次模型）：某件事绝不应发生、之后必须跟随，或之前必须先做，范围为本轮或本会话。关于语气或判断的规则会被报告为不可检查。

**回放会话** 在本地对最近的会话运行这些检查，不调用模型。对每条规则，你可以看到它适用的次数和被遵守的次数、调用样例，以及它是否在长会话后段更常被打破——这说明需要调整的是它的位置，而不是措辞。如果检查误读了某个样例，可以标记为 **不是匹配**；标记在下次回放时生效。

## 强制

未被遵守的规则可以在某个工作区的会话中或所有会话中强制执行：

- **提醒** 允许调用继续执行，并把规则附加到工具结果中。
- **阻止** 会拦下调用并告诉智能体原因。“之后必须跟随”类规则无法阻止尚未发生的调用，因此会改为提醒。

在插件设置中关闭 **运行强制规则** 可以暂停全部规则。

## 验证

对每次应用的改动，**对比** 会在改动之前创建的会话和之后创建的会话上回放相同的检查项。**评测 A/B** 会在该工作区分别于改动前（基线）和改动后（候选）运行同一个评测数据集。数据不足以得出结论时，对比结果会如实说明。

## 漂移检查与隐私

每周一次的 **配置漂移检查** 会在不调用模型的情况下重新审计，并在配置面发生变化或引用的路径、脚本消失时通知你。在你于调度器中恢复它之前，它保持暂停。

可能含有密钥的设置——钩子、MCP 服务器、权限规则——由应用汇总（事件、工具、模式、可执行文件名）。插件从不读取其内容，也从不发送给模型。
