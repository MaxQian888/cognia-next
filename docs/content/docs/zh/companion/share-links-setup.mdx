# 公开分享链接（零知识）

Cognia 可将对话记录、工作流图、A2UI 应用或备份包生成任何人都能通过浏览器打开的短链。内容在**用户设备上端到端加密**：随机密钥在本地生成，放入 URL 的 `#fragment`，且**永不上传**。worker 只保存密文，由接收方的浏览器解密。`#fragment` 不会发送给任何服务器，因此宿主也无法读取分享内容。

这是**自部署、单租户**模型，与 signaling 服务器一致：你把 worker 部署到**自己的** Cloudflare 账号，再让应用指向它。读取是公开的（拿到链接即可看）；创建和撤销链接需要只有你持有的 bearer 密钥。

<Callout type="info">
  对免费额度友好：Cloudflare R2（10&nbsp;GB 免费）、Workers KV、Workers
  均有足够个人使用的免费层。
</Callout>

## 可分享的产物

| 产物 | viewer 的呈现方式 |
| --- | --- |
| 对话导出（HTML / 动画） | 沙箱 iframe 内联渲染 |
| 对话导出（Markdown / JSON / 文本） | 预格式化文本 |
| 工作流图片 | 一张 PNG |
| 备份包 | 下载（在 设置 → 数据 里重新导入） |
| A2UI 应用 | 在浏览器中实时渲染（只读） |
| 会话中的文件（单独分享，或随对话导出一起） | 文件列表：可下载，图片、PDF 和文本可在浏览器中预览 |

## 前置条件

- 一个 Cloudflare 账号，并安装 `wrangler`（`npm i -g wrangler` 后 `wrangler login`）。
- 可选：若想用自定义域名（`share.example.com`），需要域名托管在 Cloudflare DNS；否则 worker 可经 `*.workers.dev` 访问。

## 部署 worker（API）

worker 位于仓库的 `services/share-server/worker/`，是独立项目（不在应用的 pnpm workspace 内）。它现在是纯 JSON API——viewer 改为应用自身的 `/share/view` 路由，单独部署到 Cloudflare Pages（见下一节）。

```bash
# 1. 安装依赖（独立项目——忽略应用 workspace）
cd services/share-server/worker && pnpm install --ignore-workspace

# 2. 创建 worker 绑定的存储
wrangler r2 bucket create cognia-shares
wrangler kv namespace create SHARE_KV
#   → 把打印出的 namespace id 填进 services/share-server/worker/wrangler.toml
#     的 [[kv_namespaces]] id = "..."

# 3. 设置应用用于创建/撤销链接的 bearer 密钥
wrangler secret put SHARE_UPLOAD_SECRET
#   → 输入一段长随机串；下面应用配置里要用同一个值

# 3b. 设置为文件读取票据签名的密钥（携带文件的链接需要）
wrangler secret put SHARE_TICKET_KEY
#   → 64 个十六进制字符，例如 `openssl rand -hex 32` 的输出。
#     不设置时链接仍可用，但无法携带文件。

# 4. 部署 API
wrangler deploy
```

<Callout type="info">
  `wrangler.toml` 把 worker 限定在 `share.cognia.cn/v1/*`，这样 Cloudflare Pages
  可以在同一主机上托管 viewer——改成你自己的域名（需该 zone 已托管在你账号），
  或注释掉 `routes` 行以仅使用 `*.workers.dev`。
</Callout>

## 部署 viewer（Cloudflare Pages）

viewer 就是应用的 `/share/view` 路由，随普通静态导出一起产出。构建应用后把 `out/` 部署到同一主机上的 Pages：

```bash
# 在仓库根目录
pnpm build
wrangler pages deploy out --project-name cognia-share-viewer
```

把 Pages 项目绑定到你的分享主机（如 `share.cognia.cn`）。worker 的`…/v1/*` 路由优先级更高，因此 `/v1/*` 命中 API，`/share/view`（以及其余静态应用）由 Pages 提供。详见 `services/share-server/pages/README.md`，其中也说明了整个应用壳会在该主机上公开可达。

无需账号也可随时跑测试（用 miniflare）：

```bash
cd services/share-server/worker && pnpm test
```

## 让应用指向它

在 Cognia：**设置 → 数据 → 公开分享链接**。

1. **分享 worker 地址**——部署后的源，如 `https://share.example.com`（末尾不带 `/v1`）。也可在构建期用 `NEXT_PUBLIC_SHARE_URL` 设置。
2. **上传密钥**——填入与 `wrangler secret put SHARE_UPLOAD_SECRET` 相同的值。它存在操作系统钥匙串（桌面）/ 加密 IndexedDB（Web）中，绝不以明文写入设置。

之后，「生成分享链接」会出现在对话导出对话框、工作流编辑器的溢出菜单、A2UI 工作区工具栏，以及备份导出卡片中。

## 链接控制

创建链接时可设置：

- **有效期**——1 小时 / 24 小时 / 7 天 / 最长 30 天。两种服务器实现默认强制执行 30 天上限，运维可配置更短的上限。省略 TTL 表示使用服务器上限，并非永久保存。创建后，对话框会显示服务器返回的实际过期时间。
- **查看次数上限 / 阅后即焚**——达到 N 次查看后链接自毁。
- **额外口令**——密钥由 `urlKey ‖ 口令` 派生，因此即便拿到完整链接、没有口令也打不开（口令请另行告知）。仍是零知识：服务器两者都看不到。

在同一设置面板（**我的分享链接**）里管理与撤销已有链接。撤销会立即从服务器删除该对象。**延长有效期**请求链接至少保留到当前时间的七天后（受服务器上限约束），保留已有的更晚过期时间，并显示服务器返回的过期时间。该操作不会缩短链接的有效期。

查看器首先读取 `GET /v1/share/:code/metadata`，此请求不消耗查看次数。元数据仅公开生命周期控制和是否需要额外口令，口令本身仍保密。受口令保护的链接会等待用户输入口令，再获取加密内容；限制查看次数的链接会先要求接收方主动打开，再消耗一次查看。对于受口令保护的阅后即焚链接，解锁会消耗唯一的查看次数；查看器将密文保留在内存中，口令错误时可以保持页面打开并重试。

请将已部署的 Rust 服务器或 Cloudflare Worker 与查看器一起升级，以启用元数据端点。旧服务器缺少该端点时，查看器不会回退到会消耗查看次数的内容请求。

## 分享文件

链接可以携带会话中的文件（ADR-0222）：

- 在会话的 **文件** 面板中点击 **分享文件…**（或某一行的分享操作），生成只包含这些文件的链接。
- 对话导出对话框中的 **生成分享链接** 带有 **文件** 区域，会话与文件可以一起分享。会话中的图片也会随之携带（内联或作为附件）；已不在本设备上的图片只按名称分享，对话框会提示。

可以选择文件或整个文件夹。文件夹会带上其中的全部内容，但看起来像凭据的文件（`.env`、私钥、`.ssh/` 等）会被计数并排除；按名称单独选中的疑似凭据文件需要再单独勾选确认。单个链接最多携带 200 个文件，单个文件不超过 512&nbsp;MiB，总计不超过 2&nbsp;GiB。

每个文件在上传前由应用加密，密钥由链接本身的密钥派生，因此文件与链接的其他内容一样是零知识的。如果分享过程中文件发生变化或上传失败，不会留下任何已发布内容。接收方打开链接后，文件在一小时内可读取（不超过链接本身的有效期）：阅后即焚链接被打开后，仍可在这一小时内下载文件。

**文件分享策略**（设置 → 数据）决定是否允许以链接分享文件，以及此类链接的最长有效期。若你属于某个组织，组织的所有者和管理员还会设置组织策略，分享以两者中更严格的一方为准。在共享会话中分享其文件，还需要 `files.share` 权限（所有者和维护者）。同一策略也决定是否允许实时的网络驱动器访问（WebDAV/SFTP）、是否允许写入以及最长有效期，见[实时共享](/docs/subsystems/conversation-files/live-sharing)。策略中的智能体分享暂未开放。

## 安全说明

- worker **被设计为不可信**——只存密文、生命周期计数和非秘密的「需要口令」标记。丢了链接就等于丢了内容（无法找回）。
- 分享含 API 密钥的备份会把它们（加密后）放到公开 URL——仅在你信任链接分发范围时这么做，并最好加上口令。
- 由于分享是零知识的，服务器端没有搜索或预览；产物的类型与标题都在密文内部。
- 文件名、大小与校验和同样在密文内部；服务器只能看到链接有多少个加密分块及其大小。
