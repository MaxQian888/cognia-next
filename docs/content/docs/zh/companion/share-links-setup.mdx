# 公开分享链接（零知识）

Cognia 可以把一个产物——对话记录、工作流图、A2UI 应用或备份包——变成任何人
都能用浏览器打开的短链。内容在**你的设备上端到端加密**：随机密钥本地生成、
放进 URL 的 `#fragment`、**永不上传**；worker 只存不透明的密文，解密发生在
收件人的浏览器里。`#fragment` 不会发给任何服务器，所以宿主在原理上也读不到你
的分享内容。

这是**自部署、单租户**模型，与 signaling 服务器一致：你把 worker 部署到**自己
的** Cloudflare 账号，再让应用指向它。读取是公开的（拿到链接即可看）；创建和
撤销链接需要只有你持有的 bearer 密钥。

<Callout type="info">
  对免费额度友好：Cloudflare R2（10&nbsp;GB 免费）、Workers KV、Workers
  均有足够个人使用的免费层。
</Callout>

## 可分享的产物

| 产物 | viewer 的呈现方式 |
| --- | --- |
| 对话导出（HTML / 动画） | 沙箱 iframe 内联渲染 |
| 对话导出（Markdown / JSON / 文本） | 预格式化文本 |
| 工作流图片 | 一张 PNG |
| 备份包 | 下载（在 设置 → 数据 里重新导入） |
| A2UI 应用 | 在浏览器中实时渲染（只读） |

## 前置条件

- 一个 Cloudflare 账号，并安装 `wrangler`（`npm i -g wrangler` 后 `wrangler login`）。
- 可选：若想用自定义域名（`share.example.com`），需要域名托管在 Cloudflare DNS；
  否则 worker 可经 `*.workers.dev` 访问。

## 部署 worker（API）

worker 位于仓库的 `services/share-server/worker/`，是独立项目（不在应用的 pnpm
workspace 内）。它现在是纯 JSON API——viewer 改为应用自身的 `/share/view`
路由，单独部署到 Cloudflare Pages（见下一节）。

```bash
# 1. 安装依赖（独立项目——忽略应用 workspace）
cd services/share-server/worker && pnpm install --ignore-workspace

# 2. 创建 worker 绑定的存储
wrangler r2 bucket create cognia-shares
wrangler kv namespace create SHARE_KV
#   → 把打印出的 namespace id 填进 services/share-server/worker/wrangler.toml
#     的 [[kv_namespaces]] id = "..."

# 3. 设置应用用于创建/撤销链接的 bearer 密钥
wrangler secret put SHARE_UPLOAD_SECRET
#   → 输入一段长随机串；下面应用配置里要用同一个值

# 4. 部署 API
wrangler deploy
```

<Callout type="info">
  `wrangler.toml` 把 worker 限定在 `share.cognia.cn/v1/*`，这样 Cloudflare Pages
  可以在同一主机上托管 viewer——改成你自己的域名（需该 zone 已托管在你账号），
  或注释掉 `routes` 行以仅使用 `*.workers.dev`。
</Callout>

## 部署 viewer（Cloudflare Pages）

viewer 就是应用的 `/share/view` 路由，随普通静态导出一起产出。构建应用后把
`out/` 部署到同一主机上的 Pages：

```bash
# 在仓库根目录
pnpm build
wrangler pages deploy out --project-name cognia-share-viewer
```

把 Pages 项目绑定到你的分享主机（如 `share.cognia.cn`）。worker 的
`…/v1/*` 路由优先级更高，因此 `/v1/*` 命中 API，`/share/view`（以及其余静态
应用）由 Pages 提供。详见 `services/share-server/pages/README.md`，其中也说明了整个
应用壳会在该主机上公开可达。

无需账号也可随时跑测试（用 miniflare）：

```bash
cd services/share-server/worker && pnpm test
```

## 让应用指向它

在 Cognia：**设置 → 数据 → 公开分享链接**。

1. **分享 worker 地址**——部署后的源，如 `https://share.example.com`
   （末尾不带 `/v1`）。也可在构建期用 `NEXT_PUBLIC_SHARE_URL` 设置。
2. **上传密钥**——填入与 `wrangler secret put SHARE_UPLOAD_SECRET` 相同的值。
   它存在操作系统钥匙串（桌面）/ 加密 IndexedDB（Web）中，绝不以明文写入设置。

之后，「生成分享链接」会出现在对话导出对话框、工作流编辑器的溢出菜单、A2UI
工作区工具栏，以及备份导出卡片中。

## 链接控制

创建链接时可设置：

- **有效期**——永久 / 1 小时 / 24 小时 / 7 天（由 Worker + KV TTL 强制）。
- **查看次数上限 / 阅后即焚**——达到 N 次查看后链接自毁。
- **额外口令**——密钥由 `urlKey ‖ 口令` 派生，因此即便拿到完整链接、没有口令
  也打不开（口令请另行告知）。仍是零知识：服务器两者都看不到。

在同一设置面板（**我的分享链接**）里管理与撤销已有链接。撤销会立即从服务器删除
该对象。

## 安全说明

- worker **被设计为不可信**——只存密文与计数。丢了链接就等于丢了内容（无法找回）。
- 分享含 API 密钥的备份会把它们（加密后）放到公开 URL——仅在你信任链接分发范围
  时这么做，并最好加上口令。
- 由于分享是零知识的，服务器端没有搜索或预览；产物的类型与标题都在密文内部。
