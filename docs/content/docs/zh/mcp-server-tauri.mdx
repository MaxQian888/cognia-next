# MCP 服务（Tauri 端）

<Status variant="stable">M3 已落地 · axum + bearer auth</Status>

<TLDR>
`src-tauri/src/mcp_server/` 是 External Bridge 的 HTTP 传输实现：axum 在 `127.0.0.1:<port>` 监听，bearer token 用 `subtle` 库做恒时比较防时序攻击，认证通过后把 JSON-RPC 请求按行喂给一个长生命的 Node sidecar（`node cognia-mcp.js`），读一行响应再回写。整条链路是顺序的（一把 mutex 串起 stdin/stdout），跟 MCP SDK 的 `StdioServerTransport` 同构。四个 Tauri 命令 `mcp_server_start / stop / restart / status` 把生命周期暴露给 React 前端。HTTP 限 1 MiB body，`/healthz` 不需鉴权，`/mcp/sse` 在 Phase 1 返回 501（SSE 留给 Phase 2）。
</TLDR>

## 适用场景

- 外部编码 Agent（Cursor、Claude Desktop、自定义 HTTP 客户端）通过 HTTP 而非 stdio 接入 Cognia 知识。
- 多个 Agent 同时挂在 Cognia 上 —— HTTP 模式让一台 Cognia 同时服务多个客户端（sidecar 串行，但 HTTP 层并发收）。
- 需要在 token 与 scope 之外加一层显式的"网络可达性"开关 —— 用户关掉 HTTP 服务即可断流。

## 不适用场景

- 多机访问 —— 仅绑 `127.0.0.1`，没有 TLS、没有跨主机授权。
- 在 Web 模式下运行 —— Tauri Rust 进程不存在；Web 用户只能用 stdio + 外部 sidecar 包。
- 不该直接调 `lib/external-bridge/mcp-server/server.ts` —— 在 Rust 进程里只有 sidecar 能跑 TypeScript handlers。

## 控制流

### 启动 (`mcp_server_start`)

<Steps>
<Step>前端 React 在 Settings 里点 Start → 调 `tauri-control.ts:startMcpServer({ port, token, settings, sidecarPath })`。</Step>
<Step>Tauri 路由到 `commands.rs:mcp_server_start`，传入 `State<McpServerState>` 与四个参数。</Step>
<Step>`McpServerState.start` 守卫：空 token → `TokenMissing`；`settings_json` 解析失败 → `InvalidSettings`；已运行 → `AlreadyRunning(port)`。</Step>
<Step>`SidecarProcess::spawn(sidecar_path, settings_json)` 拉起 `node <path>`，设置 env：<br/>　• `COGNIA_BRIDGED=1`<br/>　• `COGNIA_BRIDGE_SETTINGS=<JSON>`<br/>用 `kill_on_drop(true)` 保证 Drop 时杀子进程。</Step>
<Step>`spawn_server(port, token, sidecar)` 绑 `127.0.0.1:<port>`（`0` 让 OS 选），构建 axum router，`tokio::spawn` 起监听任务。返回 `ServerHandle { bound_port, shutdown: watch::Sender }`。</Step>
<Step>把 `(handle, sidecar)` 存进 `McpServerInner.server`、`status` 更新为 `running: true, port: bound_port, started_at`，返回 `bound_port` 给 TS。</Step>
</Steps>

### 一次 `/mcp` 请求

<Steps>
<Step>外部 Agent 发 `POST /mcp` + `Authorization: Bearer <token>`。</Step>
<Step>`RequestBodyLimitLayer(1 MiB)` 包外层。</Step>
<Step>`auth_middleware`：`/healthz` 旁路；其余从 header 拆 `Bearer …`，与 `state.token` 做 `subtle::ConstantTimeEq`。长度不同直接 401；内容比较恒时。</Step>
<Step>认证过 → handler `mcp_post` 把 body 转成 UTF-8 字符串、空体 → 400。</Step>
<Step>`state.sidecar.round_trip(&request_str)` —— 拿 `Mutex<SidecarIo>` 锁，`stdin.write_all(line + "\n")` + `flush()`，然后 `stdout.read_line` 读一行。空响应即 sidecar 关闭 → `SidecarIo`。</Step>
<Step>把响应字符串 `serde_json::from_str` 当 Value 透传回客户端（避免 SDK 加扩展字段时被二次序列化丢字段）。Sidecar 故障 → 502 Bad Gateway。</Step>
</Steps>

### 停止 (`mcp_server_stop`)

<Steps>
<Step>`McpServerState.stop` 拿 inner lock，把 `(handle, _sidecar)` 用 `Option::take` 取走。</Step>
<Step>`handle.shutdown.send(())` 通知 axum graceful shutdown future，监听任务跑完正在处理的请求后退出。</Step>
<Step>`_sidecar: Arc<SidecarProcess>` 离开作用域 → `kill_on_drop` 触发 → Node 子进程被杀。</Step>
<Step>`status` 重置为 `McpServerStatus::default()`（`running: false`）。</Step>
</Steps>

`restart` = 容错 `stop` + `start`，原子地完成；前端不用自己去 race 两次 IPC。

## Sidecar 进程模型

### Option A：长生命 + 串行

`sidecar.rs` 的设计注释明确选了"持久 sidecar + mutex"模式，不是"每次请求 spawn 一次"也不是"多进程多路复用"：

```rust title="src-tauri/src/mcp_server/sidecar.rs"
pub struct SidecarProcess {
    request_lock: Arc<Mutex<SidecarIo>>,
    /// Kept alive so `kill_on_drop` fires when we are dropped.
    _child: Child,
}
```

理由：

- MCP SDK 的 `StdioServerTransport` 本身就是顺序的；多路复用收益为 0。
- 单 mutex 防止两个 axum handler 的 stdin/stdout 字节交错。
- 长生命让 Node v8 引擎、handler 模块、Dexie 适配器只初始化一次，p50 延迟稳定。

### 子进程 env

| 变量                     | 来源                       | 用途                                        |
| ------------------------ | -------------------------- | ------------------------------------------- |
| `COGNIA_BRIDGED`         | 固定 `"1"`                 | `standalone-entry.ts` 用它选择 bridged 模式 |
| `COGNIA_BRIDGE_SETTINGS` | `mcp_server_start` 的 JSON | 一次性灌入；改 scope 需 restart 服务        |

注意 stderr 用 `Stdio::inherit()`，sidecar 的 console.error 直接落到 Tauri 主日志。

### 测试 hook

`sidecar.rs:spawn_echo_for_tests` 拉一段 inline node `-e "..."` 做 stdin → stdout 行回显，用于 `http_server.rs` 和 `mod.rs` 的集成测试。Node 不可达时测试返回 early skip，CI 不强依赖 Node。

## HTTP 端点

| Method | Path       | 鉴权   | 行为                                                                            |
| ------ | ---------- | ------ | ------------------------------------------------------------------------------- |
| GET    | `/healthz` | 无     | `{ "ok": true, "version": "<CARGO_PKG_VERSION>" }`                              |
| POST   | `/mcp`     | Bearer | 一行 JSON-RPC 入、一行 JSON-RPC 出                                              |
| POST   | `/mcp/sse` | Bearer | Phase 1 占位 → 501 + `{ error: "SSE streaming is not implemented in Phase 1" }` |

```rust title="src-tauri/src/mcp_server/http_server.rs"
const BODY_LIMIT_BYTES: usize = 1024 * 1024;   // 1 MiB

let app = Router::new()
    .route("/healthz", get(healthz))
    .route("/mcp", post(mcp_post))
    .route("/mcp/sse", post(mcp_sse))
    .layer(from_fn_with_state(state.clone(), auth_middleware))
    .layer(RequestBodyLimitLayer::new(BODY_LIMIT_BYTES))
    .with_state(state);
```

## Tauri 命令清单

四个命令构成完整的生命周期接口；它们与 TS 端 `lib/external-bridge/tauri-control.ts` 1:1 对齐。

| 命令                 | 入参                                                                             | 出参              | 备注                                      |
| -------------------- | -------------------------------------------------------------------------------- | ----------------- | ----------------------------------------- |
| `mcp_server_start`   | `port: u16` · `token: String` · `settings_json: String` · `sidecar_path: String` | `u16` 已绑定端口  | `port=0` 让 OS 选；返回值是真实端口       |
| `mcp_server_stop`    | —                                                                                | `()`              | 已停 → `NotRunning` 错误                  |
| `mcp_server_restart` | 同 start                                                                         | `u16` 已绑定端口  | 容错 stop + 全新 start                    |
| `mcp_server_status`  | —                                                                                | `McpServerStatus` | `{ running, port, started_at(ISO-8601) }` |

### TS 调用样例

  return transport.call<number>("mcp_server_start", {

## 错误模型

`McpServerError` 用 `thiserror` 派生，序列化时实现成单字符串（便于 React 直接 toast）。

| 变体                      | 含义                                                 |
| ------------------------- | ---------------------------------------------------- |
| `AlreadyRunning(port)`    | 已有服务在 port 上跑                                 |
| `NotRunning`              | 调 stop / status 时服务没在跑                        |
| `Bind { port, source }`   | TCP 绑定失败（端口被占、权限不足）                   |
| `InvalidSettings(reason)` | `settings_json` 不是合法 `ExternalBridgeSettings`    |
| `TokenMissing`            | token 为空字符串                                     |
| `SidecarSpawn(reason)`    | `node <path>` 拉起失败（node 不在 PATH、脚本不存在） |
| `SidecarIo(reason)`       | stdin/stdout 读写失败、sidecar 异常退出              |

## 安全考量

- **绑定面**：仅 `127.0.0.1`，无 TLS。Phase 1 假设攻击者已经能在用户机器上跑代码；不防本机其他进程嗅探（OS 级 namespace 隔离需 capabilities 系统支持）。
- **Bearer token**：32 字节随机 hex（64 字符），`subtle::ConstantTimeEq` 防时序。token 在前端用 `crypto.getRandomValues` 生成，存 IndexedDB 明文。Token 旋转通过 restart 服务 + 改 setting。
- **Body 限制**：1 MiB（MCP envelope 可能比 remote-control 的 8 KiB 大；测试里有 `assert!(BODY_LIMIT_BYTES > 8 * 1024)` 自我约束）。
- **CSRF**：MCP 是 JSON-RPC over POST，Authorization header 自带；不存在 form 重放风险。
- **DoS**：sidecar 串行 → 单条慢请求会阻塞后续；axum body limit + handler timeout（由 sidecar 内部决定）是主要兜底。

## 已知限制 / 开放问题

- **SSE 未实现**：`POST /mcp/sse` 返回 501，客户端只能用单请求-单响应。MCP SDK 已支持 SSE，Phase 2 接通。
- **IP 允许列表缺失**：本机所有进程都能访问；Linux 容器化部署时需要额外的 netns 隔离。
- **sidecar 重启策略**：当前 sidecar 崩溃后 HTTP 仍接连接但 `round_trip` 返回 `SidecarIo` 错误；自动重启留给后续版本。
- **Token 持久化**：明文落 IndexedDB。计划在桥支持远程访问后迁移到 OS keyring（参见 `lib/anthropic-subscription` 用 `keyring` crate 的范例）。
- **跨平台 sidecar 路径**：当前 `external-bridge-section.tsx` 用 `homeDir/.cognia/cognia-mcp.js` 兜底；Phase 2 npm 插件包会改成 Cognia 安装目录下的 resource 路径。
- **多 sidecar**：现在一台 HTTP 服务对应一个 sidecar。如果要把 Cognia 暴露给多个隔离的 scope 集合（同时允许"只读 wiki"和"读 + twin"两套客户端），需要做 sidecar pool 或 multi-server 重构。
- **测试覆盖**：集成测试需要 `node` on PATH，CI 上 Node 缺失时所有 round-trip 测试 early-return。单元测试用 `subtle::ConstantTimeEq` 模拟覆盖鉴权分支。
