# 个人微信（iLink）配置指南

本指南将引导你通过 **iLink 网关** 扫码登录，把一个个人微信账号接入 cognia-next。

---

## 1. 风险须知

请在开始前认真阅读：

- 这是一条经由 **iLink 网关**（`https://ilinkai.weixin.qq.com`）的 **非官方** 接入通道，**不是** 微信官方提供的机器人能力。
- 个人微信账号的自动化收发消息 **可能违反微信的使用条款**，存在 **真实的封号风险**。
- 请务必使用一个 **非主力** 的微信账号接入。不要用绑定了支付、重要社交关系或工作往来的主账号。
- 由于该通道为非官方且依赖第三方网关，其可用性、协议与限制都可能随时变化，cognia-next 无法保证其长期稳定。

如果你不能接受上述风险，请改用官方支持的连接器（如企业微信、Slack 等）。

---

## 2. 扫码登录接入

iLink 没有静态的令牌或密钥，接入完全通过手机扫码完成。**扫码登录依赖网关，仅在桌面端（Tauri）可用。**

1. 打开 cognia-next，导航到 **设置 → 平台连接 → 适配器**。
2. 点击 **添加连接器**，在列表中选择 **个人微信（iLink）**。
3. 在弹出的配置对话框中，为该连接填写一个 **显示名称**（例如 "我的微信小号"）。
4. 点击 **获取登录二维码**。对话框会展示一张二维码图片。
5. 用 **手机微信** 的「扫一扫」扫描该二维码，并在手机上 **确认登录**。
6. 登录状态会随扫码进度自动推进：**等待扫码 → 已扫码 → 登录已确认**。
7. 确认后，网关会返回 `bot_token` 与 `baseurl`，cognia-next 自动持久化——`bot_token` 写入系统钥匙串，`baseurl` 存入连接设置。
8. 点击 **创建** 完成接入。

> **二维码会过期**：如果迟迟未扫码，状态会变为「二维码已过期」。此时重新点击 **获取登录二维码** 生成新的二维码即可。

---

## 3. 验证连接

由于本通道 **仅能回复**，无法主动发起对话，因此验证步骤必须由对方先发起：

1. 让任意一个微信联系人 **主动给这个机器人账号发一条消息**。
2. cognia-next 收到该消息后即可回复，回复会出现在对方的微信会话中。
3. 检查 **设置 → 平台连接** 概览，该适配器的状态应显示为 **运行中**。

如果适配器显示 **降级** 或 **已停止**：

- 若状态原因为会话过期（`session_expired_rescan`），需要回到配置对话框 **重新扫码** 登录。
- 在 **平台连接** 的 **Audit Log**（审计日志）标签页中查看具体错误。

---

## 注意事项

- **仅回复（reply-only）**：机器人只能回复 **主动给它发过消息** 的联系人。每条回复都依赖对方那条入站消息携带的 `context_token` 作为回复锚点；没有这个锚点就无法发送。
- **不投递主动推送**：定时任务、工作流等需要 **主动推送** 的出站消息 **不会** 经由本通道送达——它没有主动发起会话的能力。
- **会话会过期**：当网关返回会话过期信号（`ret -14`）时，适配器会降级并停止收发，必须 **重新扫码** 登录才能恢复。
- **支持的消息类型**：
  - **入站**：文本、图片、语音、文件、视频均可接收。其中 **图片会被解密** 并内联给模型处理；语音、文件、视频以标记形式呈现。
  - **出站**：当前版本 **仅支持纯文本**。图片 / 语音 / 文件 / 视频等媒体段在发送时会 **降级为文本标记**（因为出站媒体需要 AES-128-ECB 加密与 CDN 上传握手，暂未实现）。
- **不支持富文本与交互组件**：iLink 只渲染纯文本，没有 Markdown、消息编辑 / 撤回等能力。A2UI 界面会通过其纯文本镜像（`plainTextMirror`）安全降级为文本后发送。
- **数字操作（numeric-action）**：当一个 A2UI 界面已为某个会话登记了绑定时，对方回复一个 **数字**（如 "1"）会被识别为 **点击操作** 并路由到对应的回调（例如工作流审批确认），此时不会再被当作一条普通聊天消息。这要求对方此前已收到带数字选项的 A2UI 消息。
- **桌面端限定**：扫码登录与长轮询收发都经由网关与 Tauri 的 HTTP 代理完成，因此该连接器仅在桌面端可用。
