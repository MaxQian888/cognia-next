# 微信公众号配置指南

本指南将引导你在微信公众平台开启服务器配置（安全模式），把回调 Webhook 接入 cognia，并填好访问令牌与解密所需的凭据。签名校验（SHA-1）与回调正文的 **AES-256-CBC** 解密均在 cognia 的 Rust webhook 处理器中完成。

---

## 1. 准备一个微信公众号

1. 准备一个微信公众号（推荐 **服务号**——订阅号的开发接口受限，无法使用客服消息等能力）。
2. 登录 [微信公众平台](https://mp.weixin.qq.com)，进入 **设置与开发 → 基本配置**。
3. 在该页面记录 **AppID（开发者 ID）** 与 **AppSecret（开发者密码）**。`AppSecret` 仅在生成或重置时完整展示一次，请妥善保存。

---

## 2. 在 cognia 中配置凭据

1. 打开 cognia 并导航到 **设置 → 平台连接 → 适配器**。
2. 点击 **添加连接器**，选择 **微信公众号**。
3. 在 **身份** 分区填入以下四项：

   | 字段                | 用途                                                                       |
   | ------------------- | -------------------------------------------------------------------------- |
   | `App ID`            | 基本配置里的 **AppID**                                                      |
   | `App Secret`        | 基本配置里的 **AppSecret**，用于获取访问令牌（`access_token`）与调用客服回复接口 |
   | `Token`             | 你将在第 3 步「服务器配置」里设置的、用于签名校验的令牌                       |
   | `EncodingAESKey`    | 服务器配置安全模式下的 **43 位** 密钥，用于解密回调正文                       |

4. 四项均会加密存放在系统钥匙串（OS keyring）中，不会写入明文配置。
5. 暂不要关闭对话框——你需要在下一步先复制 **Webhook 地址**，并保持 `Token` 与 `EncodingAESKey` 与微信公众平台两端完全一致。

---

## 3. 配置服务器回调

1. 在配置对话框的 **投递** 分区，复制 **Webhook 地址**。它形如 `/webhook/wechat-oa/{适配器ID}`——这是一段相对路径，你需要在前面加上你的 **公网基础地址**，拼成完整的 HTTPS URL。
2. 回到微信公众平台，进入 **设置与开发 → 基本配置 → 服务器配置**，点击 **修改配置** 并填入：
   - **URL（服务器地址）**：上一步拼好的完整 Webhook 地址。
   - **Token**：与 cognia 身份分区里填写的 **完全相同**。
   - **EncodingAESKey**：与 cognia 身份分区里填写的 **完全相同**（43 位）。
   - **消息加解密方式**：选择 **安全模式**（明文/兼容模式不受支持）。
3. 微信公众平台要求服务器地址必须是 **公网可访问的 HTTPS 入口**。在桌面端可使用 **设置 → 移动端伴侣** 里的 **Cloudflared Tunnel** 暴露一个公网地址。
4. 点击 **提交**。微信会向该 URL 发起一次校验请求（GET，携带 `echostr`），cognia 的 Rust webhook 处理器会先校验 SHA-1 签名（对 `token`、`timestamp`、`nonce` 排序后拼接哈希），随后原样回显 `echostr`；后续的消息推送（POST）则在 **AES-256-CBC** 解密后交给适配器解析。
5. 回到 cognia，点击 **创建** 保存适配器。

> 提示：调用访问令牌接口（`/cgi-bin/token`）时，微信可能要求把服务器的 **公网出口 IP** 加入公众平台的 **IP 白名单**（基本配置页内）。若回复发不出去并提示令牌相关错误，请先检查白名单。

---

## 4. 验证连接

1. 用一个 **已关注该公众号** 的微信号，给公众号发送一条文字消息。
2. 该消息应在一两秒内出现在 cognia 中。
3. 检查 **平台连接** 概览——该适配器的状态应显示为 **运行中**。

如果适配器显示 **已停止** 或 **降级**：

- 确认微信公众平台的 **Token** 与 **EncodingAESKey** 与 cognia 身份分区里的取值逐字一致，且加解密方式为 **安全模式**。
- 确认你的公网 HTTPS 入口（Cloudflared Tunnel）仍在运行，且微信「提交」校验已通过。
- 确认 `AppID` / `AppSecret` 正确，且服务器出口 IP 已在公众平台 IP 白名单内。
- 在 **设置 → 平台连接** 的 **Audit Log（审计日志）** 标签页中查看错误详情。

---

## 注意事项

- **48 小时客服窗口**：回复通过微信的 **客服消息接口**（`message/custom/send`）发送，平台规则只允许在用户 **最后一条消息后的 48 小时内** 主动下发。超出该窗口时平台会拒绝（`errcode 45015`），cognia 会将其标记为不可重试的错误——也就是说窗口外无法主动推送（如需窗口外触达，需另行申请并使用模板消息）。
- **安全模式 + 43 位 EncodingAESKey 必填**：本连接器只支持安全模式；`EncodingAESKey` 必须为 43 位，cognia 会在保存前做长度校验。其 `base64decode(EncodingAESKey + "=")` 得到 32 字节 AES 密钥，IV 取该密钥前 16 字节——解密在 Rust 侧完成。
- **仅桌面端可用**：该连接器依赖随 Tauri 一起运行的 Rust webhook 服务器来完成签名校验与解密。纯浏览器（Web）模式下没有这个 HTTP 入口，适配器无法接收回调。
- **消息能力**：当前版本仅声明文本能力（`send.text`），更丰富的消息类型会降级为纯文本；A2UI 交互界面同样降级为纯文本镜像。
