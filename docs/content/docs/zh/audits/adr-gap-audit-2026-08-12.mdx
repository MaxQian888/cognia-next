## 逐条实现复核

下表是目录审计后的第二轮逐条检查。结论含义如下：

- **已闭环**：当前已接受/核心范围同时具备代码、测试和可达的 runtime 或产品入口，未确认到缺失功能。
- **有限制**：核心可用，但仍有明确的平台限制或刻意排除的能力。
- **部分完成**：至少一项已描述或延期能力仍缺实现、未接线，或只有 stub。
- **Rollout**：实现已存在，但仍是实验、默认关闭、dark launch，或尚未达到 ADR 声明的 GA gate。
- **文档漂移**：实现已超过 ADR 的状态或 follow-up 文本；问题是文档对齐，不是已确认的用户功能缺失。
- **已取代 / 已移除**：行为已由后续架构接管，或产品明确移除。

“有限制”不自动等于缺陷；保留它是为了让产品边界清晰。证据路径指向当前 owner，不一定沿用 ADR 中的历史路径。

## 最高价值功能缺口队列

以下顺序来自逐条检查，已排除纯状态/文档清理：

1. 补齐 native plugin media parity（ADR-0016），避免缺少 Rust command 的四个 TS 操作在运行时失败。
2. 让 OCR 能力真实且可自维护（ADR-0024）：增加定时 TTL purge，并实现 Windows binding 或移除可选择的 placeholder。
3. 补齐 External Bridge producer（ADR-0008）：Claude Code 打包分发、被动 IDE ingest、crawler 与明确的 user-repository enrollment。
4. 补齐非 Windows Computer Use parity 与剩余 target UX（ADR-0020）。
5. 完成 managed-workspace migration 并退役旧 AgentTeam allocator（ADR-0111），再推进 ADR-0086/0113 rollout gate。
6. 决定 app 内 Lark tier 是否扩展到六个 family 之外（ADR-0026）；如果需要，应补 family contract，而不是依赖另行安装的 Codex skills。
7. 处理 terminal remote integration/binary transport 债务（ADR-0031/0033）与 remote development 后续阶段（ADR-0082）。
8. 为 Agent Browser、recorder、cookie import、mobile service worker、cloud browser 等 native-only seam 增加真实 shell smoke 证据。
