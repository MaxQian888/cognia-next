# ADR 0180：视频以模型读得懂的形式送达

**状态：** 已接受
**日期：** 2026-09-14
**相关：** [ADR-0168](./0168-an-edit-is-a-new-version-of-the-same-message)（故事板复用的图像引擎）、[ADR-0090](./0090-unified-agent-execution-and-gateway-compatibility)（运行时适配器）

## 背景

- **所有视频在入口就被拒收。** `isSupportedAttachmentDescriptor` 只接受图片和文档。
- **GIF 只处理了一半。** 入口为保留动画跳过缩放，但分发阶段对所有图片执行 `downscaleImage`，长边超过 1568 px 的 GIF 会被悄悄压成第一帧；更小的 GIF 以 `image/gif` 发出，模型也只读到一帧。
- **发送路径从不读取 `supportsVideo`。**

sidecar 中目前只有 `@ai-sdk/google` 能承载视频文件；`@ai-sdk/openai` 遇到 `video/*` 会抛错，Anthropic 不支持视频输入。

## 决定

以下 D1–D8 于 2026-09-14 与用户分两轮确定。

1. **默认抽帧，原视频只在能送达时提供（D1、D5）。** 未改动的视频变成一张 9 帧均匀抽样、带时间戳的故事板，前面附一段描述。面板另可选"逐帧"和"原视频"。原视频的条件：`supportsVideo` ∧ 运行时 `ai-sdk` ∧ 协议 `google` ∧ 非 IM 平台会话 ∧ 非团队房间 ∧ 非共享协作 ∧ 非外部 agent ∧ 非独立（浏览器内 BYOK）模式 ∧ 未开自动路由 ∧ 文件 ≤ 10 MB。不可用的选项一律禁用并说明原因，不隐藏。
2. **输入框预测，控制器裁决。** `resolveSendOptions` 可能解析出别的模型，所以解析后由 `enforceVideoDeliveryForRoute` 按实际线路重新校验，不满足时换成清单里备好的故事板并提示。
3. **GIF 并入视频管线（D2）。** 动图由纯函数解码器 `lib/images/gif.ts` 处理（已与 ffmpeg 合成结果逐像素比对）；单帧 GIF 仍按图片处理。
4. **v1 预处理（D3、D6）。** 截取时间段、抽帧策略（均匀 / 场景切换）、帧数。不做音频转写。原视频的截取需要桌面端 ffmpeg 重编码，没有时该控件禁用并说明。
5. **浏览器优先，桌面 ffmpeg 兜底（D4）。** 按宿主形态（而非 `isTauri`）判断；其他外壳给出拒绝原因。
6. **会话记录保存模型看到的内容（D7）。** 不保存原文件；视频产生的每个 part 都带 `videoAttachment`，由 `MessageVideoAttachmentCard` 合成一张卡片，并注明原文件未保存。描述文本不会进入编辑、引用或复制。
7. **上限（D8）。** 源文件 500 MB；原视频 ≤ 10 MB；派生图片 ≤ 10 MB（超出先降质量重编码一次）。草稿只保留 ≤ 10 MB 的视频字节，抽帧设置始终随草稿保存。

## 影响

- IM 平台会话保持原样：文件选择器不提供视频，管线关闭。
- 配对手机上的远程会话输入框不变，共享上传闸门仍拒收视频。
- 场景抽帧每帧搜索 4 个候选；关键帧稀疏的长视频会耗时数秒，进度显示在芯片和面板中，重新应用会取消上一轮。
- 新增能承载视频的协议需要加入 `NATIVE_VIDEO_PROTOCOLS` 并验证 sidecar 映射，而不是只改模型标记。

## v1 不包含

音频转写；配对手机与 IM 会话中的视频；移动端相机录制视频。
