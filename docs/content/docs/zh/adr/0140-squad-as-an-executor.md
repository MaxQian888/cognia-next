# ADR 0140 — 小队作为执行体

**状态：** 已接受
**日期：** 2026-08-22

## 背景

`/agent-teams` 与 `/agent-teams/workspace` 是六个界面共用一条路由：资产库、舰队命令中心、模板画廊、看板、对话 tab，以及十一个折叠面板的治理配置。它无法被读成任何单一的一件事；而其中与别处重复的部分早已各自漂移——四份看板、五处模板列表、两份计划审批面板、三套统计磁贴词汇。

外观问题之下是结构问题。**主对话根本够不到团队。** ADR-0045 自己的背景表就写着：chat→team 的唯一路径是 `action.team.run` 工作流节点。取而代之的是工作区里的一个对话 tab，而那个 tab 是演示而非产品界面：

- 它渲染了真正的 `<Composer>` 却不传 `session`，于是模型选择器变成不可点的芯片、effort 选择器 `return null`、附件 UI 挂着却拒绝每一次发送，斜杠命令、`#memory`、`!shell` 与网页搜索则全部作用到**主对话**去了。
- 它的发送路径完全绕过 `resolveSendOptions`，系统提示词是一个硬编码常量。没有 skills、memory、twin、MCP、hooks、权限上限，也没有工具审批。
- 它的记录从不落盘——store 的 `partialize` 明确排除 `messages`——刷新即失。
- 它强制要求以 `@提及` 开头，否则拒绝这一轮。

与此同时，这一切需要的接缝早已存在，且已有一个消费者。`AGENT_ORCHESTRATION_POLICIES`（ADR-0117）自发布起就含 `team`，配套 `orchestrationRef` 携带目标，选择器也已经在屏幕上。IM 链路在用它。桌面主对话则完全忽略这根轴。

最后，"team"这个词在这里指两个不相干的东西：**角色团队**（`session.kind === "team"`，多个角色同处一室——一种会话形态）与 **Agent 团队**（受编排的小队——一个执行体）。界面上两者都叫"团队"。

## 决定

**小队是执行体，与模型、子代理同处一根轴上。** 会话可以交付给它；它不是一个要导航过去的地方。

1. **改名。** Agent Team → **Squad（小队）**；Character Team 保留「团队」。一个是会话形态，另一个是由谁来跑。

2. **绑定是一个列，而不是 composition 轴。** `ChatSession.squadId`（Dexie v177，带索引）。那根轴是设备本地的 zustand；而绑定必须能挺过刷新、抵达第二台设备、并在会话列表里可见。轴仍然**携带** id 用于单次覆盖——那本来就是它自己的文档所说的用途。

3. **路由发生在 `resolveSendOptions` 之上，永远不在其内部。** 那个函数回答的是"如何跑一次模型轮次"，而小队运行不是一次轮次。控制器在任何直连聊天簿记之前分流到 `startSquadRun`——正是 IM 链路当初分流的位置，其模块头注释早已写明：*不要第二个执行器，不要改 `resolveSendOptions`*。

4. **一个原语，两个界面。** `startSquadRun` 宿主中立，包裹 `runTeamLifecycle`——与 `action.team.run` 相同的原语，所以小队轮次获得完整管线。各界面之间真正不同的只有 `triggeredFrom` 来源、是否存在可以向人发问的通道，以及是否需要连接器绑定。

5. **小队工作期间，会话保持占用。** 会话维持 `streaming` 直到运行结算，于是期间的后续消息经由既有的 steer 路径排队，而不是在第一个小队之上再起一个。

6. **一条消息，步骤折叠。** 小队成员是实现细节。每个成员一条消息会冲垮会话流，也会与角色团队的群聊撞形态——在那里，多个角色**确实就是**会话本身。

7. **解散工作区。** 配置 → 设置页，与其他跨会话资产并列。运行态 → `/squads`。单次运行明细 → `/agent-runs`。对话 → 对话本身。

8. **说清楚一个界面做不到什么。** `resolveComposition` 一直接受 `supportedOrchestrations`，但没有任何主对话调用方传过，于是 5 个策略看起来都能选，其中 3 个选了什么也不会发生。主对话现在声明 `direct` 与 `team`，并逐一说明其余三个为何不可选——两个可经由别的路径抵达，一个尚未实现。

## 后果

- 对话 tab、它 448 行的自研渲染器、抄来的工具调用卡片与 token 行、砍到三项的操作菜单，以及整条 `runtime-streamers` 发送路径，全部移除。
- 旧的小队聊天记录被丢弃。它本来就不落盘，用户不会失去任何他们本可期待找到的东西。
- `/agent-teams` 在其自身的删除落地之前仍可路由、仍被声明，但退出导航。侧栏 id 改名时配了读取期的旧 id 别名——该 id 同时是持久化键，不配别名的改名会把该项从每一份已保存布局里**删掉**，而不是移动它。

## 修订

- **ADR-0022** — 团队运行时仍是唯一编排器，但团队**界面**不再是使用团队的地方。另：该 ADR 关于持久化的说法（teams/teammates/tasks 仅在内存）自 persist v4 起即为假，在此更正。
- **ADR-0032** — 团队能力配置迁往设置页资产库。`<PresetEditor>` 仍是唯一的成员编辑器，未分叉。
- **ADR-0045** — 它所规定的 chat→orchestration 接缝，如今在桌面界面上闭合，而不再只能经由计划内的 `teammate_dispatch`。
- **ADR-0066** — 实质不变。看板保留其 guard、CQRS 投影、Companion RPC 与插件扩展点；仅宿主迁移。
- **ADR-0117** — 编排轴获得了真实消费者，并且其 `orchestrationRef` 获得了记录源，而不再由轴自身持有。

## 推迟

有两块刻意不在本次改动内，因为另一条工作线正在并发重建同一批文件：

- **在 `/issues` 与小队任务看板之间共享一个 board 组件。**

两者均记录在 `docs/plans/` 中，含各自的具体陷阱。
