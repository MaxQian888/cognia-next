# ADR 0200 — “文件”是一个视图，只保留你想保留的

**状态：** 已接受**日期：** 2026-09-27 **相关：** [ADR-0158](./0158-artifacts-and-canvas)（产物以 Dexie 为准）、[ADR-0129](./0129-unified-global-search)（⌘K 及其 Library 分组）、[ADR-0157](./0157-references-and-result-reuse)（实体引用）、[ADR-0001](./0001-backup-schema-v3)（可移植备份）

## 背景

对话产生的内容分散在四个存储中：

| 内容 | 存储 | 可见位置 |
| --- | --- | --- |
| 产物 | `artifacts`（以 Dexie 为准） | 所属对话的产物面板，或“最近” |
| 画布文档 | `canvasDocuments` | 画布 |
| 图片（上传或生成） | `messageMedia` + `messageMediaRefs` | 展示它的那条消息 |
| 上传的文件 | 会话资产（带 `sessionAsset` 的 `messageMediaRefs` 行） | 仅所属对话 |

没有任何地方把它们放在一起，也无法跨对话按正文搜索；删除对话会把这些全部删掉：`bulkDeleteSessions` 删除媒体引用，`clearSessionData` 删除产物和画布文档。附在某个对话里的设计文档，会随对话一起消失。

## 决定

### 聚合视图，而不是副本

`/files` 读取现有存储并合并成一个卡片列表（`lib/files-library/aggregate.ts`）。内容仍在原处，“文件”只增加视图需要的信息，放在两张新表中（Dexie v231）：

- `libraryItems`：用户在“文件”中操作过的每个条目一行，键为 `kind:sourceId`，记录收藏、所属文件夹、最近从“文件”打开的时间、“从文件中移除”、“文件”上传的归属，以及快照（标题、媒体类型、大小、提取文本），使来源行不存在后被保留的条目仍有名称。
- `libraryFolders`：文件夹树，结构与 `workflowFolders` 相同。

合并规则：同一图片哈希只显示一张卡片（“在 N 个对话中”）；同一上传内容哈希只显示一张卡片；图片上传使用对应的图片卡片；若某个对话中的上传与“文件”自有上传字节相同，则并入后者。

### 保留靠引用，而不是复制

条目在以下情况下被**保留**：已收藏、位于文件夹中（包括顶层）、或是上传到“文件”的。字节位于 `messageMedia` 的保留条目，会在保留的所有者 `library:<key>` 下持有一条引用行，其会话 id 为哨兵值 `library:files`。会话 id 从不包含 `:`，因此：

- 会话删除、项目级联删除和同步墓碑（都按会话 id）都不会触及它；
- 媒体 GC（按哈希）会把这些字节视为仍被引用；
- `[sessionId+hash]` 授权永远不会命中它，所以这条引用不会授予任何对话访问权。

`libraryItems` 是权威数据，引用行是派生出来的：每次改变保留状态的写入都在同一事务中同时更新两者，恢复备份后由 `reconcileLibraryPins` 重建。产物和画布文档不需要引用行：会话清理会调用 `listKeptSourceIdsForSession`，`clearSessionData` 保留这些 id，并保留其 `sessionId`（界面显示“对话已删除”）。

对会话来源的条目执行“从文件中移除”，会取消收藏、移出文件夹，并在来源再次变化前隐藏它，来源本身不受影响。“删除”只用于“文件”自有的上传，会删除其字节，除非仍有使用过它的对话引用这些字节。带数据删除工作区时，会一并删除该工作区的“文件”条目。“清除对话”不会动 `library:` 行。

### 不属于任何对话的上传

“新建 → 上传文件”：光栅图片走聊天的 `ingestImage` 流程，其他文件作为“文件”自有原件（`putLibraryAsset`）存放在 `library:upload:<assetId>` 下，计入同一个全局资产配额。上传时使用输入框同一个 `extractAttachment` 抽取文本（最大 50 MiB），因此页面和 ⌘K 都能搜索正文。

### 在对话中使用复用现有路径

- 产物和画布文档变成与 `@` 面板相同的上下文引用。画布新增了自己的引用来源 `@canvas:`。
- 图片和文件以“恢复草稿附件”的形式追加到目标对话的草稿中，发送时由存储去重。超过 150 MiB 草稿配额的来源，改为作为会话资产绑定到对话（`bindHeldSessionAsset`），不复制字节。

目标对话为当前可发送消息的活动对话，否则新建一个。

接入过程中发现：在所有加密账户数据库中，恢复的草稿附件都已损坏——内容加密器对载荷执行 `JSON.stringify`，`bytes: Uint8Array` 读回来变成 `{"0":…}`，恢复出的文件内容是 `[object Object]`。加密器现在用带标签的 base64url 编码携带字节数组，并在解密时还原；旧数据的解析方式不变。

### 运行范围

桌面端和 Web。契约为 `standalone: "full"`、`companion: "hidden"`（“文件”列出的内容都不会同步到伴随端，配对客户端的本地副本并不是主机的资源库）、`offline: "local"`。手机端是有意的休眠状态，按三个维度标注为 `filesRequiresDesktopOrWeb`：侧栏条目为 `mobileHidden`，⌘K 提供方在手机上不返回任何结果，深链接显示说明页。

### 搜索与备份

⌘K 的 Library 分组新增三种类型：`artifact`、`canvas-document`（两者都可被引用）和 `library-file`，按工作区过滤，打开 `/files?item=` 的预览。⌘K 中按名称搜索；正文搜索在“文件”页面内进行。现有 ⌘K“Library”分组保留原名，所以页面叫“文件”。

可移植备份携带 `libraryItems`、`libraryFolders` 和“文件”自有上传的元数据，并把“文件”保留或拥有的所有字节，与对话的媒体一起通过现有媒体分区一次导出。不带对话恢复备份时，“文件”保留的内容仍会恢复。

## 影响

- 被保留的内容现在可以比所属对话存在得更久。被保留的图片和文件与其他媒体一样计入会话资产配额（上传）和存储视图。
- `messageMediaRefs` 在消息和会话资产之外有了第三种所有者。所有按会话 id 过滤的使用方不受影响；扫描整表的使用方必须使用 `isMessageOwnedMediaRef` / `isLibraryMediaRef`。
- Agent 写到磁盘上的文件和知识库文档暂未纳入“文件”；它们分别在任务工作区账本和 RAG 子系统中。
