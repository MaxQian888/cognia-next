# ADR 0199 — 智能体变体跟随其基础智能体

**状态：** 已接受**日期：** 2026-09-27 **相关：** [ADR-0198](./0198-a-runs-capabilities-are-granted-not-patched)（单次运行授予）、[ADR-0161](./0161-agent-identity-runtime-and-host)（身份与运行时）、[ADR-0030](./0030-character-pack-overlay-capability)（插件角色包及其克隆）、[ADR-0144](./0144-workspace-as-the-unit-of-work)（工作区）

## 背景

智能体（`Character`）打包了提示词、模型路由、工具、MCP 子集、技能、知识库、记忆策略、沙箱等配置。用户希望同一个智能体有多套配置：宽松版和严格版审查员、针对某个仓库调优的版本、定时任务用的低成本模型版本。

以前唯一的手段是"复制"，它会写出一个互不关联的副本。副本不记录来源（只有插件角色包的克隆为了包更新流程保留了血缘），所以之后对原版的每次修正都得在每个副本里手工重复，也没有地方能看出存在哪些副本。

工作区也无法指定会话默认使用哪个智能体，仓库专用的配置每次都得手动选择。

## 决策

### 变体只拥有它改过的字段

`Character.variant = { baseId, ownFields }`（`packages/agent-config-types/src/agent-variant.ts`）。

- **行字段**（id、名称、描述、头像、时间戳、内置标记、角色包血缘）始终属于变体自己。
- `ownFields` 中列出的**配置字段**取自变体；其余配置字段取自基础智能体当前的有效配置。被拥有但没有值的字段会清除基础智能体的值，而不是继承它。
- 基础智能体可以是用户智能体、内置智能体、插件角色包覆盖层，或另一个变体。链式解析最多 `MAX_VARIANT_DEPTH` 层，并检测循环。

`resolveCharacterById` 和 `listCharactersByIds` 会应用覆盖，因此所有运行时使用方（发送选项解析器、`executeAgent`、定时任务、团队）无需改动即可拿到有效智能体。`resolveCharacterVariants` / `listResolvedCharacters` 对已加载的列表做同样的处理。

### 行内保留完整快照

变体行仍存储一份完整的、物化的配置，即上次保存时的有效值。直接读取行的代码拿到的是一个完整的智能体。当基础智能体无法解析时（已删除、插件包被禁用、循环、链过深），变体会回退到这份快照并记录警告，而不会丢失提示词和工具。

### 编辑决定归属

编辑变体时，补丁会作用于它的有效智能体，之后变体恰好拥有与基础智能体不同的那些配置字段。某个字段被改回与基础相同的值后，会重新跟随基础。`updateCharacter` 会把对变体行的所有编辑都走这套计算（忽略补丁里的 `variant` 值），所以任何调用方都无法写入一个随后被基础值遮蔽的值。

显式操作：`createCharacterVariant(baseId, name)`（初始不拥有任何字段）、`detachCharacterVariant`（变成一个普通智能体，保留当前有效配置）、`resetCharacterVariant`（清除所有覆盖）。`deleteCharacter` 会拒绝删除仍有变体的基础智能体（`CharacterHasVariantsError`），复制变体会得到一个不再关联的副本。

设置列表按解析后的结果展示变体，标注其基础智能体和覆盖的字段数，并提供创建、重置和解除关联操作。编辑器会提示当前正在编辑变体。

### 队友可以以已保存的智能体运行

团队成员解析出的 `characterPackIds`（智能体 id：用户智能体、变体或插件角色包角色）指定它以哪个智能体运行。`dispatchTeammate` 通过 `resolveCharacterById` 解析第一个 id，因此变体会带着覆盖结果到达；`teammateToCharacter` 以该配置为起点，知识库、记忆策略、输出风格等都来自该智能体。队友自己的提示词、模型、提供商和工具会覆盖它，团队的 MCP 服务器和技能会叠加到智能体自己的配置上。无法解析 id 时，派发失败，不会替换为通用队友。

### 工作区指定默认智能体

`Project.defaultCharacterId` 是用户在该工作区新建会话时默认使用的智能体（`lib/workspace/project-default-agent.ts`，在 `startNewSession` 中应用）。它不会覆盖调用方已指定的智能体、团队或小队，也不作用于无人发起的会话（`activate: false`）。无法解析的默认值会被跳过并记录警告，工作区对话框会将其标为缺失。把它指向一个变体，就能让某个仓库拥有共享智能体的专属配置。

## 影响

- 修正基础智能体会同步到其变体。变体的设置回答的是"这套配置改了什么"，而不是"我复制了什么"。
- 变体只新增一个可选、无索引的字段，无需升级 Dexie 版本。
- 用 `getCharacter` 读取原始行的代码看到的是快照，而不是实时覆盖结果；运行时路径使用 `resolveCharacterById`。
- 团队可以复用已配置的智能体，而不必为每个成员重复填写。
- 删除一个被广泛使用的基础智能体之前，需要先显式解除或删除它的变体。
