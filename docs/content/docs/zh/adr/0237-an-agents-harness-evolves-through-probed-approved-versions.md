# ADR 0237 — Agent 的 Harness 通过经探测、经批准的版本演化

**状态：** 已接受
**日期：** 2026-10-20
**关联：** ADR-0090、ADR-0101、ADR-0189、ADR-0198、ADR-0199、ADR-0202、ADR-0230、ADR-0232

## 背景

Agent 的表现不只取决于模型，还取决于人格提示词、常驻规则、长期领域事实、工具使用方式、可加载的
Skill、Skill 携带的辅助脚本、可委派的子 Agent，以及工具循环中的中间件。在 Cognia 中，这些都在运行
出错后由人手工修改。

Harness²（arXiv 2610.14224）表明：在没有标准答案的情况下，可以针对单个任务提出修改、在同一任务上
执行、再依据行为对比组合出后继配置；有证据支持的经验库还能改进后续任务。其开源版本是研究系统：
Python 驱动、Linux 文件树、执行器网络不受限且关闭了 Codex 沙箱、没有审批步骤、经验库没有容量控制，
而论文自己的失败分析也显示最终选择器可能挑中更差的输出。

Cognia 已具备这种循环所需的大部分机制：单一的运行参数解析器（`resolveSendOptions`）、以临时 Agent
无界面运行（Eval Lab 的 chat target）、只能收窄的单次运行授权（ADR-0198）、Agent 变体（ADR-0199）、
带差异预览的配置应用与回滚（ADR-0101）、盲评 A/B 与确定性评分器（`@cognia/eval-core`）、治理账本、
隔离的 git 工作区（ADR-0230）、用量账本与运行预估（ADR-0232），以及运行学习提案流程。

## 决定

### Harness 是 Agent 档案的一部分

可编辑的 Harness 有八类组件，映射到 Cognia 的数据而不是文件：`Character.systemPrompt`；新增的
`Character.harness`，包含 `guardrails`、`memory`（长期领域事实，不是记忆子系统）、`toolGuidance`、
`subagents` 与 `toolRules`；`Character.skillIds` 中的 Skill；以及这些 Skill 携带的脚本资源。新字段属于
档案字段，因此变体可以像其他字段一样继承或拥有它们。

模型、提供商、权限模式、工具允许/拒绝列表、MCP 服务器、沙箱和工作目录会被记录，但演化永远不能修改。
子 Agent 的工具列表被收敛到父 Agent 的工具之内。用户还可以锁定更多组件。

第八类组件是**声明式**的：由内置工具循环拦截器（以及无界面运行中的 `onToolResultReview` / 权限响应器）
执行 `error-hint`、`trim-output`、`call-cap`、`verify-after-write` 规则。规则只能追加文字、缩短输出或
拒绝调用，不能放行、重新允许或执行任何东西。模型编写的代码不会作为中间件运行。

### 快照不可变且内容寻址

`HarnessSnapshotV1` 保存组件、运行时所用配置以及运行时指纹，按规范化 JSON 计算 SHA-256。编辑时，快照
被投影为文件树（`systemprompt.md`、`guardrails.md`、`memory.md`、`tool_guidance.md`、
`skills/<name>/SKILL.md`、`skills/<name>/scripts/*`、`sub_agents/<name>/AGENT.md`、`tool_rules.json`），
再解析回来；任何不在该编辑面上的内容都会被拒绝，并给出可操作的说明。

### Probe 使用聊天运行时

一次 Probe 就是对临时会话执行 `resolveSendOptions` + `runAndCaptureAssistantReply`，与 Eval Lab 的
target 完全一致，只多了三项输入（作为输入传入，而不是事后修补）：`BuildOptionsContext.harnessOverlay`
（候选的 Harness 段落、内存中的 Skill 及其资源、子 Agent、工具规则）、Probe 能力授权（除非用户加入
白名单，否则不使用 MCP；禁用团队与派发工具；禁用已知有副作用的工具；权限上限；轮数与金额上限），以及
隔离的工作目录（`none`、输入文件的临时副本，或固定 git 基线上的任务工作区）。授权把权限模式上限设为
`default`，使每个有变更的调用都要经过决策，而不是走模式捷径。Probe 专用的权限响应器在无人值守时做出
决策：文件工具只允许在本次执行的目录内使用；Shell 命令只有在共享的命令分类器判定其不涉及远程、全局安装、
提权或系统命令、也不访问目录外路径时才放行；其余一律拒绝并记录在该次执行上。一方插件工具被收窄到一个
很短的白名单。会话删除之前，轨迹、交付物、span 与用量都会被采集。

### Propose–Probe–Compose，并行与顺序

循环遵循 Harness²：k 次参考执行；通用（invariant）与领域（domain）编辑器；每个候选执行一次；依据全部
证据组合；并行（2k 个候选、k 次组合）或顺序（k 轮，携带检查点与历史）。编辑器读取证据树（任务、完整
轨迹、交付物、当前 Harness、带差异的候选池、先前决策、经验库条目），返回修改后的树。无效的树会带着
校验信息重试一次，仍无效则该阶段继承当前 Harness。桌面端编辑器作为限定在临时目录、只有文件工具的
Agent 会话运行；其他环境使用结构化通道，以 JSON 返回修改后的文件。

### 选择可以保留基线，确定性检查优先

硬性门槛（Probe 策略、交付、确定性检查、已批准的验收配置）先于任何模型判断执行。盲评选择器比较各最终
候选**以及**基线参考；k = 1 时，组合出的 Harness 必须在与基线的盲评 A/B 中胜出。若没有候选通过基线能
通过的门槛，或判断不确定，则保留基线并记录原因。

### 采用即可回滚的版本

任务范围以外的每次采用都是一次 `agent-harness` 配置应用（ADR-0101 机制）：保存之前的投影、展示字段级
差异，并在出现无关修改后拒绝回滚。会话范围把会话切换到演化变体；工作区范围创建或更新演化变体，并询问
是否设为该工作区默认 Agent；全局范围直接更新 Agent。由于 Skill 是共享的，演化出的 Skill 采用写时复制，
绝不原地修改。风险等级（`low`、`medium`、`high`）决定是否需要审批；只有低风险的任务/会话范围采用在用户
开启后才可自动进行。审批与生效结果写入治理账本。插件与配对设备没有采用接口。

### 经验受治理，而不是记忆

运行结束后，反思器写出修改归因行，并至多写一条经验。条目保存采用的快照、适用条件、范围、领域、运行时
指纹与状态。只由 confounded 行支撑的经验保持 `proposed`。检索结合可见性、领域、结构化匹配与 BM25。
写入时合并近似重复项、标记相互矛盾的条目待审，并在超过上限后按效用淘汰。经验只是编辑器的输入，永远
不会写入 `memories`，也不会未经新的 Probe 就被应用。

### 成本显式可见

一次运行安排 R = 4k 次执行与 P = 3k 次编辑会话，另加选择与反思。开始前显示 ADR-0232 预估；迭代数、
候选数、并行度、模型调用数、token、金额与时长的上限，通过在每一步开始前预留该类步骤观察到的最高成本
来执行。用量记在新的 `harness-evolution` 用量面上。该功能默认关闭，模式为 `manual`、
`failure-triggered` 与 `background`；不会针对每条消息运行。

## 实现

引擎由 `lib/harness/` 下的纯模块和 `lib/harness/runtime/` 下的适配器组成，使用四张 Dexie 表
（`harnessSnapshots`、`harnessEvolutionRuns`、`harnessEvolutionSteps`、`harnessExperiences`，schema
v247），界面位于 `components/harness/`。它只在桌面端运行：设置分区、初始化器与后台清扫任务只在桌面端挂载；
由 Host 持有会话的配对客户端不会启动运行。

### 运行是带租约的任务

状态机为 `queued → snapshotting → reference_running → proposing ⇄ probing ⇄ composing → evaluating →
reflecting → awaiting_approval → adopting → completed`。反思在决策之后、等待用户之前执行，因此即使审批
拖上几天也不会占用任何工作，所有模型调用都在运行活跃时完成；反思失败不会让运行失败。保留基线的决策在
反思后结束；设置允许自动采用的低风险决策会跳过 `awaiting_approval`。

每个运行由一个驱动器通过续约的租约持有，所有运行写入都是基于 `version` 字段的比较并交换：来自另一个
窗口的取消或恢复后的驱动器会胜出，失败的驱动器停止且不再写入。步骤是以 Harness² 标签为键的行
（`base1..k`、`inv1..k`、`dom1..k`、`agg1..k` / `c1..k`、`select`、`reflect`）；成功的步骤不会再次执行，
被已终止的驱动器遗留为 `running` 的步骤只有在用户恢复运行时才会作为新的尝试重新执行。启动时租约已过期的
运行会变为 `interrupted`，不会被悄悄地再次花钱。基础设施失败（超时、服务中断、限流）会让一次执行重试
一次，之后让运行失败，因为它不是关于 Harness 的证据。

### 花费由用量账本折算

运行不在内存中累计花费。每一步开始前，都会从该运行的 `harness-evolution` 用量行重新折算账本；如果该类
步骤观察到的最高成本（尚无观察时使用开始前的预估）会超出某个上限，该步骤就被拒绝。此时运行以
`budget_exceeded` 结束并保留基线；但在顺序模式的轮次边界上，运行会提前停止并在已完成的轮次中选择。
提供商未报告价格的步骤会把账本成本标记为下限，此时由 token 与调用次数上限把关。`maxBudgetUsd` 由
Claude Agent SDK 通道强制执行；在其他通道上只是建议值，执行证据中会带有相应说明。

### 选择先看证据再看判断

每次执行都有一个确定性排名（无错误、已交付、失败检查更少、通过检查更多、工具失败更少）。候选按其最差的
一次重复计算；基线按其最好与最差两次计算。低于基线最差一次的候选属于退化，被排除；只有一个最终候选
全面优于基线时，直接选中而不调用评审模型。否则，包括基线在内的竞争者以种子化的匿名 id 交给盲评模型。
评审失败、置信度低或判定基线更好时都保留基线。这修正了 Harness² 中评审模型选了 55 分而不是 95 分输出的
失败。

### 执行结果复用

一次执行的缓存键包含 Harness 内容哈希、任务输入哈希（提示词、输入文件哈希、固定的 git 基线、检查项）、
环境指纹（应用版本、运行时、执行模型、隔离方式、轮数上限、Probe 策略、工具规则引擎版本）以及重复序号。
以下情况即使命中也拒绝复用：执行因基础设施原因失败或被取消、超过七天、其携带的库 Skill 已漂移，或它
读取了本机以外的数据——证据会记录每个网页读取工具或第三方 MCP 工具的调用（`externalReads`），这样的
执行只是变化世界中的一次采样，而不是可重复的实验。

### 经验检索

检索先按可见性（Agent、工作区、全局）和领域过滤，再用 BM25（`@cognia/rag` 索引）对情境、经验、条件与
标签排序，并结合结构化匹配，对来自其他运行时指纹的条目降权。当采用的 Harness 携带了反思认定有帮助的
修改，或后续获得该条目的运行报告有帮助且无害时，条目变为 `verified`；反复有害则被拒绝。每个 Agent 的
经验库有上限（`experienceCapPerAgent`，默认 200），超出后按效用淘汰。

### 已采用的工具规则在真实对话中生效

Probe 自行应用候选的工具规则。采用之后，同一个纯投影函数运行在 `tool.result.project` 拦截点
（ADR-0189）上，交互式聊天、无界面采集与定时运行都会派发该拦截点。只有当某个 Agent 已采用规则时才注册
该拦截器，因为注册后每一轮都要承担一次工具结果审查往返；Probe 会话被排除在外，以免规则被应用两次。
调用次数上限按轮计数。

### 触发方式

- `manual`：在 Agent 的**演化**页面通过表单启动运行，表单会显示 ADR-0232 预估以及会触及哪些上限。
- `failure-triggered`：当一轮以 Harness 相关的诊断码失败时（`budgetExhausted`、`deadlineExceeded`、
  `contextWindowExceeded`、`dispatchRejectedCycle`、`dispatchRejectedDepth`、`dispatchRejectedPolicy`），
  错误下方会出现一个提议，任务内容预填为最后一条用户请求。提议遵守冷却时间和按 Agent 的忽略设置，并且
  在该 Agent 仍有未完成的运行时不会重复出现。提供商故障与权限拒绝不属于 Harness 失败，不会触发提议。
- `background`：同样的失败改为排队一个运行。每小时一次的调度维护任务（`harness-evolution-sweep`）启动
  排队的运行，同时进行的不超过 `backgroundMaxRunsPerSweep` 个，且距上一次启动不少于
  `backgroundIntervalHours`，因此每天的花费至多为（24 / 间隔）× 每次清扫运行数 × 单次运行预算。排队超过
  一周的运行会被取消。

### 恢复早先的版本

版本历史列出 Agent 的每个快照（捕获、候选、组合、采用、恢复）。恢复某个版本会创建一个新的 `restored`
快照，其父快照是当前 Harness，并通过同一个 `agent-harness` 配置应用写入，因此恢复本身也可以撤销；它按
采用的风险规则评级、记录到治理账本，并且如果在用户查看差异之后 Agent 的 Harness 又发生了变化，恢复会被
拒绝。模型、权限与工具保持不变。

### 界面

Agent 详情页新增**演化**模式（运行、经验库、版本历史）；运行在 `/agents/evolution?run=<id>` 打开，包含
时间线、实时预算仪表、候选对比、决策与反思；设置中新增 Harness 演化分区（功能开关、启动方式、默认值、
预算、各角色模型、可在 Probe 中使用的 MCP 服务器、后台节奏、经验库上限）。

### 基准测试

`lib/harness/benchmark.ts` 使用真实的驱动器、存储、检查、账本、复用与选择逻辑，只模拟执行、编辑器与
评审，覆盖八个已知正确答案的场景（明确改进、有害修改、误导性评审、不确定的平局、不稳定的执行器、两轮
顺序修复、预算停止、服务中断重试），报告决策准确率、错误采用、错过的改进、预算超支以及 R = 4k / P = 3k
计数。它不花钱，也不需要提供商；它不衡量真实编辑器发现改进的能力。

## 影响

- Probe 复用聊天解析器的全部收敛机制（工具过滤、受限模式、父级上限、最终化器）；候选的能力永远不会
  超过 Agent 本身。
- Agent 档案新增可见的 Harness 段落；演化变体清楚地显示一次采用拥有哪些字段。
- 证据与快照占用本地存储；轨迹文本有上限，每个 Agent 保留最近 100 个已结束的运行以及所有采用仍在
  生效的运行，不再被引用的快照随之清理。
- 选择结果经常是保留基线。当证据不支持修改时，这正是预期结果。
- 读取 MCP 服务器或网络工具的执行永远不会被复用；需要外部副作用的任务除非用户把只读服务器加入白名单，
  否则不能 Probe。
- Probe 策略放行的 Shell 命令在本机运行。临时目录或工作树不是沙箱；除非 Agent 运行在沙箱运行时中，否则
  每次执行的证据都会说明这一点。
- 已采用的工具结果规则在 Claude Agent SDK 通道上不生效；对自动放行工具的调用次数上限在调用执行之后才
  生效。
- 外部运行时（Codex、Claude Code 以及其他 ADR-0217 Agent）不能演化；它们的 Harness 不归 Cognia 编辑。
- 运行、快照与经验仅保存在本设备，不会同步。
