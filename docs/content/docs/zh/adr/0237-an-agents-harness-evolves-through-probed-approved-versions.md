# ADR 0237 — Agent 的 Harness 通过经探测、经批准的版本演化

**状态：** 已接受
**日期：** 2026-10-20
**关联：** ADR-0090、ADR-0101、ADR-0189、ADR-0198、ADR-0199、ADR-0202、ADR-0230、ADR-0232

## 背景

Agent 的表现不只取决于模型，还取决于人格提示词、常驻规则、长期领域事实、工具使用方式、可加载的
Skill、Skill 携带的辅助脚本、可委派的子 Agent，以及工具循环中的中间件。在 Cognia 中，这些都在运行
出错后由人手工修改。

Harness²（arXiv 2610.14224）表明：在没有标准答案的情况下，可以针对单个任务提出修改、在同一任务上
执行、再依据行为对比组合出后继配置；有证据支持的经验库还能改进后续任务。其开源版本是研究系统：
Python 驱动、Linux 文件树、执行器网络不受限且关闭了 Codex 沙箱、没有审批步骤、经验库没有容量控制，
而论文自己的失败分析也显示最终选择器可能挑中更差的输出。

Cognia 已具备这种循环所需的大部分机制：单一的运行参数解析器（`resolveSendOptions`）、以临时 Agent
无界面运行（Eval Lab 的 chat target）、只能收窄的单次运行授权（ADR-0198）、Agent 变体（ADR-0199）、
带差异预览的配置应用与回滚（ADR-0101）、盲评 A/B 与确定性评分器（`@cognia/eval-core`）、治理账本、
隔离的 git 工作区（ADR-0230）、用量账本与运行预估（ADR-0232），以及运行学习提案流程。

## 决定

### Harness 是 Agent 档案的一部分

可编辑的 Harness 有八类组件，映射到 Cognia 的数据而不是文件：`Character.systemPrompt`；新增的
`Character.harness`，包含 `guardrails`、`memory`（长期领域事实，不是记忆子系统）、`toolGuidance`、
`subagents` 与 `toolRules`；`Character.skillIds` 中的 Skill；以及这些 Skill 携带的脚本资源。新字段属于
档案字段，因此变体可以像其他字段一样继承或拥有它们。

模型、提供商、权限模式、工具允许/拒绝列表、MCP 服务器、沙箱和工作目录会被记录，但演化永远不能修改。
子 Agent 的工具列表被收敛到父 Agent 的工具之内。用户还可以锁定更多组件。

第八类组件是**声明式**的：由内置工具循环拦截器（以及无界面运行中的 `onToolResultReview` / 权限响应器）
执行 `error-hint`、`trim-output`、`call-cap`、`verify-after-write` 规则。规则只能追加文字、缩短输出或
拒绝调用，不能放行、重新允许或执行任何东西。模型编写的代码不会作为中间件运行。

### 快照不可变且内容寻址

`HarnessSnapshotV1` 保存组件、运行时所用配置以及运行时指纹，按规范化 JSON 计算 SHA-256。编辑时，快照
被投影为文件树（`systemprompt.md`、`guardrails.md`、`memory.md`、`tool_guidance.md`、
`skills/<name>/SKILL.md`、`skills/<name>/scripts/*`、`sub_agents/<name>/AGENT.md`、`tool_rules.json`），
再解析回来；任何不在该编辑面上的内容都会被拒绝，并给出可操作的说明。

### Probe 使用聊天运行时

一次 Probe 就是对临时会话执行 `resolveSendOptions` + `runAndCaptureAssistantReply`，与 Eval Lab 的
target 完全一致，只多了三项输入（作为输入传入，而不是事后修补）：`BuildOptionsContext.harnessOverlay`
（候选的 Harness 段落、内存中的 Skill 及其资源、子 Agent、工具规则）、Probe 能力授权（除非用户加入
白名单，否则不使用 MCP；禁用团队与派发工具；禁用已知有副作用的工具；权限上限；轮数与金额上限），以及
隔离的工作目录（`none`、输入文件的临时副本，或固定 git 基线上的任务工作区）。每个需要询问的权限请求都会
被拒绝并记录。会话删除之前，轨迹、交付物、span 与用量都会被采集。

### Propose–Probe–Compose，并行与顺序

循环遵循 Harness²：k 次参考执行；通用（invariant）与领域（domain）编辑器；每个候选执行一次；依据全部
证据组合；并行（2k 个候选、k 次组合）或顺序（k 轮，携带检查点与历史）。编辑器读取证据树（任务、完整
轨迹、交付物、当前 Harness、带差异的候选池、先前决策、经验库条目），返回修改后的树。无效的树会带着
校验信息重试一次，仍无效则该阶段继承当前 Harness。桌面端编辑器作为限定在临时目录、只有文件工具的
Agent 会话运行；其他环境使用结构化通道，以 JSON 返回修改后的文件。

### 选择可以保留基线，确定性检查优先

硬性门槛（Probe 策略、交付、确定性检查、已批准的验收配置）先于任何模型判断执行。盲评选择器比较各最终
候选**以及**基线参考；k = 1 时，组合出的 Harness 必须在与基线的盲评 A/B 中胜出。若没有候选通过基线能
通过的门槛，或判断不确定，则保留基线并记录原因。

### 采用即可回滚的版本

任务范围以外的每次采用都是一次 `agent-harness` 配置应用（ADR-0101 机制）：保存之前的投影、展示字段级
差异，并在出现无关修改后拒绝回滚。会话范围把会话切换到演化变体；工作区范围创建或更新演化变体，并询问
是否设为该工作区默认 Agent；全局范围直接更新 Agent。由于 Skill 是共享的，演化出的 Skill 采用写时复制，
绝不原地修改。风险等级（`low`、`medium`、`high`）决定是否需要审批；只有低风险的任务/会话范围采用在用户
开启后才可自动进行。审批与生效结果写入治理账本。插件与配对设备没有采用接口。

### 经验受治理，而不是记忆

运行结束后，反思器写出修改归因行，并至多写一条经验。条目保存采用的快照、适用条件、范围、领域、运行时
指纹与状态。只由 confounded 行支撑的经验保持 `proposed`。检索结合可见性、领域、结构化匹配与 BM25。
写入时合并近似重复项、标记相互矛盾的条目待审，并在超过上限后按效用淘汰。经验只是编辑器的输入，永远
不会写入 `memories`，也不会未经新的 Probe 就被应用。

### 成本显式可见

一次运行安排 R = 4k 次执行与 P = 3k 次编辑会话，另加选择与反思。开始前显示 ADR-0232 预估；迭代数、
候选数、并行度、模型调用数、token、金额与时长的上限，通过在每一步开始前预留该类步骤观察到的最高成本
来执行。用量记在新的 `harness-evolution` 用量面上。该功能默认关闭，模式为 `manual`、
`failure-triggered` 与 `background`；不会针对每条消息运行。

## 影响

- Probe 复用聊天解析器的全部收敛机制（工具过滤、受限模式、父级上限、最终化器）；候选的能力永远不会
  超过 Agent 本身。
- Agent 档案新增可见的 Harness 段落；演化变体清楚地显示一次采用拥有哪些字段。
- 证据与快照占用本地存储；轨迹文本有上限，运行记录遵循保留期。
- 选择结果经常是保留基线。当证据不支持修改时，这正是预期结果。
- 涉及 MCP 服务器或网络工具的执行永远不会被缓存；需要外部副作用的任务除非用户把只读服务器加入白名单，
  否则不能 Probe。
