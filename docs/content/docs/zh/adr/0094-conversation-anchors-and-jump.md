# ADR 0094 — 对话锚点与跳转

- **状态：** 已接受
- **日期：** 2026-07-29
- **关闭：** ADR-0033 的遗留项（「消息级 locate-in-conversation —— 需要 chat 的 scroll-to-message 锚点」）
- **相关：** ADR-0037（公开分享链接 —— 刻意与本文是两件事，见下）

## 背景

长对话导航这套东西已经建成 60%，而剩下 40% 的缺失一直没人发现，因为每一处断裂都是**静默**的。

`chatViewportStore` 发布了唯一的 `jumpToMessage`；右缘 `minimap/` 时间轴派生轮次并渲染轨道；
`⌘F` 能搜；消息能加星。这些全部真实接线，没有一行死码。但是：

- **跳转控件恰好在它该出现的时候不可见。** 它是滚动容器的 `absolute bottom-4` 子元素 ——
  绝对定位子元素属于滚动内容，按未滚动时的盒子定位，然后随消息一起滚走。而它只在
  `!isAtBottom`（用户已向上滚）时渲染，那正是把它带出视口的同一个条件。它同时没有可访问名称，
  两个语言包里也没有对应文案。
- **跳转可能什么都没找到，而且不吭声。** 虚拟化渲染分支只输出 `data-index`，没有 `data-msg-id`，
  所以 `jumpToMessage` 的 DOM 路径永远匹配不上。artifact dock 的「跳转到来源」调用时不传 index，
  于是一条被压缩掉的消息点击后毫无反应 —— 与按钮坏掉无法区分。
- **所有跳转的落点都一样。** `align: "center"` 是写死的，于是时间轴锚点 —— 那是用户**自己的提问**，
  去那里的意义就是往下读回复 —— 被停在屏幕中央，上半屏还压着上一轮的尾巴。
- **「到了没有」无法确认。** 落点行没有任何标记。在一段又长又重复的对话里，「刚才那下跳对了吗」
  是个真问题，而静默滚动与滚错地方是无法区分的。
- **没有退路。** 跳过去很便宜，回来只能靠滚 + 靠猜。
- **轨道压着滚动条。** `absolute right-0 z-20` 盖在一个没做细滚动条样式的滚动容器上：在任何使用
  经典（非覆盖式）滚动条的平台上，这条 16px 轨道吞掉了所有滚动条拖拽。
- **轨道静息态不可见，且只认鼠标。** 标记 `bg-muted-foreground/40`，grip 在 hover 前 `opacity-0`，
  只有 `mousemove`，`aria-hidden`，`tabIndex={-1}`。没有任何可被发现的东西。
- **面板从第一轮打开。** 在 200 轮的对话里，读者唯一已知的就是自己在哪儿，而面板偏偏不显示这个。
- **给答案加星，指向的却是问题。** 只要轮次里任一消息被加星，该轮就算被收藏，但面板始终只显示、
  只跳转到 user 消息 —— 于是你收藏的那一条，恰恰是收藏功能带不到的那一条。
- **没有消息永久链接。** ADR-0033 早就因为缺少 scroll-to-message 缝，把终端的「在对话中定位」
  推迟到了消息级之外。

## 决策

### 唯一一份跳转，且落点意图必须声明

`jumpToMessage(messageId, index?, { align })` 返回**布尔值**。`align` 是调用方的语义而非样式：
时间轴锚点用 `start`（从它往下读），搜索命中和 artifact 来源用 `center`（是要看的兴趣点）。
两个渲染分支都输出 `data-msg-id`；选择器转义统一收在 `lib/chat/message-anchor.ts`。

调用方**必须**处理 `false`。「这条消息够不到」是一个真实且常见的状态 —— 被压缩掉了，或属于一个
没打开的会话 —— 现在它是一个 toast，而不是一次死点击。

**没有落点校正循环。** `@tanstack/react-virtual@3.14.8` 实际解析到 `virtual-core@3.17.6`，后者
已自带 `scheduleScrollReconcile`：一个逐帧重定位直到偏移稳定的 rAF 循环，上限 5s。再写第二个
校正器只会把库正在进行的滚动读成漂移，然后互相打架。

### 到达要有标记

`useJumpFlash` 把落点消息保持约 1.2s（按 `motion.speed` 缩放），`JumpFlash` 在该行上绘制一层
底色加一条前缘竖条 —— 只用 `opacity`/`transform`，所以在一条工具密集的回复里闪一行不产生任何
布局开销。nonce 保证**重复跳到同一条**时会重新标记 —— 这很重要，因为用户不确定有没有生效时，
做的正是重复一遍这个动作。开启减弱动效时，标记保持不动而不是淡出。

这与查找栏的 `activeHitId` ring 刻意区分开：后者会一直保留到用户走到下一个匹配。两者可以同时
出现在同一行上。

### 一个浮标，而不是三个按钮

面板底部只有一个 pill，在三种状态间形变 —— `↩ 返回原处`、`↓ N 条新消息`、`↓ 回到最新`。
`return` 在可用时优先：它是唯一会过期的，而且回答的是用户几秒前**主动**提出的问题。优先级规则
放在纯函数 `resolveJumpPillMode` 里，不依赖 DOM 即可测试。

它渲染在**滚动容器之外**。这就是那个不可见 bug 的真修法，而且它无法用单测覆盖 —— jsdom 没有
布局 —— 所以由 `tests/e2e/mobile/conversation-anchors.spec.ts` 断言向上滚动后 pill 的
bounding box 仍在视口内。

该 spec 跑在 Capacitor 壳而非桌面浏览器工程上：浏览器构建在聊天面板的位置渲染的是「请在 Tauri
内运行」横幅。`chromium` 工程 `testIgnore` 了 `tests/e2e/mobile/**`，所以 pill 的几何只有一个
工程覆盖。**右侧时间线轨道的几何 —— 它与滚动条的分道、静息态可见性 —— 没有 E2E 覆盖**：轨道是
桌面专属（`shouldMountTimeline` 在移动端直接返回），唯一渲染它的工程是 `tauri`，而后者是可选且
串行的。它的行为有单测，布局没有。

返回点存的是滚动**偏移**而非消息 id：用户想要回去的是当时那个**视图**，而他正在读的那条消息
未必是某个轮次锚点。只留一格而不是一个栈 —— 在聊天记录里串五级「后退」是浏览器历史模型，没人
对着聊天记录提这个需求。它 8s 后过期，用户自己滚动时立即作废，因为一个过期的返回按钮承诺的是
一个他早已不在乎的位置。

跳转自身产生的滚动在事件层面与用户滚动无法区分，因此用 700ms 窗口隔离。窗口开大只是让机会多留
一会儿，开小则是丢掉它 —— 后者是安全的方向。

### 轨道拿到自己的一条车道

时间轴的两种状态现在都在文档流内。折叠轨道自己的 16px 车道对正文列几乎没有代价，却把滚动条还
了回去。标记提到 `/55`，hover 时从圆点展开成短横线；grip 静息态弱显示而不是完全透明。指针事件
取代鼠标事件（触控笔此前完全拿不到 scrub 预览），viewport 滑块可拖拽，把轨道映射到滚动范围 ——
正是滑块渲染位置的逆运算（`scrollTopForThumb`）。

### 面板显示你在哪儿

打开时把当前轮次滚到中央。sticky 日期分隔标出每个自然日的起点 —— 对一段跨天续聊的对话来说，
一百行光秃秃的时刻毫无信息量。当星标落在 assistant 回复上时，该行直接跳到**那条回复**并明说 ——
且不改动 `TimelineTurn` 模型，因为轨道标记和滚动同步的几何都按它的索引寻址。

行用 `MotionReveal` 逐条错峰进场。面板 256px 宽度一次布局到位而不做补间：宽度补间会让正文列
逐帧重新排版，并逼主列表虚拟化每帧 re-measure。日期头渲染在 reveal 包装**之外** ——
`MotionReveal` 会留下 transform，而带 transform 的祖先会成为 `position: sticky` 的包含块，
嵌在里面的头就只会粘在它自己那 40px 的行上。

### 消息永久链接 —— 以及 ADR-0033 的遗留项

`/?session=<id>&message=<id>`，沿用静态导出的深链惯用法（`useSearchParams` 包在 `<Suspense>`
边界内；`output: "export"` 下不存在动态 `[id]` 路由）。

**这不是分享链接。** ADR-0037 的分享链接把一份对话副本发布到任何人都能打开的 URL；永久链接是
私有导航，只在本应用内、针对当前用户的本地数据库解析。UI 上两者措辞严格区分（「复制消息链接」
对「分享」），因为把错的那个递给别人，不是隐私事故就是死链。

消费时会等待目标会话的历史 hydrate 完成 —— 列表只能滚到它渲染出来的行 —— 然后跳转，并用
`replaceState` 清除 query。清除不是为了好看：query 留在那里会导致之后每次渲染都重新触发跳转，
把视图钉死在被链接的消息上。10s 上限用于放弃一个失效 id，而不是一直武装着、最后打在随便什么
后来出现的消息上。

终端 tab 在 spawn 时记录 `agentSpawnerMessageId`，由**渲染端推断**为该会话最后一条 assistant
消息。plugin-tool 线协议只携带 session id，把消息 id 串过去要动 sidecar↔renderer 契约和全部
plugin-tool 调用点 —— 而换来的精确性，在「偏一条仍然落在对话的正确部位」的场景里并不划算。
此字段出现之前生成的 tab 退回普通路由。

## 后果

- 轨道那条 16px 车道会在对话超过 `TIMELINE_THRESHOLD` 且窗格足够宽时，把正文列压窄 16px。
  接受：256px 展开面板本来就会挤压正文列，这与既有行为一致，而且这是唯一能让轨道不再吞掉滚动条
  拖拽的做法。
- `agentSpawnerMessageId` 在回放、或第二轮抢在第一轮之前的场景下可能偏一条消息。它退化为落在
  正确部位附近，而不会退化为失败。
- 永久链接只在本应用内有意义。粘到别处就是死链 —— 这正是复制入口被措辞为「消息链接」而非
  「分享」的原因。
- `jumpToMessage` 的返回值现在是承重的。任何忽略它的调用方，都会把这份 ADR 消除掉的那类静默
  失败重新引入回来。
