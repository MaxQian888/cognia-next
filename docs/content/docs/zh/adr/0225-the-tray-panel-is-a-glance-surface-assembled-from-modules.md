# ADR 0225 — 托盘面板是由模块拼装的速览界面

**状态：** 已接受
**日期：** 2026-10-11
**相关：** [ADR-0165](./0165-ambient-cost-visibility-and-the-optimization-loop)（单一用量投影；花费与全工具范围均为显式开启）、[ADR-0025](./0025-unified-subscription-module)（配额来源）、[ADR-0144](./0144-workspace-as-the-unit-of-work)（工作区范围）、[ADR-0027](./0027-mobile-offline-and-discovery)（已配对手机是只读客户端）、[ADR-0058](./0058-desktop-pet-subsystem)（桌宠速览）、[ADR-0155](./0155-plugins-reach-the-host-through-one-door) / [ADR-0156](./0156-every-in-tree-plugin-is-a-third-party-plugin)（插件作者边界）、[ADR-0093](./0093-selection-toolbar-content-hugging-window)（贴合内容的窗口）

## 背景

左键点击托盘图标会打开 `tray-panel` 窗口（`src-tauri/src/tray/panel.rs`、`components/tray-panel/tray-panel-view.tsx`）。它是一个动作启动器：头部、可选的用量读数、委派表单，以及一个高度上限为 `max-h-64` 的可编辑动作列表。用户只能自定义动作（`lib/tray-panel/store.ts`，以 `trayPanel.actions.v1` 保存在 Tauri store）。窗口在 Rust 限定的 240–720 × 120–900 之间贴合内容，失焦即关闭。

它回答不了菜单栏界面最擅长回答的问题：*什么在运行、花了多少、还剩多少、接下来发生什么*。这些答案在别处都已存在，只是面板够不到：

- 运行状态（`lib/chat/aggregate-run-state.ts`）、后台任务、Agent Fleet 及其 Island（`components/fleet/`，审批由 `island-permission-actions.tsx` 负责）。
- ADR-0165 的用量投影（`lib/usage/usage-glance.ts`）、活动统计与热力图（`components/usage/usage-heatmap.tsx`）。
- 已登录 Claude（5h/7d）与 Codex（5h/每周）账号的配额窗口，以及其他额度来源（`lib/subscription/limits/`）。
- 计划议程、通知未读数、连接与同步、桌宠视图。其中几项已由桌面状态栏绘制（`components/desktop/status-bar-*.tsx`）。

其下还有四个缺陷：

1. 面板的用量读数只在托盘**标题**指标不是 `quota` 时才会获取（`lib/tray/usage.ts`）。ADR-0165 有意把 `quota` 保留为标题默认值，因此默认安装下面板的用量区永远不渲染。面板内容被耦合到一个无关的菜单栏偏好上。
2. Capacity Dock 提供了 `quota` 仪表模式却从未被供数：其初始化器不传配额，每一行都解析为 `unknown`（`lib/usage-dock/rows.ts`）。三个维度上都是“已建成但休眠”。
3. 每个辅助窗口（托盘面板、Capacity Dock）各自接收主窗口的临时状态推送。独立的 webview 无法自行刷新配额（依赖内存中已解锁的账号），也不会激活账号数据库。
4. 在移动端，`/tray-panel` 渲染“仅桌面”。移动首页有自己的一套互不相关的速览部件（运行中卡片、快捷动作宫格、紧凑 `WelcomeStats`）和独立编辑器。已配对手机看不到桌面的用量、计划或通知：`sessionUsage`、`scheduledTasks` 与 `notifications` 不在 companion 同步范围内。

## 决定

### 1. 面板负责汇总与导航，控制权留在拥有者

面板是速览界面。每个模块一眼回答一个问题，并导航到拥有该主题的界面，不重新实现那个界面的控制。

| 主题 | 面板显示 | 面板动作 | 拥有者界面 |
| --- | --- | --- | --- |
| 运行中的工作 | 按状态计数（运行中 / 待审批 / 失败）与最近几行，只读 | 打开 Fleet：Island 已打开则聚焦它，否则打开 `/fleet` 并定位到该任务 | Agent Fleet |
| 通知 | 未读数 | 打开通知中心 | 通知 |
| 计划 | 下次运行、上次结果 | 打开计划页 | 计划 |
| 配额 | 每个窗口一条计量 | 刷新、重试、启用已发现的来源 | 订阅设置 |
| 用量 | 统计条、趋势线、预算 | 切换周期 / 范围 | 用量页 |

审批与单任务停止只在 Agent Fleet 中。面板保留的唯一全局控制是现有的自动化急停开关，因为它按设计就是有三个入口的紧急停止（[ADR-0020](./0020-computer-use-completeness)）。

### 2. 模块注册表、单列、三种尺寸

**速览模块**是一个注册单元：`id`、标签键、图标、支持的尺寸（`compact` 一行 / `standard` / `expanded`）、读取的快照切片、导航目标，以及上表中的可选轻量动作。模块**单列**堆叠，不提供二维自由网格：在 320–460 px 宽度下网格只会产生碎片，而单列正是手机可以复用的形态。

**布局**是 `{ moduleId, size, hidden }` 的有序列表（移动端条目另含 `home`，见第 9 节）加一个 `presetId`。内置预设是起点：**均衡**、**用量优先**、**Agent 运维**、**极简**。任何编辑都会让布局变为 `custom`；用户可以重置为任一预设。

一方模块目录：

- `status`：头部的总体状态胶囊（空闲 / N 个运行中 / 待审批 / 自动化中）及其计数。始终存在，不是堆叠项。
- `fleet`：第 1 节所述的 Fleet 摘要。
- `usage`：今日 / 7 天 / 全部 统计条、7 点趋势线、预算条、Top 模型。
- `quota`：见第 5 节。
- `agenda`：下次计划运行与上次结果、未读数、连接与同步状态；`compact` 下合为一行，`standard` 下为多行。
- `pet`：桌宠启用时显示心情与快捷照顾。
- `activity`：用量热力图，1M / 3M / 1Y。
- `quick-actions`：现有可编辑动作目录（`lib/tray-panel/`），`compact` 为图标行，`standard` 为列表。
- `recents`：最近会话，一键恢复。
- 插件模块：见第 6 节。

委派表单不再是模块，而是固定在面板底部的**委派栏**：单行自动增高，目标与“立即发送”收进行内菜单，打开面板时可选自动聚焦。编辑态可隐藏它。

### 3. 分组列表的视觉语言，而非卡片

面板只有一个容器。模块之间以细分隔线分开，配小号分组标题。指标渲染为“数字 + 说明”的横向统计条；状态渲染为行内圆点 + 标签。不存在卡片套卡片。委派栏是唯一带底色的元素，因为它是唯一的复合输入。

头部：品牌、工作区范围切换（*全部* / *当前工作区*）、状态胶囊、刷新、设置、关闭。底栏：**编辑**、预设切换、*打开主窗口*、快照的“更新于 *x* 前”。

### 4. 高度贴合内容，上限由用户设定

高度跟随内容，直到用户设定的**最大高度**；可在设置中用滑块设定，也可拖拽面板底边。超出后模块堆叠区滚动，头部、委派栏与底栏固定。宽度分三档：窄 320 / 标准 380 / 宽 460，模块按宽度选择内部排布（统计条在标准与宽档横排，窄档竖排）。窗口几何与左键行为仍由 Rust 保存在 `tray-panel.json`，因为在 webview 存在之前就需要它们；现有 240–720 × 120–900 限制仍是硬边界。

键盘：↑/↓ 在行间移动，Enter 打开拥有者界面，→ 展开可展开行，Esc 关闭。

### 5. 配额如实表达状态

`quota` 模块列出每个**已启用**来源，每个窗口一条细计量条，显示**已用**百分比（与 Anthropic、Codex 用量接口口径一致，进度条越满越接近上限）并附重置时间；对于本机**已发现**凭据但未启用的来源（`~/.codex` 中的 ChatGPT 登录、Claude 登录），显示一行并附*启用*动作。状态使用同一套词汇：`ok`、`warn`、`exhausted`、`error`（可重试，附消息）、`stale`、`unconfigured`。`stale` 是新增的：最近快照超出其来源新鲜度窗口的计量会如实标明，而不是把旧数字当作当前值展示。刷新与重试是发往主窗口的请求，由主窗口持有已解锁账号与来源节流（`lib/subscription/limits/coalesce.ts`）。

外部编码工具只贡献花费（ADR-0165 §3）；面板不会为没有配额来源的工具虚构配额。

### 6. 插件以声明式方式贡献模块

新的插件点 `glance.module` 允许插件以**数据**注册模块：标题、统计项、行（标签、数值、状态、导航目标），以及绑定到插件自身命令的按钮。宿主用与一方模块相同的组件与视觉语言渲染，桌面与移动端皆然。插件不能向面板注入 React：面板是独立 webview，手机可能在渲染主机快照，样式也不能分叉。插件模块数据与其他内容一样经 Glance 快照传递。该插件点登记在 `lib/plugin/contracts/plugin-points.ts`，其契约登记在插件 SDK catalog。

### 7. 单一 Glance 快照

主窗口发布一份 **`GlanceSnapshotV1`**：带版本、不含内容的对象，只有数字、id、枚举、短标签与时间戳；每个模块一个切片，每个切片各自带 `updatedAt` 与新鲜度。它延续 ADR-0165 的规则：推出渲染进程的内容不携带会话内容，用户已在托盘中看到的标题除外。

消费者：

- 托盘面板窗口，取代现在的 `tray-panel://state` 推送；
- Capacity Dock，同时接收配额切片，使其 `quota` 仪表模式终于有数据（缺陷 2；经由其自有推送，见第四阶段修订）；
- 已配对手机，经 `glance://update` 事件通道以及 `glance_subscribe` / `glance_request` / `glance_quota_enable` 伴侣命令（第三阶段修订，见下文）。

用量切片按面板自身的周期 / 范围 / 指标计算，不再依赖托盘标题指标（缺陷 1）。

新鲜度：消费者可见时订阅并实时接收更新；隐藏后退订，发布者停止计算无人读取的切片。远程数据（配额）按模块以 TTL 缓存并支持手动刷新。来自消费者的请求（刷新、启用来源、打开拥有者界面、执行快捷动作、委派）经同一请求通道返回，在主窗口执行。

### 8. 范围：默认全局，可按工作区筛选

模块默认读取全局数据，因为托盘是系统级入口。头部开关可把所有支持的模块收窄到当前工作区（ADR-0144）。无法按工作区划分的模块（配额）在筛选开启时标注为*全局*。

### 9. 移动端使用同一套组件

模块组件是基于快照、与平台无关的 React。在移动端：

- 首页的运行中卡片、快捷动作宫格与紧凑统计成为同一个移动布局中的模块，只有一个编辑器。每个移动布局条目带有 `home` 标记：被图钉固定的模块按布局顺序同时出现在首页；抽屉始终渲染全部可见模块。`settings.mobileHomeLayout` 迁移到新的布局模型，现有分区成为被固定的条目。
- 移动顶栏的 **Glance** 按钮打开底部抽屉（`components/ui/drawer.tsx`），渲染完整的移动模块堆叠，即手机上的托盘面板。
- 独立使用的手机从本地数据计算切片。已配对手机对自己无法回答的主题（Fleet、用量、活跃度、计划、通知、配额，以及开关属于桌面设置的宠物）渲染主机切片，并为每个切片标注来源主机与时效。设备上不可用的模块就地说明。

### 10. 布局按设备保存在设置中

布局、预设与模块选项迁入 Dexie `AppSettings`（桌面为 `trayPanelLayout`，移动端为移动布局），因而像移动首页布局一样参与备份与账号同步。桌面与移动布局相互独立，各自可复制对方的布局。`trayPanel.actions.v1` 下的动作目录一次性导入设置，此后从设置读取。

### 11. 菜单栏标题可组合

托盘标题变为字段的有序列表：一个或多个周期的用量（`1D 103.3M · 7D 12.6B`）、运行中数量、待审批数量、最低剩余配额百分比。默认仍为**关闭**（ADR-0165）。Windows 上标题无效；设置界面会如实说明，而不是提供一个什么都不做的控件。

### 12. 原地编辑与设置页编辑

面板底栏的**编辑**进入原地编辑态：拖拽手柄（dnd-kit）、每个模块的尺寸与显隐、*添加模块*列表、预设切换、完成。设置 → 桌面 → 托盘面板提供同一布局模型的完整编辑器与实时预览，另含宽度、最大高度、标题字段与动作目录编辑器。两处写入同一个设置字段。

## 交付

每个阶段自身完整，附同目录测试、双语、changeset 与文档，并分别提交。

1. **注册表、快照、桌面面板。** 模块注册表与一方模块、`GlanceSnapshotV1` 及其发布者、重建的面板（头部、堆叠区、委派栏、底栏、宽度档位、最大高度、键盘）、Fleet 导航、含 `stale` 的配额状态、缺陷 1。
2. **编辑。** 原地编辑态、预设、带实时预览的设置编辑器、布局与动作的设置迁移。
3. **移动端。** 移动首页迁移到组件套件、Glance 抽屉、配对手机的 `glance` 通道、按切片的来源标注。
4. **扩展。** `glance.module` 插件点与 SDK 契约、可组合菜单栏标题、Capacity Dock 配额供数（缺陷 2）。

## 影响

- `tray-panel://state` 被快照通道取代，相应测试随之迁移。Capacity Dock 保留自有推送，并在其中获得配额切片（见第四阶段修订）。
- `AppSettings` 新增桌面布局字段与移动布局字段（`mobileGlanceLayout`）；手机第一次保存后者之前，读取时会把 `mobileHomeLayout` 读入其中。不涉及 Dexie 表变更。
- 新增一个插件点与 SDK catalog 条目，由 `plugin:contract:check` 与运行时插件点可达性测试（`runtime-proof-audit.test.ts`）覆盖（第四阶段修订：`audit:slots` 只检查 UI 插槽）。
- 修正两处文档漂移：`lib/tray-panel/types.ts` 中的 `action-icon.tsx` 引用（图标经 `lib/a2ui/resolve-icon` 解析），以及 `app/tray-panel/page.tsx` 中的 `BYPASS_PREFIXES` 引用（绕过列表在 `lib/shell/bypass-routes.ts`）。
- Agent Fleet 仍是审批或停止单个任务的唯一位置；面板的 Fleet 模块由测试固定为不暴露任何审批或停止控件。

## 验证

- 注册表：每个一方模块声明其尺寸、拥有者路由与快照切片；缺少任一项的模块会让注册表测试失败。
- 快照：schema 测试固定 `GlanceSnapshotV1`；内容测试断言任何切片中都不出现消息文本、提示词或文件路径。
- 缺陷 1：默认安装（标题指标 `quota`）下面板的用量模块会渲染。
- 缺陷 2：存在已登录配额来源时，Capacity Dock 的 `quota` 仪表显示比例而非 `unknown`。
- 移动端：抽屉在独立使用时从本地数据渲染同样的模块，在已配对时渲染带来源标注的主机切片。
- 桌面壳冒烟：从托盘打开面板、拖拽边缘调整高度、编辑并重排、从某行打开 Fleet、委派一个任务。

## 修订（第三阶段）：配对手机通道是事件通道，而非 host-state

§7 写的是 host-state 服务上的 `glance` 通道。实际上该服务是一套只为会话设计的持久化账本协议：通道类型封闭、有 reducer、所有副本都要处理的全局序号，以及每次提交都写入的 Dexie 账本行。速览快照恰好相反：短暂、在主窗口里由 React 数据源重新计算、被新快照取代后即无价值。因此第三阶段沿用 `fleet://update` 与文件页为手机提供桌面数据的先例：

- `glance_subscribe`（`host.observe`，读）用手机的**需求**（屏幕上需要的桌面来源模块及其依赖的选项，从不包含布局）宣告、续约或结束租约，并返回最新快照。租约以经验证的设备 id 加手机的消费者 id 为键，TTL 与托盘面板相同，为 60 秒。
- 租约存续期间，桌面按合并后的需求构建，并在按需订阅的 `glance://update` 事件通道上推送每份快照。手机收到的副本从不包含托盘操作目录与目标标题。
- `glance_request`（`host.observe`，读）刷新全部或单个额度来源；`glance_quota_enable`（`client.write`）为保险库账号开启额度查询。三个命令都不会从离线队列重放。
- 桌面声明 `glance.remote`；headless 大脑回答 `headless_host`，手机会就地说明该宿主不提供速览。

宠物也成为桌面来源的主题：它的档案会同步，但是否开启（`petSettings`）是桌面专属设置。

## 修订（第四阶段）：插件模块、标题与 Dock

第四阶段确定了上文未定或写错的五点：

- **配对手机上的插件模块只读。** 已配对的手机只显示桌面端的插件模块，从不显示自己的，并像所有桌面切片一样标注宿主；它们的动作按钮显示为禁用并注明「在桌面上操作」，也不为此新增任何写命令。需求会列出插件条目（`plugin:<pluginId>:<id>`，最多 24 个），并新增 `catalog`，使手机的编辑器在屏幕上没有桌面来源模块时也能提供桌面端的插件模块。未配对的手机运行自己的插件。需求的变化发生在配对手机通道发布之前，因此没有已部署的手机或桌面使用第三阶段的格式。
- **插件动作按名称而非命令发出。** 消费端发送 `plugin-action`，携带模块条目与动作 id；主窗口在插件发布的数据里查到命令，只运行该插件自己的 `<pluginId>.<command>`。
- **Capacity Dock 保留自己的推送。** §7 与后果一节说 Dock 的推送会被快照通道取代。它的预算行是按供应商统计的当日花费并计入未定价轮次，不是速览切片，所以 Dock 保留 `usage-dock://state`，主窗口在其中附加速览额度切片，使用与面板相同的构建器（不做登录发现；Dock 显示期间按共享节流刷新）。额度模式改为每个正在查询的来源一行，取其最紧窗口的已用比例，而不是在每个供应商行上显示同一个账户级数值。
- **标题中的额度显示为已用 %。** §11 写的是「最低剩余额度 %」。面板以已用 % 显示额度，因此标题的额度字段取最高的已用比例，口径一致（用户的选择）。标题字段保存在 `TrayDisplayPrefs.titleFields`，位于 设置 › 桌面 › 托盘 中读数模式旁，而非托盘面板的设置（§12），并且按桌面区分。字段出现之前保存的标题会迁移为其原指标对应的那一个数字。Windows 不提供标题选项，并说明原因。
- **预算读数原本没有数字。** 托盘的用量数据源从未把花费预算并入其速览，所以 `budget` 指标让图标角标与悬浮提示一直为空。现在每次速览构建都并入同一个 `usageGlanceBudget`。
