# ADR-0104 — 提供商诊断控制平面

**状态**：已接受（2026-08-01）

## 背景

旧版健康页把模型列表延迟当作模型健康，且没有可比较的历史。余额读取使用多种传输形态，也无法在不暗示“余额可相加”的情况下表达多账户。诊断必须真实有用，但不能污染生产路由健康；扩展也不能获得文件系统、进程、Cookie、环境变量或原始凭据的隐式权限。

本决策扩展 [ADR-0025](/docs/en/adr/0025-unified-subscription-module) 与 [ADR-0043](/docs/zh/adr/0043-llm-provider-execution)。

## 决策

- 通过生产提供商快照解析目标。只持久化提供商、模型、凭据记录指纹、端点身份、能力、指标、价格版本及脱敏错误；永不保存密钥、提示词、响应、请求头或响应正文。
- 分别记录网络可达性、身份验证、能力和真实执行。HTTP 400 与任意响应头都不能算作模型测试成功。
- 付费文本和向量采样复用 Sidecar `feature_call` 及聊天使用的声明式或关联代码适配器。固定版本提示词经过 PII 门禁，并禁用工具、记忆、路由回退和掩盖失败的重试。快速模式一次采样；精确模式保留一次预热并进行三次计量采样。
- 强制并发 1–5、单样本超时、最多 64 输出 token、50 个请求及已知价格 0.25 美元预算。未知价格必须确认；取消会传播到活动流并保存部分状态。
- Dexie v140 保存任务、样本、余额、刷新状态和端点回滚日志，保留 90 天且不超过 20,000 行。预热不参与汇总；P95 至少需要 20 个可比样本。
- 余额来源按账户和原生单位分开展示，不自动求和或换算。旧 `subscriptionBalance` 与 `providerLimits` 通过只读投影兼容，并展示官方、声明式、沙箱、插件或不支持类别。
- 原生认证 HTTP 保留真实状态并限制请求头和正文。QuickJS 使用全新 16 MiB 运行时，每阶段最多 250 ms、最多三个 1 MiB GET/POST 响应，并逐次重定向和 DNS 校验。额外域名、HTTP 及私网访问均需显式授权；脚本求值后仅由宿主解析该来源自己的安全凭据引用。
- 单一 Rust 调度时钟每 15 分钟检查可达性、每 30 分钟刷新主要余额来源、每两小时刷新其他来源。离线或凭据库锁定时暂停，遵循 `Retry-After`，绝不定时运行付费测速；通知只在状态跨越时触发且带冷却。
- 端点仅来自内置目录、当前配置、用户明确输入和本地 CCSwitch 只读数据。免费比较只按可达性，付费比较需单独确认。应用前展示差异，回滚使用比较并交换保护后续手动修改。
- 配对设备只获得带采集时间与桌面修订号的脱敏投影。远程任务要求桌面显式开启、设备拥有对应的 Companion 设备控制授权、主机在线且已解锁，并由发起设备确认费用。远程载荷不能携带端点、凭据、脚本、授权或价格覆盖。
- 诊断徽标仅为建议性镜像，不参与路由。生产被动流量遥测仍是自动路由与熔断健康的唯一输入。

## 验证

同目录测试覆盖统计、限制、取消、适配器、传输、沙箱策略、调度、持久化、回滚、响应式界面及配对授权。`provider-diagnostics:live` 为每个必需协议与余额类别输出 `verified`、`failed` 或 `unverified`；缺少凭据时绝不以 mock 替代。
