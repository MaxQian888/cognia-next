# ADR 0101 — 完整模型评估实验室

**状态：** 已接受
**日期：** 2026-07-31

## 背景

旧评估工作区可以承担回归测试，但一次运行由组件内 Promise 持有，用例只有单个文本输入，目标快照缺少提供方和运行环境事实，而且完成状态可能早于逐例检查点落盘。它无法可靠回答同时涉及费用、延迟、隐私、多模态、重试和统计不确定性的模型选型问题；跨数据集比较还可能产生错误分母。

## 决策

Cognia 新增面向项目的评估体系，同时保留所有旧数据集、版本、运行、校准 ID、工作流节点和插件工具的可读性。

- `@cognia/eval-core` 提供纯 schema、预检、带种子的配对 Bootstrap、Pareto 选型、决策策略、盲评分配、校准门限、自适应重复和 `cognia-eval/v2` 格式。
- Dexie v137 新增项目、不可变清单、持久任务、加密样本与资产、评分、评审、裁决、推荐、配置应用记录和 Web 密钥信封。旧报告标记为 `legacy-non-reproducible`，不得产生正式推荐。
- 云端被测模型和评审器负载经过统一 PII 门；确认本地的目标可接收原文。云端媒体必须经过扫描或人工放行；参考答案只留在评分端。
- 制品使用随机 AES-GCM 数据密钥。桌面端由系统钥匙串保护账户密钥；Web 端用 PBKDF2 密钥包装，并只在解锁会话中持有。修改密码只重包数据密钥。
- 执行持久化 `draft`、`preflight`、`queued`、`running`、`paused`、`interrupted`、`completed`、`failed` 和 `cancelled`。每次调度前预留最坏费用，云模型必须有价格；重试遵循 `Retry-After`、指数抖动和提供方并发；缺少幂等键的中断请求不得静默重复扣费。
- 纯模型执行固定复用 `createProviderSettingsSnapshot → resolveFeatureProvider → createFeatureProviderModel → generateText`。Agent 模式复用隔离的聊天、团队和工作流适配器。
- 正式选型先让所有候选运行一次，仅对接近约束或排序边界的候选增加最多两次重复；使用带种子的 95% 配对 Bootstrap，先构建 Pareto 前沿，再只对满足全部硬约束的候选应用效用权重。有效留出用例少于 30、评审校准失败、证据区间重叠或无合格候选时明确返回“无结论”。
- 主观评分采用匿名随机 A/B。低置信、格式错误或冲突结果升级到第二评审器，再进入人工盲审和裁决。正式校准要求 30 个锚点、Cohen's κ ≥ 0.6、准确率 ≥ 0.8。
- 应用推荐前展示字段级差异并显式选择目标；系统保存旧配置，应用后发生无关修改时拒绝不安全回滚。
- CLI `eval preflight/run/status/report/export` 使用原子检查点。退出码 0 表示有结论成功，2 表示无结论或门限失败，1 表示配置/执行失败，130 表示取消。

## 交互与发布

`/eval` 变为七步工作台：目标、数据、变体、评分、预检、运行、审阅。桌面端有项目栏和可调宽证据面板；平板折叠项目栏；手机使用单步画布、固定底部操作栏和抽屉。旧数据集、对比、轨迹、版本、质量门和校准保留为辅助工具。

`NEXT_PUBLIC_EVAL_LAB=1` 开启工作台；一个发布周期内可用 `NEXT_PUBLIC_EVAL_LEGACY_ROLLBACK=1` 回退。只有单测、覆盖率、类型、Lint、i18n、静态导出、PII、浏览器、Tauri、CLI 和带凭据提供方门禁全部通过后才允许切换。

## 后果

评估占用更多本地存储，查看原始证据要求账户已解锁。正式推荐更慢，也会更频繁返回“无结论”。作为交换，每个推荐都有可复现分母、明确不确定性、持久费用账本、评审来源和可逆配置变更。
