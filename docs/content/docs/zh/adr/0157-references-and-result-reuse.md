# ADR 0157 — 引用与结果复用

**Status:** Accepted
**Date:** 2026-08-29
**Related:** [ADR-0094](./0094-conversation-anchors-and-jump), [ADR-0099](./0099-chat-history-search), [ADR-0100](./0100-unified-template-platform), [ADR-0129](./0129-unified-global-search), [ADR-0134](./0134-remote-document-providers)

## 背景

组合器的 `@` 菜单长出了一层一方记录引用——`@memory:`、`@issue:`、`@plan:`、
`@chat:`、`@artifact:` 五个命名空间，注册表形状照抄
[ADR-0134](./0134-remote-document-providers) 的文档提供方——但没有 ADR。它能用，
理由散落在源码注释里。

随后，缺什么这件事从三个方向同时显形。

**粒度停在了高一层。** `@chat:` 引用的是整个会话（尾部 40 条），而且**只能靠标题**
找到那个会话。与此同时，[ADR-0099](./0099-chat-history-search) 的跨会话全文检索从
上线起就一直在跑，[ADR-0129](./0129-unified-global-search) 还把它接进了 ⌘K。组合器
一行都没用上。人记住一个对话，靠的是里面说了什么，不是它叫什么。

**唯一引用不到的，恰恰是想要的那个。** 搜索投影**刻意**丢弃工具输出
（`lib/chat/search/project-text.ts` 写明了原因：一次文件读取就是几十 KB，索引进去
会把真正的散文淹没在工具日志里，而这个语料是要常驻内存的）。`@chat:` 继承了这一点，
因为它的转录快照走的是同一个投影。于是一轮对话的产出——读到的文件、跑过的命令、
抓到的网页——在整个应用里既搜不到也引用不了。「把另一个对话里跑出来的那个结果拿过来」
这句话没有任何表达方式。

**引用记录只写不读。** 每条产生引用的用户消息都会写 `metadata.mentions`，它自己的
类型注释称之为「这一轮引用过该文档的唯一记录」。读者只有一个——搜索投影把标签折进去，
好让 chip 式的选择至少能被搜到。没有人反着读，所以应用能回答「这条消息引用了什么」，
永远回答不了「什么引用了这条记录」。

同一片区域还掉出两个小缺陷。`@chat:` 从未调用 `filterExposedSessions`，会把 subagent
内部转录和工作台旁支当成可引用的对话列出来。而每个源在去抖之后的**每次击键**都读整张
表——`listSessions()` 拉的是每一行完整的会话行——这正是
`lib/chat/search/engine.ts` 点名的「旧内容搜索犯过的同一个错误」。

## 决定

### 一份注册表，两道门

引用是一条注册表条目，不是一个功能。新增命名空间 = 一次
`registerEntityMentionSource`：纯触发器、弹层、拾取处理器、暂存路径、chip 和提示词
格式化器全部从注册表读。三张穷尽表（`ENTITY_ROW_ICONS`、`ENTITY_NOUNS`、
`UNTRUSTED_ENTITY_KINDS`）会在新 kind 未被逐一考虑前让构建失败。

注册表同时拥有**触发字符**。一个源可以声明单字符 `shortcut`；`^` 是第一个，它不需要
输入命名空间就打开结果选择器。它是同一个源的第二道**门**，不是第二套机制：检测返回的
就是普通的带命名空间实体触发，所以下游没有任何 shortcut 分支。`isMentionStart` 泛化
为 `isTriggerStart`，让 `2^3` 和 `git rev-parse HEAD^` 用早已保证 `user@host` 不是
mention 的那段代码来回答边界问题。保留字符（`@`、`!`、`#`、`/`）和重复声明在注册时抛错。

### 两种新粒度，建在索引上而不是扫描上

`@msg:` 是组合器里 ADR-0099 引擎的第一个消费者：候选按消息**内容**跨会话检索，排序和
摘要与 ⌘K 里的同一条命中完全一致。它的身份是 `<sessionId>#<messageId>`——会话那一半
不是冗余：chip 的链接、提示词里的永久链接、以及反向链接索引都需要在不做第二次查询的
前提下知道归属会话。已暂存的消息引用可以向两侧扩展成一段对话，这与 `range` 为产物或
文件选区回答的是同一个问题。

`@result:` 与 `^` 跑在新的派生表 `chatResultIndex` 上——每个工具结果一行精简记录：
跑了什么、关于什么、输出的真实体积，以及一段钳过的摘录。是**句柄**，不是输出本身。

产物与画布文档**刻意不入索引**。它们的消息 part 携带的是指针（`artifactId` 加一份标题
快照），正文活在 `@artifact:` 已经在实时读取的 store 里；在这里再存一行，会让同一个
文档有两道门两份正文，而被内联进提示词的偏偏是过期的那份。

### 一次遍历，三张派生表

带 `parts` 读 `messages` 是建索引里昂贵的那一半——一个回填批次是 500 行完整记录。
`chatResultIndex` 和 `mentionLinks` 搭在已经付过这笔钱的那次遍历上，而不是再开两次。
一次遍历只有一个游标，这正是每次 schema 升级都要回卷 `chatSearchState` 的原因：在
回填已经跑完的安装上，保留 complete 会让新索引永远建不起来。重新投影搜索文本按
`messageId` 幂等且在空闲时运行，所以代价是一次重复遍历，不是一个错误的索引。

三张表都按会话对账而不是追加，理由相同：编辑过或截断过的一轮会**移除**消息和引用。

### 快照保持冻结，并说出自己过期

暂存的引用是快照——在选择器里读到的就是模型拿到的，也是 chip 唯一能同步展示的版本。
但记录会在它脚下移动。发送时静默重读是更糟的失败：用户批准了一份正文，发出去的是另一份。

于是正文永不重写，把**偏离**报告给两侧。每个源声明一个不透明的 `fingerprint`——只有源
知道「变了」对自己意味着什么，这里唯一要问的是两个字符串是否仍然相等。chip 长出徽章和
一键重读；提示词块加一行写明快照时间。不声明 fingerprint 的 kind、以及 fingerprint
出现之前暂存的 chip，都不做标记：**无法校验不等于已经改变**，把它报成过期只会训练人
忽略这个徽章。

### 引用记录被反着读出来

`mentionLinks` 从 `metadata.mentions` 派生——没有新的写入路径。会话头部多了一枚自隐藏的
「被 N 个对话引用」徽章，与分支、导入徽章并列；记忆和 Issue 得到同一份列表的内联版本，
在那里「到底有没有东西在用它」决定这条记录是否还值得留着。每一行都落到发生引用的那一轮。

`getMessageMentions` 的遗留文本回退在这里**刻意不用**：`resolveMentions` 把每个无法解析
的 token 都判为**文件**，重新解析散文会把文件反向链接塞满从来不是文件的东西，同时一条
实体引用也救不回来——chip 式的选择在文本里根本没留下 token。

### ⌘K 交接，而不只是导航

可引用的行多出一个次级动作（行内 `@` 控件，或高亮行上的 `⌘↵`）。它是一次**翻译**，
不是第二条暂存路径：行被转换成 `@` 面板产出的同一个 `EntityMentionCandidate`，走同一个
暂存 hook，所以两处产生的引用逐字节相同。`⌘↵` 在不可引用的行上也照样被吃掉——一个在
某些行意味着「引用」、在另一些行意味着「打开」的修饰键，比一个在其余行什么都不做的
修饰键更糟。

### 不可信包装看作者归属，不看存储位置

`issue`、`session`、`message`、`result`、`memory` 会被包装。工具输出按定义就是这个应用
没有写的文本——它读到的文件、抓到的网页、某条命令的 stdout——这让它最有可能携带一条
冲着模型去的指令。`plan` 与 `artifact` 不包装：两者都是在这里写下、准备继续推进的工作，
给一份计划加上「不要遵循」的前缀比没有计划更糟。

## 影响

- 新增一种引用 kind = 一次注册加三处编译器会点名的表项。新增一个触发字符 = 那次注册上
  的一个字段。
- 三张派生表共用一次遍历和一个游标。每张都可重建、都不是真相源，这正是升级时回卷游标
  安全的原因。
- 组合器 `@` 面板每次选择会话只读一次各自的 store（`lib/global-search/cache.ts`，按
  工作区与会话建键），而不是每次击键读一次。
- 暂存引用现在可以**过期但诚实**，不再是静默过期。消费方必须渲染 `stale`；忽略它的界面
  会把这个缺陷重新打开。
- `@result:` 只覆盖工具输出。第二个 `ChatResultKind` 必须带着这个索引真能作为真相源的
  正文再来。
- ContextRef 之前的历史消息没有反向链接。这是诚实的答案，另一个选项是嘈杂的答案。

## 备选方案

**把工具输出并进搜索投影。** 否决：会把散文淹没在工具日志里，而这个语料必须常驻；
而且「说了什么」和「产出了什么」这两个问题，对同一批 parts 的要求正好相反。两个投影，
一次遍历。

**发送时重读暂存引用。** 否决：用户批准的是一份正文，发出另一份比发出一份自己承认过期的
更糟。

**把产物与画布也当作结果入索引。** 否决：它们的 part 是指针，正文活在 `@artifact:`
已经在实时读取的 store 里。

**给结果索引做 `*grams` 预筛。** 不需要。选择器是一次带 limit 的索引游走，搜索路径也在
凑满一页后立刻停止；[ADR-0099](./0099-chat-history-search) 的 phase B 仍然未被认领。
