# 架构决策记录

本目录保存 Cognia 重大架构选择的背景、决策、后果与验证意图。它是决策历史，不是根据当前 runtime 自动生成的实现说明。

## 真理源规则

确认当前行为时，应核对实现、共址测试，以及 runtime 的注册或 bootstrap 入口。ADR 解释为什么选择某个方向。若这些来源发生分歧，面向实现的文档必须描述实际已交付的行为，并明确指出与 ADR 的偏移。

不要为了填补编号空洞而创建 ADR，也不要为了修复序列而重编号既有 ADR。编号是稳定的历史标识符，不代表此前每个编号都存在或全局唯一。

## 目录健康快照

截至 2026-08-12，当前工作树包含：

- 112 个英文 ADR 文件，以及 112 个同 slug 的中文文件。
- 中英文侧栏完全对齐：每个 ADR 文件都在各自 locale 的侧栏中恰好出现一次。
- 三组历史编号冲突：`0013`、`0025` 与 `0026` 均各自对应两份记录。
- 五个未使用编号：`0029`、`0080`、`0099`、`0103` 与 `0105`。不能仅凭编号空洞推断缺少决策。
- 一组仍待复核的旧记录：其 `Proposed` 标签可能已经不能反映当前实现状态。在核对代码、测试和注册入口前，不自动升级状态。

详细证据与后续队列见 [2026-08-12 ADR 缺口审计](../audits/adr-gap-audit-2026-08-12)。

## 状态阅读方式

- **Proposed** 表示方向尚未被确认成仓库已接受的契约。
- **Accepted** 表示决策已被采纳；它本身并不证明所有 rollout phase 都已完成。
- **Implemented** 是部分历史记录使用的措辞；依赖该结论前仍应核对当前代码。
- **Superseded** 或 **removed** 表示记录继续作为历史保留，但在被替换的范围内不再是当前权威。
- partial、experimental、dark launch、default-off 等 rollout 限定词应与决策状态分开理解。

## 维护清单

新增或复核 ADR 时：

1. 分配新编号或描述缺口前，先搜索既有 ADR 与实现。
2. 将决策状态与 rollout 状态分开陈述。
3. 链接能够证明当前契约的实现、测试与注册入口。
4. 在两个 locale tree 与两个 `meta.json` 侧栏中加入相同 slug。
5. 明确记录 supersession 或实现偏移；保留历史文件与 slug。
6. 运行 docs build，验证 MDX、链接与两个 locale route。
