# ADR 0220 — 智能体拥有独立控制台与对话式构建助手

**状态：** 已接受
**日期：** 2026-10-09
**相关：** [ADR-0030](./0030-character-pack-overlay-capability)（角色包）、
[ADR-0199](./0199-an-agent-variant-follows-its-base)（变体）、
[ADR-0198](./0198-a-runs-capabilities-are-granted-not-patched)（单次运行授权）、
[ADR-0204](./0204-a-project-coordinator-runs-threads-in-the-background)（内置工具族模式）、
[ADR-0132](./0132-issue-tracker)（分配给智能体的议题）

## 背景

自定义智能体就是一行 `Character`。此前唯一的管理入口是 设置 → 角色：一个很长的列表加一个上千行的内联表单。
没有任何地方能看到智能体正在做什么、做过什么、花了多少；创建智能体必须手动填写每个字段；
智能体也无法指定自己应该运行在哪个运行时（内置通道、Codex 或 Claude Code 这类本地外部智能体、或主机配置），
因此与它开始的每个新对话都沿用输入框上次使用的运行时。

## 决策

### 1. 唯一入口：`/agents`

智能体列表迁移到顶层 `/agents` 路由，而不是复制一份。设置 → 角色只保留与单个智能体无关的内容
（角色包、知识库），以及一张链接到 `/agents` 的入口卡片。所有打开智能体管理的入口都改为指向新页面，
旧代码随之删除：文件 → 新建智能体（菜单 id `new-agent`，包括 Rust 菜单与命令的一致性）打开
`/agents?new=1`；⌘K `manage-agents` 打开 `/agents`；目标追踪器以编辑模式打开它的智能体；
手机上「我」页面的条目打开 `/agents`；`app/me/characters` 被删除。所有「查看这个智能体任务」的链接
（议题追踪器中聚合的智能体任务行、工作区的「正在工作的智能体」列表）都改为打开该任务所属智能体的看板
（`agentTaskBoardHref`），不再指向已经没有看板的设置分区。`"character"` 类型从
`pendingCreateRequest` 中移除。导航栏新增 `agents` 入口，并补齐界面契约、前往菜单分区和全视口路由。

静态导出：视图是同一路由上的查询参数（`?id=&mode=edit|tasks`、`?new=1|blank|ai`、`?builder=<sessionId>`、
列表的 `?q=&source=&sort=`），沿用 `/squads` 的模式。

### 2. 布局与 Cognia 其他控制台一致

最初尝试的全宽表格和四标签详情页被放弃：它们看起来像另一个产品，并把很少的信息分散在几乎空白的页面上。
控制台改用 `/squads`、`/bots`、`/skills` 的结构：

- **左侧列表。** 每个智能体一行（带实时状态点的头像、名称、仅在工作中或等待处理时显示的状态词、内置徽标、描述）。
  搜索、自带计数的来源筛选、排序菜单，以及带批量栏（导出、删除）的多选模式。同一组件也是手机上的根列表。
- **未选择时的中央区域。** 角色插画、两种创建方式，以及所有未完成的构建草稿。「新建智能体」打开的也是这一视图。
- **智能体概况页，单页呈现。** 顶部是身份信息与操作（对话、分配工作、编辑或「复制后编辑」、生命周期菜单）；
  容器宽度达到 `4xl` 后分为两栏：主栏是动态（进行中的在前，然后是已完成的对话、任务和议题）和进行中的工作；
  侧栏是概况（来源、运行时、模型、权限、工作目录）、最近 30 天统计，以及紧凑排列的能力。`?mode=edit` 会用表单替换概况页。
- **进行中的工作，按议题追踪器的样式绘制。** 未完成的持久任务和分配给它的未完成议题合为一个列表，按最近更新排序，
  使用追踪器自己的状态和优先级图标（任务的映射方式与追踪器的智能体任务来源一致）。议题行打开该议题；
  区块链接到 `/issues?assignee=agent:<id>`，这是新增的深链接，会把议题控制台筛选到该智能体。
- **任务看板是独立模式，不再内嵌。** `?mode=tasks` 让八列看板占满标题栏下方的整个区域。议题页无法替代它：
  追踪器只聚合属于某个工作区的任务，而且是只读的；看板才是运行、暂停、审阅和评论任务的地方。

动态由数据推导，从不单独存储：会话按 `characterId`，智能体任务按 `agentId`，议题按负责人，
费用来自 `sessionUsage`，实时状态来自聊天存储中的运行状态。

### 3. `Character.runtime` —— 智能体的默认运行时

`CharacterRuntimeBinding` 可以是 `builtin`、`external`（智能体 id）或 `host`（配置 id）。
通过唯一的新对话路径（`startNewSession`）与智能体开始对话时，该绑定会应用到会话的运行时通道；
输入框仍可按对话切换。如果绑定在本机无法满足（外部智能体未安装、主机配置已删除、被禁用或无法连接），
会保留应用默认运行时并发出 `agentRuntimeUnavailable` 诊断，回退不会悄无声息。
该字段的账号同步策略为 `local`（外部智能体 id 只在本机有效），也不会导出到角色包中。

### 4. 用 AI 创建

构建对话是一个 `agent-builder` 类型、`visibility: "embedded"` 的 `ChatSession`，
因此不会出现在对话列表、搜索或连接器中。它的 `agentBuilder` 状态包含草稿、修订号、最后编辑者，
以及 `drafting | created`（同步策略为 `local`：草稿引用的是本机的服务器、知识库和运行时）。

- **准备阶段** 复用一个全新的构建会话，并把输入框自带的运行时与模型选择器绑定到它，
  因此每种通道和模型都与聊天中完全一致。这里选择的运行时会成为新智能体的默认运行时。
- **工具** 遵循内置工具族模式：`agent_builder_get_draft`、`agent_builder_list_catalog`
  （技能、插件技能、MCP 服务器、知识库、模型）、`agent_builder_update_draft`（经校验的补丁，
  未知 id 会被拒绝并返回有效集合）以及 `agent_builder_create_agent`。规则集允许除 `create_agent`
  以外的全部工具，`create_agent` 需要询问。这些工具只在构建类型的会话中出现，执行时会再次校验会话类型，
  智能体创建后拒绝继续编辑。外部运行时通过渲染进程工具宿主使用它们。
- **协议** 写入系统提示，当前草稿作为每轮动态片段附加。
- **工作区**：对话与受控的智能体表单并排。构建助手的写入按修订号采纳；用户自己的编辑经防抖写回，
  不会被自己的回显覆盖。「创建并打开」始终可用，因此即使运行时无法调用 Cognia 工具也能完成创建
  （准备页和对话标题会说明需要用户自己填写草稿）。
- 所有开始创建的地方都会列出未完成草稿；放弃草稿会删除它的会话。

### 5. 一个编辑器，一套操作

智能体表单（`CharacterEditor`）移到 `components/agents/editor/`，增加受控模式和运行时字段；
编辑器与 `Character` 之间的转换是一个纯函数模块（`lib/agents/editor-state.ts`）；
所有行操作（复制、创建/脱离/重置变体、导出、角色包更新、删除）是一个 hook（`useAgentActions`）。
左侧列表、概况页、构建助手和手机端都使用它们，没有任何东西被实现两遍。

## 影响

- 设置 → 角色变短：只有角色包、知识库和一个链接。
- 智能体的默认运行时属于智能体本身，而不是上一次运行的对话。
- 一次构建对话按所选模型计费，与普通聊天轮次相同；没有用户批准或点击，不会创建任何东西。
- 构建会话在设计上只存在于本机；同步到其他设备时不会出现草稿。
