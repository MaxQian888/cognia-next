# ADR 0165：环境化成本可见性与优化闭环

**状态：** 已接受
**日期：** 2026-09-03
**建立在：** [ADR-0025](./0025-unified-subscription)、[ADR-0062](./0062-agent-session-import)、[ADR-0090](./0090-unified-agent-execution)、[ADR-0130](./0130-cost-and-trace)、[ADR-0136](./0136-cross-device-placement)

## 背景

CodeBurn 真正有价值的不是又一个仪表盘，而是一条环境化的控制闭环：本地采集用量、在任务栏保持可瞥见、解释哪里低效、给出可回滚的修复，再度量修复是否奏效。这条链路的每一步 Cognia 都已有比 CodeBurn 更强的基础，但底下藏着一个缺陷。

缺陷是：`sessionUsage` 与 `providerCostDaily` 由不同代码在不同时钟上写入。各个界面的记录器写入每轮账本行，而 `recordProviderOutcome` 用自己的成本估算独立累加日汇总。两者从结构上就必然不一致。重试的一轮会就地覆盖账本行，却给汇总加了**第二次**。SDK 成本为 0 但 Token 可定价的一轮，会进汇总而不进账本。这两种情况都无人发现，因为从没有读取方比对过它们，而预算闸门读的正是汇总。

在此之上，托盘只能回答「套餐还剩多少」，无法回答「我花了多少」，而后者恰恰是菜单栏读数最擅长的问题。任何想回答它的界面都得自己推导总额，并在边界上与其他界面产生分歧。

## 决策

1. **账本只有一个写入方。** `lib/usage/usage-ledger.ts` 是提交用量行的唯一路径。成本冻结一次，先在同一事务内读取旧行，使覆盖写入应用增量而不是再加一次，两张表要么一起提交要么都不提交。`providerCostDaily` 变成 `sessionUsage` 的投影，而不再是并行的猜测。`recordProviderOutcome` 保留健康度、限流、熔断与亲和性职责，不再触碰成本。一次性的空闲重建会收敛已经漂移的投影，失败时不写标记，下次启动重试。`usage-ledger.test.ts` 对每个来源断言守恒。

2. **所有环境化界面读同一份投影。** `UsageGlanceSnapshotV1` 是托盘标题、悬浮提示、菜单、快捷面板、用量边栏、CLI 与 MCP 工具共同读取的对象。它在结构上强制两件事：未知成本永不按 0 计入，因此部分定价的区间渲染为下限、完全无定价的区间渲染为破折号；面向操作系统的对象不含任何会话内容，只有数字、ID 与枚举，因为它会被推送进 Rust 进程并绘制到菜单栏上。

3. **外部花费被索引、被隔离、永不进预算。** `AgentSessionSourceAdapter` 上的 `scanUsage` 接缝加上通用的有界扫描器，让全部 11 个一方会话来源无需改动适配器即可索引外部花费。它写入的每一行都带 `imported: true`，正是预算早已排除的谓词。`usageSourceStates` 记录扫描降级的原因，使「读不到这个工具」不再渲染成「这个工具没有花费」。全部工具范围需显式开启，也是唯一会读取其他 Agent 文件的开关。

4. **用量边栏是第二个环境化界面，不是第二个真相源。** 它复用灵动岛的悬浮窗配方，并锚定工作区而非整块显示器边框。摆放数学是纯函数，在所有平台上跑单测，每个坐标都对齐到整像素，而 CodeBurn 记录的空闲重排漂移正来自这里。可见性只有一个真相源，即渲染端的 `enabled` 偏好：Rust 持久化几何形状，刻意不持久化可见性，任何一侧写入失败都无法让两者分歧。Linux 上报能力而不是假设能力，拒绝客户端摆放窗口的 Wayland 会话会得到一张禁用的卡片，说明原因并指出托盘仍然可用。

5. **每一条效率结论都带上证据。** 现有证据支撑不了的指标一律返回 `null` 并给出具名缺口，而不是读起来像测量结果的 0。产出归因把花费接到 Task Workspace 的采纳账本上，后者记录了接受、部分接受、拒绝与回滚。缺少证据永远不等于被拒绝，覆盖率与每个分桶一同上报，`canJudgeWaste` 独立成函数，任何调用方都不能靠瞄一眼比例得出该结论。导入的会话永远是 `unknown`，不能被判定为浪费。

6. **建议是确定性的，且可回滚。** 没有任何检测器调用模型：一条产出本身要花钱、且在相同数据上重跑会给出不同答案的建议，不值得据以行动。每条结论都说明其影响是实测还是估算，并携带所依据的轮数、单元数与天数。应用 Cognia 自有设置走 compare-and-swap，比对预览时看到的值。度量需要至少三天与二十个可比轮次才会给出评级，达不到时结论是 `inconclusive` 而不是 `no-effect`。自动回滚需显式开启，且只在当前值仍与该动作写入的哈希一致时才触碰。

7. **外部 Agent 只读。** `usage_query`、`session_health` 与 `optimization_findings` 位于新增的 `usage:read` 权限之后，默认关闭。会话 ID 做假名化返回，修复背后的设置键被隐去，因此 Agent 能讨论花费，却学不到项目内容，也无法重新配置本应用。

## 影响

- Dexie **v218**：新增 `usageSourceStates`（派生、仅本机、可重建），`sessionUsage` 增加 `sourceId` 与 `[sourceId+sourceSessionId]` 索引，以及五个增量字段。
- 新增 `gateway` 用量来源。网关流量现在写入规范账本行，而不再经遥测汇聚器进入日汇总。
- 升级后托盘默认值不变：套餐额度、仅本应用。花费读数与全部工具范围都需显式开启。
- 空闲安装不做任何轮询与文件读取。本地花费走 Dexie 实时查询，外部扫描只在进入该范围、显式刷新或来源失效时运行。
- **声明式休眠：** 应用/撤销动作机已完整，但当前没有任何检测器产出 `fix` 类结论，因此尚无路径进入它。该事实由一条测试钉住，第一个加入修复的人应更新它而不是删除它。

## 非目标

对齐 CodeBurn 全部 41 个供应商、再起一个 MCP 服务、再打一个桌面二进制、让外部花费影响 Cognia 预算、把原始用量同步给伴侣端、自动修改其他 Agent 的全局配置，以及仅凭时间戳给出的生产力结论。CodeBurn 是设计与算法上的先例。任何直接移植的 MIT 代码都必须保留署名。
