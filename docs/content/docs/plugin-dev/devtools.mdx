# Devtools

Cognia's Plugin DevTools is a Dev Session workbench. It presents one connected flow instead of
independent build, hot-reload, log, and profiler panels:

`select project → build → install → quiesce old runtime → activate → verify`

## Enable Developer Mode

Open **Settings → Plugins** and enable **Developer Mode**. This is the only feature gate; it is
stored as `pluginSettings.developerModeEnabled`. Enabling it permits trusted local plugin code to
run. The legacy local-storage key is migrated once at boot and is not a second source of truth.

Web builds keep manifest validation and explanatory UI available, but starting or reloading a
runtime requires Cognia Desktop.

## Start a Dev Session

Choose a plugin project and select **Start**, or run:

```bash
cognia plugin dev
```

The CLI registers its watcher before immediately running attempt 1. Later changes are debounced
for 250 ms, builds stay serial, and one pending build is retained when files change during a build.
Build or activation failures do not stop watch mode; fix the problem and the next change retries in
the same session.

The App launcher adds `--session-id <uuid>` before opening the integrated terminal. That association
is memory-only, so App-started sessions can expose **Open terminal**, **Stop**, and **Restart**. An
external CLI session is observable but does not show terminal actions the App cannot perform.

## What counts as success

Installing or scanning a bundle is not a successful reload. The bridge returns success only when:

- the artifact manifest ID matches the requested plugin;
- Rust installed the artifact and calculated its deterministic SHA-256 revision;
- the old runtime quiesced safely;
- the renderer observed `actualState: active` with no dirty or pending transition;
- lifecycle `generation` is greater than `previousGeneration`; and
- the proof carries the installed artifact revision and package version.

Frontend, Python, hybrid, WASM, and VS Code extension plugins use the same capability decision. A
runtime that cannot be safely unloaded returns `restart_required`; Web/mobile returns `unsupported`.
Neither case is presented as hot-reload success.

`cognia plugin dev --once --json` emits schema version 1 with `outcome`, `activationProof`, and a
structured `{code, message, action, retriable}` error. A host that returns legacy `{ok: true}` without
an activation proof fails closed as `host_unverified`. Without a running App endpoint the build still
finishes, but reload is reported as `skipped: no-endpoint` and `--once` returns non-zero because no
runtime activation was proven.

## Activity and diagnostics

The workbench retains up to 10 in-memory sessions and 50 attempts per session. Heartbeats arrive
every 5 seconds; a session becomes stale after 15 seconds without one. The current attempt timeline
shows build, install, discovery, quiesce, activation, and verification stages. Successful attempts
show the generation and artifact revision.

Runtime logs come from the structured plugin logger and are filtered by `pluginId + generation`.
Raw `console.*` output that cannot be attributed to a runtime generation is not presented as a
complete plugin log. Advanced diagnostics contains only implemented lifecycle state, trigger audit,
and extension-point diagnostics.

The unpacked-plugin dropzone uses the actual dropped directory and sends it through the same
manifest, conflict, permission, and configuration review as a picked directory.

## Stop and recovery

A single Ctrl+C requests graceful shutdown, interrupts an active child build, sends the terminal
session event, and exits with code 130. App **Stop** sends that interrupt once. Dirty or stuck loaders
return an actionable `restart_required` result instead of claiming success.
