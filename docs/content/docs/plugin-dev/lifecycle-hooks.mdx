# Lifecycle Hooks

Plugins subscribe to host lifecycle events inside `onActivate()`. The hooks system (`lib/plugin/messaging/hooks-system.ts`) dispatches events to all registered listeners.

## Available hooks

| Hook                    | When it fires                              | Payload                                  | Can cancel?                             |
| ----------------------- | ------------------------------------------ | ---------------------------------------- | --------------------------------------- |
| `chat.before-send`      | Before a user message is sent to the AI    | `{ sessionId, content, characterId }`    | Yes — return `{ cancel: true, reason }` |
| `chat.after-response`   | After the AI finishes streaming a response | `{ sessionId, messageId, content }`      | No                                      |
| `twin.ingest.completed` | When a TwinSource finishes ingest          | `{ sourceId, jobId, chunkCount }`        | No                                      |
| `connector.inbound`     | When ConnectorBus receives an event        | `{ platform, conversationKey, content }` | No                                      |
| `plugin.activated`      | When any plugin is activated               | `{ pluginId }`                           | No                                      |
| `plugin.deactivated`    | When any plugin is deactivated             | `{ pluginId }`                           | No                                      |

## Subscribing

```ts title="main.js"
export async function onActivate(ctx) {
  // Chat before-send: prepend a system hint
  ctx.hooks.on("chat.before-send", async (payload) => {
    if (payload.characterId === "my-character") {
      payload.content = `[Plugin hint] Consider using tool X.\n\n${payload.content}`
    }
  })

  // Chat after-response: log to plugin storage
  ctx.hooks.on("chat.after-response", async (payload) => {
    await ctx.storage.set(`last-response-${payload.sessionId}`, payload.messageId)
  })

  // Twin ingest: trigger re-distill
  ctx.hooks.on("twin.ingest.completed", async (payload) => {
    if (payload.chunkCount > 100) {
      ctx.notifications.create({
        title: "Twin ingestion complete",
        message: `Twin source ${payload.sourceId} ingested ${payload.chunkCount} chunks`,
        type: "success",
      })
    }
  })

  // Scheduled work is not a hook. Register a handler for your own tasks and
  // observe their runs with ctx.scheduler (see "Scheduled tasks" below).
  ctx.scheduler.registerHandler("dailySync", async () => {
    await runDailySync(ctx)
    return { success: true }
  })
}
```

## Scheduled tasks

There is no `scheduler.job.run` hook. A scheduled task reaches a plugin in one of three ways:

- **Your own tasks run your handler.** Declare the `scheduler` capability, register a handler with `ctx.scheduler.registerHandler(name, handler)`, and create tasks with `ctx.scheduler.createTask` or `manifest.scheduledTasks`. The handler is the code that runs when the task fires.
- **Observe your own tasks' runs** with `ctx.scheduler.onExecution(listener)`, which reports `started`, `completed`, `failed`, `cancelled` and `skipped` for your plugin's tasks only, and is removed on deactivate.
- **Observe every scheduled task on the host** with the plugin hooks `onScheduledTaskStart(taskId, executionId)`, `onScheduledTaskComplete(taskId, executionId, result)` and `onScheduledTaskError(taskId, executionId, error)`. These fire for every task, not only yours, and cannot cancel a run.

See [Scheduler APIs](../en/plugin-dev/scheduler).

## Cancelling events

Only `chat.before-send` supports cancellation. Return a cancellation object:

```ts
ctx.hooks.on("chat.before-send", async (payload) => {
  if (containsForbiddenWords(payload.content)) {
    return { cancel: true, reason: "Content violates plugin policy" }
  }
})
```

The chat UI shows the reason to the user.

## Cleanup on deactivate

```ts
export async function onDeactivate(ctx) {
  // ctx.* subscriptions and registrations are removed automatically.
  // Only clean up resources that were allocated outside the Plugin API.
}
```

## Hook ordering

Hooks run in registration order. If multiple plugins register the same hook, they execute sequentially. A cancellation in `chat.before-send` stops the chain.
