# Connector Adapters

TypeScript plugins can contribute a `PlatformAdapter` through
`manifest.connectors[]`. The host registers the returned object with the same
`ConnectorBus` used by built-in adapters, so policy, routing, durable outbound
delivery, and execution-run presentation stay shared.

## Declaration

The `factory` value is the name of a function exported by the plugin entrypoint.

```json title="cognia-plugin.json"
{
  "id": "com.example.acme-chat",
  "type": "frontend",
  "capabilities": ["connectors"],
  "connectors": [
    {
      "type": "acme-chat",
      "factory": "createAcmeChatAdapter",
      "transportModes": ["forward-ws"],
      "configSchema": {
        "type": "object",
        "properties": {
          "endpoint": { "type": "string" }
        }
      }
    }
  ]
}
```

## Adapter factory

The factory receives plugin identity and the manifest contribution. It returns
the complete `PlatformAdapter`; inbound events are emitted through the
`AdapterContext` passed to `start`.

```ts title="src/index.ts"
import {
  buildA2UICapabilityMatrix,
  type AdapterFactory,
} from "@cognia/plugin-sdk/api/connector"

export const createAcmeChatAdapter: AdapterFactory = ({ pluginId, connectorDef }) => {
  let socket: WebSocket | undefined
  let state: "down" | "running" = "down"

  return {
    id: `${pluginId}:${connectorDef.type}`,
    meta: {
      type: "acme-chat",
      displayName: "Acme Chat",
      version: "1.0.0",
      capabilities: [],
      transportModes: ["forward-ws"],
      configSchema: connectorDef.configSchema,
    },

    async start(ctx) {
      socket = new WebSocket("wss://configured-by-your-adapter")
      socket.onmessage = (message) => {
        const inbound = JSON.parse(String(message.data))
        void ctx.emit({
          messageId: inbound.id,
          adapterId: ctx.adapterId,
          selfId: inbound.botId,
          platform: "acme-chat",
          kind: "create",
          conversationKey: `acme-chat:${ctx.adapterId}:${inbound.roomId}`,
          conversationRef: {
            platform: "acme-chat",
            adapterId: ctx.adapterId,
            roomId: inbound.roomId,
          },
          sender: {
            id: `acme-chat:${ctx.adapterId}:${inbound.senderId}`,
            platform: "acme-chat",
            adapterId: ctx.adapterId,
            remoteUserId: inbound.senderId,
          },
          channel: {
            id: inbound.roomId,
            kind: "group",
            platformChannelId: inbound.roomId,
          },
          mentions: { selfMentioned: false, users: [] },
          timestamp: inbound.timestamp,
          plainText: inbound.text,
          segments: [{ type: "text", text: inbound.text }],
          raw: inbound,
          channelData: {},
        })
      }
      state = "running"
    },

    async stop() {
      socket?.close()
      state = "down"
    },

    health() {
      return { state }
    },

    a2uiCapability: () => buildA2UICapabilityMatrix({ Text: "native" }),

    async send(request) {
      socket?.send(JSON.stringify(request))
      return { ok: true }
    },
  }
}
```

The exact inbound and outbound structures are exported by the connector types.
Conversation keys must be stable and include enough account and topic identity
to prevent two remote conversations from sharing a local session.

## Durable Agent and workflow presentation

All execution types—Agent, Workflow, Plan, Goal, Team, and Scheduled—flow
through one host-owned chain:

`ExecutionRun → RunProjectionSnapshot → RunPresentationDriver`

A TypeScript adapter can add `runPresentation` to render the safe snapshot with
a platform-native timeline. The plugin bridge preserves the driver object
unchanged. Do not create a plugin-specific run model or derive activities from
raw prompts and tool payloads.

```ts title="src/fake-run-driver.ts"
import type {
  RunPresentationDriver,
  RunPresentationRef,
} from "@cognia/plugin-sdk/api/connector"

export const fakeRunDriver: RunPresentationDriver = {
  capabilities: {
    textStreaming: true,
    messageEditing: true,
    interactiveControls: false,
  },

  async open(target, snapshot, options) {
    const ref: RunPresentationRef = {
      platformMessageId: `run-${snapshot.runId}`,
      opaqueState: { revision: snapshot.revision },
    }
    await options?.checkpoint?.(ref)
    return ref
  },

  async update(ref, snapshot, options) {
    const next = {
      ...ref,
      opaqueState: { revision: snapshot.revision },
    }
    await options?.checkpoint?.(next)
    return next
  },

  async finish(ref, snapshot, options) {
    const frozen = {
      ...ref,
      opaqueState: { revision: snapshot.revision, frozen: true },
    }
    await options?.checkpoint?.(frozen)
    return frozen
  },
}
```

`RunProjectionSnapshot.activities` contains stable activity IDs, deterministic
status/category labels, optional redacted targets, and timestamps. The host
excludes reasoning, raw prompts, tool arguments, commands, queries, URL
parameters, file contents, raw outputs, and error bodies before the driver is
called. A driver must keep that boundary intact.

`finish` freezes the progress presentation. The final assistant answer is sent
separately through the normal outbound path in the same conversation or topic.

## Runtime capabilities and fallback

Declare `runtimeCapabilities` beside the driver. These values describe the
platform's real behavior; a platform message ID alone does not mean a message
can be edited.

```ts
return {
  // ...the base PlatformAdapter members
  runPresentation: fakeRunDriver,
  runtimeCapabilities: {
    topicIsolation: "native",
    unmentionedDelivery: true,
    historyPagination: false,
    liveSteer: true,
    textStreaming: true,
    componentMutation: false,
    fullReplacement: false,
    messageEditing: true,
    appendFallback: true,
    interactiveControls: false,
    followUpBubbles: false,
    staticMenus: false,
    suggestedPrompts: false,
    ambiguousDelivery: "remote_idempotent",
  },
}
```

When `runPresentation` is absent or fails for the current run, the host uses the
same safe activity projection and selects the best available delivery mode:

1. native presenter
2. generic A2UI card edit
3. throttled append-only updates
4. terminal status only

A native failure is fixed to the generic path for that run to prevent duplicate
timelines. The next run may try the native driver again.

## Python connector v1

Python-backed connectors support the serializable `describe`, `start`, `stop`,
and `send` bridge. They intentionally do not expose `runPresentation` or
`runtimeCapabilities` in v1 because driver functions and checkpoints cannot
cross that process boundary safely. They receive the generic A2UI/plain-text
fallback automatically.

## Lifecycle

1. On plugin enable, the host resolves every declared factory and registers its
   returned adapter.
2. On adapter start, the host supplies `AdapterContext`, including the inbound
   `emit` callback and cancellation signal.
3. Inbound events enter the shared connector routing pipeline.
4. Outbound messages and final answers use the durable outbound queue.
5. Execution updates use the native driver or the capability-aware generic
   fallback.
6. On plugin disable or uninstall, the host stops and unregisters the adapter.
