# P2c admission inventory

`S` = `/v1/orgs/{org_id}/chat-sessions/{session_id}`;
`D` = `/v1/orgs/{org_id}/canvas-documents/{document_id}`;
`W` = `/v1/orgs/{org_id}/workspaces/{workspace_id}`.

New admission requires `available`. Existing writes accept `available` and
`existing-only`; `read-only` refuses them. Recovery bypasses rollout, while
retaining ordinary authorization. A supplied protocol below the stored resource
contract refuses mutations (including recovery mutations); read tickets remain
reads. The legacy chat 426 floor is unchanged.

Every mutation in the three scoped routers is classified below. Store methods
read policy inside their existing memory lock / PostgreSQL transaction; PostgreSQL
resource admission locks the session/document before reading the complete bounded
policy set in one statement snapshot, including all transitive prerequisites. Byte upload
and cursor checks use the same store admission helper before publishing bytes or
frames. Metadata commit / file dispatch rechecks admission in its own transaction.
Canvas sockets retain the REST ticket issuer's protocol on every frame; a ticket
issued without the header retains legacy `None`, independently of handshake
headers. Chat streams accept no inbound writes. A blocked file write remains
pending and eligible for a later poll after rollout recovers; the poll scans past
it to find authorized reads. Contract incompatibility and policy-store failure
remain errors and are not skipped.

All scoped GET routes (lists, content/history, run state, audit, export
authorization, live-file reads, streams, Canvas sync/presence) bypass rollout.
There is no reaction-specific mutating handler in the current chat router;
`append_event` accepts only message.created/corrected/redacted. No route was added
for an operation the existing protocol does not support.

`org-governance` is client presentation only: existing org/workspace membership,
invitation, ownership, file-sharing-policy and notification administration retain
their existing authorization, with no new server feature gate. `environment-binding`
has no collab-server route; its Host owner enforces P1. The process master switches
still unmount chat/Canvas routes when disabled (A05); rollout pause/kill do not.

The new admission module keeps transport context and transactional enforcement out
of the pure rollout evaluator. Migration 0017 adds the pinned columns; the named
protocol constant supplies creation values and `/health`.
